# 提供给数据中心的销售订单零件链路只读追踪说明

> 编制日期：2026-08-27  
> 适用对象：数据中心只读数据库监测、销售订单零件状态追踪  
> 追踪范围：销售订单零件在 `MES 物料号 -> WMS 锁库存 -> MES 待生产下发` 这条链路中的状态  
> 使用方式：数据中心使用 QPO 只读数据库账号查询，不写入、不回调、不直接修改业务表

## 1. 结论摘要

数据中心要追踪“一个销售订单下的一个零件当前走到哪一步”，应以 QPO 的提单行 `order_delivery_ticket.id` 作为最稳定的零件追踪 ID，即 `ticket_id`。

当前 QPO 销售订单导入后会自动生成提单行。后续 MES 获取物料号、WMS 锁库存、MES 待生产下发都围绕提单行和锁库 allocation 行推进，因此只读追踪建议按以下主链路理解：

```text
sales_order_header / sales_order_item
  -> order_delivery_ticket
  -> MES 物料号状态：order_delivery_ticket.material_no / mes_sync_status
  -> WMS 锁库状态：order_delivery_ticket.wms_allocate_status + wms_reservation_*
  -> MES 生产下发状态：order_delivery_ticket_allocation.mes_production_status
```

业务主阶段建议使用以下口径：

| 阶段编码 | 阶段名称 | 判定口径 |
| --- | --- | --- |
| `NEED_MES_MATERIAL` | 未获取物料号 | `material_no` 为空，或 `mes_sync_status <> SUCCESS`。 |
| `NEED_WMS_RESERVE` | 已获取物料号，未锁库存 | `material_no` 非空且 `mes_sync_status = SUCCESS`，但 `wms_allocate_status <> SUCCESS`。 |
| `WMS_RESERVED_NEED_MES_DISPATCH` | 锁库存成功，未下发 MES | `wms_allocate_status = SUCCESS`，且存在 `PRODUCTION_REQUIRED` 待产 allocation 未全部 `mes_production_status = SUCCESS`。 |
| `MES_DISPATCH_SUCCESS` | 已下发 MES 成功 | `PRODUCTION_REQUIRED` allocation 全部 `mes_production_status = SUCCESS`。 |
| `WMS_COVERED_NO_MES_DISPATCH` | WMS 已覆盖，无需 MES 下发 | `wms_allocate_status = SUCCESS`，但没有 `PRODUCTION_REQUIRED` allocation；表示库存或在产覆盖已经满足，不会进入 MES 待生产下发。 |

最后一类是 QPO 现行实现中的正常终态。因为只有 `allocation_type = PRODUCTION_REQUIRED` 的行会下发 MES 生产，如果一个零件被库存或在产完全覆盖，它不会有 MES 生产下发记录，不能把它误判为“卡在未下发 MES”。

## 2. 唯一零件识别方法

### 2.1 推荐方法：`ticket_id`

最推荐给数据中心保存和回查的唯一键是：

```text
order_delivery_ticket.id AS ticket_id
```

原因：

- QPO 的已提零件、WMS 锁库、锁库结果拆分、待产下发都以 `ticket_id` 为主线。
- WMS 结果拆分表 `wms_reservation_ticket.ticket_id` 指向它。
- 锁库结果表 `order_delivery_ticket_allocation.ticket_id` 指向它。
- MES 物料号批次行 `mes_material_batch_item.ticket_id` 指向它。

只要数据中心能拿到 `ticket_id`，就可以无歧义追踪一条提单零件。

### 2.2 销售订单行方法：`sales_order_item_id`

如果数据中心从销售订单行视角追踪，可以使用：

```text
sales_order_header.id + sales_order_item.id
```

在当前销售订单导入场景下，通常一个销售订单行会生成一个提单行。为了兼容系统实际实现中的两种来源关系，建议使用下面的映射规则找到 `ticket_id`：

1. 优先使用 `sales_order_item.source_ticket_id = order_delivery_ticket.id`。
2. 若 `source_ticket_id` 为空，则使用销售订单直接提单关系：

   ```text
   order_delivery_ticket.source_type = 'SALES_ORDER'
   order_delivery_ticket.source_order_id = sales_order_header.id
   order_delivery_ticket.source_item_id = sales_order_item.id
   ```

说明：QPO 运行时 WMS 和 MES 生产下发解析销售订单来源时也是先识别 `source_ticket_id`，再回退到 `source_type/source_order_id/source_item_id`。

### 2.3 业务单据行方法：销售订单号 + 行号

如果数据中心侧不保存 QPO 内部 ID，可以使用业务字段定位后再查出 `ticket_id`：

```text
COALESCE(sales_order_header.document_no, sales_order_header.sales_order_no) + sales_order_item.line_no
```

注意：

- `document_no` 是正式销售订单号优先字段，MES 生产下发使用 `document_no -> sales_order_no`。
- `sales_order_no` 是 QPO 销售订单导入后的订单号。
- WMS 锁库请求的 `saleNo` 使用客户订单号，即 `sales_order_item.customer_order_no -> sales_order_header.customer_order_no -> ticket.customer_order_no`。
- 因此数据中心展示时可以同时显示 `document_no`、`sales_order_no`、`customer_order_no`，但不要把三者混成同一个字段。

### 2.4 展示兜底方法：客户订单号 + 客户项目号 + 图号版本

以下组合只建议用于页面展示和人工核对，不建议作为程序唯一键：

```text
customer_order_no + customer_project_no + part_no + version + line_no
```

原因是同一客户订单下可能存在相同图号版本、不同拆分行或后续业务变更。数据中心如果必须使用该方法，应先查询出唯一 `ticket_id` 后再进入后续追踪。

### 2.5 不建议方法

不要单独使用以下字段判定一个唯一零件：

| 字段 | 不建议原因 |
| --- | --- |
| `material_no` / `productCode` | 多个销售订单、多个提单行可能共用同一 MES 物料号。 |
| `part_no` | 同一图号可能多版本、多订单复用。 |
| `wms_reservation_batch.external_biz_id` | 这是 WMS 请求批次 ID，一个批次可包含多个 ticket。 |
| `mes_integration_batch.biz_id` | 这是 MES 批次 ID，一个批次可包含多个物料或待产行。 |
| `mes_production_request_id` | 这是 MES 待生产下发行请求 ID，只有待产 allocation 才有。 |

## 3. 关键表关系

| 业务对象 | 表 | 关键字段 | 说明 |
| --- | --- | --- | --- |
| 销售订单头 | `sales_order_header` | `id`, `sales_order_no`, `document_no`, `customer_order_no`, `u9_sync_status` | 销售订单维度入口。U9 同步状态不是本链路阶段判定字段，只可作背景展示。 |
| 销售订单行 | `sales_order_item` | `id`, `sales_order_id`, `line_no`, `source_ticket_id`, `part_no`, `version` | 销售订单零件行。 |
| 提单零件 | `order_delivery_ticket` | `id`, `source_type`, `source_order_id`, `source_item_id`, `material_no`, `mes_sync_status`, `wms_allocate_status` | 链路追踪主表。 |
| MES 物料批次 | `mes_integration_batch` | `id`, `batch_type`, `biz_id`, `status` | `batch_type = MATERIAL_PREPARATION` 表示物料号获取批次。 |
| MES 物料批次行 | `mes_material_batch_item` | `batch_id`, `ticket_id`, `line_request_id`, `status`, `product_code` | 可查看物料号获取请求和回调进度。 |
| WMS 锁库批次 | `wms_reservation_batch` | `id`, `external_biz_id`, `sale_order_id`, `sale_order_no`, `status` | QPO 调 WMS 的批量请求流水。 |
| WMS 锁库物料行 | `wms_reservation_item` | `batch_id`, `product_code`, `reserve_count`, `frozen_count`, `in_production_count`, `surplus_count` | WMS 按物料聚合返回的数量。 |
| WMS 锁库拆分行 | `wms_reservation_ticket` | `batch_id`, `ticket_id`, `stock_frozen_count`, `in_production_count`, `surplus_count`, `status` | QPO 把 WMS 聚合结果拆回每个 ticket。 |
| 锁库 / 待产结果 | `order_delivery_ticket_allocation` | `ticket_id`, `allocation_type`, `qty`, `mes_production_status` | WMS 成功后生成。只有 `PRODUCTION_REQUIRED` 会进入 MES 待生产下发。 |
| MES 生产批次 | `mes_integration_batch` | `id`, `batch_type`, `biz_id`, `status` | `batch_type = PRODUCTION_DEMAND` 表示待生产下发批次。 |
| MES 生产批次行 | `mes_production_batch_item` | `batch_id`, `allocation_id`, `sale_order_no`, `sale_order_item_no`, `product_code`, `status`, `mes_plan_no` | 可查看待产行下发到 MES 的批次结果。 |

## 4. 状态字段口径

### 4.1 MES 物料号阶段

主字段在 `order_delivery_ticket`：

| 字段 | 含义 |
| --- | --- |
| `material_no` | MES 返回并确认的物料号。 |
| `mes_sync_status` | 物料号获取状态。常见值：`PENDING`, `PROCESSING`, `CALLBACK_PENDING`, `SUCCESS`, `FAILED`, `RESULT_UNKNOWN`。 |
| `mes_request_id` | QPO 物料号行请求 ID。 |
| `mes_external_task_id` | MES 或数据中心返回的外部追踪号。 |
| `mes_synced_at` | QPO 确认物料号成功时间。 |
| `mes_callback_received_at` | MES 回调到达 QPO 时间。 |
| `mes_sync_message`, `mes_callback_message` | 摘要消息。 |

判定：`material_no` 非空且 `mes_sync_status = SUCCESS` 才表示已获取物料号。

### 4.2 WMS 锁库存阶段

主字段在 `order_delivery_ticket`：

| 字段 | 含义 |
| --- | --- |
| `wms_allocate_status` | 锁库应用到 QPO 后的主状态。成功为 `SUCCESS`。 |
| `wms_allocate_message` | WMS 锁库摘要消息。 |
| `wms_allocated_at` | QPO 本地应用 WMS 结果成功时间。 |

批次细节在 `wms_reservation_batch`、`wms_reservation_item`、`wms_reservation_ticket`：

| 状态 | 含义 |
| --- | --- |
| `RESERVED` | 本地已预留请求流水，尚未完成外部发送。 |
| `SUBMITTING` | 正在请求 WMS。 |
| `RESPONSE_RECEIVED` | 已收到 WMS 响应，待本地 apply。 |
| `SUCCESS` | WMS 响应已成功应用到 QPO。 |
| `FAILED` | 明确失败。 |
| `RESULT_UNKNOWN` | 外部结果不确定，需要按 `external_biz_id` 和请求快照核对或重放。 |
| `APPLY_FAILED` | WMS 响应已到达，但 QPO 本地写入 allocation 失败，需本地修复或重放 apply。 |

数量口径：

| 字段 | 含义 |
| --- | --- |
| `wms_reservation_item.frozen_count` | WMS 总冻结量。 |
| `wms_reservation_item.in_production_count` | 在产覆盖量。 |
| `wms_reservation_item.surplus_count` | 待生产缺口量。 |
| `wms_reservation_ticket.stock_frozen_count` | QPO 拆回 ticket 后的现货锁库量。 |
| `wms_reservation_ticket.in_production_count` | QPO 拆回 ticket 后的在产覆盖量。 |
| `wms_reservation_ticket.surplus_count` | QPO 拆回 ticket 后的待生产量。 |

WMS 返回聚合物料后，QPO 会拆成三类 allocation：

| `allocation_type` | 中文含义 | 是否下发 MES 生产 |
| --- | --- | --- |
| `IN_STOCK_LOCK` | 现货锁库 | 否 |
| `IN_PRODUCTION_LOCK` | 在产覆盖 | 否 |
| `PRODUCTION_REQUIRED` | 待生产 | 是 |

### 4.3 MES 待生产下发阶段

待生产下发只看 `order_delivery_ticket_allocation` 中：

```text
allocation_type = 'PRODUCTION_REQUIRED'
```

主字段：

| 字段 | 含义 |
| --- | --- |
| `mes_production_status` | 生产下发状态。常见值：`PENDING`, `PROCESSING`, `SUCCESS`, `FAILED`, `RESULT_UNKNOWN`。 |
| `mes_production_request_id` | QPO 待生产行请求 ID。 |
| `mes_production_external_id` | MES 返回的生产计划号或记录 ID。 |
| `mes_production_synced_at` | QPO 确认待生产下发成功或失败的时间。 |
| `mes_production_message` | 摘要消息。 |

批次细节可查 `mes_production_batch_item`，通过 `allocation_id = order_delivery_ticket_allocation.id` 关联。

## 5. 推荐总览 SQL

以下 SQL 面向 PostgreSQL，只读账号可直接查询。参数按数据中心实际能力替换，例如 `:sales_order_no`、`:document_no`、`:ticket_id`。

```sql
WITH sales_order_part AS (
    SELECT
        so.id AS sales_order_id,
        so.sales_order_no AS qpo_sales_order_no,
        so.document_no AS official_sales_order_no,
        so.customer_order_no AS header_customer_order_no,
        so.customer_project_no AS header_customer_project_no,
        so.customer_name,
        so.u9_sync_status,
        soi.id AS sales_order_item_id,
        soi.line_no AS sales_order_line_no,
        soi.part_no,
        soi.version,
        soi.qty AS sales_order_item_qty,
        soi.customer_order_no AS item_customer_order_no,
        soi.customer_project_no AS item_customer_project_no,
        t.id AS ticket_id,
        t.qty AS ticket_qty,
        t.material_no,
        COALESCE(NULLIF(BTRIM(t.mes_sync_status), ''), 'PENDING') AS mes_sync_status,
        t.mes_sync_message,
        t.mes_request_id,
        t.mes_external_task_id,
        t.mes_synced_at,
        t.mes_callback_received_at,
        COALESCE(NULLIF(BTRIM(t.wms_allocate_status), ''), 'PENDING') AS wms_allocate_status,
        t.wms_allocate_message,
        t.wms_allocated_at,
        t.customer_order_no AS ticket_customer_order_no,
        t.customer_project_no AS ticket_customer_project_no
    FROM sales_order_header so
    JOIN sales_order_item soi ON soi.sales_order_id = so.id
    LEFT JOIN LATERAL (
        SELECT ticket.*
        FROM order_delivery_ticket ticket
        WHERE (
                soi.source_ticket_id IS NOT NULL
                AND ticket.id = soi.source_ticket_id
            )
           OR (
                ticket.source_type = 'SALES_ORDER'
                AND ticket.source_order_id = so.id
                AND ticket.source_item_id = soi.id
            )
        ORDER BY
            CASE WHEN ticket.id = soi.source_ticket_id THEN 0 ELSE 1 END,
            ticket.id DESC
        LIMIT 1
    ) t ON TRUE
    WHERE t.id IS NOT NULL
), allocation_summary AS (
    SELECT
        ticket_id,
        SUM(CASE WHEN allocation_type = 'IN_STOCK_LOCK' THEN qty ELSE 0 END) AS in_stock_lock_qty,
        SUM(CASE WHEN allocation_type = 'IN_PRODUCTION_LOCK' THEN qty ELSE 0 END) AS in_production_cover_qty,
        SUM(CASE WHEN allocation_type = 'PRODUCTION_REQUIRED' THEN qty ELSE 0 END) AS production_required_qty,
        COUNT(*) FILTER (WHERE allocation_type = 'PRODUCTION_REQUIRED') AS production_required_rows,
        COUNT(*) FILTER (
            WHERE allocation_type = 'PRODUCTION_REQUIRED'
              AND COALESCE(NULLIF(BTRIM(mes_production_status), ''), 'PENDING') = 'SUCCESS'
        ) AS production_success_rows,
        BOOL_OR(
            allocation_type = 'PRODUCTION_REQUIRED'
            AND COALESCE(NULLIF(BTRIM(mes_production_status), ''), 'PENDING') = 'PROCESSING'
        ) AS any_production_processing,
        BOOL_OR(
            allocation_type = 'PRODUCTION_REQUIRED'
            AND COALESCE(NULLIF(BTRIM(mes_production_status), ''), 'PENDING') = 'FAILED'
        ) AS any_production_failed,
        BOOL_OR(
            allocation_type = 'PRODUCTION_REQUIRED'
            AND COALESCE(NULLIF(BTRIM(mes_production_status), ''), 'PENDING') = 'RESULT_UNKNOWN'
        ) AS any_production_unknown,
        MAX(mes_production_synced_at) AS mes_production_synced_at,
        STRING_AGG(DISTINCT mes_production_external_id, ', ' ORDER BY mes_production_external_id) FILTER (
            WHERE NULLIF(BTRIM(mes_production_external_id), '') IS NOT NULL
        ) AS mes_production_external_ids
    FROM order_delivery_ticket_allocation
    WHERE COALESCE(NULLIF(BTRIM(status), ''), 'ACTIVE') = 'ACTIVE'
    GROUP BY ticket_id
), latest_wms AS (
    SELECT DISTINCT ON (wrt.ticket_id)
        wrt.ticket_id,
        wrt.id AS wms_reservation_ticket_id,
        wrt.batch_id AS wms_batch_id,
        wrb.external_biz_id AS wms_external_biz_id,
        wrb.sale_order_no AS wms_sale_no,
        wrb.status AS wms_batch_status,
        wrt.status AS wms_ticket_status,
        wrt.stock_frozen_count,
        wrt.in_production_count,
        wrt.surplus_count,
        wrb.submitted_at AS wms_submitted_at,
        wrb.responded_at AS wms_responded_at,
        wrb.completed_at AS wms_completed_at
    FROM wms_reservation_ticket wrt
    JOIN wms_reservation_batch wrb ON wrb.id = wrt.batch_id
    ORDER BY wrt.ticket_id, wrt.id DESC
), latest_mes_material AS (
    SELECT DISTINCT ON (mmi.ticket_id)
        mmi.ticket_id,
        mib.id AS mes_material_batch_id,
        mib.biz_id AS mes_material_biz_id,
        mib.status AS mes_material_batch_status,
        mmi.line_request_id AS mes_material_line_request_id,
        mmi.status AS mes_material_line_status,
        mmi.product_code AS mes_material_product_code,
        mmi.mes_task_no AS mes_material_task_no,
        mmi.completed_at AS mes_material_completed_at
    FROM mes_material_batch_item mmi
    JOIN mes_integration_batch mib ON mib.id = mmi.batch_id
    WHERE mib.batch_type = 'MATERIAL_PREPARATION'
    ORDER BY mmi.ticket_id, mmi.id DESC
), latest_mes_production AS (
    SELECT
        alloc.ticket_id,
        MAX(mib.id) AS mes_production_batch_id,
        STRING_AGG(DISTINCT mib.biz_id, ', ' ORDER BY mib.biz_id) AS mes_production_biz_ids,
        STRING_AGG(DISTINCT mpi.status, ', ' ORDER BY mpi.status) AS mes_production_batch_item_statuses,
        MAX(mpi.completed_at) AS mes_production_batch_completed_at
    FROM order_delivery_ticket_allocation alloc
    JOIN mes_production_batch_item mpi ON mpi.allocation_id = alloc.id
    JOIN mes_integration_batch mib ON mib.id = mpi.batch_id
    WHERE mib.batch_type = 'PRODUCTION_DEMAND'
      AND alloc.allocation_type = 'PRODUCTION_REQUIRED'
      AND COALESCE(NULLIF(BTRIM(alloc.status), ''), 'ACTIVE') = 'ACTIVE'
    GROUP BY alloc.ticket_id
)
SELECT
    p.sales_order_id,
    p.sales_order_item_id,
    p.ticket_id,
    p.qpo_sales_order_no,
    p.official_sales_order_no,
    p.sales_order_line_no,
    COALESCE(p.item_customer_order_no, p.header_customer_order_no, p.ticket_customer_order_no) AS customer_order_no,
    COALESCE(p.item_customer_project_no, p.header_customer_project_no, p.ticket_customer_project_no) AS customer_project_no,
    p.customer_name,
    p.part_no,
    p.version,
    p.ticket_qty,
    p.material_no,
    p.mes_sync_status,
    p.wms_allocate_status,
    COALESCE(a.in_stock_lock_qty, 0) AS in_stock_lock_qty,
    COALESCE(a.in_production_cover_qty, 0) AS in_production_cover_qty,
    COALESCE(a.production_required_qty, 0) AS production_required_qty,
    CASE
        WHEN NULLIF(BTRIM(p.material_no), '') IS NULL
          OR p.mes_sync_status <> 'SUCCESS'
            THEN 'NEED_MES_MATERIAL'
        WHEN p.wms_allocate_status <> 'SUCCESS'
            THEN 'NEED_WMS_RESERVE'
        WHEN COALESCE(a.production_required_rows, 0) = 0
            THEN 'WMS_COVERED_NO_MES_DISPATCH'
        WHEN COALESCE(a.production_success_rows, 0) = COALESCE(a.production_required_rows, 0)
            THEN 'MES_DISPATCH_SUCCESS'
        ELSE 'WMS_RESERVED_NEED_MES_DISPATCH'
    END AS stage_code,
    CASE
        WHEN NULLIF(BTRIM(p.material_no), '') IS NULL
          OR p.mes_sync_status <> 'SUCCESS'
            THEN '未获取物料号'
        WHEN p.wms_allocate_status <> 'SUCCESS'
            THEN '已获取物料号，未锁库存'
        WHEN COALESCE(a.production_required_rows, 0) = 0
            THEN 'WMS已覆盖，无需MES下发'
        WHEN COALESCE(a.production_success_rows, 0) = COALESCE(a.production_required_rows, 0)
            THEN '已下发MES成功'
        ELSE '锁库存成功，未下发MES'
    END AS stage_name,
    CASE
        WHEN COALESCE(a.production_required_rows, 0) > 0 THEN TRUE
        ELSE FALSE
    END AS needs_mes_dispatch,
    CASE
        WHEN COALESCE(a.any_production_failed, FALSE) THEN 'MES生产下发失败'
        WHEN COALESCE(a.any_production_unknown, FALSE) THEN 'MES生产下发结果待核对'
        WHEN COALESCE(a.any_production_processing, FALSE) THEN 'MES生产下发处理中'
        ELSE NULL
    END AS exception_hint,
    lm.mes_material_biz_id,
    lm.mes_material_line_request_id,
    lm.mes_material_line_status,
    lw.wms_batch_id,
    lw.wms_external_biz_id,
    lw.wms_batch_status,
    lw.wms_ticket_status,
    lp.mes_production_batch_id,
    lp.mes_production_biz_ids,
    lp.mes_production_batch_item_statuses,
    p.mes_synced_at,
    p.wms_allocated_at,
    a.mes_production_synced_at,
    p.u9_sync_status
FROM sales_order_part p
LEFT JOIN allocation_summary a ON a.ticket_id = p.ticket_id
LEFT JOIN latest_wms lw ON lw.ticket_id = p.ticket_id
LEFT JOIN latest_mes_material lm ON lm.ticket_id = p.ticket_id
LEFT JOIN latest_mes_production lp ON lp.ticket_id = p.ticket_id
WHERE (:ticket_id IS NULL OR p.ticket_id = :ticket_id)
  AND (:sales_order_id IS NULL OR p.sales_order_id = :sales_order_id)
  AND (:sales_order_no IS NULL OR p.qpo_sales_order_no = :sales_order_no OR p.official_sales_order_no = :sales_order_no)
  AND (:customer_order_no IS NULL OR COALESCE(p.item_customer_order_no, p.header_customer_order_no, p.ticket_customer_order_no) = :customer_order_no)
ORDER BY p.sales_order_id DESC, p.sales_order_line_no NULLS LAST, p.sales_order_item_id, p.ticket_id;
```

## 8. 只读账号注意事项

- 数据中心只读账号只能 `SELECT`，不能 `INSERT/UPDATE/DELETE`。
- 不要读取或展示完整请求体、完整响应体、token、共享密钥或敏感配置。
- `request_payload`、`source_payload` 等 JSON 快照只用于 QPO 内部核对，数据中心日常监控不建议展示。
- 追踪状态以 QPO 数据库已落库状态为准，不直接推断 MES 或 WMS 内部未回写状态。
- 如发现 `RESULT_UNKNOWN`，只能表示 QPO 无法确认外部结果，不表示外部一定失败。

## 9. 常见问题

### 9.1 为什么不能只用物料号追踪？

物料号是 MES 主数据身份，不是销售订单零件身份。同一个物料号可以被多个销售订单、多条提单行、多次锁库或多个待产行复用。追踪销售订单零件必须落到 `ticket_id` 或销售订单行。

### 9.2 为什么 WMS 成功后有些零件没有 MES 生产下发？

因为 WMS 返回结果会被 QPO 拆成三类：现货锁库、在产覆盖、待生产。只有待生产缺口 `PRODUCTION_REQUIRED` 需要下发 MES。若库存和在产已经覆盖全部数量，就不会生成待生产下发行。

### 9.3 `sale_order_no`、`sales_order_no`、`document_no`、`customer_order_no` 有什么区别？

- `sales_order_header.sales_order_no`：QPO 销售订单号。
- `sales_order_header.document_no`：正式单据号，MES 生产下发优先使用它。
- `customer_order_no`：客户订单号，WMS 锁库请求的 `saleNo` 使用它。
- WMS 表里的 `wms_reservation_batch.sale_order_no` 实际保存 WMS 请求 `saleNo`，即客户订单号，不等同于 QPO 销售订单号。

### 9.4 锁库存失败或结果待核对时看哪里？

先看 `order_delivery_ticket.wms_allocate_status/wms_allocate_message`，再看最新 `wms_reservation_batch.status/response_code/response_msg/last_error_type` 和 `wms_reservation_ticket.status/message`。

### 9.5 MES 生产下发失败时看哪里？

先看 `order_delivery_ticket_allocation` 中 `allocation_type = PRODUCTION_REQUIRED` 的 `mes_production_status/mes_production_message`，再通过 `mes_production_batch_item.allocation_id` 查批次行和 MES 返回计划号。

## 10. 实现依据

本文档按当前 QPO 实现整理，主要依据：

- `DeliveryService.generateImportedSalesOrderTickets()`：销售订单导入后生成 `order_delivery_ticket`。
- `DeliveryService.insertSalesOrderTicket()`：写入 `source_type/source_order_id/source_item_id`、客户订单号、客户项目号、物料号状态和 WMS 状态。
- `WmsReservationPlanService.prepare()`：WMS 以 ticket 为输入，解析销售订单行，按客户订单号分组并按物料号聚合。
- `WmsReservationStateService.applyResponse()`：WMS 成功后写入 `wms_reservation_ticket` 并生成三类 allocation。
- `MesProductionDispatchService.dispatchBatch()`：只把 `PRODUCTION_REQUIRED` allocation 下发 MES 生产。
- `DeliveredItemService.applyFlowStage()`：已提零件页面的 MES/WMS 阶段筛选口径。
