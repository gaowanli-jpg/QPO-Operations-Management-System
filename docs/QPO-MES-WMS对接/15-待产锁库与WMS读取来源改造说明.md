# 待产、锁库与 WMS 数据读取来源改造说明

## 当前口径

物料号获取成功后，`sales_order_item.allocation_id` 关联到有效的
`order_delivery_ticket_allocation`。待产零件、锁库零件的业务读取以这条销售订单零件为准：

- 物料号读取 `sales_order_item.material_no`；
- 数量读取 `sales_order_item.qty`；
- 图号、版本、材料、工艺、描述、重量、项目号和客户订单号等基础字段读取销售订单零件；
- Allocation 继续提供拆分类型、拆分来源、废弃状态、MES/WMS 状态和任务编号。

提单仍保留为物料号获取和来源追溯的中间表，不再作为已关联行的待产、锁库或 WMS 数量来源。

## 列表读取

待产和锁库列表通过 `order_delivery_ticket_allocation.id = sales_order_item.allocation_id`
进行左连接查询。已关联行使用销售订单零件字段，数量为 `0` 的行保留在销售订单详情和锁库拆行页面，
但从待产池、锁库池、MES 下发、提库存工单和 WMS 可获取范围中过滤。未关联的历史 Allocation
使用自身快照字段回退，避免旧数据因本次读取切换而消失。

列表和计数查询使用同一连接条件、筛选条件和数据权限条件。MES 和提库存工单异步批量任务先按
Allocation ID 批量加载销售订单零件，再批量加载销售订单头和装配关系，避免逐行查询。

## MES 与 WMS

MES 生产、提库存工单和 WMS 请求使用关联销售订单零件的当前物料号、数量及业务基础字段。
交期按“内部交期 → 零件下单日期 → 订单下单日期”取值；历史未关联行继续使用 Allocation 快照。
`drawingUrls` 不发送给 MES。

WMS 请求快照继续保存 Allocation ID、销售订单零件 ID、行号、物料号和请求数量。WMS 响应应用时：

1. 使用快照数量校验响应拆分总量；
2. 校验当前销售订单零件的关联 ID、行号、物料号和数量仍与快照一致；
3. 按现有通用拆分服务更新 Allocation 和销售订单零件行；
4. 不再要求 Allocation 当前数量等于原 WMS 请求数量，避免把 Allocation 当成新的数量来源。

人工拆分的上限读取当前销售订单零件数量。人工拆分与 WMS 初次拆分互斥，已完成拆分后只能使用现有
拆分行数量维护；人工拆分不修改提单和历史 WMS 快照。

## 兼容和性能

本次不新增 API、权限或数据库迁移，不删除 Allocation 冗余字段，也不修改历史 MES/WMS 请求快照。
已有权限、数据范围和审计动作保持不变。关联字段 `sales_order_item.allocation_id` 已有外键和唯一索引，
批量任务使用批量 ID 查询；只有确实找不到关联销售订单零件的历史行才回退快照字段。
