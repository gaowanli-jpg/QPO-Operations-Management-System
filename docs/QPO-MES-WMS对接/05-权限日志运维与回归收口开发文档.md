# QPO MES/WMS 权限日志运维与回归收口开发文档

## 1. 背景

`02-基础数据模型与已提零件模块开发文档.md`、`03-MES物料号同步开发文档.md`、`04-WMS锁库分配与锁库零件模块开发文档.md` 完成后，QPO 将新增两个订单分组下的模块：

- 已提零件：展示 `order_delivery_ticket` 需求池，并承载 MES/WMS 操作入口。
- 锁库零件：展示 `order_delivery_ticket_allocation` 锁库拆分结果。

同时系统会新增 MES/WMS 外部系统任务、权限点、操作日志动作和文件日志事件。为避免企业级治理漂移，本开发文档作为最终收口阶段，统一处理权限清单、管理员说明、日志运维、旧 APS 能力退役和全量回归。

## 2. 目标

### 2.1 本阶段目标

- 权限树、路由、菜单、后端接口权限保持一致。
- 操作日志动作中文化完整。
- 文件日志事件名进入运维说明。
- MES/WMS 配置进入部署说明。
- 旧 APS 对外出口明确退役或隐藏，不再作为新业务说明主路径。
- 文档能指导管理员给角色配置“已提零件 / 锁库零件 / MES / WMS”权限。
- 全量回归覆盖市场、订单、提单、MES、WMS、权限、日志。

### 2.2 非目标

- 不新增新的业务能力。
- 不改变 MES/WMS 已实现逻辑。
- 不做 WMS 释放或重算。
- 不做定时自动同步。
- 不删除历史数据库业务数据。

## 3. 收口范围

| 范围 | 收口要求 |
| --- | --- |
| 权限 | 新增权限全部进入 fallback catalog、Flyway、权限树、管理员说明和测试。 |
| 前端菜单 | `/delivered-items`、`/locked-items` 均为独立路由和独立 `MENU` 权限。 |
| 后端接口 | 所有新增接口必须有 `@RequirePermission`，不能只靠前端隐藏。 |

| 文件日志 | taskId、ticketId、requestId 可关联排查。 |
| 运维配置 | MES/WMS URL、token、path、timeout 有说明。 |
| 旧 APS | 文档中不再把 APS 作为后续主数据出口；代码是否删除按本阶段决策执行。 |

## 5. 日志与审计收口

### 5.1 操作日志动作清单

| 动作编码 | 中文名 | 模块 | 目标 |
| --- | --- | --- | --- |
| `DELIVERY_MES_MATERIAL_SYNC_SUBMIT` | 提交MES物料号任务 | `DELIVERY` | `order_delivery_ticket` |
| `DELIVERY_MES_MATERIAL_SYNC_SUCCESS` | MES物料号获取成功 | `DELIVERY` | `order_delivery_ticket` |
| `DELIVERY_MES_MATERIAL_SYNC_FAILED` | MES物料号获取失败 | `DELIVERY` | `order_delivery_ticket` |
| `DELIVERY_WMS_ALLOCATION_SUBMIT` | 提交WMS锁库任务 | `DELIVERY` | `order_delivery_ticket` |
| `DELIVERY_WMS_ALLOCATION_SUCCESS` | WMS锁库分配成功 | `DELIVERY` | `order_delivery_ticket` |
| `DELIVERY_WMS_ALLOCATION_FAILED` | WMS锁库分配失败 | `DELIVERY` | `order_delivery_ticket` |

### 5.2 操作日志摘要标准

MES 成功摘要：

```json
{
  "ticketId": 123,
  "taskId": 456,
  "rfqId": 88,
  "partNo": "P-1001",
  "version": "A",
  "internalProjectNo": "IP-20260721-001",
  "materialNo": "MAT-000123"
}
```

WMS 成功摘要：

```json
{
  "ticketId": 123,
  "taskId": 789,
  "rfqId": 88,
  "materialNo": "MAT-000123",
  "demandQty": 10,
  "allocationCount": 4,
  "inStockQty": 3,
  "inProductionQty": 6,
  "productionRequiredQty": 1
}
```

失败摘要：

```json
{
  "ticketId": 123,
  "taskId": 789,
  "rfqId": 88,
  "reason": "material not found"
}
```

要求：

- 操作日志不记录 token。
- 操作日志不记录完整外部系统大 JSON。
- 操作日志的 `requestId` 应能关联提交接口的后端文件日志。

### 5.3 文件日志事件名

MES：

```text
MES material sync submitted ticketId={} taskId={} rfqId={} partNo={}
MES material sync started ticketId={} taskId={} rfqId={} partNo={}
MES material sync completed ticketId={} taskId={} rfqId={} partNo={} materialNo={} durationMs={}
MES material sync rejected ticketId={} reason={}
MES material sync failed ticketId={} taskId={} rfqId={} partNo={} durationMs={}
```

WMS：

```text
WMS allocation submitted ticketId={} taskId={} rfqId={} materialNo={} demandQty={}
WMS allocation started ticketId={} taskId={} rfqId={} materialNo={} demandQty={}
WMS allocation completed ticketId={} taskId={} allocationCount={} inStockQty={} inProductionQty={} productionRequiredQty={} durationMs={}
WMS allocation rejected ticketId={} reason={}
WMS allocation failed ticketId={} taskId={} rfqId={} materialNo={} durationMs={}
```

要求：

- `submitted`、`started`、`completed` 为 INFO。
- `rejected` 为 WARN。
- `failed` 为 ERROR，并传异常对象。
- ERROR 必须进入 `qpo-error.log`。
- 不打印 token、Authorization header、完整图纸内容。

- 文档中不再把 APS 作为目标系统。

- 新开发不得继续引用 `ApsSourceService` 作为 MES/WMS 数据源。

如果用户明确要求彻底清理 APS 出口，再单独执行小阶段：

- 删除 `ApsSourceController`。
- 删除 `ApsSourceService`。
- 删除 `dto/aps`。
- 删除或改写相关测试。
- 删除 `ERP_APS_SOURCE_TOKEN`、`APS_ERP_BASE_URL`、`APS_ERP_AUTH_TOKEN` 等未使用配置。
- 更新 docs 中所有 APS 同步描述。

## 11. 数据验收 SQL

查看提单需求池字段：

```sql
SELECT id, rfq_id, item_id, part_no, version, qty,
       material_no, mes_sync_status, wms_allocate_status
FROM order_delivery_ticket
ORDER BY id DESC
LIMIT 20;
```

查看 allocation 拆分：

```sql
SELECT ticket_id,
       SUM(qty) AS allocated_qty,
       COUNT(*) AS allocation_count
FROM order_delivery_ticket_allocation
GROUP BY ticket_id
ORDER BY ticket_id DESC
LIMIT 20;
```

校验 allocation 合计等于 ticket 数量：

```sql
SELECT t.id AS ticket_id,
       t.qty AS ticket_qty,
       COALESCE(SUM(a.qty), 0) AS allocation_qty
FROM order_delivery_ticket t
LEFT JOIN order_delivery_ticket_allocation a ON a.ticket_id = t.id
WHERE t.wms_allocate_status = 'SUCCESS'
GROUP BY t.id, t.qty
HAVING t.qty <> COALESCE(SUM(a.qty), 0);
```

期望：返回 0 行。
