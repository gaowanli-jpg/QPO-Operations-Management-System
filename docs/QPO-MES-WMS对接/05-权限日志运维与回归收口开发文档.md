# QPO MES/WMS 权限日志运维与回归收口开发文档

本文描述 MES/WMS 现行治理口径。WMS 库存锁库只走数据中心批量 reserve 契约；MES 真实批量阶段 7 收口仍保留既有材料号、生产下发和回调治理要求。

## 1. 权限边界

| 能力 | 权限 | 说明 |
| --- | --- | --- |
| MES 获取物料号 | `market:delivered-item:mes-sync` | 控制已提零件获取/重试 MES 物料号。 |
| WMS 批量锁库 | `market:delivered-item:wms-allocate` | 控制已提零件提交 `WMS_ALLOCATION_BATCH`。 |
| 锁库结果查询 | `market:locked-item:view` | 控制锁库零件页面和 ticket 追溯。 |
| 待产下发 MES | `market:production-item:mes-production-submit` | 控制待产 allocation 下发 MES 生产。 |

不新增 `common:*` 权限。只读账号可以查看需求池和结果池，但不具备 MES/WMS 写操作。

## 2. WMS 批量锁库契约

| 项目 | 内容 |
| --- | --- |
| 任务类型 | `WMS_ALLOCATION_BATCH` |
| endpoint | `WMS_INVENTORY_ALLOCATE` |
| 链路 | `QPO -> 数据中心 -> WMS` |
| 路径 | `/api/v1/wms/admin-api/wms/datacenter/sale-lading/reserve` |
| requestAdapter | `WMS_SALE_LADING_RESERVE_V1` |
| responseAdapter | `WMS_SALE_LADING_RESERVE_RESPONSE_V1` |

请求字段：`externalBizId`、`saleNo`、`items[].productCode`、`items[].reserveCount`、`items[].remark`。单个零件也必须走批量数组。

响应字段：`saleOrderNo`、`externalBizId`、`items[].productCode`、`items[].reserveCount`、`items[].stockCount`、`items[].inProductionCount`、`items[].frozenCount`、`items[].surplusCount`。

`inProductionCount` 归入“在产覆盖”，写入 `IN_PRODUCTION_LOCK`；库存覆盖为 `frozenCount - inProductionCount`，缺口为 `surplusCount`。

## 3. WMS 审计动作

| 动作 | 模块 | targetType | 说明 |
| --- | --- | --- | --- |
| `DELIVERY_WMS_ALLOCATION_SUBMIT` | `DELIVERY` | `system_task` | 用户提交 WMS 批量锁库任务。 |
| `DELIVERY_WMS_ALLOCATION_SUCCESS` | `DELIVERY` | `wms_reservation_batch` | WMS 结果成功写入本地。 |
| `DELIVERY_WMS_ALLOCATION_FAILED` | `DELIVERY` | `wms_reservation_batch` | 明确失败或本地业务校验失败。 |
| `DELIVERY_WMS_ALLOCATION_RESULT_UNKNOWN` | `DELIVERY` | `wms_reservation_batch` | 传输结果未知，等待核对或同 ID 重放。 |
| `DELIVERY_WMS_ALLOCATION_APPLY_FAILED` | `DELIVERY` | `wms_reservation_batch` | 外部成功响应已保存，本地 allocation 写入待修复。 |
| `DELIVERY_WMS_ALLOCATION_RECONCILED` | `DELIVERY` | `wms_reservation_batch` | 运维核对后完成确认。 |

操作日志只记录安全摘要：`taskId`、`batchId`、`externalBizId`、`saleOrderNo`、`count`、`status`、`durationMs`、成功/失败统计和脱敏错误摘要。

## 4. WMS 文件日志

固定事件：

```text
WMS reservation batch started taskId={} batchId={} externalBizId={} saleOrderNo={} count={} status={}
WMS reservation batch completed taskId={} batchId={} externalBizId={} saleOrderNo={} count={} status={} durationMs={}
WMS reservation group completed taskId={} batchId={} externalBizId={} saleOrderNo={} count={} status={} durationMs={}
WMS reservation group failed taskId={} batchId={} externalBizId={} saleOrderNo={} count={} status={} durationMs={}
WMS reservation recovery failed taskId={} batchId={} externalBizId={} saleOrderNo={} count={} status={} durationMs={}
```

排查示例：

```powershell
docker exec quote-backend sh -lc "grep -R 'WMS reservation batch' /data/backups/logs/backend"
docker exec quote-backend sh -lc "grep -R 'externalBizId=QPO-WMS-' /data/backups/logs/backend"
docker exec quote-backend sh -lc "grep -R 'batchId=501' /data/backups/logs/backend/qpo-error.log"
```

不得记录 token、Authorization header、完整请求 JSON 或完整响应 JSON。失败堆栈进入 `qpo-error.log`，必须包含 `taskId` 或 `batchId`。

## 5. MES 真实批量阶段 7 收口

MES 真实批量阶段 7 收口要求继续适用：

- 物料号与生产下发链路：`QPO -> 数据中心 -> MES`。
- MES 回调链路：`MES -> 数据中心 -> QPO`。
- 物料号路径：`/api/v1/mes/openapi/material-preparation/create`。
- 生产下发路径：`/api/v1/mes/openapi/demand/create`。
- QPO 回调路径：`/api/integrations/mes/material-callback`。
- 已提零件 MES 权限：`market:delivered-item:mes-sync`。
- 待产 MES 权限：`market:production-item:mes-production-submit`。
- 人工核对动作：`MES_INTEGRATION_BATCH_RECONCILE`。

MES 文件日志与操作日志同样只能记录安全摘要，不记录 token、Authorization header 或完整业务报文。

## 6. 回归收口

阶段 7 验收命令：

```powershell
.\mvnw.cmd -Dtest=AuditActionCoverageTests,LoggingConventionTest,DataCenterConfigStage1Test,DataCenterConfigStage8DocumentationTest,ExternalIntegrationConfigServiceTest test
```

发布前检查：

- `erp.env.example`、`docker-compose.yml` 和 `application.yaml` 不再包含 WMS 直连 fallback。
- 现行 WMS 文档只描述 `WMS_ALLOCATION_BATCH`、`WMS_INVENTORY_ALLOCATE` 和 sale-lading reserve 契约。
- 权限清单、运维说明和日志说明都能按 `taskId/batchId/externalBizId/saleOrderNo` 关联排查。
- 锁库结果继续落入 `order_delivery_ticket_allocation`，并保留 `ticket_qty`、材料编码、材料类型、材质分类、材料形态等快照口径。
