# 自动触发 MES 物料号获取设计

## 背景

QPO 目前有两条链路会把零件批量落到已提零件模块：

- RFQ 询价订单在议价提单模块生成提单行，落库到 `order_delivery_ticket`。
- 销售订单导入完成后自动生成提单行，同样落库到 `order_delivery_ticket`。

落库后，业务员还需要进入已提零件模块手动选择本批行并点击“获取物料号”。本设计把这一步自动化：在两条链路成功生成本批提单行后，系统自动针对本批 `ticketIds` 提交一次 MES 物料号批量获取任务。

## 目标

- RFQ 议价提单成功后，自动提交本批新生成提单行的 MES 物料号批量任务。
- 销售订单导入并自动提单成功后，自动提交本批新生成提单行的 MES 物料号批量任务。
- 自动任务语义等同于业务员在已提零件页面手动批量点击一次“获取物料号”。
- MES 自动获取失败不回滚 RFQ 提单或销售订单导入结果；失败状态保留在任务和已提零件行中，业务员后续可手动重试。
- 继续复用现有 MES 批量去重、跳过、回调、来源主表回写、权限、日志逻辑。

## 非目标

- 不新增新的主业务状态。
- 不改变 MES 物料号接口契约。
- 不自动触发 WMS 库存锁库。
- 不在提单事务内同步等待 MES 响应。
- 不覆盖已确认物料号，不重复请求已成功或处理中的提单行。
- 不记录完整 MES 请求、响应、图纸内容、token 或完整 JSON 快照。

## 当前可复用能力

- `DeliveryBatchResultDTO.ticketIds` 已返回 RFQ 提单生成的本批提单行 ID。
- `DeliveryService.generateImportedSalesOrderTickets(Long salesOrderId)` 已返回销售订单导入自动生成的本批 `OrderDeliveryTicket`。
- `SystemTaskService.submitMesMaterialBatchSyncTask(List<Integer> ticketIds)` 已负责创建 `MES_MATERIAL_BATCH_SYNC` 异步任务并记录提交日志。
- `DeliveryIntegrationBatchService.syncMesMaterialBatch(...)` 已负责归一化 ticket ID、数据权限检查、跳过已成功/处理中/待回调行、调用 `MesMaterialSyncService`、汇总结果。
- `MesMaterialSyncService` 已负责同图号版本去重、即时成功或回调等待、写回 `order_delivery_ticket`，并按来源回写 `item_quote_version` 或 `sales_order_item`。

## 推荐方案

采用“事务后异步触发”方案：

1. 两条业务链路保持现有提单/导入事务边界。
2. 提单行成功落库后收集本批 `ticketIds`。
3. 在当前事务提交后提交 `MES_MATERIAL_BATCH_SYNC` 异步任务。
4. 自动任务失败只影响 MES 同步状态，不影响前置提单/导入成功。

这个方案把自动触发建模为一次系统代点的手动批量操作，最贴近用户期望，也能避免 MES 超时或失败污染核心业务事务。

## 组件设计

### 自动触发服务

建议新增轻量服务：`DeliveryAutoMesMaterialSyncService`。

职责：

- 接收来源类型、来源订单 ID、本批 `ticketIds` 和触发场景。
- 过滤空 ID，并保留顺序去重。
- 注册事务提交后回调；如果当前没有活动事务，则直接提交任务。
- 调用 `SystemTaskService.submitMesMaterialBatchSyncTask(ticketIds)`。
- 记录安全摘要日志：触发场景、来源类型、来源订单 ID、ticket 数、taskId、失败原因。

建议方法：

```java
public void submitAfterCommit(ReleaseSourceType sourceType, Long sourceOrderId, List<Integer> ticketIds, String triggerScene)
```

### RFQ 议价提单入口

修改 `DeliveryService.generateRfqReleaseBatch(...)`：

- 保持调用 `rfqReleaseSalesOrderService.generate(req)`。
- 从返回的 `DeliveryBatchResultDTO.ticketIds` 获取本批提单行。
- 成功且 `ticketIds` 非空时调用自动触发服务。
- 返回值保持兼容，不要求前端等待 MES 任务完成。

若旧入口 `DeliveryService.generateTickets(...)` 内部通过 `rfqReleaseSalesOrderService.generate(req)` 生成 RFQ 提单，也应保证不会重复提交。建议只在统一 RFQ batch 结果出口触发，或用 `releaseBatchKey + ticketIds` 保持本次调用只触发一次。

### 销售订单导入入口

修改 `SalesOrderQpoImportService.autoGenerateDeliveryTickets(...)` 或 `DeliveryService.generateImportedSalesOrderTickets(...)` 的调用末尾：

- 使用返回的 `List<OrderDeliveryTicket>` 提取本批 `ticketIds`。
- 成功且 `ticketIds` 非空时调用自动触发服务。
- 导入响应仍以导入和自动提单结果为准，MES 任务只作为后台动作。

建议把触发点放在 `SalesOrderQpoImportService` 侧，因为它天然代表“导入后自动提单”场景，便于后续在响应或日志里区分触发来源。

## 数据流

### RFQ 议价提单

```text
业务员提交议价提单
  -> DeliveryService.generateRfqReleaseBatch(req)
  -> RfqReleaseSalesOrderService.generate(req)
  -> order_delivery_ticket 批量落库
  -> 返回 DeliveryBatchResultDTO.ticketIds
  -> 事务提交后自动提交 MES_MATERIAL_BATCH_SYNC(ticketIds)
  -> MES 同步服务按现有规则跳过/去重/调用/回写
```

### 销售订单导入

```text
业务员导入销售订单
  -> parse Excel
  -> create sales_order_header / sales_order_item
  -> auto match snapshots
  -> DeliveryService.generateImportedSalesOrderTickets(salesOrderId)
  -> order_delivery_ticket 批量落库
  -> 返回本批 tickets
  -> 事务提交后自动提交 MES_MATERIAL_BATCH_SYNC(ticketIds)
  -> MES 同步服务按现有规则跳过/去重/调用/回写
```

## 错误处理

- 自动触发服务提交任务失败：记录文件日志摘要，不抛出到 RFQ 提单或销售订单导入主链路。
- MES 批量任务内部失败：沿用当前手动批量获取物料号失败处理，任务失败或行级失败保留在系统任务和已提零件状态中。
- 部分 ticket 已有已确认物料号：沿用当前 `DeliveryIntegrationBatchService` 跳过规则。
- 部分 ticket 处于 `PROCESSING` 或 `CALLBACK_PENDING`：沿用当前跳过或等待规则。
- 自动触发服务不可用：记录 warn/error 摘要，不阻断主链路。

## 权限与日志

- 不新增用户权限点。自动触发不是独立按钮权限，而是提单/导入成功后的系统代操作。
- 后台任务仍复用 `DELIVERY_MES_MATERIAL_SYNC_SUBMIT` 操作日志和 `MES_MATERIAL_BATCH_SYNC` 任务类型。
- 文件日志新增或复用摘要级日志，字段限于：触发场景、来源类型、来源订单 ID、ticketCount、taskId、状态、失败摘要。
- 不记录完整请求体、完整响应体、图纸内容、token、cookie 或完整 JSON 快照。

## 测试方案

后端建议新增或调整：

- RFQ 议价提单成功后，提交一次 MES 物料号批量任务，入参为本批 `ticketIds`。
- RFQ 重放或重复生成不重复触发不属于本批的新 ticket。
- 销售订单导入自动提单成功后，提交一次 MES 物料号批量任务，入参为导入本批 ticket。
- 自动 MES 任务提交异常不影响 RFQ 提单成功。
- 自动 MES 任务提交异常不影响销售订单导入成功。
- 已有物料号、处理中、待回调行继续由 `DeliveryIntegrationBatchService` 跳过，不在新服务重复实现规则。

前端不需要新增交互；如后续希望展示“已自动提交物料号获取任务”，可单独扩展导入或提单成功提示。

## 验收标准

- RFQ 议价提单和销售订单导入后，业务员无需再手动点一次“获取物料号”即可看到后台 MES 物料号任务执行。
- MES 失败时，前置提单/导入仍成功，失败信息可在已提零件或任务记录中查看并手动重试。
- 已确认物料号不被覆盖，处理中和待回调行不重复请求 MES。
- 现有手动“获取物料号”能力保留并继续可用。

## 分阶段开发计划

### 阶段 1：自动触发基础设施与 RFQ 结果标识

**目标：** 先建立一个可复用的“事务提交后自动提交 MES 物料号任务”服务，并让 RFQ 提单结果能区分首次生成和幂等重放。

**修改文件：**

- 新增：`quote-backend/src/main/java/com/machining/quote/service/DeliveryAutoMesMaterialSyncService.java`
- 修改：`quote-backend/src/main/java/com/machining/quote/dto/DeliveryBatchResultDTO.java`
- 修改：`quote-backend/src/main/java/com/machining/quote/service/RfqReleaseSalesOrderService.java`
- 新增测试：`quote-backend/src/test/java/com/machining/quote/DeliveryAutoMesMaterialSyncServiceTest.java`
- 调整测试：`quote-backend/src/test/java/com/machining/quote/RfqReleaseSalesOrderIntegrationTest.java` 或新增独立 characterization 测试

**实现要点：**

- 新增服务方法：`submitAfterCommit(ReleaseSourceType sourceType, Long sourceOrderId, List<Integer> ticketIds, String triggerScene)`。
- 服务内部只做顺序去重、空集合跳过、事务提交后回调、调用 `SystemTaskService.submitMesMaterialBatchSyncTask(ticketIds)`、摘要日志记录。
- 当前有活动事务时使用 `TransactionSynchronizationManager.registerSynchronization(...)`，确保主事务提交后再提交 MES 任务。
- 当前无活动事务时直接提交 MES 任务，便于单元测试和未来复用。
- 自动提交异常只记录 warn/error 摘要，不向调用方抛出。
- `DeliveryBatchResultDTO` 增加 `private boolean idempotentReplay;`。
- `RfqReleaseSalesOrderService.generate(...)` 首次生成结果设置 `idempotentReplay=false`，`buildExistingResult(...)` 返回结果设置 `idempotentReplay=true`。

**测试清单：**

- `submitAfterCommit(...)` 在无事务时立即调用 `SystemTaskService.submitMesMaterialBatchSyncTask(...)`。
- `submitAfterCommit(...)` 在 ticketIds 为空时不调用系统任务。
- `submitAfterCommit(...)` 捕获系统任务异常，不向调用方抛出。
- RFQ 首次生成结果 `idempotentReplay=false`。
- RFQ 幂等重放结果 `idempotentReplay=true`。

**验证命令：**

```powershell
cd quote-backend
.\mvnw.cmd -q "-Dtest=DeliveryAutoMesMaterialSyncServiceTest,RfqReleaseSalesOrderIntegrationTest" test
```

### 阶段 2：RFQ 议价提单自动触发 MES 物料号任务

**目标：** RFQ 议价提单成功生成本批 ticket 后，自动提交一次本批 `ticketIds` 的 MES 物料号批量任务；幂等重放不重复提交。

**修改文件：**

- 修改：`quote-backend/src/main/java/com/machining/quote/service/DeliveryService.java`
- 测试：`quote-backend/src/test/java/com/machining/quote/RfqReleaseMesMaterialDualWriteIntegrationTest.java`
- 建议新增测试：`quote-backend/src/test/java/com/machining/quote/RfqReleaseAutoMesMaterialSyncTest.java`

**实现要点：**

- 在 `DeliveryService` 注入 `DeliveryAutoMesMaterialSyncService`，使用 `@Autowired(required = false)` 保持测试装配兼容。
- `generateRfqReleaseBatch(req)` 调用 `rfqReleaseSalesOrderService.generate(req)` 后，若 `result.isSuccess()`、`!result.isIdempotentReplay()`、`result.getTicketIds()` 非空，则调用自动触发服务。
- 触发参数建议为：`ReleaseSourceType.RFQ`、`result.getSalesOrderId()` 或第一个 `sourceRfqId` 按日志需要记录、`result.getTicketIds()`、`"RFQ_RELEASE"`。
- 如果旧 RFQ 入口 `generateTickets(req)` 仍会被外部调用，也应在 RFQ 分支复用同一触发 helper；同一请求路径只调用一次，不能在 `generateRfqReleaseBatch` 和 `generateTickets` 双重触发。
- 自动触发失败不影响 `DeliveryBatchResultDTO` 返回。

**测试清单：**

- RFQ 议价提单首次成功时，自动触发服务收到本批 `ticketIds`。
- RFQ 幂等重放时，不调用自动触发服务。
- 自动触发服务抛异常时，RFQ 提单结果仍 `success=true`，ticket 已落库。
- 手动 MES 获取物料号测试继续通过，证明自动触发没有改变底层批量同步规则。

**验证命令：**

```powershell
cd quote-backend
.\mvnw.cmd -q "-Dtest=RfqReleaseAutoMesMaterialSyncTest,RfqReleaseMesMaterialDualWriteIntegrationTest,DeliveryIntegrationBatchTaskTest,MesMaterialSync*Test" test
```

### 阶段 3：销售订单导入自动提单后触发 MES 物料号任务

**目标：** 销售订单导入完成自动匹配和自动提单后，针对导入本批生成的 ticket 自动提交 MES 物料号批量任务。

**修改文件：**

- 修改：`quote-backend/src/main/java/com/machining/quote/service/SalesOrderQpoImportService.java`
- 测试：`quote-backend/src/test/java/com/machining/quote/SalesOrderQpoImportAutoDeliveryWorkflowTest.java`
- 可选测试：`quote-backend/src/test/java/com/machining/quote/SalesOrderQpoImportServiceWorkflowTest.java`

**实现要点：**

- 在 `SalesOrderQpoImportService` 注入 `DeliveryAutoMesMaterialSyncService`，使用 `@Autowired(required = false)` 保持旧测试兼容。
- `autoGenerateDeliveryTickets(header)` 从 `deliveryService.generateImportedSalesOrderTickets(header.getId())` 返回的 `List<OrderDeliveryTicket>` 提取本批 ticket ID。
- ticket ID 非空时调用 `submitAfterCommit(ReleaseSourceType.SALES_ORDER, header.getId(), ticketIds, "SALES_ORDER_IMPORT")`。
- 导入响应仍以导入和自动提单数量为准，不要求返回 MES taskId。
- 自动触发服务为空或提交异常时，不影响导入成功、不影响自动提单成功。

**测试清单：**

- 销售订单导入自动提单成功后，自动触发服务收到本批 ticket ID。
- 导入生成多个销售订单时，每个销售订单各自按本批 ticket ID 触发一次。
- 自动触发服务抛异常时，导入响应仍 `success=true`，自动提单数量仍正确。
- 命中历史快照、未命中历史快照、价格为空但允许导入的既有测试继续通过。

**验证命令：**

```powershell
cd quote-backend
.\mvnw.cmd -q "-Dtest=SalesOrderQpoImportAutoDeliveryWorkflowTest,SalesOrderQpoImportServiceWorkflowTest,SalesOrderQpoImportDefaultsTest,SalesOrderDeliveryTicketWorkflowTest" test
```
