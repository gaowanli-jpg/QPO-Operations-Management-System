# 本地验证手册

本文记录在本机用 Docker 跑通 QPO、以及分层验证的具体操作。适用于 Windows + Docker Desktop，服务器部署不适用（服务器走离线包，见根目录 `QPO部署说明.md`）。

## 1. 本机环境约定

| 项 | 值 | 说明 |
| --- | --- | --- |
| 前端 | http://localhost:8088 | 只绑 `127.0.0.1` |
| 后端 | http://127.0.0.1:18088 | 只绑 `127.0.0.1`，健康检查 `/api/health` |
| PostgreSQL | 127.0.0.1:15432 | 宿主端口 15432 → 容器 5432 |
| 数据库账号 | `postgres` / 见本机 `erp.env` | 本地密码与 `application.yaml` 默认值一致，便于跑测试 |
| 镜像标签 | `qpo-backend:local`、`qpo-frontend:local` | 由 `erp.env` 的 `QPO_IMAGE_TAG=local` 决定 |
| 配置文件 | 根目录 `erp.env` | 已被 `.gitignore` 的 `*.env` 忽略，**不要提交** |

端口按测试服务器（`10.2.25.100`）的布局对齐：15432 / 18088 / 8088。

### `erp.env` 必须整份复制模板

不要只写几行关键配置。后端有若干配置类测试（`MesMaterialClientTest`、`LockedItemMesProductionClientTest`、`MesRealBatchGovernanceCharacterizationTest`、`DataCenterConfigEnvironmentContractTest`）会直接读仓库根目录的 `erp.env`，断言 `ERP_MES_MATERIAL_PATH`、`ERP_MES_TIMEOUT_MS`、`ERP_DATA_CENTER_MES_*_PATH` 等键存在且取值正确。

正确做法是先 `cp erp.env.example erp.env`，再只覆盖本机需要变的项：

```powershell
Copy-Item erp.env.example erp.env
```

需要覆盖的项：`POSTGRES_PASSWORD`、`POSTGRES_BIND`、`POSTGRES_PORT`、`POSTGRES_DATACENTER_RO_PASSWORD`、`BACKEND_PORT`、`FRONTEND_BIND`、`ERP_JWT_SECRET`、`ERP_CORS_ALLOWED_ORIGINS`、`QPO_IMAGE_TAG`、`ERP_DATA_CENTER_ENABLED`。其余保持模板原值。

## 2. 日常启停

```powershell
cd C:\Users\Administrator\IdeaProjects\QPO-Operations-Management-System

# 启动（已构建过）
docker compose --env-file erp.env up -d --no-build

# 改了后端或前端代码后重建
docker compose --env-file erp.env up -d --build

# 查看状态
docker compose --env-file erp.env ps

# 停止（保留数据卷）
docker compose --env-file erp.env stop

# 查看日志
docker compose --env-file erp.env logs -f --tail=200 backend
```

### 重置数据库（会清空所有本地数据）

```powershell
docker compose --env-file erp.env down -v
docker compose --env-file erp.env up -d --no-build
```

`down -v` 会删除 `quote-system_postgres_data`、`quote-system_uploads_data`、`quote-system_backups_data` 三个卷，只允许在本地环境使用。

## 3. 分层验证

| 层级 | 命令 | 依赖 | 规模 |
| --- | --- | --- | --- |
| 编译 | `.\mvnw.cmd -q -DskipTests package`（`quote-backend`） | 无 | — |
| 编译 | `npm ci && npm run build`（`quote-frontend`） | 无 | — |
| 单元测试 | `.\mvnw.cmd test -Dtest="*ServiceTest,*ControllerTest"` | 无 | 约 1452 个 |
| 契约与特征 | `.\mvnw.cmd test -Dtest="*Contract*,*CharacterizationTest"` | 无 | 约 52 个 |
| 集成测试 | 见下方命令 | 需本地 PostgreSQL | 约 143 个 |
| 人工端到端 | 浏览器登录后走链路 | 需全栈 | — |

### 集成测试连接本地库

`application.yaml` 默认连 `localhost:5432`，本机数据库映射在 **15432**，因此必须覆盖 `DB_URL`。用**环境变量**传，不要用 `-DargLine`：

```powershell
cd quote-backend
$env:DB_URL='jdbc:postgresql://localhost:15432/postgres'
.\mvnw.cmd test
```

Git Bash 写法：

```bash
DB_URL='jdbc:postgresql://localhost:15432/postgres' ./mvnw.cmd test
```

说明：

- **不要用 `-DargLine=-DDB_URL=...`**。`argLine` 会覆盖 surefire 的 JVM 参数，导致 Mockito 报 `Could not initialize plugin: Mockito/plugins/MockMaker`，出现大片假失败（实测 892 个错误）。`DB_URL` 走环境变量，Spring 的 `${DB_URL:...}` 占位符能直接读到。
- 用户名、密码沿用 `application.yaml` 默认值（`postgres` / `123456`），与本地 `erp.env` 保持一致，所以只需覆盖 URL。
- 单跑某一个：`.\mvnw.cmd test -Dtest=RfqReleaseSalesOrderIntegrationTest`（同样先设 `$env:DB_URL`）。
- 集成测试会写入真实本地库并回滚，跑完不影响登录；如果出现脏数据，用第 2 节的「重置数据库」恢复。

### 本地已知的一处测试差异

`DatacenterReadonlyDirectConnectConfigTest` 会直接读仓库根目录的 `erp.env`，并断言 `POSTGRES_BIND=0.0.0.0`（服务器上供数据中心直连只读库）。本地为了安全把 PostgreSQL 绑在 `127.0.0.1`，所以这一条会失败，属**预期差异**，不是代码问题。

本地跑全量时排除它：

```powershell
.\mvnw.cmd test '-Dtest=!DatacenterReadonlyDirectConnectConfigTest'
```

其余用例应当全绿。

## 4. 登录账号

种子数据 `V2__qpo_baseline_seed_data.sql` 内置三个账号，初始密码 `admin123`：

| 账号 | 角色 | 用途 |
| --- | --- | --- |
| `admin` | ADMIN / SUPER_ADMIN | 用户管理、系统配置、全流程兜底 |
| `market` | MARKET | 询价导入、报价、提单 |
| `engineer` | ENGINEER | 材料工艺核价 |

正式环境必须改密。本地若因多次输错被锁定，重置方式：

```sql
update erp_user set failed_login_attempts = 0, locked_until = null where username = 'admin';
```

## 5. 本地没有业务数据

种子只包含权限、角色、账号、部门、岗位、字典和数据中心端点，**没有任何客户、询价单、订单、图纸**。本地要验证业务链路，需要自己准备数据或从测试服务器导一份库。数据方案另行处理，不在本文范围。

## 6. 常见问题

### Docker Hub 拉不到镜像

本机直连 `registry-1.docker.io` 会超时。可用镜像源拉取后重命名：

```powershell
docker pull docker.m.daocloud.io/library/postgres:15
docker tag docker.m.daocloud.io/library/postgres:15 postgres:15
```

需要的镜像：`postgres:15`、`maven:3.9-eclipse-temurin-17`、`eclipse-temurin:17-jre`、`node:22-alpine`、`nginx:1.27-alpine`。

### `Invalid CORS request`

`erp.env` 的 `ERP_CORS_ALLOWED_ORIGINS` 必须包含浏览器实际访问的完整 origin，例如 `http://localhost:8088`。改完只需重启后端：

```powershell
docker compose --env-file erp.env up -d --no-build --force-recreate backend
```

### 后端起不来，日志报数据库或密钥

检查 `erp.env` 里 `POSTGRES_PASSWORD`、`POSTGRES_DATACENTER_RO_PASSWORD`、`ERP_JWT_SECRET` 三项是否为空。后两项为空时后端会在 Flyway 阶段直接退出。

### 数据中心 / MES 被误调用

本地 `erp.env` 默认 `ERP_DATA_CENTER_ENABLED=false`，避免本地点击操作打到真实 MES/WMS/U9。需要联调时再改为 `true`，并把 `ERP_DATA_CENTER_BASE_URL` 指向测试数据中心。
