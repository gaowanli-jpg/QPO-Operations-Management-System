# MES 销售订单生产需求同步接口开发文档

## 1. 最终口径

本接口用于 MES 定时从 QPO 拉取销售订单生产需求所需的最小数据集，不再按外部系统主数据镜像返回全量销售订单字段。

接口保留原有入口、鉴权、游标分页和增量水位能力：

```http
GET /api/integrations/sales-orders
Authorization: Bearer {QPO_OPEN_API_TOKEN}
```

统一 token 仍由 **系统配置 > 入站接口** 顶部维护，MES 回调和销售订单同步共用 `QPO_OPEN_API_TOKEN`。
系统配置 > 入站接口列表中，销售订单同步必须以 `SALES_ORDER_SYNC_QUERY` 作为数据库配置元数据展示和维护，来源系统为 `EXTERNAL_SALES_ORDER_SYNC`，接口路径为 `/api/integrations/sales-orders`；不得再由前端补成 `BUILT_IN` / “内置元数据”的只读展示行。

本接口只读：不触发 MES / WMS / U9，不修改销售订单状态，不写普通业务操作日志。

## 2. 查询参数

| 参数 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `pageSize` | integer | 否 | 允许 `20 / 50 / 100`，默认 `100`。 |
| `cursor` | string | 否 | 游标，首次同步为空，后续使用上次响应的 `nextCursor`。 |
| `saleOrderNo` | string | 否 | 销售订单号精确查询，用于补同步单据。 |
| `materialNo` | string | 否 | 物料号筛选，用于补同步命中物料行。 |
| `partNo` | string | 否 | 图号筛选，保留兼容补同步能力，不在响应中返回。 |
| `version` | string | 否 | 版本筛选，保留兼容补同步能力，不在响应中返回。 |
| `status` | string | 否 | 销售订单状态筛选。 |
| `createdFrom` / `createdTo` | datetime | 否 | 销售订单创建时间区间。 |
| `updatedFrom` / `updatedTo` | datetime | 否 | 订单头或任意明细最后变更时间区间。 |

时间格式：`yyyy-MM-dd'T'HH:mm:ss`。

## 4. 字段契约

### 4.1 订单字段

| 字段 | 类型 | 必填 | 来源 | 说明 |
| --- | --- | --- | --- | --- |
| `saleOrderNo` | string | 是 | `sales_order_header.sales_order_no` | 销售订单唯一编号。 |
| `createdAt` | datetime | 是 | `sales_order_header.created_at` | 销售订单创建时间。 |
| `changedAt` | datetime | 是 | `GREATEST(sales_order_header.updated_at, MAX(sales_order_item.updated_at))` | 订单或任意明细最后变更时间。 |
| `status` | string | 否 | `sales_order_header.status` | 仅用于 MES 展示和查询，不限制 MES 创建生产需求。 |
| `orderType` | string | 否 | `sales_order_header.order_type` | 销售订单类型。 |
| `internalProjectNo` | string | 否 | `sales_order_header.internal_project_no` | 内部项目号。 |
| `items` | array | 是 | `sales_order_item` | 当前订单完整有效明细集合。 |

### 4.2 明细字段

| 字段 | 类型 | 必填 | 来源 | 说明 |
| --- | --- | --- | --- | --- |
| `saleOrderItemNo` | string | 是 | `sales_order_item.line_no` | 订单内稳定且唯一的明细编号，不使用 QPO 内部 ID 兜底。 |
| `materialNo` | string | 是 | `sales_order_item.material_no` | 销售物料号，用于匹配 MES 物料编码。 |
| `releasedQty` | decimal | 是 | `GREATEST(COALESCE(sales_order_item.released_qty, 0), 0)` | 已提数量，按 QPO 内部 `released_qty` 原语义传给 MES。 |
| `description` | string | 否 | `sales_order_item.description` | 明细描述。 |
| `surfaceTreatment` | string | 否 | `sales_order_item.surface_treatment` | 表面处理要求。 |
| `remark` | string | 否 | `sales_order_item.remark` | 明细级备注。 |

## 5. 业务身份与数据治理

- 订单业务键：`saleOrderNo`。
- 明细业务键：`saleOrderNo + saleOrderItemNo`，其中 `saleOrderItemNo` 固定来自 `sales_order_item.line_no`。
- `sales_order_item.line_no` 为空时接口不使用内部 ID 兜底，应阻断并先做数据治理。
- `sales_order_item.material_no` 为空时不满足 MES 必填契约，应阻断并先补齐物料号。
- `releasedQty` 来源就是 `sales_order_item.released_qty`，不映射 `qty`，不改成销售数量。

上线前数据检查 SQL：

```sql
SELECT sales_order_id, id
FROM sales_order_item
WHERE line_no IS NULL
   OR NULLIF(BTRIM(material_no), '') IS NULL;
```

## 6. 增量与游标

订单级分页排序保持：

```sql
ORDER BY changed_at ASC, so.id ASC
```

`changedAt` 定义：

```sql
changedAt = GREATEST(
  sales_order_header.updated_at,
  COALESCE(MAX(sales_order_item.updated_at), sales_order_header.updated_at)
)
```

游标内容仍为 Base64URL(JSON)：

```json
{
  "changedAt": "2026-08-14T11:00:00",
  "salesOrderId": 123
}
```

下一页条件：

```sql
changed_at > :cursorChangedAt
OR (changed_at = :cursorChangedAt AND sales_order_id > :cursorSalesOrderId)
```

## 8. 日志与只读边界

成功日志只记录低噪声摘要：

```text
Sales order sync query completed caller=EXTERNAL_SALES_ORDER_SYNC pageSize=100 orderCount=80 itemCount=240 hasMore=true durationMs=35
```

失败日志只记录失败摘要：

```text
Sales order sync query failed caller=EXTERNAL_SALES_ORDER_SYNC pageSize=100 reason=missingMaterialNo durationMs=3
```

日志不得记录 token、Authorization header、完整请求 URL、完整响应 JSON、客户敏感信息、价格字段、图纸 URL、工艺路线、feeData 或 materialData。

### 阶段 8：联调与回归

建议验证命令：

```powershell
cd D:\QPO-Operations-Management-System\quote-backend
.\mvnw.cmd test

cd D:\QPO-Operations-Management-System\quote-frontend
npm test
npm run build
```

阶段 8 验收记录继续覆盖：

- 首次全量同步。
- `updatedFrom` 增量同步。
- `cursor + pageSize` 连续翻页。
- 使用 `saleOrderNo` 精确补同步。
- 使用 `materialNo`、`partNo + version` 补同步命中零件行。
- 外部/MES 可用 `saleOrderNo + saleOrderItemNo` 幂等落库。
- 旧 token 访问销售订单同步返回 `401`。
- 旧 token 访问 MES 回调返回 HTTP `200` 且响应体 `code=401`。
- 接口不触发 MES / WMS / U9。
- 接口不修改销售订单状态。

## 10. 最终结论

销售订单同步接口从“外部系统全量销售订单主数据同步”收敛为“MES 生产需求最小字段同步”：

```text
GET /api/integrations/sales-orders
Authorization: Bearer {QPO_OPEN_API_TOKEN}
订单字段：saleOrderNo、createdAt、changedAt、status、orderType、internalProjectNo、items
明细字段：saleOrderItemNo、materialNo、releasedQty、description、surfaceTreatment、remark
releasedQty：固定来源 sales_order_item.released_qty，不映射 qty
```
