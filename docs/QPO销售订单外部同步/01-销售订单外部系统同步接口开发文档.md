# 销售订单外部系统同步接口开发文档

## 1. 背景与目标

外部系统需要定时同步 QPO 的销售订单数据到本地。该接口不是前端页面列表接口，而是面向机器调用方的只读同步接口，重点是字段契约稳定、支持增量拉取、支持幂等落库、脱敏且不泄露价格字段。

本次接口消费 QPO 已有独立销售订单表：

- 订单头：`sales_order_header`
- 订单零件行：`sales_order_item`

本接口只读，不改变销售订单、提单、MES、WMS、U9 业务状态。

## 2. 已确认口径

### 2.1 接口性质

- 新增独立机器接口，不复用前端销售订单管理接口。
- 外部系统定时调用接口，将数据同步到其本地库。
- 接口必须支持全量同步、增量同步和条件补同步。
- 接口返回订单头和零件行，价格字段和内部敏感字段不返回。

### 2.2 必返业务身份

订单头必须返回：

```text
saleOrderNo
```

每个零件行必须返回：

```text
saleOrderNo
saleOrderItemNo
```

业务身份定义：

```text
订单唯一键：saleOrderNo
零件行唯一键：saleOrderNo + saleOrderItemNo
```

说明：

- `saleOrderNo` 来源于 `sales_order_header.sales_order_no`。
- `saleOrderItemNo` 来源于 `sales_order_item.line_no`，转为字符串返回。
- `saleOrderItemNo` 不允许使用 QPO 内部 `salesOrderItemId` 冒充。
- 如果发现历史数据 `sales_order_item.line_no` 为空，应先做数据治理或迁移补齐，再对外开放同步；接口层不制造假的销售订单行号。

### 2.3 必返订单类型

订单头和零件行都必须返回订单类型字段：

```text
orderType
items[].orderType
```

取值规则：

```text
订单头 orderType：sales_order_header.order_type
零件行 orderType：优先 sales_order_item.order_type；为空时回退 sales_order_header.order_type
```

订单类型示例：

```text
备货订单 / 正式订单 / 预测订单
```

## 3. 推荐接口

### 3.1 URL

```http
GET /api/integrations/sales-orders
```

### 3.2 鉴权

```http
Authorization: Bearer {QPO_OPEN_API_TOKEN}
```

要求：

- 不复用前端用户登录 token。
- 使用 QPO 入站开放接口统一 token；该 token 同时用于 MES 物料号回调、销售订单外部同步和后续新增的入站开放接口。
- 后端只存统一 token 的哈希值，不存明文；所有入站开放接口共用同一套校验逻辑。
- token 明文只在生成 / 轮换时展示一次，后续仅展示掩码和更新时间。
- 轮换统一 token 后，旧 token 立即对所有入站开放接口失效，外部调用方必须同步替换。
- 请求日志、操作日志、异常日志不得记录 token、Authorization header、Cookie。

### 3.3 查询参数

| 参数 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `pageSize` | integer | 否 | 可选 `20 / 50 / 100`，默认 `100`。含义是本次最多返回订单数量，不是零件行数量。 |
| `cursor` | string | 否 | 游标。首次同步为空；后续使用上次响应的 `nextCursor`。 |
| `saleOrderNo` | string | 否 | 销售订单号，精确或前缀/模糊规则见第 5 节。 |
| `materialNo` | string | 否 | QPO / MES 物料号，对应 `sales_order_item.material_no`。 |
| `partNo` | string | 否 | 图号，对应 `sales_order_item.part_no`。 |
| `version` | string | 否 | 图纸版本号，对应 `sales_order_item.version`。 |
| `status` | string | 否 | 订单状态，对应 `sales_order_header.status`。 |
| `createdFrom` | datetime | 否 | 订单创建时间起，闭区间。 |
| `createdTo` | datetime | 否 | 订单创建时间止，闭区间。 |
| `updatedFrom` | datetime | 否 | 订单或零件变更时间起，闭区间。 |
| `updatedTo` | datetime | 否 | 订单或零件变更时间止，闭区间。 |

时间格式：

```text
yyyy-MM-dd'T'HH:mm:ss
```

示例：

```text
2026-08-14T10:00:00
```

### 3.4 pageSize 规则

```text
允许值：20 / 50 / 100
默认值：100
最大值：100
非法值：返回 400 参数错误
```

说明：

- 外部系统是定时同步，默认 `100` 能减少调用次数。
- 限制最大 `100`，避免订单头加 `items[]` 后响应体过大。
- 对机器接口建议参数严格校验，避免调用方长期带着错误参数运行。

## 5. 查询语义

### 5.1 订单号筛选

`saleOrderNo` 建议采用精确匹配，避免外部同步误拉过多数据。

```sql
so.sales_order_no = :saleOrderNo
```

如果后续外部系统明确需要模糊查询，应新增单独参数 `saleOrderNoLike`，不要改变 `saleOrderNo` 的精确语义。

### 5.2 行级筛选

以下参数属于零件行筛选：

```text
materialNo
partNo
version
```

处理规则：

- 订单头只返回存在命中行的订单。
- `items[]` 只返回命中的零件行。
- 如果不传行级筛选参数，则 `items[]` 返回该订单全部零件行。

行级筛选 SQL 语义：

```sql
EXISTS (
  SELECT 1
  FROM sales_order_item soi
  WHERE soi.sales_order_id = so.id
    AND (:materialNo IS NULL OR soi.material_no = :materialNo)
    AND (:partNo IS NULL OR soi.part_no = :partNo)
    AND (:version IS NULL OR soi.version = :version)
)
```

零件行加载时复用同一组行级条件，确保返回行与筛选条件一致。

### 5.3 状态筛选

`status` 对应订单头状态：

```sql
so.status = :status
```

不传 `status` 时返回所有状态，包括 `废弃`。原因是外部系统做本地同步，需要知道订单被废弃或恢复，不能默认过滤掉状态变化。

### 5.4 创建时间筛选

创建时间只看订单头：

```sql
so.created_at >= :createdFrom
so.created_at <= :createdTo
```

### 5.5 修改时间 / changedAt 筛选

外部系统做增量同步时，不能只看订单头 `updated_at`，否则零件行单独变更会漏同步。例如：MES 回写物料号、零件状态变化、交期补录。

本接口定义订单级 `changedAt`：

```sql
changedAt = GREATEST(
  so.updated_at,
  COALESCE(MAX(soi.updated_at), so.updated_at)
)
```

`updatedFrom / updatedTo` 过滤 `changedAt`：

```sql
changedAt >= :updatedFrom
changedAt <= :updatedTo
```

## 6. 分页与游标

### 6.1 为什么不用 page/pageSize

定时同步过程中数据可能持续写入或更新，普通 `page=1/2/3` 容易出现跳页或重复。外部同步应使用稳定游标。

### 6.2 排序规则

订单级分页排序：

```sql
ORDER BY changed_at ASC, so.id ASC
```

游标内容：

```json
{
  "changedAt": "2026-08-14T11:00:00",
  "salesOrderId": 123
}
```

游标编码：

```text
Base64URL(JSON)
```

### 6.3 下一页条件

```sql
(
  changed_at > :cursorChangedAt
  OR (changed_at = :cursorChangedAt AND so.id > :cursorSalesOrderId)
)
```

### 6.4 hasMore 判断

服务端查询 `pageSize + 1` 条订单：

- 如果多出 1 条，返回前 `pageSize` 条，`hasMore = true`，并生成 `nextCursor`。
- 如果没有多出，`hasMore = false`，`nextCursor = null`。

## 8. 脱敏与禁止返回字段

本接口虽然返回客户和项目字段，但必须排除价格、成本、报价和内部治理字段。

### 8.1 禁止返回价格字段

以下字段不得出现在响应中：

```text
taxIncludedUnitPrice
untaxedUnitPrice
taxIncludedTotalPrice
untaxedTotalPrice
assemblyFee
baseCost
```

对应数据库字段：

```text
sales_order_item.tax_included_unit_price
sales_order_item.untaxed_unit_price
sales_order_item.tax_included_total_price
sales_order_item.untaxed_total_price
sales_order_item.assembly_fee
sales_order_item.base_cost
```

### 8.2 禁止返回内部结构字段

以下字段不得出现在响应中：

```text
materialData
processRoute
feeData
drawingUrl
importBatchId
importRecordId
createdBy
ownerUserId
ownerDeptId
u9SyncRequestHash
u9SyncAttemptId
sourceReleaseRequestHash
```

说明：

- `drawingUrl` 不返回，避免外部系统直接拿到文件地址。
- `processRoute`、`feeData`、`materialData` 可能包含内部报价、工艺或结构化明细，本接口不开放。
- U9 同步内部追踪字段和导入批次字段不属于外部销售订单同步契约。

## 9. 鉴权与入站配置设计

### 9.1 推荐复用现有入站配置模式

当前项目已有 `system_inbound_callback_config` 和 `SystemInboundCallbackConfigService`，用于入站接口配置管理。最终口径调整为：入站接口页面顶部管理一个 **QPO 入站开放接口统一 token**，接口列表只维护各入站接口的路径、启停、来源系统和说明，不再按接口行分别生成 token。

新增入站接口编码：

```text
SALES_ORDER_SYNC_QUERY
```

元数据建议：

```text
sourceSystemCode = EXTERNAL_SALES_ORDER_SYNC
name = 销售订单外部同步查询
callbackPath = /api/integrations/sales-orders
enabled = true
authMode = QPO_OPEN_API_TOKEN
```

说明：`SALES_ORDER_SYNC_QUERY` 是接口元数据编码，不代表新增独立 token。销售订单同步接口和 MES 物料号回调接口都读取同一个全局入站开放接口 token。

### 9.2 AuthInterceptor 放行

`AuthInterceptor.isPublicPath(...)` 增加：

```text
/api/integrations/sales-orders
```

该路径不走前端用户登录态，但 Controller 必须自己校验 `QPO_OPEN_API_TOKEN`。

### 9.3 Token 校验

新增全局入站开放接口 token 校验方法，避免把 token 绑定到某一个回调编码：

```java
hasValidOpenApiBearerToken(authorization)
```

如果继续沿用现有 `SystemInboundCallbackConfigService`，应把“接口元数据”与“全局 token”拆开：`InboundCallbackCode` 只用于识别接口路径和启停状态，token 校验不再以 `callbackCode` 作为隔离维度。

### 9.4 数据范围

本接口面向受信内部系统同步销售订单主数据，不使用普通用户登录态下的 `DataScopeService`。

安全边界为：

```text
QPO 入站开放接口统一 token + 接口只读 + 字段脱敏 + 低噪声审计/文件日志
```

如果未来同一 QPO 要给多个外部调用方开放不同客户范围，应在入站接口配置上新增调用方数据范围，例如 `allowedCustomerCodes`；当配置为空集合时必须返回空列表，不能默认泄露全量数据。

## 11. 查询实现建议

### 11.1 订单分页查询

伪 SQL：

```sql
WITH order_changed AS (
  SELECT
    so.id,
    GREATEST(so.updated_at, COALESCE(MAX(soi.updated_at), so.updated_at)) AS changed_at
  FROM sales_order_header so
  LEFT JOIN sales_order_item soi ON soi.sales_order_id = so.id
  WHERE 1 = 1
    AND (:saleOrderNo IS NULL OR so.sales_order_no = :saleOrderNo)
    AND (:status IS NULL OR so.status = :status)
    AND (:createdFrom IS NULL OR so.created_at >= :createdFrom)
    AND (:createdTo IS NULL OR so.created_at <= :createdTo)
    AND (
      :hasItemFilter = false
      OR EXISTS (
        SELECT 1
        FROM sales_order_item f
        WHERE f.sales_order_id = so.id
          AND (:materialNo IS NULL OR f.material_no = :materialNo)
          AND (:partNo IS NULL OR f.part_no = :partNo)
          AND (:version IS NULL OR f.version = :version)
      )
    )
  GROUP BY so.id, so.updated_at
)
SELECT so.*, oc.changed_at
FROM order_changed oc
JOIN sales_order_header so ON so.id = oc.id
WHERE 1 = 1
  AND (:updatedFrom IS NULL OR oc.changed_at >= :updatedFrom)
  AND (:updatedTo IS NULL OR oc.changed_at <= :updatedTo)
  AND (
    :cursorChangedAt IS NULL
    OR oc.changed_at > :cursorChangedAt
    OR (oc.changed_at = :cursorChangedAt AND so.id > :cursorSalesOrderId)
  )
ORDER BY oc.changed_at ASC, so.id ASC
LIMIT :limitPlusOne
```

### 11.2 零件行查询

不传行级筛选时：

```sql
SELECT *
FROM sales_order_item
WHERE sales_order_id IN (:orderIds)
ORDER BY sales_order_id ASC, line_no ASC, id ASC
```

传行级筛选时：

```sql
SELECT *
FROM sales_order_item
WHERE sales_order_id IN (:orderIds)
  AND (:materialNo IS NULL OR material_no = :materialNo)
  AND (:partNo IS NULL OR part_no = :partNo)
  AND (:version IS NULL OR version = :version)
ORDER BY sales_order_id ASC, line_no ASC, id ASC
```

- token 错误返回 401。

- 统一 token 轮换后，MES 物料号回调也必须使用新 token；旧 token 仍按 MES 回调既有契约返回 HTTP 200、响应体 `code=401`。

- `pageSize=20/50/100` 成功。
- `pageSize=10/500/abc` 返回 400。
- `createdFrom/createdTo/updatedFrom/updatedTo` 格式错误返回 400。
- cursor 格式错误返回 400。

- 订单头必返 `saleOrderNo`。

- 订单头必返 `orderType` 字段。
- 零件行必返 `orderType` 字段。

- `sales_order_item.line_no` 为空时，接口不得用内部 ID 冒充 `saleOrderItemNo`。

taxIncludedUnitPrice

### 15.5 查询测试

- 按 `materialNo` 查询只返回命中订单，且 `items[]` 只包含命中行。
- 按 `partNo + version` 查询只返回命中行。

### 15.6 增量同步测试

- 只更新 `sales_order_item.updated_at`，`updatedFrom` 也能查到订单。
- 游标分页按 `changedAt ASC, salesOrderId ASC` 稳定推进。
- 同一 `changedAt` 下多张订单不会漏页或重复。

## 16. 不做事项

本接口不做以下事情：

- 不新增、修改、删除销售订单。
- 不同步价格字段。
- 不开放图纸文件 URL。
- 不返回工艺路线、费用明细、材料 JSON 原文。
- 不触发 MES / WMS / U9。
- 不复用前端页面接口。
- 不复用前端用户登录 token。
- 不新增销售订单同步专用 token。
- 不把 QPO 内部 ID 作为外部系统的主要业务键。

## 17. 外部系统落库建议

外部系统本地建议按以下键幂等 upsert：

订单表：

```text
saleOrderNo
```

订单行表：

```text
saleOrderNo + saleOrderItemNo
```

同步策略：

1. 首次不传 `cursor`，可不传 `updatedFrom` 做全量同步。
2. 每页处理完成后保存响应中的 `nextCursor`。
3. `hasMore=true` 时继续拉取下一页。
4. `hasMore=false` 时保存本轮完成时间。
5. 定时增量时可使用上次成功水位的 `updatedFrom`，同时允许重叠 1 至 5 分钟窗口，依赖业务键 upsert 去重。

## 18. 最终结论

本接口采用独立只读机器同步方案：

```text
GET /api/integrations/sales-orders
Authorization: Bearer {QPO_OPEN_API_TOKEN}
业务主键：saleOrderNo + saleOrderItemNo
分页：cursor + pageSize(20/50/100，默认100)
增量水位：订单头或零件行任一更新时间 changedAt
脱敏：不返回价格、成本、图纸 URL、工艺/费用/材料 JSON 原文
```

该方案能满足外部系统定时同步到本地的需求，同时保持 QPO 原有销售订单、MES、WMS、U9 链路不被扰动。

## 19. 分阶段开发计划

本计划按“先统一入站鉴权，再开放销售订单同步接口”的顺序实施，避免先把销售订单接口做成独立 token，后续再返工。

### 阶段 1：统一 token 后端基础

目标：建立 `QPO_OPEN_API_TOKEN` 的后端统一鉴权能力，供 MES 回调、销售订单同步和后续入站开放接口共用。

修改范围：

- 扩展 `SystemInboundCallbackConfigService`，新增 `hasValidOpenApiBearerToken(String authorization)` 之类的统一校验方法。
- 新增统一 token 状态查询和生成 / 轮换接口：
  - `GET /api/system/inbound-callback-configs/open-api-token`
  - `POST /api/system/inbound-callback-configs/open-api-token`
- token 只存 hash，不存明文；生成 / 轮换时明文只返回一次。
- 轮换统一 token 后，旧 token 对所有入站开放接口立即失效。
- 保留 `system:config:inbound:token-rotate` 权限作为统一 token 轮换权限，不新增 `common:*` 权限。

验收标准：

- 无 token、错误 token 均无法通过统一 token 校验。
- 正确 `QPO_OPEN_API_TOKEN` 可通过统一 token 校验。
- 轮换后旧 token 失效，新 token 生效。
- 操作日志和文件日志不出现 token 明文、token hash、Authorization header。

### 阶段 2：入站接口配置页面调整

目标：把统一 token 管理入口放到 **系统配置 > 入站接口** 页面顶部、刷新按钮旁，接口列表只维护元数据。

修改范围：

- 调整 `SystemInboundCallbackConfigPanel.vue` 顶部工具条：刷新、统一 token 状态、生成 token、轮换 token。
- 移除或弱化接口行级 token 操作，避免管理员误认为 MES 回调和销售订单同步各有独立 token。
- 接口列表展示：接口名称、来源系统、接口路径、启停状态、`authMode=QPO_OPEN_API_TOKEN`、最近校验状态。
- `systemConfigApi.js` 增加统一 token API，并把接口配置 API 泛化为 `{interfaceCode}` 维度。

验收标准：

- 入站接口页顶部能看到统一 token 状态和轮换入口。
- MES 物料号回调、销售订单外部同步查询都展示 `QPO_OPEN_API_TOKEN`。
- token 明文只在生成 / 轮换成功弹窗展示一次。
- 无 `system:config:inbound:token-rotate` 权限时不能生成或轮换 token。

### 阶段 3：现有 MES 回调接入统一 token

目标：先让既有入站接口跑通统一 token，证明全局鉴权链路可用。

修改范围：

- 改造 `MesIntegrationCallbackController`，从原 MES 专用 token 校验切换为统一 token 校验。
- 保持 MES 回调业务契约不变：鉴权失败仍返回 HTTP `200`，响应体 `code=401`。
- 保持现有 `mesRequestId + drawingNo + drawingVersion` 定位、幂等、冲突拒绝和 fan-out 写回逻辑不变。
- 更新 MES 回调相关测试中的 token 占位符和断言。

验收标准：

- 正确 `QPO_OPEN_API_TOKEN` 可完成 MES 物料号回调。
- 错误 token 不进入物料号写回逻辑。
- MES 回调原有成功、失败、重复、冲突、旧请求拒绝测试不回退。
- 日志仍不输出完整回调体或 token。

### 阶段 4：销售订单同步接口骨架

目标：新增只读机器接口入口，先完成参数接收、统一 token 鉴权和空结果响应骨架。

修改范围：

- 新增 `SalesOrderIntegrationController`：`GET /api/integrations/sales-orders`。
- `AuthInterceptor.isPublicPath(...)` 放行 `/api/integrations/sales-orders`，但 Controller 必须自行校验 `QPO_OPEN_API_TOKEN`。
- 新增请求参数 DTO：`pageSize`、`cursor`、`saleOrderNo`、`materialNo`、`partNo`、`version`、`status`、`createdFrom/To`、`updatedFrom/To`。
- 实现 `pageSize` 严格校验：只允许 `20 / 50 / 100`，默认 `100`。
- 鉴权失败按销售订单同步接口标准返回 HTTP `401`。

验收标准：

- 无 token / 错误 token 返回 HTTP `401`。
- 正确 token 可进入查询 service。
- `pageSize=20/50/100` 成功，非法 `pageSize` 返回 HTTP `400`。
- 该接口不要求普通用户登录态，不进入前端用户权限树。

### 阶段 5：销售订单查询与游标分页

目标：完成订单头分页、行级筛选和增量同步水位，保证外部系统定时同步稳定。

修改范围：

- 新增 `SalesOrderIntegrationSyncService` 和专用 mapper，例如 `SalesOrderIntegrationMapper`。
- 订单级分页按 `changedAt ASC, salesOrderId ASC` 推进。
- `changedAt = GREATEST(sales_order_header.updated_at, MAX(sales_order_item.updated_at))`。
- 支持 `createdFrom/createdTo`、`updatedFrom/updatedTo`、`status`、`saleOrderNo` 查询。
- 支持行级筛选：`materialNo`、`partNo`、`version`；命中订单后 `items[]` 只返回命中行。
- 游标使用 `Base64URL(JSON)`，内容包含 `changedAt` 和 `salesOrderId`。

验收标准：

- 不传行级筛选时返回订单全部零件行。
- 传 `materialNo` 或 `partNo + version` 时，只返回命中订单和命中行。
- 只更新订单头或只更新零件行，`updatedFrom` 都能查到该订单。
- 同一 `changedAt` 下多张订单分页不漏、不重。

### 阶段 6：响应 DTO、字段脱敏和业务身份

目标：完成对外响应契约，确保业务键稳定、字段足够详细且不泄露价格和内部治理字段。

- `saleOrderItemNo` 固定来自 `sales_order_item.line_no`，不得使用 QPO 内部 ID 冒充。
- `items[].orderType` 优先取行级 `order_type`，为空时回退订单头 `order_type`。
- 响应不得包含价格、成本、图纸 URL、工艺路线、费用 JSON、材料 JSON、U9 内部追踪字段。

验收标准：

- 订单头和零件行均包含 `saleOrderNo`。
- 零件行均包含 `saleOrderItemNo`。
- 订单头和零件行均包含 `orderType`。
- 响应 JSON 不包含第 8 节列出的禁止字段。
