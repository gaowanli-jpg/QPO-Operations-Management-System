# 22 Action Loading And Duplicate Guard

本规范用于 QPO 前端所有按钮、批量操作、导入导出、外部系统同步和异步任务触发场景。

核心判断：用户点击后只要需要等待后端结果，页面必须立即给出反馈；只要操作会改变数据或触发外部动作，必须防重复点击。

## 适用范围

必须处理加载状态和防重复提交的操作：

- 保存、提交、完成、审批、回滚、作废、恢复、删除、重置。
- 导入 RFQ、上传图纸、替换图纸、补图、上传模板。
- 生成提单、保存报价单、刷新核价、批量设置交期。
- 同步 MES 物料号、提交 WMS 锁库、后续推送外部系统。
- 导出报价单、导出提单、导出工艺表等需要等待文件生成的动作。

可以只做轻量 loading 的操作：

- 列表查询、筛选、翻页、刷新表格。
- 查看详情、打开预览、加载下拉选项。
- 普通只读统计、只读摘要、只读联想查询。

## 交互规则

### 按钮级 loading

用于单个按钮触发单个请求的场景。

规则：

- 点击后 100ms 内进入 loading 或 disabled 状态。
- 当前按钮必须禁用，防止连续点击产生重复请求。
- 按钮文案应保持稳定，必要时显示“处理中”“保存中”“导出中”。
- 请求成功、失败或取消后必须恢复按钮状态。
- 失败时必须显示可理解的错误提示，不能静默恢复。

典型场景：

- 保存整单默认设定。
- 保存单个零件核价。
- 同步某一行 MES 物料号。
- 提交某一行 WMS 锁库。

### 行级 loading

用于表格中某一行的操作，不应影响其它无关行。

规则：

- 使用当前行 id 记录 loading，例如 `loadingRowId` 或 `wmsAllocationLoadingId`。
- 当前行相关按钮禁用，其它行可以继续查看或处理。
- 如果同一行存在多个会互相冲突的动作，执行期间应一起禁用。

典型场景：

- 单行同步 MES。
- 单行提交 WMS 锁库。
- 单行查看或刷新外部状态。

### 区域级 loading

用于表格、表单或页面区域整体刷新。

规则：

- 表格查询使用表格 loading，不锁住整个页面。
- 表单提交可以锁当前表单或弹窗，不锁无关导航。
- 批量操作执行期间，应禁用同一区域内会改变同一批数据的按钮。

典型场景：

- 列表筛选和翻页。
- 加载订单明细、已提零件、锁库零件。
- 批量设置报价交期。

### 页面级 loading

仅用于强依赖页面状态的长操作。

规则：

- 只有当前页面数据状态在操作完成前不应被继续编辑时，才使用页面级遮罩。
- 页面级 loading 不应阻断顶部导航或退出路径，除非离开会造成数据损坏。
- 超过 3 秒的操作，应优先改成异步任务反馈，而不是一直遮罩等待。

典型场景：

- 首次加载核心工作台数据。
- 需要整体重建页面数据的批量刷新。

## 同步操作与异步任务

### 同步请求

同步请求指前端等待接口直接返回最终结果。

规则：

- 必须有按钮 loading。
- 必须禁用当前触发按钮。
- 写操作必须用 `try / catch / finally` 恢复状态。
- 同一业务对象的冲突按钮应一起禁用。

### 异步任务

异步任务指接口只返回 `taskId`，实际处理在后台继续执行。

规则：

- 提交任务按钮必须短暂 loading，直到拿到 `taskId`。
- 拿到 `taskId` 后显示“任务已提交 / 处理中 / 查看任务状态”。
- 同一对象同一任务未完成前，不允许重复提交。
- 页面应提供刷新任务状态或进入任务详情的路径。
- 任务失败必须展示失败原因或引导用户查看任务详情。

典型场景：

- 大批量刷新核价。
- 大文件导出。
- 外部系统同步或推送。

## 禁用范围

禁用范围要按影响面控制，避免过度锁页。

| 操作类型 | 推荐禁用范围 | 说明 |
| --- | --- | --- |
| 单行查询 | 当前按钮 | 不影响其它操作 |
| 单行写入 | 当前行相关按钮 | 防止同一行重复提交 |
| 表格查询 | 当前表格区域 | 筛选、翻页、刷新互斥 |
| 表单保存 | 当前表单/弹窗 | 防止重复保存 |
| 批量写入 | 当前批量区域 | 禁用同批次冲突动作 |
| 删除/作废/回滚 | 当前对象相关动作 | 需要确认弹窗和执行中禁用 |
| 异步任务提交 | 当前对象同类任务按钮 | 后续由任务状态接管 |

## 前后端职责

前端必须做加载反馈和防重复点击，但不能把它当成唯一防线。

前端负责：

- loading、disabled、确认弹窗、错误提示。
- 防止用户短时间重复触发同一动作。
- 用任务状态引导用户理解后台仍在处理。

后端负责：

- 对关键写操作做状态校验。
- 对外部同步和异步任务做重复提交保护。
- 对删除、回滚、作废、生成提单、WMS 锁库等操作保证数据一致性。
- 返回清晰错误信息，方便前端提示用户。

## QPO 实现约定

Vue 页面中推荐模式：

```js
const saving = ref(false)

const handleSave = async () => {
  if (saving.value) return
  saving.value = true
  try {
    await saveSomething(payload)
    ElMessage.success('保存成功')
  } catch (error) {
    ElMessage.error(readableError(error) || '保存失败，请稍后重试')
  } finally {
    saving.value = false
  }
}
```

Element Plus 按钮推荐：

```vue
<el-button
  type="primary"
  :loading="saving"
  :disabled="saving"
  @click="handleSave"
>
  保存
</el-button>
```

表格行级操作推荐：

```js
const loadingRowId = ref(null)

const handleRowAction = async (row) => {
  if (loadingRowId.value === row.id) return
  loadingRowId.value = row.id
  try {
    await submitRow(row.id)
  } finally {
    loadingRowId.value = null
  }
}
```

## 验收清单

- [ ] 写操作按钮点击后有 loading 或 disabled 状态。
- [ ] 同一按钮连续点击不会发起重复请求。
- [ ] 同一业务对象的冲突按钮在执行期间不可点。
- [ ] 查询类操作使用局部 loading，不阻塞无关页面区域。
- [ ] 批量和外部同步操作有明确的处理中反馈。
- [ ] 异步任务拿到 `taskId` 后有任务状态入口或刷新机制。
- [ ] 成功和失败都有用户可理解的提示。
- [ ] `finally` 或等价逻辑保证异常后状态能恢复。
- [ ] 后端关键写接口仍有状态校验和重复提交保护。
