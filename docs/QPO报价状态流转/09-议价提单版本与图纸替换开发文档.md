# QPO 议价提单版本与图纸替换开发文档

## 1. 背景

议价提单处于询价、核价、报价之后，正式生成提单之前。客户在报价期间可能更新零件版本或图纸，市场部也可能上传客户打码后的新版图纸。

因此，议价提单页面需要支持提单前修订零件版本和替换图纸，确保生成的正式提单使用最新资料。

## 2. 目标

- 在议价提单候选零件表中支持单行版本修改。
- 在议价提单页面支持批量导入 PDF 图纸并按图号替换旧图纸。
- 图纸替换范围为当前已选择的所有订单，不受当前分页限制。
- 替换成功后刷新候选零件分页并保留跨页选中态。
- 不影响已生成提单行；历史提单快照保持不可逆。

## 3. 不做范围

- 不修改 `提单表据` 页面，表据仍只负责生成后的查看与导出。
- 不回写已生成的 `order_delivery_ticket` 历史记录。
- 不新增筛选框、索引或新的独立模块。
- 不按版本匹配图纸，图纸替换只按图号匹配。
- 不新增可分配 `common:*` 权限。

## 4. 权限口径

沿用议价提单现有权限：

- 查看候选零件：`market:release:view`
- 修改版本：`market:release:create`
- 导入替换图纸：`market:release:create`
- 生成正式提单：`market:release:create`

本次不新增 `market:release:update-version` 或 `market:release:replace-drawing`，除非后续需要把“能生成提单”和“能维护提单前资料”拆权。

## 5. 日志口径

### 5.1 操作日志

新增动作建议：

- `RELEASE_ITEM_VERSION_UPDATE`：议价提单修改零件版本。
- `RELEASE_DRAWING_REPLACE`：议价提单导入替换图纸。

记录摘要：

- `rfqId`
- `rfqNo`
- `itemId`
- `partNo`
- `beforeVersion / afterVersion`
- `uploadCount`
- `matchedCount`
- `replacedCount`
- `unmatchedCount`
- `skippedCount`

不得记录 PDF 内容、完整请求体、Authorization header、token、Cookie。

### 5.2 文件日志

低噪声摘要事件：

- `Release item version updated`
- `Release drawings replace completed`
- `Release drawings replace completed with warnings`
- `Release drawings replace failed`

文件日志只记录汇总数量和关键 ID，不在每个图纸或零件循环内打 INFO。

## 6. 后端设计

### 6.1 修改单行版本

新增接口：

```text
POST /api/market/release/items/{itemId}/version
Permission: market:release:create
```

请求：

```json
{
  "rfqId": 123,
  "version": "B"
}
```

规则：

- `itemId` 必须存在。
- `item.rfqId` 必须等于请求 `rfqId`。
- 当前用户必须有该订单数据权限。
- 零件已全部提单仍允许修改版本和替换图纸；变更只影响 RFQ 零件主表和后续新提单，不改历史 ticket 快照。
- 只更新当前单一零件的 `item_quote_version.version`。
- 返回更新后的候选零件行结构，便于前端局部刷新。

### 6.2 批量替换图纸

新增接口：

```text
POST /api/market/release/drawings/replace
Permission: market:release:create
Content-Type: multipart/form-data
```

表单字段：

- `rfqIds`：JSON 数组，例如 `[101,102]`
- `drawings`：多个 PDF 文件

规则：

- `rfqIds` 为空时拒绝。
- 每个 `rfqId` 必须执行数据权限校验。
- 只在这些订单的候选零件中匹配。
- 文件名解析图号，复用现有 `DrawingPartNoResolver`。
- 匹配到同一图号的所有零件全部替换 `drawing_url`。
- 已有图纸也覆盖，不再走“已有图纸不覆盖”的补传逻辑。
- 非 PDF 跳过并返回原因。
- 未匹配图纸返回未匹配列表。
- 保存路径继续使用订单图纸目录。

返回：

```json
{
  "success": true,
  "message": "图纸替换完成，成功替换 8 项。",
  "uploadCount": 5,
  "matchedCount": 8,
  "replacedCount": 8,
  "unmatchedCount": 1,
  "skippedCount": 0,
  "replacedItems": [],
  "unmatchedDrawings": [],
  "skippedFiles": []
}
```

## 7. 前端设计

### 7.1 候选零件表调整

在 `MarketRelease.vue` 候选零件表中：

- `版本` 列改为可编辑。
- 版本保存只作用于当前行零件，不联动同图号其他订单或其他零件。
- 建议使用行内保存按钮，避免失焦误保存。
- 新增 `图纸` 状态列：
  - `已绑定`
  - `缺图`
- 替换图纸后刷新当前页，状态立即更新。

候选接口需返回：

- `drawingUrl`
- `hasDrawing`

### 7.2 图纸替换入口

在候选零件表头附近新增按钮：

```text
导入替换图纸
```

交互复用订单管理的上传体验：

- 支持多个 PDF。
- 支持文件夹拖拽或选择。
- 只收集 PDF。
- 上传前提示：匹配成功的图号会覆盖旧图纸。
- 上传后展示替换结果摘要。

### 7.3 多订单行为

- 使用 `selectedOrderIds` 作为替换范围。
- 不依赖当前分页。
- 上传 PDF 后从文件名解析图号，在当前已选择的所有订单候选零件里匹配。
- 只要匹配成功，就全部替换对应零件的旧图纸。
- 替换成功后调用 `fetchReleaseItemsBatch()`。
- 保留 `selectedItemIdMap` 中的跨页选中项。
- 如果某个已选零件版本被用户改过，保留已选数量和通过数量。

## 8. 数据一致性

- 版本修改在 `item_quote_version` 上生效，生成提单时自然进入 `order_delivery_ticket.version`。
- 图纸替换在 `item_quote_version.drawing_url` 上生效，后续 MES 物料号同步读取最新图纸。
- 已生成提单不回改，避免破坏历史快照。
- 如果零件已全部提单，仍允许修改版本和替换图纸；历史已生成 ticket 保持不可变。

## 9. 测试计划

### 9.1 后端测试

- 有 `market:release:create` 才能修改版本。
- 无数据权限订单不能修改版本或替换图纸。
- 修改版本只影响指定 `itemId`。
- 图纸替换按图号匹配多个订单中的所有零件。
- 非 PDF 跳过。
- 未匹配文件返回未匹配结果。
- 已提单零件拒绝修改版本和替换图纸。
- 操作日志动作和文件日志事件存在且不记录敏感内容。

### 9.2 前端测试

- 候选零件表展示图纸状态列。
- 版本列可编辑并调用新接口。
- 图纸替换上传传入 `rfqIds + drawings`。
- 多订单场景下图纸替换范围为全部已选订单。
- 替换后刷新批量分页接口。
- 跨页选中态不丢失。

## 10. 实施阶段

### 阶段 1：后端接口与权限日志

目标：先落地安全边界和审计边界。

修改：

- 新增版本修改请求 DTO。
- 新增图纸替换服务方法。
- `MarketController.java` 新增两个 release 接口。
- 补操作日志中文映射。
- 补后端测试。

验收：

- 无 `market:release:create` 不能修改版本或替换图纸。
- 无数据权限订单不能被修改。
- 版本修改和图纸替换有操作日志和低噪声文件日志。

### 阶段 2：候选接口补图纸状态

目标：前端候选表可展示图纸状态。

修改：

- `InternalTargetLeadTimeService.buildItemRow()` 返回 `drawingUrl / hasDrawing`。
- 批量分页接口同步返回图纸状态。
- 补分页结构测试。

验收：

- 单订单和多订单候选分页都返回图纸状态。
- 不改变现有后端分页口径。

### 阶段 3：前端版本编辑

目标：市场可修改单一候选零件版本。

修改：

- `marketApi.js` 新增版本更新 API。
- `MarketRelease.vue` 版本列改为单行编辑保存。
- 保存成功后局部更新或刷新当前页。
- 补前端测试。

验收：

- 修改版本只影响当前行零件。
- 生成提单使用修改后的版本。
- 跨页选中态不丢失。

### 阶段 4：前端图纸替换

目标：市场可在议价提单页批量替换图纸。

修改：

- 抽取或复用订单管理现有图纸上传收集逻辑。
- 新增“导入替换图纸”按钮。
- 调用 release 图纸替换接口。
- 展示替换结果并刷新候选分页。
- 补前端测试。

验收：

- 上传 PDF 后按图号匹配当前已选所有订单。
- 同图号匹配到多个订单零件时全部替换。
- 非 PDF、未匹配图纸有明确结果提示。

### 阶段 5：文档与回归

目标：权限、日志和流程说明收口。

修改：

- 更新权限文档：说明沿用 `market:release:create`。
- 更新日志文档：说明版本修改和图纸替换审计口径。
- 跑完整回归：
  - `mvnw.cmd test`
  - `npm test`
  - `npm run build`

验收：

- 权限不新增噪声。
- 日志不记录图纸内容或完整请求体。
- 前后端测试与构建全部通过。

## 11. 验收标准

- 市场用户可在议价提单页面修改单一零件版本。
- 上传图纸后，当前已选订单范围内同图号零件全部替换为新图纸。
- 多订单、多分页场景下仍使用后端分页，不前端全量分页。
- 已生成提单记录不被回改。
- 无权限用户不能修改版本或替换图纸。
- 操作日志和文件日志有摘要，无敏感内容和高频噪声。
- 前后端测试与构建全部通过。
