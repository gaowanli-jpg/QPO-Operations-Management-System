## 1. 背景与最终结论

当前 QPO 已经完成销售订单 U9 同步重构，第 42 号文档确认了 U9 创建销售订单的最小字段契约。后续还需要把客户来源和 U9 同步页的销售员/部门选择补齐。

本轮最终结论：

1. **客户资料模块保留，但改成 U9 客户只读缓存**：全系统客户选择都来自该缓存，QPO 用户不能在系统内维护客户。
2. **销售员和销售部门不单独建设管理模块**：它们只作为 U9 同步销售订单时的下拉选项能力存在。
3. **`orgCode` 不进入业务操作心智**：后台固定使用 U9 组织 `101` 拉取客户、销售员和部门；用户不需要选择组织，也不需要理解组织编码。
4. **新单客户必须来自 U9 客户缓存**：不再允许自由文本客户名进入 RFQ 或销售订单。
5. **销售订单保存快照**：保存客户编码/名称，以及 U9 同步时选择的 Seller、SaleDepartment 编码/名称，避免 U9 主数据后续变化影响历史订单。
6. **允许清空旧订单数据**：因此本轮可以做不兼容字段和数据权限口径调整，不需要为了旧 `customer_name` 订单继续保守兼容。

## 2. `orgCode` 的定位

`orgCode` 是 U9 组织编码，本轮固定为 `101`。它只用于：

- 调 U9 CommonEntity 查询客户、销售员、部门时过滤 U9 组织。
- 调 U9 创建销售订单时保证订单创建在正确 U9 组织下。
- 后台排查同步问题时知道数据来自哪个 U9 组织。

`orgCode` 不用于：

- 不给用户选择。
- 不作为客户选择弹窗的主要字段。
- 不作为销售订单页面的业务输入。
- 不作为角色数据范围页面需要用户理解的授权维度。

实现建议：

- 后端继续使用配置项 `erp.u9.org-code=101` 或系统配置中的 U9 组织设置。
- 数据库缓存表可以保存 `u9_org_code` 作为技术字段，便于排查和未来扩展。
- 前端普通业务页面默认不展示该字段；如客户资料页需要排查，可在“同步信息”中展示“来源组织：101”，但不提供切换。

## 3. 当前系统冲突点

### 3.1 客户资料仍是本地 CRUD

当前实现：

- `CustomerMasterController` 提供客户分页、选项、新增、编辑、删除接口。
- `CustomerMasterService.saveCustomer/deleteCustomer` 支持本地维护客户。
- `CustomerManage.vue` 有新增、编辑、删除按钮和维护弹窗。
- 权限清单中存在 `system:customer:create/update/delete`。
- 日志文档中存在 `CUSTOMER_MASTER_CREATE/UPDATE/DELETE` 维护动作。

目标实现：

- 客户资料页面只读。
- 后端不允许通过构造请求新增、编辑或删除客户。
- 客户数据来自 U9 同步缓存。
- 页面允许查询、刷新、查看同步状态。

### 3.2 客户选择仍可被旧自由文本影响

当前不少流程仍围绕 `customer_name` 工作：

- RFQ 导入传 `customerName`。
- 订单筛选和数据范围按 `customer_name` 匹配。
- 客户选择弹窗仍以名称作为主要选中判断。

目标实现：

- 新建 RFQ 和销售订单必须选 U9 客户对象。
- 后端以 `customer_code` 作为客户稳定身份，`customer_name` 只作为展示快照。
- 由于本轮允许清空旧订单，可以直接切换新单口径，不保留自由文本客户名兼容。

### 3.3 销售员/部门只应服务 U9 同步

当前 `U9MasterDataService` 已经能查 U9 销售业务员和部门，但只是内存缓存。

目标实现：

- 不新增“销售部门管理”左侧菜单。
- 不建设销售员/部门 CRUD 页面。
- 后端可以做持久化选项缓存，供 U9 同步页下拉框使用。
- U9 同步页继续支持 Seller / SaleDepartment 为空、选择销售员自动带出部门、部门可覆盖或清空。

## 4. 目标与非目标

### 4.1 开发目标

- 将客户资料模块改造为 U9 客户只读缓存模块。
- 移除客户资料本地新增、编辑、删除能力。
- 建立 U9 客户同步服务和本地缓存。
- 建立 U9 同步页专用的销售员/部门选项缓存。
- 全系统客户选择统一使用 U9 客户缓存。
- 清空旧订单后，新 RFQ、新销售订单必须保存 U9 客户编码和名称快照。
- 销售订单 U9 同步时保存 Seller / SaleDepartment 编码和名称快照。
- U9 同步请求继续遵守第 42 号文档的最小字段契约。
- 权限、日志、文档和测试与只读客户口径一致。

### 4.2 非目标

- 不在 QPO 创建、编辑、删除 U9 客户。
- 不建设独立销售部门或销售员管理模块。
- 不在 QPO 创建、编辑、删除 U9 销售部门或销售员。
- 不让用户选择 U9 组织。
- 不建设 U9 客户税率、收货地址、币种、站点等完整主数据平台。
- 不改变第 42 号文档确认的 U9 销售订单创建字段契约。
- 不在 QPO 计算 U9 税率、税额或含税金额。
- 不新增 `common:*` 权限。
- 不保留旧订单数据兼容要求；本轮允许清空旧询价订单和销售订单。

## 5. 清库与不兼容迁移边界

### 5.1 清库原则

允许清空订单数据，但清库不能作为普通 Flyway 自动迁移无提示执行。

推荐方式：

- Flyway 迁移只做结构变更、约束变更、权限变更和安全默认值。
- 另建一次性运维脚本，例如 `docs/ops/sql/clear_order_business_data_before_u9_customer_cutover.sql`。
- 部署前先备份数据库，再由开发/运维明确执行清库脚本。
- 清库脚本执行完成后，再运行新版本服务和迁移。

### 5.2 建议清空的数据范围

允许清空：

- RFQ：`order_rfq`
- RFQ 零件与组合关系：`item_quote_version`、`item_assembly_relation`
- 提单与后续池：`order_delivery_ticket`、`order_delivery_ticket_allocation`、`order_delivery_ticket_mes_request`、`order_delivery_ticket_mes_waiter`
- 销售订单：`sales_order_header`、`sales_order_item`、`sales_order_item_assembly_relation`、`sales_order_source_rfq`
- 销售订单导入记录：`sales_order_import_batch`、`sales_order_import_record`
- 与订单强绑定的系统任务，可按任务类型清理。

不建议清空：

- 用户、角色、权限、组织身份。
- 系统配置、数据中心配置、出站接口配置。
- 字典、材料、工艺、费用等主数据。
- 操作日志和运行日志。
- U9 客户缓存和 U9 同步选项缓存；这些表可由同步任务重建，但不需要和订单一起清空。

## 7. U9 CommonEntity 字段契约

- 实体：`UFIDA.U9.CBO.HR.Operator.Operators`

### 7.3 客户字段

阶段 1 已通过数据中心 `U9_COMMON_ENTITY_QUERY` 探测并锁定 U9 客户实体字段。

| 用途 | U9 实体 / 字段 | 说明 |
| --- | --- | --- |
| 客户实体 | `UFIDA.U9.CBO.SCM.Customer.Customer` | 组织 `101` 的客户主数据来源。 |
| 客户 U9 ID | `ID` | QPO 缓存排查字段。 |
| 客户编码 | `Code` | QPO `customerCode`，也是 U9 销售订单 `OrderBy` 来源。 |
| 客户名称 | `Name` | QPO `customerName` 展示快照。 |
| 客户简称 | `ShortName` | QPO `customerShortName`；`GSS1` 实测简称为 `GSS1`。 |
| 来源组织 | `Org.Code` / `Org.Name` | 后台固定过滤组织 `101`，不在 QPO 暴露 U9 组织选择。 |
| 有效状态 | `Effective.IsEffective` | QPO `enabled` 来源。 |
| 有效期辅助 | `Effective.EffectiveDate` / `Effective.DisableDate` | 可作为后续同步排查字段。 |

阶段 1 真实探测结论：

- 后台过滤：`Org.Code eq 101` 可返回有效客户列表。
- 已确认 `GSS1` 可查询，组织 `101` 下为有效客户，名称为“盛美半导体设备（上海）股份有限公司”。
- 已回查真实创建成功的 U9 销售订单 `QPO-S8-260811161318780-EMPTY`，`OrderBy.Code=GSS1`、`OrderBy.Name=盛美半导体设备（上海）股份有限公司`，确认 `customerCode` 作为 U9 销售订单 `OrderBy` 来源。
- U9 客户实体多条件过滤在数据中心侧需要谨慎使用；实施客户精确校验时优先使用单一 U9 过滤条件并在 QPO 侧做安全后置过滤。
- 原始错误中的 token、Authorization、client secret 和 `Data.Headers` 不进入日志、文档或 API 响应。

## 8. 同步机制设计

### 8.1 同步对象

同步分两类：

1. **客户主数据同步**：服务全系统客户选择。
2. **U9 同步选项同步**：同步销售员和部门，仅服务销售订单 U9 同步页面。

### 8.2 触发方式

推荐：

- 应用启动后延迟同步一次。
- 定时同步，例如每 30 分钟或每 1 小时。
- 客户资料页面提供“同步 U9 客户”按钮。
- U9 同步页面加载选项时，如果缓存为空或过期，后台可触发刷新或提示管理员刷新。

不建设独立销售部门/销售员管理页面，也不提供给用户维护销售部门/销售员的入口。

### 8.3 事务和失败处理

- 查询 U9 不开启数据库事务。
- 拉取完整页数据后，短事务批量 upsert。
- 同步失败保留上一轮成功缓存。
- 本轮 U9 未返回但本地存在的记录，不物理删除，标记 `enabled=false`。
- 新单选择只允许 `enabled=true` 的客户。
- U9 同步页 Seller / Department 可为空；如果选择了已停用项，提交前阻断。

## 11. 订单链路改造

### 11.1 RFQ 询价订单

新建 RFQ 时：

- 前端必须通过客户选择器选择 U9 客户。
- 请求必须传 `customerCode`，同时可传客户名称快照用于前端展示一致性。
- 后端按 `customerCode` 查询 `customer_master` 中 `enabled=true` 的客户。
- 后端写入 `order_rfq.customer_code/customer_short_name/customer_name` 快照。
- 清库后不再支持自由文本客户名导入。

### 11.2 销售订单直接导入

直接导入销售订单时：

- 默认客户必须来自 U9 客户缓存。
- 后端保存 `sales_order_header.customer_id/customer_code/customer_short_name/customer_name` 快照。
- 客户停用或不存在时，导入预览阻断。
- 清库后不再支持自由文本客户名导入。

### 11.3 RFQ 派生销售订单

RFQ 派生销售订单时：

- 使用 RFQ 订单快照中的 `customerCode`，不再按 `customerName` 查客户。
- 派生销售订单复制 RFQ 客户快照。
- 若 RFQ 客户快照缺失，直接阻断；清库后新 RFQ 不应出现缺失。

### 11.4 U9 同步

U9 同步时：

- 客户来自销售订单快照，不在 U9 同步阶段更改客户。
- Seller / SaleDepartment 来自 U9 同步页选项缓存。
- 选择值保存到 `sales_order_header.u9_seller_code/name` 和 `u9_sale_department_code/name`。
- 提交前校验所选 Seller / Department 当前仍有效；为空时允许。
- 请求字段仍遵守第 42 号文档，不新增客户料号、图号、版本、单位、换算率、税额、金额等字段。

- 完整 U9 请求体。
- 完整 U9 响应体。
- token、Authorization header、Cookie、client secret。
- 数据中心完整请求/响应。
- U9 `Data.Headers`。

建议 INFO 摘要：

- `U9 customer sync started syncRunId={}`

## 17. 风险与处理

### 17.1 U9 客户实体字段未确认

风险：U9 客户 CommonEntity 实体名或字段与预期不同。

处理：阶段 1 先做实体探测，测试通过后再进入表结构和页面开发；实体字段以真实查询结果锁定。

### 17.2 清库误执行

风险：清库脚本误在不该清空的环境执行。

处理：清库脚本不进入 Flyway 自动迁移；脚本头部写明环境确认、备份确认和二次确认步骤。

### 17.3 数据权限口径切换影响角色

风险：旧角色按客户名称授权，切换后无客户权限。

处理：清库后由管理员按 U9 客户重新授权；如需保留旧授权，提供一次性客户名称到客户编码匹配迁移报告。

### 17.4 U9 主数据同步失败

风险：U9 或数据中心短期不可用。

处理：页面读取上次成功缓存并展示过期状态；新建订单可继续使用未过期有效客户缓存，超过阈值时给出阻断或管理员提示。

## 18. 推荐实施顺序

1. 探测并锁定 U9 客户实体字段。
2. 准备清库脚本和数据库结构迁移。
3. 建 U9 客户同步缓存。
4. 改造客户资料为只读 U9 客户模块。
5. 建 U9 同步页 Seller / Department 选项缓存。
6. 改造客户选择器和数据权限。
7. 改造 RFQ、销售订单和 U9 同步链路。
8. 更新权限、日志、文档并做全量回归。
