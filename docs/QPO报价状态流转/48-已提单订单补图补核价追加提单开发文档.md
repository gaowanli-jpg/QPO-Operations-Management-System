# 已提单订单补图补核价追加提单开发文档

## 1. 背景

当前 RFQ 询价订单已经支持 `部分已提单`、`已生成提单` 订单继续进入议价提单，并允许已提单零件继续追加提单。新的业务场景是：

- RFQ 初始导入时，某些零件没有图纸，不能核价，也不能进入议价提单。
- 后续业务员补上这些零件图纸。
- 此时整单可能已经是 `部分已提单` 或 `已生成提单`。
- 工程仍需要能对补图零件进行核价。
- 市场仍需要确认补充报价。
- 补充报价确认后，该零件应能进入议价提单并生成新的 `order_delivery_ticket`。

本功能解决“已进入提单流程的 RFQ 订单中，后补图零件如何重新进入核价、报价确认和追加提单”的闭环问题。

## 2. 核心原则

1. 不回退整单主流程，不把 `部分已提单 / 已生成提单` 强制改回 `已核价`。
2. 历史 `order_delivery_ticket` 是不可变快照，补图、补核价、补充报价只影响 RFQ 零件主表和后续新提单。
3. 工程保存核价后，零件只能进入 `已核价`，不能直接进入 `已报价`。
4. 市场确认补充报价后，零件才进入 `已报价`，才允许在议价提单中被选中。
5. `已生成提单` 不再表示业务完全终止，只表示当前已报价可提单零件曾经全部覆盖原始询价数量。
6. 订单状态应按“当前已报价可提单零件是否都已覆盖原始询价数量”动态回算。

## 3. 目标状态口径

### 3.1 订单状态

本功能不新增订单状态，继续使用现有状态：

| 状态 | 本功能中的含义 |
| --- | --- |
| `部分已提单` | 已有提单行，且当前存在至少一个已报价可提单零件未覆盖原始询价数量。 |
| `已生成提单` | 已有提单行，且当前所有已报价可提单零件均已覆盖原始询价数量。 |

当补图零件完成市场补充报价后，如果它还没有提单，订单应从 `已生成提单` 回算为 `部分已提单`。这不是业务回退，而是因为“可提单零件范围扩大了”。该补图零件完成追加提单后，订单可再次回算为 `已生成提单`。

### 3.2 零件状态

本功能不新增零件状态，继续使用现有状态：

| 状态 | 本功能中的含义 |
| --- | --- |
| `无图` | 无图且未核价，不进入核价完成和议价提单范围。 |
| `未核价` | 已有图纸但工程尚未保存核价结果。 |
| `已核价` | 工程已保存核价结果，等待市场确认补充报价。 |
| `已报价` | 市场已确认补充报价，可进入议价提单。 |
| `已提单` | 累计提单数量已经覆盖原始询价数量，但仍允许后续追加提单。 |

## 4. 目标流程

```text
原状态：
订单：部分已提单 / 已生成提单
零件：无图 / 未核价，无价格，无 ticket

补传图纸：
零件：无图 -> 未核价

工程补核价：
零件：未核价 -> 已核价
订单：保持部分已提单 / 已生成提单

市场确认补充报价：
零件：已核价 -> 已报价
订单：按当前已报价可提单零件覆盖情况回算

追加议价提单：
生成新的 order_delivery_ticket
零件：累计已提数量 >= 原始询价数量时为 已提单
订单：按当前已报价可提单零件覆盖情况回算
```

## 5. 详细规则

### 5.1 补图状态恢复

RFQ 零件图纸补传或替换成功后：

- 若零件原状态为 `无图`，且 `tax_included_unit_price` 为空，则状态改为 `未核价`。
- 若零件原状态为 `未核价`，保持 `未核价`。
- 若零件已有核价结果或已进入 `已核价 / 已报价 / 已提单`，只替换图纸，不改状态。
- 不因补图动作修改历史 ticket 图纸快照。

补图动作完成后不立即把订单改为 `已核价`。订单如果已经 `部分已提单 / 已生成提单`，继续保持提单流程状态。

### 5.2 工程补核价入口

零件核价模块需要新增一个与现有“选择订单”并列的入口，用于工程查看并处理以下订单中的补图待核价零件：

- 订单状态为 `部分已提单 / 已生成提单`。
- 零件有图纸。
- 零件价格为空，或状态为 `未核价 / 无图` 且补图后恢复为 `未核价`。

推荐前端入口文案：

```text
补图待核价
```

该入口只展示有补核价需求的已提单订单，避免工程在普通核价列表中看到大量已完成订单。用户选择订单后，应进入并完全复用现有零件核价模块的订单加载、全局设定、逐件核价、普通件核价、组合件核价、重复件复用、实时价格预估、备注保存和提交核价等既有实现；不要另做一套补核价页面或简化版核价流程。

与现有选择订单入口的差异只在候选订单和零件可见范围：

- 候选订单只包含 `部分已提单 / 已生成提单` 且存在补图待核价零件的订单。
- 进入核价页后，当前订单只显示需要处理的补图待核价零件。
- 已经 `已报价 / 已提单` 的历史零件不在该入口的核价列表中展示，避免误改历史已确认零件。
- 全局工艺、材料模板、核价保存、组合件关系和提交核价仍沿用现有逻辑。
- 该入口不改变历史 ticket，也不改变已经生成的工艺表行。

工程保存普通件或组合件核价时沿用现有核价逻辑：

- 写入材料、工艺、费用、价格快照。
- 零件状态写为 `已核价`。
- 不改订单状态为 `已核价`。
- 不改历史 ticket。

需要特别区分“单个零件保存核价”和“整单完成核价提交”：

- 单个零件保存核价：补图待核价入口完全复用现有普通件 / 组合件保存逻辑，保存成功后只把当前补图零件写为 `已核价`。
- 普通入口的整单完成核价提交：继续调用现有整单完成接口，用于 `未核价 -> 已核价` 的 RFQ 主流程。
- 补图待核价入口的“完成核价提交”：不能直接调用现有整单完成接口，必须走补充核价完成分支。
- 补充核价完成分支只校验本次补图待核价零件是否都已保存核价，不修改 `order_rfq.status`。
- 补充核价完成后，订单继续保持 `部分已提单 / 已生成提单`，等待市场在报价处理模块执行补充报价确认。

补充核价完成分支建议后端规则：

```text
订单状态必须是：部分已提单 / 已生成提单
校验范围：仅校验当前补图待核价范围内的有图零件均已保存核价
允许完成条件：补图待核价零件状态均为 已核价，且已有价格
更新订单状态：不更新
更新历史 ticket：不更新
后续流转：市场补充报价确认 -> 零件已报价 -> 议价提单追加
```

### 5.3 市场补充报价确认入口

报价处理模块需要允许市场处理以下订单中的补充报价零件：

- 订单状态为 `部分已提单 / 已生成提单`。
- 订单中存在状态为 `已核价` 且有价格的补图零件。

推荐在报价处理模块增加筛选或提示：

```text
补充报价待确认
```

市场保存补充报价时：

- 只把当前订单下符合条件的 `已核价` 补图零件改为 `已报价`。
- 不覆盖已经 `已报价 / 已提单` 的零件。
- 不修改历史 ticket。
- 不解锁整单历史报价单的已确认字段。
- 保存后按“已报价可提单零件”重新计算订单状态。

对于已提单订单，报价处理页面不应恢复完整整单报价编辑能力，只提供补图零件的报价交期确认和补充保存能力。

### 5.4 议价提单可选规则

议价提单模块继续允许订单状态为：

```text
已报价 / 部分已提单 / 已生成提单
```

RFQ 零件可选规则需要收紧为“市场已确认报价”：

- `tax_included_unit_price` 非空。
- 零件状态为 `已报价 / 已提单`，或兼容旧状态 `已部分提单 / 已生成提单`。
- 零件状态为 `已核价` 时，即使已有价格，也不能在议价提单中选中，因为市场尚未确认补充报价。

这样可以避免工程刚补完核价、市场未确认报价单时，零件被直接提单。

### 5.5 订单状态回算

订单状态回算应基于“当前可提单零件”，而不是所有零件：

```text
可提单零件 = 有图纸 + 有市场确认报价 + 非废弃
已提数量 = SUM(order_delivery_ticket.qty WHERE item_id = 当前零件ID)
覆盖原询价数量 = 已提数量 >= item.qty
```

回算规则：

- 没有任何 ticket：沿用未提单前状态，不进入 `部分已提单 / 已生成提单`。
- 有 ticket，且所有可提单零件都覆盖原询价数量：订单为 `已生成提单`。
- 有 ticket，且至少一个可提单零件未覆盖原询价数量：订单为 `部分已提单`。

`已核价` 零件不算可提单零件，直到市场确认补充报价后才纳入回算。

## 6. 权限设计

本功能不新增权限点。

| 能力 | 复用权限 |
| --- | --- |
| RFQ 图纸补传 / 替换 | 现有询价订单或议价提单图纸维护权限。 |
| 工程补核价 | `engineer:pricing:view`、`engineer:pricing:save-item`。 |
| 市场补充报价确认 | 现有报价处理保存权限。 |
| 议价提单追加 | `market:release:create`。 |

后端仍必须执行已有数据范围校验，不能因为订单已提单就绕过 RFQ 订单数据权限。

## 7. 日志设计

本功能不新增高频读日志。

写操作沿用或扩展现有审计摘要：

- 补图：沿用当前 RFQ 图纸上传 / 替换审计动作，摘要增加 `statusBefore/statusAfter` 和 `restoredUnpricedCount`。
- 工程补核价：沿用 `Item quote saved` 文件日志和既有核价保存审计，摘要包含 `toStatus=已核价`。
- 市场补充报价确认：沿用报价单保存审计动作，摘要增加 `supplemental=true`、`supplementalItemCount`、`orderStatusBefore/orderStatusAfter`。
- 议价提单追加：沿用 `DELIVERY_TICKET_GENERATE` 或 RFQ 议价提单派生销售订单审计，摘要记录本次 ticket 数量。

任何日志不得记录完整图纸文件内容、完整报价快照、完整工艺路线 JSON、Authorization、Cookie、token 或外部系统密钥。

## 8. 后端改造范围

### 8.1 图纸补传 / 替换服务

- 识别 RFQ 零件从无图变为有图的场景。
- 对 `无图 + 无价格` 的零件恢复为 `未核价`。
- 返回结果中可展示“已恢复待核价”的计数，便于前端提示。

### 8.2 零件核价查询服务

- 增加补图待核价订单 / 零件查询口径。
- 允许工程对 `部分已提单 / 已生成提单` 订单中的补图待核价零件进入核价弹窗。
- 保存核价时只更新零件状态和核价字段，不修改订单主状态为 `已核价`。

### 8.3 报价处理服务

- 允许报价处理读取存在补充报价待确认零件的 `部分已提单 / 已生成提单` 订单。
- 增加补充报价保存分支。
- 只确认状态为 `已核价` 的补图零件。
- 保存后调用统一订单状态回算。

### 8.4 议价提单服务

- RFQ 行 `canSelect` 改为依赖“市场已确认报价”，不能只看价格非空。
- `已核价` 补图零件在市场确认前显示为不可选，原因建议为 `补充报价尚未确认`。
- `已报价 / 已提单` 零件继续可选，剩余数量仍只作为展示参考。

### 8.5 统一状态回算服务

建议抽出统一 helper，避免多个服务重复写状态规则：

```java
refreshRfqReleaseStatus(Integer rfqId)
refreshRfqItemReleaseStatus(ItemQuoteVersion item)
isReleaseEligibleItem(ItemQuoteVersion item)
```

其中 `isReleaseEligibleItem` 第一版口径：

```text
有图纸
taxIncludedUnitPrice 非空
status in 已报价 / 已提单 / 历史已部分提单 / 历史已生成提单
```

## 9. 前端改造范围

### 9.1 零件核价模块

- 增加“补图待核价”入口或筛选。
- 只展示有补图待核价零件的 `部分已提单 / 已生成提单` 订单。
- 进入核价页后，只允许补核价零件正常保存核价；历史已报价 / 已提单零件不被误改。

### 9.2 报价处理模块

- 增加“补充报价待确认”筛选或提示。
- 对已提单订单只开放补图零件的报价交期确认和补充保存。
- 保存成功后提示“补充报价已确认，可进入议价提单追加提单”。

### 9.3 议价提单模块

- 已核价但未市场确认的补图零件不可选。
- 提示原因展示为“补充报价尚未确认”。
- 市场确认后刷新列表，该零件变为可选。

## 10. 测试计划

### 10.1 后端测试

- 图纸补传：`无图 + 无价格` 零件补图后状态变为 `未核价`。
- 图纸替换：已有价格或已提单零件替换图纸不改变状态，不改历史 ticket。
- 工程补核价：`已生成提单` 订单中的补图零件保存核价后状态为 `已核价`，订单仍保持提单流程状态。
- 报价确认：市场确认补充报价后，补图零件状态变为 `已报价`。
- 议价提单：`已核价` 补图零件不可选，`已报价` 后可选。
- 状态回算：已生成提单订单新增一个已报价未提单补图零件后，订单回算为 `部分已提单`；追加提单后回到 `已生成提单`。
- 历史快照：补图、补核价、补充报价不修改既有 `order_delivery_ticket`。

### 10.2 前端测试

- 零件核价模块出现“补图待核价”入口或筛选。
- 补图待核价订单能进入核价页。
- 报价处理模块能看到补充报价待确认订单。
- 议价提单中 `已核价` 补图零件显示不可选原因。
- 市场确认后，议价提单刷新后该零件可选。

### 10.3 文档和治理测试

- 权限 characterization 确认不新增权限点。
- 日志 characterization 确认补充报价确认审计不记录完整图纸、快照或 token。
- 状态流转 characterization 覆盖 `无图 -> 未核价 -> 已核价 -> 已报价 -> 已提单` 的补充链路。

## 11. 分阶段实施计划

### 阶段 1：状态 helper 和补图状态恢复

目标：建立统一补图状态恢复和 RFQ release eligibility 判断。

- 新增 / 调整状态 helper。
- 图纸补传或替换后恢复 `无图 + 无价格` 零件为 `未核价`。
- 补齐后端测试。

### 阶段 2：工程补核价入口

目标：工程能看到并核价已提单订单中的补图待核价零件。

- 后端增加补图待核价查询口径。
- 前端增加筛选或入口。
- 核价保存不回退订单状态。

### 阶段 3：市场补充报价确认

目标：市场确认补图零件报价后，零件进入 `已报价`。

- 报价处理支持补充报价待确认订单。
- 保存补充报价只更新补图 `已核价` 零件。
- 保存后执行订单状态回算。

### 阶段 4：议价提单接入补图零件

目标：只有市场确认后的补图零件可追加提单。

- RFQ 可选规则改为依赖市场确认状态。
- 增加不可选原因。
- 覆盖追加提单后状态回算。

### 阶段 5：端到端回归和文档收口

目标：确认补图、补核价、补充报价、追加提单完整闭环。

- 跑 RFQ 状态流转、核价、报价处理、议价提单、提单表据相关测试。
- 更新权限和日志文档收口说明。
- 确认不影响销售订单导入、销售订单直提、U9 同步和历史 ticket 展示。

## 12. 验收标准

- 已生成提单订单补传一个原无图零件图纸后，该零件能进入工程补核价。
- 工程补核价后，零件为 `已核价`，但不能直接议价提单。
- 市场确认补充报价后，零件为 `已报价`，能进入议价提单。
- 追加提单成功后生成新的 ticket，历史 ticket 不变。
- 订单状态能从 `已生成提单` 因新增可提单补图零件回算为 `部分已提单`，追加完成后再回到 `已生成提单`。
- 全链路不新增权限点，不泄露图纸、快照、token 或密钥。
