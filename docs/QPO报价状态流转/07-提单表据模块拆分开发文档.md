# QPO 提单表据模块拆分开发文档

## 1. 背景

当前 `议价提单` 页面同时承担两类职责：

```text
选择订单、选择通过零件、维护提单参数、生成正式提单
  + 查看已生成提单行、查看已生成工艺表行、导出提单 Excel、导出工艺表 Excel
```

其中“已生成提单行”和“已生成工艺表行”是提单生成后的只读表据，不再参与新一批提单生成。把它们继续放在 `议价提单` 页面下方会带来三个问题：

- 议价提单页面过长，生成动作和历史表据查看混在一起。
- 用户只是查看或导出表据时，仍要进入带有左侧提单参数面板的生成页面。
- 权限边界不够清晰，查看/导出已生成表据不应天然等同于拥有议价提单生成页面的完整查看能力。

本次需求是将这两张只读表据独立为新模块 **提单表据**。

## 2. 目标

新增左侧模块：

```text
市场 -> 议价提单 -> 提单表据
```

页面结构：

```text
页面标题 + 选择订单按钮
  -> 订单摘要
  -> 已生成提单行表
  -> 已生成工艺表行表
```

订单选择规则：

- 复用现有 `OrderPickerDialog.vue` 的客户、状态、订单三级选择交互。
- 订单状态只允许：
  - `部分已提单`
  - `已生成提单`
- 选中订单后，上下展示两张表：
  - 已生成提单行
  - 已生成工艺表行
- 两张表继续支持分页和导出对应 Excel。

议价提单页面目标：

- 继续保留选择订单、选择通过零件、内部目标交期、内部项目号、订单类型、生成正式提单等生成职责。
- 提单生成成功后刷新当前生成页面的候选零件状态和可提数量。
- 不再在议价提单页面下方承载“已生成提单行”和“已生成工艺表行”两个只读表据区。

## 3. 非目标

本次不做以下事情：

- 不改变提单生成规则、分批提单规则、剩余可提数量计算规则。
- 不恢复或新增提单删除、工艺表删除、提单重置、工艺重置能力。
- 不改变 `order_delivery_ticket` 作为不可逆发布记录和 MES/WMS 需求池的职责。
- 不恢复 `order_process_sheet` 表；工艺表继续从 `order_delivery_ticket.process_route` 快照动态生成。
- 不新增可分配 `common:*` 权限。
- 不改变 MES 物料号、WMS 锁库、已提零件、锁库零件页面逻辑。

## 5. 方案比较

### 5.1 方案 A：复制现有两张表到新页面

做法：

- 新增 `DeliveryDocumentManage.vue`。
- 从 `MarketRelease.vue` 复制两张表和导出逻辑。
- 议价提单页删除原表据区。

优点：

- 改动最快。

缺点：

- 表格列、分页、导出按钮、格式化函数会重复。
- 后续提单表字段调整时需要改两个地方。

### 5.2 方案 B：抽出可复用表据组件

做法：

- 抽出两个只读表组件：
  - `DeliveryTicketRowsTable.vue`
  - `ProcessSheetRowsTable.vue`
- 新页面复用这两个组件。
- 如果议价提单页过渡期仍需保留表据区，也使用同一组件；最终按本需求从议价提单页移除表据区。

优点：

- 符合组件复用要求。
- 表格列、分页、导出按钮和空状态统一。
- 降低后续维护风险。

缺点：

- 初次改动略多，需要补组件级测试。

### 5.3 方案 C：只新增后端权限和路由，前端继续复用原页面

做法：

- 新增菜单跳转到原 `MarketRelease.vue`，通过参数隐藏左侧生成面板。

优点：

- 后端改动少。

缺点：

- 页面职责仍然混乱。
- “新页面左边没有一栏东西碍眼”的目标无法稳定达成。
- 路由参数会让一个组件承担两种页面形态，后续更难维护。

### 5.4 推荐方案

采用 **方案 B：抽出可复用表据组件 + 新增独立提单表据页面**。

原因：

- 新模块是只读表据工作台，不应继续依赖议价提单生成页面的内部布局。
- 表据列和导出逻辑仍来自同一业务源，抽成组件可避免重复。
- 权限、路由、接口可以按新模块独立治理，符合当前 QPO 权限规范。

## 6. 信息架构

### 6.1 菜单分组

将 `提单表据` 放在左侧 **市场** 分组下，并紧跟 `议价提单`：

```text
市场
  新单导入
  报价处理
  议价提单
  提单表据
  报价模板
```

原因：

- 用户认知上它是 `议价提单` 生成后的直接结果查看与导出入口，放在 `议价提单` 下方最顺。
- 它仍是独立模块、独立路由、独立权限，不作为 `议价提单` 页内子面板。
- 议价提单页面专注“生成正式提单”，提单表据页面专注“查看和导出生成结果”。

## 7. 权限设计

### 7.1 新增权限点

新增独立模块权限，不复用 `market:release:view`。

| 权限编码 | 类型 | 权限名称 | 用途 | 默认角色 |
| --- | --- | --- | --- | --- |
| `market:delivery-document:view` | `MENU` | 提单表据 | 控制左侧入口、页面进入、订单摘要、提单行分页、工艺表行分页。 | `SUPER_ADMIN`, `MARKET_USER`, `MARKET_MANAGER`, `READONLY` |
| `market:delivery-document:customer-select` | `API` | 提单表据选择客户 | 控制新页面客户选择弹窗。 | `SUPER_ADMIN`, `MARKET_USER`, `MARKET_MANAGER`, `READONLY` |
| `market:delivery-document:order-select` | `API` | 提单表据选择订单 | 控制新页面订单选择弹窗，仅允许部分已提单和已生成提单订单。 | `SUPER_ADMIN`, `MARKET_USER`, `MARKET_MANAGER`, `READONLY` |
| `market:delivery-document:export` | `BUTTON` | 导出提单表据 | 控制导出提单 Excel 和导出工艺表 Excel 两个按钮。 | `SUPER_ADMIN`, `MARKET_USER`, `MARKET_MANAGER` |

只读账号可以查看和选择订单，但默认不授予导出权限。

### 7.2 不复用的权限

本模块不得复用以下权限作为新页面安全边界：

- `market:release:view`
- `market:release:order-select`
- `market:release:customer-select`
- `market:order:view`
- `market:delivered-item:view`
- 新增或恢复任何 `common:*`

原因：

- 同一个“选择订单”能力按模块归属管理，避免用户能在议价提单选择订单就自动获得提单表据查看能力。
- 表据查看和导出是提单后的只读输出能力，不等同于生成提单能力。

### 7.3 后端权限树迁移

新增 Flyway 迁移：

```text
quote-backend/src/main/resources/db/migration/V57__delivery_document_module_permissions.sql
```

迁移职责：

- 插入 `market:delivery-document:view` 菜单权限。
- 插入 `market:delivery-document:customer-select`、`market:delivery-document:order-select`、`market:delivery-document:export` 子权限。
- 给 `SUPER_ADMIN`、`MARKET_USER`、`MARKET_MANAGER` 授予完整权限。
- 给 `READONLY` 授予 `view`、`customer-select`、`order-select`，不授予 `export`。
- 保证 `market:release:reset` 不被恢复。

建议排序：

```text
market:release:view            140
market:delivery-document:view  146
market:template:view           150
```

前端左侧展示以 `App.vue` 的 `market` 分组顺序为准，确保 `/delivery-documents` 紧跟 `/release`。

## 8. 后端设计

### 8.1 新增控制器

推荐新增独立控制器：

```text
quote-backend/src/main/java/com/machining/quote/controller/DeliveryDocumentController.java
```

统一前缀：

```text
/api/market/delivery-documents
```

接口：

| 方法 | 路径 | 权限 | 说明 |
| --- | --- | --- | --- |
| `GET` | `/customers` | `market:delivery-document:customer-select` | 返回当前数据范围内可选客户。 |
| `GET` | `/orders` | `market:delivery-document:order-select` | 分页返回 RFQ / 销售订单中 `部分已提单`、`已生成提单` 订单，并返回 `sourceType`、`sourceOrderId`、`sourceOrderNo`。 |
| `GET` | `/summary/{sourceOrderId}` | `market:delivery-document:view` | 通过可选 `sourceType=RFQ/SALES_ORDER` 返回来源订单摘要和两张表总数。 |
| `GET` | `/tickets/{sourceOrderId}` | `market:delivery-document:view` | 通过可选 `sourceType=RFQ/SALES_ORDER` 返回已生成提单行分页。 |
| `GET` | `/process-sheets/{sourceOrderId}` | `market:delivery-document:view` | 通过可选 `sourceType=RFQ/SALES_ORDER` 返回已生成工艺表行分页。 |
| `GET` | `/export/tickets/{sourceOrderId}` | `market:delivery-document:export` | 通过可选 `sourceType=RFQ/SALES_ORDER` 导出提单 Excel。 |
| `GET` | `/export/process-sheets/{sourceOrderId}` | `market:delivery-document:export` | 通过可选 `sourceType=RFQ/SALES_ORDER` 导出工艺表 Excel。 |

保留现有 `MarketController` 中的旧接口，避免影响历史调用和过渡期测试：

```text
/api/market/tickets/{rfqId}
/api/market/process-sheets/{rfqId}
/api/market/export/tickets/{rfqId}
/api/market/export/process-sheets/{rfqId}
```

新页面只调用新接口。

### 8.2 新增服务

推荐新增轻量服务：

```text
quote-backend/src/main/java/com/machining/quote/service/DeliveryDocumentService.java
```

职责：

- 复用 `OrderManagementService.listCustomers()` 做客户列表。
- 新增或复用订单分页查询，但强制状态范围为：
  - `部分已提单`
  - `已生成提单`
- 校验 `sourceType + sourceOrderId` 对应 RFQ 或销售订单存在、当前用户有数据权限、订单状态允许查看表据。
- 汇总提单行总数、工艺表行总数、提单数量合计。
- 调用来源感知的 `DeliveryService.pageTickets(sourceType, sourceOrderId, ...)` 和 `DeliveryService.pageProcessSheets(sourceType, sourceOrderId, ...)`。
- 调用来源感知的 `ExcelExportService.exportDeliveryTickets(sourceType, sourceOrderId, sourceOrderNo, ...)` 和 `ExcelExportService.exportProcessSheets(sourceType, sourceOrderId, sourceOrderNo, ...)`。

建议方法：

```java
public List<String> listDocumentCustomers()
public PageResult<Map<String, Object>> listDocumentOrders(String customerName, String keyword, String status, Integer page, Integer pageSize)
public Map<String, Object> documentSummary(String sourceType, Long sourceOrderId)
public PageResult<OrderDeliveryTicket> pageTickets(String sourceType, Long sourceOrderId, Integer page, Integer pageSize)
public PageResult<ProcessSheetDTO> pageProcessSheets(String sourceType, Long sourceOrderId, Integer page, Integer pageSize)
public void exportTickets(String sourceType, Long sourceOrderId, HttpServletResponse response) throws IOException
public void exportProcessSheets(String sourceType, Long sourceOrderId, HttpServletResponse response) throws IOException
```

### 8.3 状态校验

订单列表和直接访问 `sourceType + sourceOrderId` 都要做状态校验。

允许状态：

```java
Set.of("部分已提单", "已生成提单")
```

行为：

- 订单选择弹窗只显示允许状态。
- `/orders` 接口收到其他状态时返回空分页，不泄露不该出现的订单。
- `/summary/{sourceOrderId}`、`/tickets/{sourceOrderId}`、`/process-sheets/{sourceOrderId}` 直接访问其他状态时抛出业务异常：

```text
只有部分已提单或已生成提单订单可以查看提单表据
```

### 8.4 数据权限

数据权限必须继续由后端兜底。

要求：

- 客户列表调用当前数据范围过滤后的客户列表。
- 订单列表调用 `DataScopeService.applyOrderScope()`。
- 明细查询和导出调用 `DataScopeService.assertCanAccessOrder()`。
- 当数据范围为空时返回空列表，不泄露订单存在性。
- 导出接口不能只依赖前端隐藏按钮。

## 10. 日志规范

### 10.1 不记录的日志

以下都是正常读操作，不新增操作日志：

- 打开提单表据页面。
- 选择客户。
- 查询订单列表。
- 查询订单摘要。
- 分页查看已生成提单行。
- 分页查看已生成工艺表行。

这些操作依赖请求日志和访问日志即可，避免高频读取产生噪声。

### 10.2 需要记录的日志

导出 Excel 是用户主动输出业务表据，应记录操作日志和文件日志摘要。

新增操作日志动作：

| 动作编码 | 中文名 | 模块 | targetType | targetId |
| --- | --- | --- | --- | --- |
| `DELIVERY_TICKET_EXPORT` | 导出提单表 | `DELIVERY` | `order_rfq` / `sales_order_header` | `sourceOrderId` |
| `DELIVERY_PROCESS_SHEET_EXPORT` | 导出工艺表 | `DELIVERY` | `order_rfq` / `sales_order_header` | `sourceOrderId` |

`AuditService.labelForAction()` 增加中文映射。

`AuditService.inferModule()` 已将 `DELIVERY_` 归入 `DELIVERY`，无需新增模块规则。

操作日志 afterData 建议字段：

```json
{
  "sourceType": "RFQ",
  "sourceOrderId": 123,
  "sourceOrderNo": "RFQ-20260723-0001",
  "status": "部分已提单",
  "exportType": "tickets",
  "rowCount": 20
}
```

文件日志建议：

```java
log.info("Delivery document export started sourceType={} sourceOrderId={} exportType={}", sourceType, sourceOrderId, exportType);
log.info("Delivery document export completed sourceType={} sourceOrderId={} exportType={} rowCount={} durationMs={}", sourceType, sourceOrderId, exportType, rowCount, durationMs);
log.warn("Delivery document export rejected sourceType={} sourceOrderId={} exportType={} reason={}", sourceType, sourceOrderId, exportType, reason);
log.error("Delivery document export failed sourceType={} sourceOrderId={} exportType={} durationMs={}", sourceType, sourceOrderId, exportType, durationMs, e);
```

注意：

- 不记录完整 Excel 内容。
- 不记录 Authorization、token、Cookie。
- 用户无权限、订单状态不允许、订单不存在、数据范围不可见属于可预期拒绝，使用 WARN。
- IO 异常或未预期异常使用 ERROR。
