# QPO 销售订单独立主表开发文档
最后更新：2026-08-06

> 2026-08-09 材料主数据阶段 10 收口：销售订单零件的工程材料快照补齐 `材料编码 / 材料类型 / 材质分类 / 材料形态`。销售订单导入材料仍是客户侧事实字段，销售订单导入自动快照补全或 RFQ 派生写入的工程材料以 `engineeringMaterialCode` 为身份；材料类型是可维护字典，材质分类是材料类别细分，材料形态是板材、棒材、管材等加工形态。

> 2026-08-07 价格字段收口：销售订单只使用 `tax_included_unit_price`、`tax_included_total_price`、`untaxed_unit_price`、`untaxed_total_price`。导入、自动补全和自动提单允许价格为空；U9 同步前必须补齐含税单价。`final_*` 不再是兼容字段，也不属于当前模型。

> 2026-08-08 两级工艺主数据阶段 15 收口：销售订单导入自动快照补全命中历史 RFQ 时复制标准工艺路线快照，字段包括 `processDetailId / processCode / categoryName / detailName / hourlyRate / unitWorkHours / lineCost / sortNo`。销售订单导入自动补全不按当前字典重新计价；自动提单把销售订单零件的工艺快照固化到 `order_delivery_ticket.process_route`。

## 1. 背景与最新决策

前一版方案 `13-销售订单导入进入QPO主流程开发文档.md` 规划把销售订单写入 `order_rfq` 和 `item_quote_version`，并通过 `source_type = SALES_ORDER` 区分来源。进一步讨论后确认该方向风险较高：

- 销售订单和 RFQ 订单业务来源不同，混在一张订单主表里，后续订单管理、重复订单判断、状态管理、数据权限解释都会变复杂。
- 销售订单零件和询价零件生命周期不同，混在 `item_quote_version` 里会污染重复件匹配、核价历史和现有 RFQ 主流程。
- 销售订单需要保留更多销售字段、价格字段和 U9 字段，不应强行扩展 RFQ 零件主表来承载。

最新决策：

> 原 RFQ / 报价 / 议价提单主流程保持不动。销售订单使用独立订单主表和独立零件表，导入成功后在同一事务内自动补全历史生产快照并自动生成销售订单来源提单行，随后直接进入已提零件、MES/WMS、待产 / 锁库和 U9 同步链路。

2026-08-06 新口径补充：市场部销售订单模板已删除 `料号`、`已出数量`、`未出数量`，价格列允许为空。销售订单导入不再引入销售料号口径，正式 `material_no` 只等待后续已提零件向 MES 获取成功后回写；价格为空不阻断导入，U9 同步前必须补齐。

2026-08-10 手工模块退役收口：销售订单导入成功后仍自动补全历史生产快照并自动生成已提零件；原手工异常治理入口、预览和确认 API 已删除；销售订单不再进入议价提单页面手动生成提单；价格补齐前不可同步 U9。

因此，本文件取代 `13-销售订单导入进入QPO主流程开发文档.md` 作为销售订单进入 QPO 生产链路的最新开发依据。13 号文档只保留为历史讨论记录，不再作为实施计划。

## 2. 目标

- 市场仍在 `新单导入` 页面下使用 `销售订单` 子入口，不新增左侧模块。
- 销售订单导入后写入独立表：`sales_order_header` 和 `sales_order_item`。
- 不再创建 QPO `order_rfq`，不再创建 `item_quote_version`，不再向 RFQ 主表写销售订单字段。
- 销售订单导入事务先落为 `已报价`，随后自动执行历史生产快照补全和整单提单；事务完成后正常状态为 `已生成提单`，价格可以暂为空。
- 销售订单零件表承载销售订单模板所需字段，包括 MES 回写 `material_no`、价格、交期、工艺快照、材料快照、图纸快照等；`sales_material_no`、`shipped_qty`、`unshipped_qty` 仅作为历史兼容字段保留。
- 导入链路负责写独立表、绑定图纸、自动补全空缺生产快照、自动生成 `order_delivery_ticket` 并返回导入结果。
- 议价提单页面只服务 RFQ 主流程；销售订单提单由导入链路自动生成，不再由用户手动进入议价提单处理。
- U9 同步仍作为后续阶段：优先在销售订单零件取得或确认 `material_no` 后再同步 U9。

## 3. 非目标

- 不改 RFQ 导入、零件核价、报价处理、订单管理的现有数据模型和状态流转。
- 不把销售订单作为 `order_rfq.source_type = SALES_ORDER` 的特殊记录继续维护。
- 不把销售订单零件作为 `item_quote_version` 的特殊记录继续维护。
- 不让销售订单零件进入 RFQ 重复件匹配主候选池，除非后续明确批准。
- 本阶段不要求立即打通 U9 `SO_Create`；U9 同步在独立表稳定和物料号口径确认后再做。
- 本阶段不新增销售订单左侧菜单；如后续需要销售订单管理页，再单独设计 `market:sales-order:*` 权限。

## 4. 现有实现回收原则

当前仓库已经存在旧方向的部分实现，例如 `V63__sales_order_qpo_import_fields.sql` 对 `order_rfq` 和 `item_quote_version` 扩展销售订单字段。因为 Flyway 迁移可能已经在环境中执行，实施新方案时不要直接修改已发布迁移文件。

处理原则：

- 已经加到 RFQ 主表上的销售订单字段先标记为废弃字段，后续代码停止写入和读取。
- 如果生产环境尚未执行旧迁移，可由部署负责人评估是否回滚旧迁移；如果已执行，优先通过新迁移和代码隔离完成方向修正。
- 不为了“立刻清爽”强行 `DROP COLUMN`，避免破坏已部署环境；字段清理可作为稳定后的单独数据库治理任务。
- `customer_master` 客户主数据、模板下载、U9 配置、安全日志等已完成能力仍保留复用。

## 6. 销售订单模板字段映射

- 一次导入只创建一个 `sales_order_header`。

## 7. 导入自动快照补全规则

销售订单导入阶段已经从“导入后人工补全”调整为“导入事务内自动补全”：

1. 导入成功后，系统按 `part_no + version` 自动查询历史 `item_quote_version.status = 已提单` 的 RFQ 最新零件快照。
2. 命中时只补空缺生产快照：真实材料、材料形态、材料核价快照、工艺路线、费用快照、重量和组合件关系。
3. 自动补全不得覆盖销售订单 Excel 导入的数量、价格、客户订单号、客户项目号、内部项目号、描述、导入材料、表面处理、图纸和 `material_no`。
4. 未命中不阻断导入，也不阻断自动提单；导入结果返回 `matchedItemCount / unmatchedItemCount`，便于页面提示和后续数据排查。
5. 原手工异常治理模块已退役，不再提供独立页面、手工预览或手工确认；自动补全异常后续通过销售订单、已提零件、MES/WMS、U9 等实际业务页面排查。
6. 销售订单零件不作为 RFQ 重复件来源，避免影响现有零件核价模块重复匹配口径；销售订单数据不写回 `order_rfq` / `item_quote_version`。

后续如果需要让销售订单已提历史也参与复购匹配，应新建独立“生产历史快照查询服务”，统一读取 RFQ 已提零件和销售订单已提零件，而不是把销售订单行塞回 `item_quote_version`。

## 8. 自动提单和下游来源字段

`order_delivery_ticket` 当前已经是不可逆发布记录和 MES/WMS 需求池。销售订单来源提单行由销售订单导入自动生成，不再要求市场用户手动销售匹配或手动议价提单。为支持 RFQ 和销售订单双来源，保留以下来源字段：

| 字段 | 说明 |
| --- | --- |
| `source_type` | `RFQ` / `SALES_ORDER` |
| `source_order_id` | 来源订单 ID |
| `source_item_id` | 来源零件 ID |

兼容规则：

- RFQ 提单：继续写 `rfq_id`、`item_id`，同时写 `source_type = RFQ`、`source_order_id = rfq_id`、`source_item_id = item_id`。
- 销售订单提单：由导入自动提单写入，`rfq_id`、`item_id` 可为空，必须写 `source_type = SALES_ORDER`、`source_order_id = sales_order_header.id`、`source_item_id = sales_order_item.id`。
- 提单表据、已提零件、锁库零件、MES/WMS 优先使用 `order_delivery_ticket` 快照字段展示和同步，不应强依赖回查 `item_quote_version`。

`order_delivery_ticket_allocation` 已通过 `ticket_id` 关联提单行，通常不需要重复写来源字段；如后续查询性能需要，可再补充来源快照字段。

## 9. 权限与日志口径

### 9.1 权限

| RFQ 议价提单生成 | 继续使用 `market:release:create` |

如果后续新增独立销售订单管理页，再新增：

- `market:sales-order:view`
- `market:sales-order:import`
- `market:sales-order:update`
- `market:sales-order:delete`
- `market:sales-order:export`

不要新增可分配 `common:*` 权限。

### 9.2 数据权限

- 销售订单头表必须保存 `customer_name` 快照，用于沿用现有按客户数据范围过滤。
- 客户主数据选择仍来自 `customer_master`。
- 无客户数据权限时，销售订单选择、候选零件分页、提单生成均返回空或拒绝，不能只靠前端隐藏。

### 9.3 操作日志和文件日志

建议沿用或明确改造现有动作：

| 动作 | targetType | 说明 |
| --- | --- | --- |
| `SALES_ORDER_IMPORT_QPO` | `sales_order_import_batch` | 导入销售订单到独立主表 |

## 10. 实施阶段

### 阶段 1：旧方向隔离与独立表骨架

目标：先把数据边界修正，不再向 RFQ 主表写销售订单。

修改：

- 新增迁移，例如 `V65__sales_order_independent_tables.sql`；若其他会话已占用编号，实施时使用实际下一迁移编号。
- 新增 `sales_order_header`。
- 新增 `sales_order_item`。
- 扩展 `sales_order_import_batch` / `sales_order_import_record`，让导入记录可关联独立销售订单。
- 停止销售订单导入代码写入 `order_rfq` 和 `item_quote_version`。
- 将旧方向中已加入 RFQ 主表的销售订单字段标记为 deprecated，不再读写。
- 更新权限清单、日志说明和销售订单讨论文档。

验收：

- 销售订单导入相关代码不新增 `order_rfq` 记录。
- 销售订单导入相关代码不新增 `item_quote_version` 记录。
- 独立表可保存客户、单据类型、订单号、零件、价格、物料号和状态。
- 原 RFQ 导入、订单管理、零件核价、报价处理测试不受影响。

### 阶段 2：后端销售订单导入写独立表

目标：市场实际模板可导入为独立销售订单。

修改：

- 新增 / 改造 `SalesOrderQpoExcelParser`，解析市场实际 `销售订单模版.xlsx`。
- 新增 `SalesOrderHeader`、`SalesOrderItem` 实体和 Mapper。
- 新增 `SalesOrderQpoImportService` 独立表写入逻辑。
- 导入时按页面客户、单据类型编码和 Excel 分组生成销售订单头。
- 每行生成 `sales_order_item`，价格字段完整落库。
- 导入结果返回销售订单号、零件数、未匹配数、失败明细。
- 补后端测试：必填校验、价格计算、分组、重复导入保护、数据权限。

验收：

- 必填字段缺失返回明确行号和字段名。
- 同一客户订单号 / 内部项目号分组可生成销售订单头。
- 未税 / 含税单价和总价可追溯。
- `material_no` 字段可导入或后续为空等待回写。

### 阶段 3：历史快照补齐

目标：建立销售订单生产快照补齐能力，并由导入事务自动执行。

修改：

- 新增历史快照补齐服务能力，供销售订单导入自动调用。
- 复用现有重复件查询口径，按 `part_no + version` 查历史 `item_quote_version.status = 已提单` 最新记录。
- 确认补全时复制材料、工艺、图纸、重量、组合件等生产字段到 `sales_order_item`。
- 不覆盖销售订单价格、数量、交期、客户字段和 `material_no`。
- 补后端测试：匹配成功、未匹配、价格不被覆盖、多候选取最新。

验收：

- 销售订单导入后，匹配成功的销售订单零件可看到历史工艺 / 材料快照。
- 未匹配零件仍导入成功并返回警告。
- RFQ 重复件匹配结果不包含销售订单零件。

### 阶段 4：前端销售订单导入页面改造

目标：页面展示独立销售订单导入结果，不再提示创建 RFQ。

修改：

- `MarketDashboard.vue` 销售订单页签保留在 `新单导入` 页面下。
- 页面选择客户来自客户主数据。
- 页面支持输入 / 选择单据类型编码，默认 `SO01`。
- 模板下载改为市场实际销售订单表头。
- 导入按钮文案使用 `导入销售订单`，不写 `同步 U9`。
- 结果表展示销售订单号、客户订单号、零件数、匹配数、未匹配数、状态和警告。
- 补前端测试：无权限隐藏按钮、客户选择、单据类型默认值、导入结果展示。

验收：

- 原询价单导入不受影响。
- 销售订单入口仍在新单导入页内。
- 无 `market:rfq:import-sales-order` 不能导入或下载销售订单模板。
- 页面不再展示 RFQ 号作为销售订单导入结果。

### 阶段 5：销售订单自动提单与 RFQ 派生来源收口

目标：销售订单导入自动提单，议价提单只处理 RFQ；RFQ 议价提单另行生成一张派生销售订单进入 U9。

修改：

- 销售订单导入在同一事务内自动生成销售订单来源提单行，价格为空允许进入已提零件。
- `MarketRelease.vue` 订单选择和候选零件只使用 RFQ 来源，并支持同客户多个 RFQ 一次批次提交。
- RFQ 议价提单一次生成一张 `RFQ_RELEASE` 派生销售订单，并保存 RFQ 来源关联和 ticket 关联。
- 派生销售订单与直接导入销售订单共用 U9 列表、预览、整单同步和状态回写。
- 补前后端测试：RFQ 批次事务、销售订单自动提单、来源追溯、MES 双写和 U9 阻断。

验收：

- 销售订单导入成功后可在已提零件看到销售订单来源行。
- 议价提单页面不展示销售订单候选，只展示 RFQ。
- 翻页仍请求后端分页接口，不全量拉取。
- 原单订单 RFQ 生成行为不回退。

### 阶段 6：销售订单生成提单与下游兼容

目标：销售订单零件可生成正式提单，并进入提单表据、已提零件、锁库零件。

修改：

- `order_delivery_ticket` 新增来源字段：`source_type`、`source_order_id`、`source_item_id`。
- RFQ 提单生成同步写来源字段。
- 销售订单提单生成写提单快照，更新销售订单头 / 行状态和已提数量。
- 提单表据、已提零件、锁库零件查询避免强依赖 `item_quote_version` 回查。
- MES 物料号同步成功后回写 `order_delivery_ticket.material_no`，必要时同步回写 `sales_order_item.material_no`。
- 补回归测试：RFQ 提单、销售订单提单、部分提单、已提零件查询、锁库查询。

验收：

- 销售订单部分提单后头表为 `部分已提单`。
- 销售订单全部提单后头表为 `已生成提单`。
- 提单表据可查看 / 导出销售订单提单行。
- 已提零件和锁库零件能展示销售订单来源提单行。

### 阶段 7：U9 同步重接

目标：基于独立销售订单和已确认物料号同步 U9。

修改：

- 导入链路只负责写独立表、绑定图纸并返回导入结果。
- U9 同步由独立 **U9同步** 模块执行。
- U9 同步从 `sales_order_header` / `sales_order_item` 组装请求。
- 不再从 `order_delivery_ticket` 实时组装 U9 请求。
- `OrderBy` 使用客户主数据 `customer_code`。
- `DocumentType` 使用页面 `document_type_code`。
- `ItemCode` 使用 `sales_order_item.material_no`，且必须满足 `material_no_status = 已确认`。
- 同步结果回写 `u9_sync_status`、`u9_order_id`、`u9_order_code`、失败原因摘要。
- 保留重试能力，避免重复创建 U9 订单。
- 补测试：未取得物料号不可同步、U9 成功、U9 部分失败、失败重试。

验收：

- 无物料号的销售订单不能同步 U9，并返回明确提示。
- 未完成物料号确认的销售订单不能同步 U9，并返回明确提示。
- 同步成功回写 U9 编码。
- 同步失败不影响已生成的 QPO 提单记录。
- 日志不记录 token、密钥或完整请求体。

## 12. 最终验收标准

- 销售订单导入使用独立订单主表和独立零件表。
- 原 RFQ 主流程不写入销售订单数据。
- 销售订单零件拥有完整销售字段、价格字段、生产快照字段和 `material_no` 字段。
- 销售订单导入成功后自动补全历史生产快照并自动生成已提零件。
- 销售订单自动生成的提单可进入提单表据、已提零件、锁库零件和 MES/WMS 后续流程。
- U9 同步可以在物料号确认后基于独立销售订单数据重接。

### 阶段 8 收口补充：销售订单来源统一

`sales_order_header.source_type` 现行值包括 `DIRECT_IMPORT` 和 `RFQ_RELEASE`。后者表示 RFQ 议价提单一批生成的一张派生销售订单；派生订单和直接导入订单共用销售订单管理、已提零件和 U9 同步主链路，但不进入 RFQ 主表。

RFQ 派生订单的零件通过 `sales_order_item.source_ticket_id` 追溯 RFQ ticket。MES 确认物料号回写 RFQ 零件与派生销售订单零件，U9 只读取销售订单主表的已确认物料号和含税单价。权限和数据范围沿用现有模块，不新增权限；查询日志保持低噪声。
