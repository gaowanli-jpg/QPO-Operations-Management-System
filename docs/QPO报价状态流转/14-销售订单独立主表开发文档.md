# QPO 销售订单独立主表开发文档
最后更新：2026-07-31

## 1. 背景与最新决策

前一版方案 `13-销售订单导入进入QPO主流程开发文档.md` 规划把销售订单写入 `order_rfq` 和 `item_quote_version`，并通过 `source_type = SALES_ORDER` 区分来源。进一步讨论后确认该方向风险较高：

- 销售订单和 RFQ 订单业务来源不同，混在一张订单主表里，后续订单管理、重复订单判断、状态管理、数据权限解释都会变复杂。
- 销售订单零件和询价零件生命周期不同，混在 `item_quote_version` 里会污染重复件匹配、核价历史和现有 RFQ 主流程。
- 销售订单需要保留更多销售字段、价格字段和 U9 字段，不应强行扩展 RFQ 零件主表来承载。

最新决策：

> 原 RFQ / 报价 / 议价提单主流程保持不动。销售订单使用独立订单主表和独立零件表，后续通过“来源适配层”接入议价提单、提单表据、已提零件、锁库零件和 U9 同步。

因此，本文件取代 `13-销售订单导入进入QPO主流程开发文档.md` 作为销售订单进入 QPO 生产链路的最新开发依据。13 号文档只保留为历史讨论记录，不再作为实施计划。

## 2. 目标

- 市场仍在 `新单导入` 页面下使用 `销售订单` 子入口，不新增左侧模块。
- 销售订单导入后写入独立表：`sales_order_header` 和 `sales_order_item`。
- 不再创建 QPO `order_rfq`，不再创建 `item_quote_version`，不再向 RFQ 主表写销售订单字段。
- 销售订单头和零件导入成功后状态为 `已报价`，业务含义是“销售订单已具备价格，可进入提单候选”。
- 销售订单零件表承载销售订单模板所需字段，包括 `material_no`、销售料号、价格、交期、出货数量、工艺快照、材料快照、图纸快照等。
- 导入链路只负责写独立表、绑定图纸并返回导入结果；历史生产快照补齐由后续 **销售匹配** 模块显式预览和确认后写入。
- 议价提单后续通过统一候选 DTO 同时支持 RFQ 订单和销售订单。
- U9 同步仍作为后续阶段：优先在销售订单零件取得或确认 `material_no` 后再同步 U9。

## 3. 非目标

- 不改 RFQ 导入、零件核价、报价处理、订单管理的现有数据模型和状态流转。
- 不把销售订单作为 `order_rfq.source_type = SALES_ORDER` 的特殊记录继续维护。
- 不把销售订单零件作为 `item_quote_version` 的特殊记录继续维护。
- 不让销售订单零件进入 RFQ 重复件匹配主候选池，除非后续明确批准。
- 本阶段不要求立即打通 U9 `SO_Create`；U9 同步在独立表稳定和物料号口径确认后再做。
- 本阶段不新增销售订单左侧菜单；如后续需要销售订单管理页，再单独设计 `market:sales-order:*` 权限。

## 4. 现有实现回收原则

当前仓库已经存在旧方向的部分实现，例如 `V63__sales_order_qpo_import_fields.sql` 对 `order_rfq` 和 `item_quote_version` 扩展销售订单字段。因为 Flyway 迁移可能已经在环境中执行，实施新方案时不要直接修改已发布迁移文件。

处理原则：

- 已经加到 RFQ 主表上的销售订单字段先标记为废弃字段，后续代码停止写入和读取。
- 如果生产环境尚未执行旧迁移，可由部署负责人评估是否回滚旧迁移；如果已执行，优先通过新迁移和代码隔离完成方向修正。
- 不为了“立刻清爽”强行 `DROP COLUMN`，避免破坏已部署环境；字段清理可作为稳定后的单独数据库治理任务。
- `customer_master` 客户主数据、模板下载、U9 配置、安全日志等已完成能力仍保留复用。

现有 `sales_order_import_batch` / `sales_order_import_record` 可以保留，但需要从“只服务 U9 同步”扩展为“销售订单导入批次”：

- `sales_order_import_batch.import_mode` 增加 `QPO_INDEPENDENT`。
- `sales_order_import_record` 增加 `sales_order_id`、`sales_order_no`、`item_count`、`matched_item_count`、`unmatched_item_count`、`warning_message`。
- 旧 U9 字段保留，不记录 token、密钥、完整 Excel 内容或完整 U9 请求体。

## 7. 历史匹配与补齐规则

销售订单导入阶段不再自动执行历史快照补齐。导入只初始化销售订单头、销售订单行、图纸绑定结果和待匹配摘要：

1. 导入成功后，`sales_order_item.match_status` 默认保持 `未匹配`，`match_message` 提示“已导入价格，未补齐历史生产快照”。
2. 导入结果只返回销售订单号、客户订单号、零件数、图纸绑定结果、待补齐 / 未匹配数量和失败明细，不在导入事务中写入历史生产快照。
3. 历史生产快照补齐由 **销售匹配** 模块显式触发：用户选择销售订单，按 `part_no + version` 预览历史 `item_quote_version.status = 已提单` 最新零件，再确认写入。
4. 销售匹配确认后只复制生产相关快照：材料明细、工艺路线、图纸、重量、组合件关系、工程材料名、费用结构说明等。
5. 销售匹配不得覆盖销售订单 Excel 导入的数量、价格、客户订单号、客户项目号、内部项目号、销售料号、`material_no` 和交期。
6. 未匹配不阻断导入，也不阻断销售匹配补全；销售订单零件仍保留在独立表中等待人工处理或后续提单前补齐。
7. 销售订单零件不作为 RFQ 重复件来源，避免影响现有零件核价模块重复匹配口径；销售订单数据不写回 `order_rfq` / `item_quote_version`。

后续如果需要让销售订单已提历史也参与复购匹配，应新建独立“生产历史快照查询服务”，统一读取 RFQ 已提零件和销售订单已提零件，而不是把销售订单行塞回 `item_quote_version`。

## 8. 议价提单适配设计

### 8.1 统一来源 DTO

议价提单不应只依赖 `rfqId`，后续应使用来源感知 DTO：

```java
public enum ReleaseSourceType {
    RFQ,
    SALES_ORDER
}

public class ReleaseOrderSource {
    private ReleaseSourceType sourceType;
    private Long sourceOrderId;
}

public class ReleaseItemSource {
    private ReleaseSourceType sourceType;
    private Long sourceOrderId;
    private Long sourceItemId;
}
```

RFQ 适配器读取 `order_rfq` / `item_quote_version`；销售订单适配器读取 `sales_order_header` / `sales_order_item`。前端已选订单列表需要保存 `sourceType + sourceOrderId`，不能再只保存 `rfqId`。

### 8.2 候选订单与候选零件

- 订单选择弹窗仍展示客户、订单号、状态。
- RFQ 来源展示 RFQ 号；销售订单来源展示销售订单号 / 客户订单号。
- 候选零件分页保持后端分页，接口接收多个来源订单，不全量拉取到前端分页。
- Excel 导入选件匹配也要支持来源字段：有订单号时按指定来源订单匹配，没有订单号时在全部已选来源订单内匹配。

### 8.3 生成提单

生成正式提单时按来源分组：

- RFQ 来源继续走现有 `generateTicket()` 逻辑。
- 销售订单来源新增 `generateSalesOrderTicket()` 或在服务层通过适配器统一组装提单快照。
- 销售订单生成后更新 `sales_order_item.released_qty / remaining_qty / status` 和 `sales_order_header.status`。
- 部分零件或部分数量提单时，头表为 `部分已提单`；全部完成后为 `已生成提单`。

### 8.4 提单表和下游来源字段

`order_delivery_ticket` 当前已经是不可逆发布记录和 MES/WMS 需求池。为支持 RFQ 和销售订单双来源，建议新增：

| 字段 | 说明 |
| --- | --- |
| `source_type` | `RFQ` / `SALES_ORDER` |
| `source_order_id` | 来源订单 ID |
| `source_item_id` | 来源零件 ID |

兼容规则：

- RFQ 提单：继续写 `rfq_id`、`item_id`，同时写 `source_type = RFQ`、`source_order_id = rfq_id`、`source_item_id = item_id`。
- 销售订单提单：`rfq_id`、`item_id` 可为空，必须写 `source_type = SALES_ORDER`、`source_order_id = sales_order_header.id`、`source_item_id = sales_order_item.id`。
- 提单表据、已提零件、锁库零件、MES/WMS 优先使用 `order_delivery_ticket` 快照字段展示和同步，不应强依赖回查 `item_quote_version`。

`order_delivery_ticket_allocation` 已通过 `ticket_id` 关联提单行，通常不需要重复写来源字段；如后续查询性能需要，可再补充来源快照字段。

## 9. 权限与日志口径

### 9.1 权限

短期入口仍在市场 `新单导入` 下：

| 能力 | 权限 |
| --- | --- |
| 销售订单导入 | `market:rfq:import-sales-order` |
| 销售订单模板下载 | `market:rfq:import-sales-order` |
| 议价提单选择 / 查看候选 | 继续使用 `market:release:view`、`market:release:order-select` |
| 议价提单生成 | 继续使用 `market:release:create` |

如果后续新增独立销售订单管理页，再新增：

- `market:sales-order:view`
- `market:sales-order:import`
- `market:sales-order:update`
- `market:sales-order:delete`
- `market:sales-order:export`

不要新增可分配 `common:*` 权限。

### 9.2 数据权限

- 销售订单头表必须保存 `customer_name` 快照，用于沿用现有按客户数据范围过滤。
- 客户主数据选择仍来自 `customer_master`。
- 无客户数据权限时，销售订单选择、候选零件分页、提单生成均返回空或拒绝，不能只靠前端隐藏。

| 动作 | targetType | 说明 |
| --- | --- | --- |
| `SALES_ORDER_IMPORT_QPO` | `sales_order_import_batch` | 导入销售订单到独立主表 |
| `DELIVERY_TICKET_GENERATE` | `order_delivery_ticket` | 生成提单，before/after 只记录摘要 |
| 后续 U9 同步动作 | `sales_order_header` 或 `sales_order_import_batch` | 只记录同步摘要和 U9 返回摘要 |

日志要求：

- 操作日志记录批次号、成功订单数、成功零件数、失败数、未匹配数、操作人。
- 文件日志只写低噪声摘要，例如 `Sales order import completed batchId=... orderCount=... itemCount=... warningCount=...`。
- 不记录完整 Excel 内容、完整 U9 请求体、token、client secret、客户敏感大对象。

## 10. 实施阶段

### 阶段 1：旧方向隔离与独立表骨架

目标：先把数据边界修正，不再向 RFQ 主表写销售订单。

修改：

- 新增迁移，例如 `V65__sales_order_independent_tables.sql`；若其他会话已占用编号，实施时使用实际下一迁移编号。
- 新增 `sales_order_header`。
- 新增 `sales_order_item`。
- 扩展 `sales_order_import_batch` / `sales_order_import_record`，让导入记录可关联独立销售订单。
- 停止销售订单导入代码写入 `order_rfq` 和 `item_quote_version`。
- 将旧方向中已加入 RFQ 主表的销售订单字段标记为 deprecated，不再读写。
- 更新权限清单、日志说明和销售订单讨论文档。

验收：

- 销售订单导入相关代码不新增 `order_rfq` 记录。
- 销售订单导入相关代码不新增 `item_quote_version` 记录。
- 独立表可保存客户、单据类型、订单号、零件、价格、物料号和状态。
- 原 RFQ 导入、订单管理、零件核价、报价处理测试不受影响。

### 阶段 2：后端销售订单导入写独立表

目标：市场实际模板可导入为独立销售订单。

修改：

- 新增 / 改造 `SalesOrderQpoExcelParser`，解析市场实际 `销售订单模版.xlsx`。
- 新增 `SalesOrderHeader`、`SalesOrderItem` 实体和 Mapper。
- 新增 `SalesOrderQpoImportService` 独立表写入逻辑。
- 导入时按页面客户、单据类型编码和 Excel 分组生成销售订单头。
- 每行生成 `sales_order_item`，价格字段完整落库。
- 导入结果返回销售订单号、零件数、未匹配数、失败明细。
- 补后端测试：必填校验、价格计算、分组、重复导入保护、数据权限。

验收：

- 必填字段缺失返回明确行号和字段名。
- 同一客户订单号 / 内部项目号分组可生成销售订单头。
- 未税 / 含税单价和总价可追溯。
- `material_no` 字段可导入或后续为空等待回写。

### 阶段 3：历史快照补齐

目标：建立销售订单生产快照补齐能力，但不再隐藏在导入事务中自动执行。

修改：

- 新增历史快照补齐服务能力，供后续 **销售匹配** 模块复用。
- 复用现有重复件查询口径，按 `part_no + version` 查历史 `item_quote_version.status = 已提单` 最新记录。
- 确认补全时复制材料、工艺、图纸、重量、组合件等生产字段到 `sales_order_item`。
- 不覆盖销售订单价格、数量、交期、客户字段和 `material_no`。
- 补后端测试：匹配成功、未匹配、价格不被覆盖、多候选取最新。

验收：

- 销售匹配确认后，匹配成功的销售订单零件可看到历史工艺 / 材料快照。
- 未匹配零件仍导入成功并返回警告。
- RFQ 重复件匹配结果不包含销售订单零件。

### 阶段 4：前端销售订单导入页面改造

目标：页面展示独立销售订单导入结果，不再提示创建 RFQ。

修改：

- `MarketDashboard.vue` 销售订单页签保留在 `新单导入` 页面下。
- 页面选择客户来自客户主数据。
- 页面支持输入 / 选择单据类型编码，默认 `SO01`。
- 模板下载改为市场实际销售订单表头。
- 导入按钮文案使用 `导入销售订单`，不写 `同步 U9`。
- 结果表展示销售订单号、客户订单号、零件数、匹配数、未匹配数、状态和警告。
- 补前端测试：无权限隐藏按钮、客户选择、单据类型默认值、导入结果展示。

验收：

- 原询价单导入不受影响。
- 销售订单入口仍在新单导入页内。
- 无 `market:rfq:import-sales-order` 不能导入或下载销售订单模板。
- 页面不再展示 RFQ 号作为销售订单导入结果。

### 阶段 5：议价提单来源适配

目标：议价提单能选择 RFQ 和销售订单两类来源。

修改：

- 后端新增来源感知订单选择接口或扩展现有接口，返回 `sourceType + sourceOrderId`。
- 候选零件分页接口支持 RFQ / SALES_ORDER 混合来源，保持后端分页。
- Excel 导入选件支持在已选 RFQ 和销售订单范围内匹配。
- `MarketRelease.vue` 的已选订单状态改为保存来源对象，不再只保存 `rfqId`。
- 提单参数从销售订单头默认带出：订单类型、内部项目号、客户订单号、客户项目号。
- 补前后端测试：混合来源分页、移除销售订单、跨页选中、导入选件。

验收：

- 销售订单状态为 `已报价` 时可被议价提单选择。
- 销售订单零件和 RFQ 零件可统一展示在候选表中。
- 翻页仍请求后端分页接口，不全量拉取。
- 原单订单 RFQ 生成行为不回退。

### 阶段 6：销售订单生成提单与下游兼容

目标：销售订单零件可生成正式提单，并进入提单表据、已提零件、锁库零件。

修改：

- `order_delivery_ticket` 新增来源字段：`source_type`、`source_order_id`、`source_item_id`。
- RFQ 提单生成同步写来源字段。
- 销售订单提单生成写提单快照，更新销售订单头 / 行状态和已提数量。
- 提单表据、已提零件、锁库零件查询避免强依赖 `item_quote_version` 回查。
- MES 物料号同步成功后回写 `order_delivery_ticket.material_no`，必要时同步回写 `sales_order_item.material_no`。
- 补回归测试：RFQ 提单、销售订单提单、部分提单、已提零件查询、锁库查询。

验收：

- 销售订单部分提单后头表为 `部分已提单`。
- 销售订单全部提单后头表为 `已生成提单`。
- 提单表据可查看 / 导出销售订单提单行。
- 已提零件和锁库零件能展示销售订单来源提单行。

### 阶段 7：U9 同步重接

目标：基于独立销售订单和提单物料号同步 U9。

修改：

- U9 同步从 `sales_order_header` / `sales_order_item` / `order_delivery_ticket` 组装请求。
- `OrderBy` 使用客户主数据 `customer_code`。
- `DocumentType` 使用页面 `document_type_code`。
- `ItemCode` 使用确认后的 `material_no`。
- 同步结果回写 `u9_sync_status`、`u9_order_id`、`u9_order_code`、失败原因摘要。
- 保留重试能力，避免重复创建 U9 订单。
- 补测试：未取得物料号不可同步、U9 成功、U9 部分失败、失败重试。

验收：

- 无物料号的销售订单不能同步 U9，并返回明确提示。
- 同步成功回写 U9 编码。
- 同步失败不影响已生成的 QPO 提单记录。
- 日志不记录 token、密钥或完整请求体。

### 阶段 8：文档与回归

目标：方向切换收口，确保旧 RFQ 主流程稳定。

修改：

- 更新权限清单。
- 更新日志运维说明。
- 更新销售订单直提讨论文档。
- 标记 13 号文档已废弃。
- 补前后端测试和构建验证。

验收：

- `mvnw.cmd test` 通过。
- `npm test` 通过。
- `npm run build` 通过。
- RFQ 导入、核价、报价、议价提单、提单表据、已提零件、锁库零件原流程不回退。
- 销售订单数据不进入 `order_rfq` / `item_quote_version`。

## 11. 风险与待确认

| 问题 | 当前建议 |
| --- | --- |
| 旧 V63 已经给 RFQ 表加了字段 | 不继续使用，先 deprecated；稳定后再单独清理 |
| 销售订单模板里的“料号”是否就是 U9 `ItemCode` | 需要业务确认；表内同时保留 `sales_material_no` 和 `material_no` |
| 销售订单是否需要独立管理页 | 第一阶段不新增；导入和提单跑通后再判断 |
| 销售订单已提历史是否参与重复件匹配 | 默认不参与 RFQ 重复件匹配；如要参与，做统一生产历史快照服务 |
| 销售订单和 RFQ 是否允许混合一次提单 | 技术上可通过来源适配支持；业务上建议先允许同一页面选择，但生成时按来源分组 |
| U9 创建销售订单的时点 | 建议等物料号明确后再同步，避免 U9 `ItemCode` 缺失 |

## 12. 最终验收标准

- 销售订单导入使用独立订单主表和独立零件表。
- 原 RFQ 主流程不写入销售订单数据。
- 销售订单零件拥有完整销售字段、价格字段、生产快照字段和 `material_no` 字段。
- 销售订单可被议价提单选择并生成提单。
- 销售订单生成的提单可进入提单表据、已提零件、锁库零件和 MES/WMS 后续流程。
- U9 同步可以在物料号确认后基于独立销售订单数据重接。
