## 1. 文档目的

阶段 38 已完成工时工艺的两级主数据重构：工艺已经具备稳定的 `processCode / categoryName / detailName / processDetailId`。材料侧目前仍主要依赖 `materialName` 和 `materialData.name`，缺少同等级的稳定身份。

本次改造目标：

- 新增可维护的材料类型字典，当前默认类型为 `RAW_MATERIAL / 原材料`。
- 材料主数据新增全局唯一 `materialCode`。
- 将旧 `dict_material.material_type` 的“钢铁 / 铝 / 塑料”等含义收口为 `materialCategory / 材质分类`。
- 工程核价真实材料快照保存材料编码、材料类型、材质分类、材料名称和材料形态。
- RFQ、销售订单、提单、WMS allocation、已提、待产、锁库、导出和外部接口展示均能看到材料编码和材料类型。
- 销售订单 U9 仍以 MES 物料号 `materialNo` 为发送物料身份，材料编码不替代 MES 物料号。

目标链路：

```text
材料类型字典
    -> 材料主数据（materialCode + materialName + materialType + materialCategory）
    -> 全局默认材料 / 零件核价材料选择
    -> RFQ 主表材料快照
    -> 销售订单直接导入或 RFQ 派生销售订单材料快照
    -> 提单 ticket 材料快照
    -> WMS allocation / 待产 / 锁库材料快照
    -> 导出、页面展示和外部接口字段
```

## 2. 当前实现和问题

### 2.1 当前材料字典

当前表为 `dict_material`，关键字段如下：

| 字段 | 当前语义 | 问题 |
| --- | --- | --- |
| `material_name` | 材料名称，例如 `45#`、`A6061` | 不是稳定唯一身份，当前种子数据中存在同名不同备注材料。 |
| `material_type` | 当前存 `钢铁`、`铝`、`塑料` 等 | 实际是“材质分类”，不是未来业务材料类型。 |
| `remarks` | 备注 | 过去通过 `material_name + remarks` 做唯一性兜底，不适合作为外部系统身份。 |
| `plate_density / plate_price / bar_density / bar_price / tube_density / tube_price` | 不同材料形态下的密度和价格 | 需要保留。 |

当前唯一索引 `idx_dict_material_name_remarks(material_name, remarks)` 只能避免同名同备注重复，不能解决外部系统材料编码问题。

### 2.2 当前核价材料快照

当前核价保存时，前端提交的 `materialData` 主要包含材料名称、形态、密度、单价、重量和成本。后端 `EngineerService.calculateMaterialCost(...)` 主要按 `materialData.name` 查询 `dict_material.material_name`，保存后把 `engineeringMaterialName` 设置为 `materialData.name`。

这会导致两个风险：

- 同名材料无法稳定区分。
- 后续复制快照时只复制名称，无法知道真实主数据编码和材料业务类型。

### 2.3 当前材料快照位置

| 数据位置 | 当前字段 | 说明 |
| --- | --- | --- |
| `item_quote_version` | `engineering_material_name`、`material_shape`、`material_data` | RFQ 工程核价后的真实材料。 |
| `sales_order_item` | `engineering_material_name`、`material_shape`、`material_data` | 销售订单补全或 RFQ 派生销售订单的生产快照。 |
| `order_delivery_ticket` | `engineering_material_name`、`material_shape`、`material_data` | 已提零件材料快照。 |
| `order_delivery_ticket_allocation` | `engineering_material_name`、`material_shape`、`material_data` | WMS 拆分后的待产 / 锁库材料快照。 |
| DTO / 页面 | `engineeringMaterialName`、`materialShape`、`materialData` | 已提、待产、锁库、销售订单、异常治理和导出展示。 |

这些位置都需要新增材料编码和材料类型信息，否则只改字典表仍然不够。

## 3. 范围与不变项

### 3.1 本次范围

- 新增 `dict_material_type` 可维护材料类型字典。
- 将 `dict_material` 改造成以 `material_code` 为唯一身份的材料主数据。
- 将旧 `material_type` 语义改为 `material_category`。
- 核价材料选择改为按 `materialCode` 识别材料。
- `materialData` 标准化保存材料编码、材料类型、材质分类和材料形态。
- RFQ、销售订单、提单、WMS allocation、已提、待产、锁库、导出和相关 DTO 增加材料编码和材料类型字段。
- 更新材料工艺页面，提供材料类型增删改查管理入口。
- 更新权限、日志、测试和相关文档口径。
- 因当前数据库可清空，本次直接调整 Flyway 新基线 `V1 / V2`，不维护旧业务数据兼容迁移。

### 3.2 不在本次范围

- 不重构 BOM 结构；BOM 在材料和工艺主数据稳定后另行设计。
- 不接入真实 MES 材料主数据同步接口；本阶段只把 QPO 本地材料主数据结构改到位。
- 不强制 RFQ 导入或销售订单导入的客户原始材料字段必须匹配材料字典。
- 不改变销售订单 U9 同步以 MES 物料号为核心的规则。
- 不新增左侧菜单模块，不新增用户权限点。
- 不新增普通读取操作日志。

### 3.3 业务边界

- `item_quote_version.material_name` 仍表示客户或 Excel 导入材料名称，不等同于工程核价材料。
- `sales_order_item.material_name` 仍表示销售订单导入行内材料或客户材料，不等同于工程核价材料。
- `engineering_material_*` 才表示工程核价后选择的真实材料主数据快照。
- `material_shape` / `materialData.shape` 表示材料形态，例如板材、棒材、管材；页面不再称为“材料类型”。
- 新的材料类型表示业务类型，例如 `原材料`，未来可扩展为半成品、辅料、外购件等。

## 4. 目标数据模型

### 4.1 材料类型字典

新增表：

```sql
CREATE TABLE dict_material_type (
    id BIGSERIAL PRIMARY KEY,
    type_code VARCHAR(64) NOT NULL,
    type_name VARCHAR(120) NOT NULL,
    remarks VARCHAR(500),
    enabled BOOLEAN NOT NULL DEFAULT TRUE,
    sort_no INTEGER NOT NULL DEFAULT 0,
    created_at TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP,
    updated_at TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP,
    CONSTRAINT uk_dict_material_type_code UNIQUE (type_code),
    CONSTRAINT uk_dict_material_type_name UNIQUE (type_name)
);

CREATE INDEX idx_dict_material_type_enabled_sort
    ON dict_material_type(enabled, sort_no, id);
```

字段规则：

| 字段 | 规则 |
| --- | --- |
| `type_code` | 必填，全局唯一，建议大写英文、数字、下划线，例如 `RAW_MATERIAL`。 |
| `type_name` | 必填，全局唯一，例如 `原材料`。 |
| `remarks` | 可空，记录类型说明。 |
| `enabled` | 禁用后不可被新材料选择，但历史材料快照仍可展示。 |
| `sort_no` | 页面排序。 |

基线种子至少写入：

| type_code | type_name | remarks |
| --- | --- | --- |
| `RAW_MATERIAL` | `原材料` | 当前材料主数据默认类型。 |

### 4.2 材料主数据表

改造后 `dict_material` 目标结构：

```sql
CREATE TABLE dict_material (
    id BIGSERIAL PRIMARY KEY,
    material_code VARCHAR(80) NOT NULL,
    material_name VARCHAR(100) NOT NULL,
    material_type_id BIGINT NOT NULL REFERENCES dict_material_type(id),
    material_category VARCHAR(80),
    density NUMERIC(12,4),
    plate_density NUMERIC(12,4),
    plate_price NUMERIC(12,2),
    bar_density NUMERIC(12,4),
    bar_price NUMERIC(12,2),
    tube_density NUMERIC(12,4),
    tube_price NUMERIC(12,2),
    remarks TEXT,
    enabled BOOLEAN NOT NULL DEFAULT TRUE,
    sort_no INTEGER NOT NULL DEFAULT 0,
    created_at TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP,
    updated_at TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP
);

CREATE UNIQUE INDEX uk_dict_material_code_upper
    ON dict_material(UPPER(material_code));

CREATE INDEX idx_dict_material_type_enabled_sort
    ON dict_material(material_type_id, enabled, sort_no, id);

CREATE INDEX idx_dict_material_name
    ON dict_material(material_name, id);

CREATE INDEX idx_dict_material_category
    ON dict_material(material_category, id);
```

字段规则：

| 字段 | 规则 |
| --- | --- |
| `material_code` | 必填，大小写不敏感唯一。系统只 trim，不自动改写真实编码。 |
| `material_name` | 必填，显示名称，可重复。 |
| `material_type_id` | 必填，指向材料类型字典。当前旧材料全部默认 `RAW_MATERIAL / 原材料`。 |
| `material_category` | 可空，保存旧 `material_type` 的语义，例如 `钢铁`、`铝`、`塑料`。 |
| `enabled` | 禁用后不允许新核价选择，但历史快照可展示。 |
| `sort_no` | 页面排序。 |

当前 `V2__qpo_baseline_seed_data.sql` 中已有材料可临时生成确定性编码，例如：

```text
MAT-000005 -> 45#
MAT-000006 -> Q235
MAT-000038 -> A5052
```

后续真实材料编码确定后，可通过材料维护页逐条改为业务编码；唯一约束会防止重复。

## 5. 标准 `materialData` 契约

核价保存后的 `materialData` 必须统一为以下结构的超集：

```json
{
  "materialId": 5,
  "materialCode": "MAT-000005",
  "materialName": "45#",
```

## 11. 最终验收标准

### 数据库

- `dict_material_type` 存在，且有 `RAW_MATERIAL / 原材料`。
- `dict_material.material_code` 存在且唯一。
- `dict_material.material_category` 保存旧材质分类语义。
- `dict_material.material_type` 不再作为字段存在。
- RFQ、销售订单、ticket 和 allocation 表均有工程材料编码和材料类型快照字段。

### 业务

- 工程核价材料选择按材料编码识别。
- 后端按材料编码取价，不信任前端传入价格。
- 重复件复用、销售订单自动补全和 RFQ 派生销售订单复制完整材料身份。

- 销售订单 U9 仍使用 MES 物料号，不把材料编码误当作 U9 物料号。

### 前端

- 材料工艺页面可维护材料类型和带编码材料。
- 材料选择器可搜索和展示材料编码。
- 全局默认材料按编码保存。
- 已提、待产、锁库、导出和表据展示材料编码、材料类型、材质分类和材料形态。
- 页面文案不再混用“材料类型”和“材料形态”。

### 权限和日志

- 不新增权限点。
- 材料类型维护复用 `engineer:dict:material-manage`。
- 普通查询不写操作日志。
- 字典写操作记录摘要，不记录完整价格矩阵或完整材料 JSON。

## 12. 风险和处理原则

| 风险 | 处理原则 |
| --- | --- |
| 旧本地缓存只有材料名称 | 提示重新选择材料，不做名称模糊匹配。 |
| 同名材料存在多个编码 | 按编码区分，页面同时展示名称、编码和备注。 |
| 材料类型和材质分类混淆 | 页面和 DTO 明确区分 `materialTypeName` 与 `materialCategory`。 |
| 清库后 Flyway 校验和变化 | 本阶段明确要求清库重建，只重建 `public` schema。 |
| 外部系统误用材料编码替代 MES 物料号 | U9 和 MES 物料号规则保持不变，文档和 DTO 注释明确区分。 |
| 日志泄露完整材料核价 JSON | 日志只记录编码、名称、类型和数量摘要。 |

## 13. 交付结果

完成后，QPO 材料链路统一为：

```text
材料类型：materialTypeCode + materialTypeName
材料主数据：materialCode + materialName + materialType + materialCategory
核价材料快照：engineeringMaterialCode + engineeringMaterialName + engineeringMaterialType + engineeringMaterialCategory + materialShape + materialData
下游复制：RFQ / 销售订单 / ticket / WMS allocation 使用同一材料快照
外部发送：MES 物料号仍为 materialNo，材料编码作为工程材料身份字段保留
```

这样后续继续改 BOM、接 MES 材料主数据同步或扩展其他材料类型时，系统已经具备稳定的材料编码、可维护材料类型和全链路快照能力，不需要再围绕材料名称做二次返工。
