# 待产零件与锁库零件模块解耦开发文档

## 1. 背景

当前 `order_delivery_ticket_allocation` 同时保存三类 WMS 拆分结果：

| `allocation_type` | 含义 | 当前问题 |
| --- | --- | --- |
| `IN_STOCK_LOCK` | 已入库库存锁定数量 | 属于锁库结果展示 |
| `IN_PRODUCTION_LOCK` | 在产库存锁定数量 | 属于锁库结果展示 |
| `PRODUCTION_REQUIRED` | 未被 WMS 覆盖、需要下发 MES 生产的数量 | 属于待生产工作台 |

现有“锁库零件”页面同时承担库存结果展示和 MES 生产下发两类职责，用户理解成本高，首页跳转、权限、日志和接口文档也都把“待生产下发”挂在锁库零件下面。用户已确认本次采用：**一张表，两套模块口径，不做旧语义兼容，一次到位。**

## 2. 目标口径

### 2.1 模块拆分

| 模块 | 路由 | 数据范围 | 页面职责 |
| --- | --- | --- | --- |
| 待产零件 | `/production-items` | `allocation_type = 'PRODUCTION_REQUIRED'` 且 MES 生产下发未成功 | 处理仍需下发 MES 生产的待产行 |
| 锁库零件 | `/locked-items` | `allocation_type IN ('IN_STOCK_LOCK', 'IN_PRODUCTION_LOCK')` | 查看 WMS 已锁定库存结果 |

### 2.2 一次到位原则

- 不拆物理表，继续使用 `order_delivery_ticket_allocation`。
- 不搬迁、不删除历史 allocation 数据。
- 不保留旧“锁库零件下发 MES 生产”按钮、接口、权限语义。
- 不新增可分配 `common:*` 权限。
- 成功下发 MES 生产后的 `PRODUCTION_REQUIRED` 行从待产零件默认列表消失，但仍保留在数据库、系统任务和操作日志中用于追溯。

## 3. 查询 Scope

| Scope | SQL 口径 | 用途 |
| --- | --- | --- |
| `PRODUCTION_ACTIVE` | `alloc.allocation_type = 'PRODUCTION_REQUIRED' AND COALESCE(NULLIF(TRIM(alloc.mes_production_status), ''), 'PENDING') <> 'SUCCESS'` | 待产零件默认列表 |
| `PRODUCTION_PENDING` | `alloc.allocation_type = 'PRODUCTION_REQUIRED' AND COALESCE(NULLIF(TRIM(alloc.mes_production_status), ''), 'PENDING') = 'PENDING'` | 待下发筛选 |
| `PRODUCTION_PROCESSING` | `alloc.allocation_type = 'PRODUCTION_REQUIRED' AND alloc.mes_production_status = 'PROCESSING'` | 下发中筛选 |
| `PRODUCTION_FAILED` | `alloc.allocation_type = 'PRODUCTION_REQUIRED' AND alloc.mes_production_status = 'FAILED'` | 下发失败筛选和首页异常 |
| `LOCKED_STOCK` | `alloc.allocation_type IN ('IN_STOCK_LOCK', 'IN_PRODUCTION_LOCK')` | 锁库零件默认列表 |

数据流：

```text
已提零件提交 WMS
  -> WMS 返回库存覆盖结果
  -> QPO 写入 order_delivery_ticket_allocation
      -> IN_STOCK_LOCK / IN_PRODUCTION_LOCK 进入锁库零件
      -> PRODUCTION_REQUIRED 进入待产零件

待产零件下发 MES 生产
  -> SUCCESS：待产默认列表隐藏
  -> FAILED：继续展示，可重试
  -> PROCESSING：继续展示，按钮禁用
```

## 4. 权限设计

### 4.1 新增待产零件权限

| 权限编码 | 类型 | 父级 | 中文名 | 说明 |
| --- | --- | --- | --- | --- |
| `market:production-item:view` | `MENU` | 无 | 待产零件 | 控制左侧入口、路由和列表查询 |
| `market:production-item:customer-select` | `API` | `market:production-item:view` | 待产零件选择客户 | 控制客户选择弹窗 |
| `market:production-item:mes-production-submit` | `BUTTON` | `market:production-item:view` | 待产零件下发MES生产 | 控制下发按钮和后端提交接口 |

### 4.2 收窄锁库零件权限

| 权限编码 | 类型 | 新说明 |
| --- | --- | --- |
| `market:locked-item:view` | `MENU` | 只控制 WMS 已入库库存锁定和在产库存锁定结果查询 |
| `market:locked-item:customer-select` | `API` | 只控制锁库结果页面客户选择 |

### 4.3 旧权限处理

`market:locked-item:mes-production-submit` 不再作为系统能力存在：

- 从 `PermissionService.defaultPermissions()` 移除。
- 从默认角色映射移除。
- 数据库迁移将该权限标记为 `enabled=false, assignable=false, visible=false`。
- 删除所有角色到该权限的绑定。
- 后端不再有接口使用该权限。
- 前端不再引用该权限。

### 4.4 默认角色

| 角色 | 待产查看 | 待产选客户 | 下发 MES 生产 | 锁库查看 | 锁库选客户 |
| --- | --- | --- | --- | --- | --- |
| `SUPER_ADMIN` | 是 | 是 | 是 | 是 | 是 |
| `MARKET_MANAGER` | 是 | 是 | 是 | 是 | 是 |
| `MARKET_USER` | 是 | 是 | 是 | 是 | 是 |
| `READONLY` | 是 | 是 | 否 | 是 | 是 |

## 5. 数据库与性能

### 5.1 新迁移

新增迁移：`quote-backend/src/main/resources/db/migration/V84__production_item_module_split.sql`。若编号被占用，使用实际下一编号。

迁移内容：

- Upsert 三个 `market:production-item:*` 权限。
- 分配默认角色权限。
- 禁用并解绑 `market:locked-item:mes-production-submit`。
- 新增部分索引，避免两个模块互扫无关数据。

建议索引：

```sql
CREATE INDEX IF NOT EXISTS idx_delivery_allocation_production_active_id
    ON order_delivery_ticket_allocation(id DESC)
    WHERE allocation_type = 'PRODUCTION_REQUIRED'
      AND (mes_production_status IS NULL OR TRIM(mes_production_status) = '' OR mes_production_status <> 'SUCCESS');

CREATE INDEX IF NOT EXISTS idx_delivery_allocation_locked_stock_id
    ON order_delivery_ticket_allocation(allocation_type, id DESC)
    WHERE allocation_type IN ('IN_STOCK_LOCK', 'IN_PRODUCTION_LOCK');
```

### 5.2 性能原则

- 两个模块都必须由后端分页查询，前端不得全量拉取后本地过滤。
- Scope 条件必须进入 SQL。
- 客户选择弹窗也按各自模块 scope 查询。
- 首页待生产计数通过聚合 SQL 计算，不调用列表接口后统计。

### 6.1 文件职责

| `PermissionService.java` | 修改 | 新增待产权限，移除旧锁库下发权限 |

| `LockedItemService.java` | 修改 | 只查询 `LOCKED_STOCK` |

| `LockedItemQueryReq.java` | 修改 | 锁库结果筛选 DTO，不再承载生产下发状态主筛选 |
| `ProductionItemQueryReq.java` | 新增 | 待产筛选 DTO，包含 `mesProductionStatus` |

| `MesProductionDispatchService.java` | 修改 | 文案和审计 action 从 locked item 改为 production item |
| `DashboardOverviewService.java` | 修改 | 待生产卡片和异常跳转到 `/production-items` |

### 6.2 新接口

锁库零件：

```text
GET /api/order-delivery/locked-items
GET /api/order-delivery/locked-items/customers
```

后端强制 `allocation_type IN ('IN_STOCK_LOCK', 'IN_PRODUCTION_LOCK')`，权限为 `market:locked-item:view` 和 `market:locked-item:customer-select`。

待产零件：

```text
GET  /api/order-delivery/production-items
GET  /api/order-delivery/production-items/customers
POST /api/order-delivery/production-items/mes-production
```

后端强制 `allocation_type = 'PRODUCTION_REQUIRED'`，默认排除 `mes_production_status = 'SUCCESS'`，权限为 `market:production-item:*`。

旧接口处理：移除 `POST /api/order-delivery/allocations/mes-production`，前端和测试全部改为新接口，不保留转发。

### 6.3 筛选 DTO

`ProductionItemQueryReq`：`page`、`pageSize`、`customerName`、`rfqNo`、`partNo`、`version`、`materialNo`、`internalProjectNo`、`customerOrderNo`、`customerProjectNo`、`itemType`、`mesProductionStatus`、`dateFrom`、`dateTo`。

`LockedItemQueryReq`：`page`、`pageSize`、`customerName`、`rfqNo`、`partNo`、`version`、`materialNo`、`internalProjectNo`、`customerOrderNo`、`customerProjectNo`、`itemType`、`allocationType`、`wmsProductionOrderNo`、`dateFrom`、`dateTo`。

锁库接口如果收到 `allocationType=PRODUCTION_REQUIRED`，必须返回空列表或忽略该值，不得返回待产行。

### 6.4 MES 生产下发规则

保留现有核心规则：

- 只允许 `PRODUCTION_REQUIRED` 下发。
- `SUCCESS` 禁止重复下发。
- `PROCESSING` 禁止重复下发。
- `FAILED` 可重试。
- 普通件父子关系为空数组。
- RFQ 组合件查 `item_assembly_relation`。
- 销售订单组合件查 `sales_order_item_assembly_relation`。

调整日志和审计口径：

- 操作日志 action 使用 `PRODUCTION_ITEM_MES_PRODUCTION_SUBMIT / SUCCESS / FAILED`。
- 文件日志事件仍保持 `MES production dispatch submitted/started/completed/skipped/failed`。
- 日志字段保留 `allocationId`、`ticketId`、`taskId`、`requestId`、`sourceType`、`sourceOrderId`、`sourceItemId`、`productionQty`、`ticketQty`、`externalId`、`durationMs`。
- 严禁记录 token、Authorization header、完整请求体和完整响应体。
