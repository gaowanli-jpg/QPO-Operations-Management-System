# QPO 零件核价预览与重复件复用职责拆分开发文档

> 2026-08-07 价格字段收口：本文所称核价价格统一指 `tax_included_unit_price`、`tax_included_total_price`、`untaxed_unit_price`、`untaxed_total_price`；不再使用 `final_*` 作为现行字段。

## 1. 背景

当前零件核价流程中，全局设定页承担了过多职责：

- 订单概览接口返回订单全部零件。
- 全局设定页展示全部零件。
- 点击保存全局设定时立即调用重复件自动核价。
- 组合件缺少当前订单子件时，缺少子件原因会在全局设定页弹出。

这与目标产品口径不一致。全局设定页的职责应该是帮助工程师快速判断订单大致材料、工艺和全局默认配置，而不是承担完整核价、重复件复用、组合件关系校验。

目标流程应调整为：

```text
选择订单
  -> 全局设定页只预览前 10 个零件
  -> 工程师保存全局设定
  -> 进入逐件核价页
  -> 逐件核价页加载全部零件
  -> 对全部零件执行重复件复用
  -> 普通重复件自动带入历史核价参数
  -> 组合件重复件按当前订单图号+版本重建子件关系
  -> 缺少子件的父件保持未核价，由工程师手动补齐
```

## 2. 核心结论

1. 全局设定页只做轻量预览，不再展示全量零件。
2. 全局设定页预览数量固定为前 10 个零件，后端同时返回订单总零件数。
3. 全局设定页不再调用 `applyRepeatQuotes()`。
4. 重复件复用迁移到逐件核价页加载完整订单后执行。
5. 重复件复用必须仍针对订单全部零件执行，不受前 10 个预览限制。
6. 普通重复件继续自动带入材料、工艺、成本、价格等历史核价结果。
7. 组合件重复件继续支持多层嵌套复用，并按当前订单图号+版本重建 `item_assembly_relation`。
8. 如果组合件历史子件在当前订单中不存在，父件保持 `未核价`，不新增弹窗、不新增行内提示、不新增额外状态。
9. “未核价”本身就是工程师需要手动处理的提示。
10. 不新增数据库字段，不改变组合件关系表模型。

## 3. 非目标

- 不新增“缺少子件”专用状态。
- 不新增“缺少子件”前端标签、tooltip、弹窗、告警条或行内提示。
- 不把组合件父子关系冗余保存到 `item_quote_version`。
- 不在全局设定页展示完整零件清单。
- 不在全局设定页执行完整重复件套用。
- 不改变订单、零件既有状态文案。
- 不改变手动组合件核价弹窗的核心录入模型。
- 不新增权限点；继续复用现有工程核价权限。

## 4. 现状与目标差异

| 范围 | 当前行为 | 目标行为 |
| --- | --- | --- |
| 全局设定页订单概览 | 返回并展示全部零件 | 只展示前 10 个零件，同时显示总零件数 |
| 全局设定页保存 | 保存全局设定后调用重复件自动核价 | 只保存全局设定并跳转逐件核价页 |
| 重复件复用时机 | 全局设定页保存时执行 | 逐件核价页加载完整订单后执行 |
| 重复件复用范围 | 全部零件 | 全部零件 |
| 缺少组合件子件 | 全局设定页弹持久警告 | 不额外提示，父件保持未核价 |
| 工程师处理入口 | 保存设定后被提示，再跳转 | 在逐件核价页看到父件未核价后手动处理 |

## 5. 后端设计

### 5.1 全局设定摘要接口

修改文件：

```text
quote-backend/src/main/java/com/machining/quote/controller/EngineerController.java
```

当前 `/api/engineer/setup/summary/{rfqId}` 与 `/api/engineer/pricing/summary/{rfqId}` 共用 `getOrderSummary(rfqId)`，都会返回全量 `itemList`。

目标拆分：

- `/api/engineer/setup/summary/{rfqId}`：返回前 10 个零件预览。
- `/api/engineer/pricing/summary/{rfqId}`：继续返回全部零件。

建议实现：

```java
private static final int SETUP_PREVIEW_LIMIT = 10;
```

新增或改造方法：

```java
private Map<String, Object> getSetupOrderSummary(Integer rfqId) {
    OrderRfq order = orderRfqMapper.selectById(rfqId);
    if (dataScopeService != null) {
        dataScopeService.assertCanAccessOrder(order);
    }

    QueryWrapper<ItemQuoteVersion> countQw = new QueryWrapper<>();
    countQw.eq("rfq_id", rfqId);
    Long itemCount = itemQuoteVersionMapper.selectCount(countQw);

    QueryWrapper<ItemQuoteVersion> previewQw = new QueryWrapper<>();
    previewQw.eq("rfq_id", rfqId).orderByAsc("id").last("LIMIT " + SETUP_PREVIEW_LIMIT);
    List<ItemQuoteVersion> previewItems = itemQuoteVersionMapper.selectList(previewQw);

    Map<String, Object> result = new HashMap<>();
    result.put("orderInfo", order);
    result.put("itemList", previewItems);
    result.put("previewItemList", previewItems);
    result.put("itemCount", itemCount == null ? 0 : itemCount);
    result.put("previewLimit", SETUP_PREVIEW_LIMIT);
    return result;
}
```

说明：

- 保留 `itemList` 为前端兼容字段，但语义调整为预览列表。
- 新增 `previewItemList` 是更清晰的新字段，后续前端可逐步切换。
- 新增 `itemCount` 用于展示订单总零件数。
- `pricing/summary` 继续返回全量 `itemList`，不得受预览限制影响。

### 5.2 重复件复用接口

保留现有接口：

```text
POST /api/engineer/apply-repeat-quotes/{rfqId}
```

保留权限：

```java
@RequirePermission("engineer:pricing:save-item")
```

接口职责不变：

- 针对订单全部零件执行重复件复用。
- 重复件匹配专项标准见 `05-重复件匹配仅使用已提单历史零件开发文档.md`；当前实现只使用 `item_quote_version.status = 已提单` 的历史零件，按图号 + 版本匹配；全局设定页只展示分析结果和推荐文案，不传达“同客户”口径。
- 普通件复用历史材料、工艺、费用、价格结果。
- 组合件复用 `quoteMode = ASSEMBLY`、`assemblyFee`、子件关系、`qtyPerParent`、`sortNo`。
- 组合件子件按当前订单 `partNo + version` 映射，不复制历史 `child_item_id`。
- 支持多层嵌套组合件。
- 当前订单缺少历史子件时，跳过该父件，父件保持未核价。

重要调整：

- 后端仍可在 `skippedItems` 中返回缺少子件原因，便于调试和测试。
- 前端逐件核价页不展示这些原因。
- 不持久化缺少子件原因。
- 不新增 `repeat_skip_reason` 字段。

### 6.2 逐件核价页

修改文件：

```text
quote-frontend/src/components/ItemPricing.vue
```

目标：

- 页面加载完整订单后执行重复件自动复用。
- 复用完成后刷新完整核价数据。
- 普通重复件被自动填入历史核价结果。
- 组合件可自动重建关系时直接进入已核价。
- 组合件缺少当前子件时保持未核价。
- 不新增缺少子件提示。

建议新增状态：

```js
const repeatApplyAttempted = ref(false)
const repeatApplyLoading = ref(false)
```

建议流程：

```js
const applyRepeatQuotesOnPricingLoad = async () => {
  if (!rfqId.value || repeatApplyAttempted.value) return
  repeatApplyAttempted.value = true
  repeatApplyLoading.value = true
  try {
    const response = await applyRepeatQuotes(rfqId.value)
    if (response?.appliedCount > 0) {
      ElMessage.success(`已自动套用 ${response.appliedCount} 个重复零件的历史核价。`)
      await loadData()
    }
  } catch (error) {
    console.error(error)
    ElMessage.warning('重复件自动核价失败，可继续手动核价。')
  } finally {
    repeatApplyLoading.value = false
  }
}
```

不展示缺少子件原因：

- 不读取 `response.skippedItems` 做页面提示。
- 不在父件行新增“缺少子件”标签。
- 不在父件行新增 tooltip。
- 不在组合件弹窗里自动弹出缺子件说明。

父件行的可见结果：

```text
状态：未核价
操作：去核价
```

这就是工程师需要手动补齐组合件关系的入口。

### 6.3 防止重复执行

逐件核价页应避免每次刷新或局部重载都重复执行自动复用。

第一版建议：

- 每次进入页面只自动执行一次。
- 使用组件内 `repeatApplyAttempted` 控制。
- 不把“已执行过自动复用”持久化到数据库。

原因：

- 重复件复用不会覆盖已有报价。
- 页面内重复执行没有价值。
- 持久化执行标记会增加状态复杂度，当前没有必要。

## 7. 组合件缺子件口径

### 7.1 后端行为

如果历史组合件父件需要的子件在当前订单中不存在：

- 当前父件不写 `quoteMode = ASSEMBLY`。
- 当前父件不写 `assemblyFee`。
- 当前父件不写 `taxIncludedUnitPrice`。
- 当前父件不写 `item_assembly_relation`。
- 当前父件保持 `未核价`。
- 返回 `skippedItems` 供测试和排查。

### 7.2 前端行为

不做额外提示。

也就是说，不做以下内容：

- 不弹窗。
- 不 toast。
- 不在父件行显示“缺少子件”。
- 不在状态列旁边显示特殊标签。
- 不在组合件弹窗自动显示缺少哪些子件。

工程师看到父件仍是 `未核价` 后，点击 `去核价` 进入正常手动组合件核价流程即可。

### 7.3 理由

- `未核价` 已经是明确的待处理状态。
- 缺少子件可能需要工程师结合图纸和业务判断，不适合用一次性提示打断流程。
- 全局设定页不是处理组合件关系的地方。
- 避免页面出现过多临时提示，降低误解和维护成本。

## 8. 权限设计

不新增权限。

沿用现有权限：

| 能力 | 权限 |
| --- | --- |
| 查看全局设定页 | `engineer:setup:view` |
| 保存全局设定 | `engineer:setup:save-config` |
| 查看逐件核价页 | `engineer:pricing:view` |
| 自动复用重复件核价结果 | `engineer:pricing:save-item` |
| 手动保存单件核价 | `engineer:pricing:save-item` |

注意：

- 全局设定页不再调用 `applyRepeatQuotes`，因此不应要求全局设定保存用户拥有 `engineer:pricing:save-item`。
- 逐件核价页自动复用需要 `engineer:pricing:save-item`。
- 如果用户只有查看逐件核价权限但没有保存权限，不应自动执行重复件复用。
