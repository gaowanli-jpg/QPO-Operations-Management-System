# QPO 销售订单导入与 U9 同步开发文档

最后更新：2026-07-24

## 1. 背景

市场部新增“销售订单”场景：部分老客户不走询价、核价、报价流程，而是直接下销售订单。当前先分两步做：

1. **阶段一：销售订单导入并同步 U9**。在 QPO 市场 `新单导入` 页面下新增 `销售订单` 入口，用户导入销售订单 Excel，系统校验后直接调用 U9 `SO_Create` 创建销售订单，并保存同步结果。
2. **阶段二：销售订单直提生产链路**。后续再讨论如何把销售订单转成 QPO 内部可提单订单、如何匹配历史工艺材料快照、如何进入议价提单。

本文档只覆盖阶段一。

U9 接口来源：

- 文档页面：`U9C OPENAPI / SO / SO_Create`
- 接口：`POST /webapi/SO/Create`
- 说明：创建 SO / 创建销售订单。

## 2. 目标

- 在市场 `新单导入` 页面下面新增 `销售订单` 子入口。
- 支持上传销售订单 Excel。
- 解析 Excel 为 U9 `SO_Create` 请求 DTO。
- 调用 U9 创建销售订单。
- 保存每次导入批次、请求摘要、U9 返回结果和同步状态。
- 展示导入 / 同步结果，让市场知道哪些订单成功、哪些失败、失败原因是什么。
- 权限、操作日志、文件日志、配置和测试同步收口。

## 3. 非目标

- 本阶段不生成 QPO `order_rfq`。
- 本阶段不生成 QPO `item_quote_version`。
- 本阶段不把订单状态置为 `已报价`。
- 本阶段不进入 `议价提单` 候选零件。
- 本阶段不复制历史核价、材料、工艺、图纸或重量快照。
- 本阶段不对接 MES/WMS。
- 本阶段不实现 U9 销售订单修改、删除、提交、审核、关闭等接口。

## 4. 页面入口

### 4.1 入口位置

位置：市场分组 `新单导入` 页面内部。

页面结构建议：

- 顶部标题保持新单导入大模块。
- 在内容区新增模式切换：
  - `询价单`
  - `销售订单`
- 默认进入原 `询价单` 流程，避免影响现有 RFQ 导入。
- 选择 `销售订单` 后显示销售订单导入流程。

### 4.2 销售订单导入流程

建议页面步骤：

1. `步骤 1：客户与 U9 基础信息`
   - 客户选择复用现有客户选择能力。
   - 展示或选择 U9 客户编码、单据类型、业务员、部门、币种、税组合等默认配置。
2. `步骤 2：上传销售订单 Excel`
   - 上传一份销售订单 Excel。
   - 前端只做文件类型和必选校验，字段校验以后端为准。
3. `步骤 3：校验并同步 U9`
   - 用户点击 `导入并同步 U9`。
   - 后端解析、校验、调用 U9。
   - 前端展示批次结果。

本阶段不上传图纸。图纸属于后续 QPO 提单生产链路，不进入 U9 销售订单创建的第一步。

## 5. Excel 模板

### 5.1 推荐表头

为了让 QPO 能一次性构造 U9 `SO_Create` 请求，销售订单 Excel 建议分为订单头字段和订单行字段。第一版可以采用单 Sheet 扁平结构：每一行代表一个销售订单行，同一销售订单号的多行合并成一个 U9 销售订单。

必填表头：

| 表头 | 用途 | U9 字段 |
| --- | --- | --- |
| 客户编码 | U9 客户编码 | `OrderBy` |
| 单据类型编码 | U9 销售订单单据类型 | `DocumentType` |
| 客户订单号 | 外部订单号 / QPO 批次匹配 | `OtherID` 或扩展字段 |
| 业务日期 | 销售订单日期 | `BusinessDate` |
| U9料号 | U9 料号 | `SOLineDTOList[].ItemCode` |
| 客户料号 | 客户料号 | `SOLineDTOList[].CustomerItemNo` |
| 客户品名 | 客户品名 | `SOLineDTOList[].CustomerItemName` |
| 数量 | 销售数量 / 计划出货量 | `OrderByQtyTU`, `SOShiplineDTOList[].ShipPlanQtyTU` |
| 销售单位 | 销售单位编码 | `TU`, `SOShiplineDTOList[].TU` |
| 计价单位 | 计价单位编码 | `PU`, `SOShiplineDTOList[].PU` |
| 单价 | 手工定价 / 最终价 | `OrderPriceTC`, `FinallyPriceTC` |
| 交期 | 计划行交期 | `SOShiplineDTOList[].RequireDate` |

建议表头：

| 表头 | 用途 | U9 字段 |
| --- | --- | --- |
| 业务员编码 | U9 业务员 | `Seller` |
| 部门编码 | U9 销售部门 | `SaleDepartment` |
| 交易币编码 | 交易币 | `TC` |
| 核币编码 | 核币 | `AC` |
| 税组合编码 | 税组合 | `TaxSchedule` |
| 是否含税 | 价格是否含税 | `IsPriceIncludeTax` |
| 收货位置编码 | 订单头 / 行 / 计划行收货位置 | `ShipToSite` |
| 立账位置编码 | 立账位置 | `BillToSite` |
| 付款客户编码 | 付款客户 | `PayerCustomer` |
| 付款位置编码 | 付款位置 | `PayerToSite` |
| 项目编码 | U9 项目 | `Project` |
| 任务编码 | U9 任务 | `Task` |
| 存储地点编码 | 计划行存储地点 | `SOShiplineDTOList[].Wh` |
| 备注 | 备注 | `Memo` |

默认值口径：

- `FreeType`：默认 `-1`。
- `FreeReason`：默认 `-1`。
- `ShipTogetherFlag`：默认 `-1`。
- `PriceSource`：默认 `1`，即手工定价。
- 每个销售订单行默认生成一条计划行，计划行数量和交期来自同一 Excel 行。

### 5.2 字段来源原则

第一版不建议让市场每次手填所有 U9 编码。推荐三层来源：

1. Excel 明确提供，优先使用 Excel。
2. 客户默认配置提供，例如客户编码、币种、税组合、收货位置。
3. 系统默认值提供，例如 `FreeType=-1`、`ShipTogetherFlag=-1`、`PriceSource=1`。

如果必填字段三层来源都无法得到，则导入失败，不调用 U9。

## 6. U9 接口映射

### 6.1 调用方式

U9 通用调用流程：

1. 调用 U9 授权接口获取 token。
2. 调用 `POST /webapi/SO/Create`。
3. Header 携带 `token`。
4. Body 为销售订单 DTO 数组。
5. 解析 `ResCode` 和 `Data[]` 明细结果。

U9 token 获取接口参数：

- `userCode`
- `entcode`
- `orgcode`
- `clientid`
- `clientsecret`

这些值不允许写死在代码里，必须通过配置读取。

### 6.2 请求结构

订单头：

- `OtherID`：传 QPO 导入批次号或 `批次号-订单序号`，用于对应返回结果。
- `DocNo`：默认不传，由 U9 生成。
- `BusinessDate`：来自 Excel。
- `OrderBy`：客户编码。
- `DocumentType`：单据类型编码。
- `Seller`、`SaleDepartment`、`TC`、`AC`、`ShipToSite`、`BillToSite`、`PayerCustomer`、`PayerToSite`：来自 Excel 或客户默认配置。
- `IsPriceIncludeTax`：来自 Excel 或默认配置。
- `SOLineDTOList`：按销售订单行分组生成。

订单行：

- `CustomerItemNo`：客户料号。
- `CustomerItemName`：客户品名。
- `ItemCode`：U9 料号。
- `ItemVersion`：如 Excel 提供则传。
- `OrderByQtyTU`：销售数量。
- `OrderByQtyPU`：计价数量，默认等于销售数量。
- `TU`：销售单位编码。
- `PU`：计价单位编码。
- `TBUToPBURate`：换算率，默认 `1` 或来自配置。
- `OrderPriceTC`：定价。
- `FinallyPriceTC`：最终价。
- `TaxSchedule`：税组合编码。
- `PriceSource`：默认 `1`。
- `FreeType`：默认 `-1`。
- `FreeReason`：默认 `-1`。
- `ShipTogetherFlag`：默认 `-1`。
- `SOShiplineDTOList`：每行至少一条计划行。

计划行：

- `ItemCode`：同订单行 U9 料号。
- `RequireDate`：交期。
- `ShipPlanQtyTU`：计划出货量，默认等于订单行销售数量。
- `ShipPlanQtyPU`：计划出货计价数量，默认等于订单行计价数量。
- `TU` / `PU`：同订单行。
- `TUBaseToPUBaseRate`：默认 `1` 或来自配置。
- `ShipToSite`、`Wh`、`SupplyOrg`、`PlanOrg`：来自 Excel 或默认配置。

### 6.3 响应解析

不能只看 HTTP 200 或 `ResCode = 0`。

解析规则：

- `ResCode != 0`：整次接口调用失败。
- `ResCode = 0` 且 `Data[].m_isSucess = true`：该条销售订单创建成功。
- `ResCode = 0` 且 `Data[].m_isSucess = false`：该条销售订单创建失败，失败原因取 `m_errorMsg`。
- `m_otherID`：用于反查 QPO 导入批次或订单序号。
- `m_iD`：保存为 U9 业务 ID。
- `m_code`：保存为 U9 销售订单号候选字段，实际是否等同销售订单号需测试确认。
- `m_datas`：保存摘要，不记录过大内容。

## 7. 后端设计

### 7.1 新增配置

在 `application.yaml` 增加 U9 配置，值从 `erp.env` 读取：

```yaml
erp:
  u9:
    base-url: ${ERP_U9_BASE_URL:}
    user-code: ${ERP_U9_USER_CODE:}
    ent-code: ${ERP_U9_ENT_CODE:}
    org-code: ${ERP_U9_ORG_CODE:}
    client-id: ${ERP_U9_CLIENT_ID:}
```

### 7.5 事务边界

推荐口径：

- Excel 解析失败：不调用 U9，保存失败批次或直接返回校验错误。
- U9 调用前校验失败：不调用 U9。
- U9 调用成功但部分业务失败：保存 `PARTIAL_SUCCESS`，逐条展示失败原因。
- U9 调用异常：保存 `FAILED`，返回异常摘要。
- 本阶段不创建 QPO 业务订单，所以不涉及 QPO 订单回滚。

## 13. 风险与待确认

1. U9 `m_code` 是否一定是销售订单号，需要实测确认。
2. QPO 客户和 U9 `OrderBy` 客户编码是否已有映射，需要确认。
3. QPO 图号 / 版本与 U9 `ItemCode` / `ItemVersion` 是否一致，需要确认。
4. 税组合、币种、单位、收货位置、业务员、部门是否由 Excel 提供，还是做客户默认配置，需要确认。
5. U9 token 过期、重试和并发调用频率需要确认。
6. 是否需要 dry-run 预览作为正式功能开关，需要确认。
7. 是否允许同一个客户订单号重复导入，需要确认；第一版建议不拦截，只记录批次，但提示可能重复。

## 14. 推荐口径

本阶段推荐采用：

> `新单导入` 下新增 `销售订单` 面板，独立权限控制，Excel 导入后先只同步 U9 并保存同步结果；不创建 QPO 提单订单，不进入议价提单。等 U9 同步入口稳定后，再做第二步“销售订单转 QPO 可提单订单”。

这样做的好处：

- U9 对接风险先单独消化。
- 不把 U9 同步失败和 QPO 提单准入混在一起。
- 后续第二步可以基于已保存的销售订单同步结果继续扩展。
- 对现有 RFQ 导入、核价、报价、议价提单主流程影响最小。
