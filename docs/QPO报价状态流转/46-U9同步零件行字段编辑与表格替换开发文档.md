# 46-U9同步零件行字段编辑与表格替换开发文档

最后更新：2026-08-17

文档状态：待开发

## 1. 背景与最终口径

当前 **U9同步** 模块已经完成销售订单选择、U9 Seller / SaleDepartment 保存、同步预览、提交 U9、结果核对和同步状态回写。现有 U9 创建请求已经收敛为最小已验证契约：销售订单行使用 `sales_order_item.material_no` 作为 U9 `ItemCode`，使用 `sales_order_item.qty` 作为订单行和计划行数量，使用 `sales_order_item.untaxed_unit_price` 作为 U9 未税单价，并把客户项目号、客户订单号、内部项目号、客户交期、内部交期、未税单价和备注写入 U9 销售订单行私有字段。

本次优化的业务目标不是调整 U9 接口契约，而是在同步前让业务人员在 **U9同步页面** 直接整理将要发给 U9 的零件行数据，避免回到销售订单导入源文件或其他页面反复改数。

最终确认口径：

1. U9 同步不向 U9 传图纸，也不维护 U9 物料档案图号 / 版本 / 图纸字段。
2. U9 同步页面 **不做“导入替换图纸”功能**。
3. U9 同步页面只新增两类能力：
   - 零件行指定字段可编辑并保存。
   - 通过 Excel 做表格数据替换，逻辑参考议价提单，但只作用于当前销售订单零件行。
4. 本次只允许维护以下 `sales_order_item` 字段：
   - `qty`
   - `customerDeliveryDate`
   - `internalDeliveryDate`
   - `untaxedUnitPrice`
   - `customerOrderNo`
   - `customerProjectNo`
   - `internalProjectNo`
   - `remark`
5. 不允许在 U9 同步页面修改 `saleOrderNo`、`documentNo`、`lineNo`、`partNo`、`version`、`materialNo`、`materialNoStatus`、客户、Seller、SaleDepartment 以外的字段。
6. 保存或表格替换只改 QPO 本地销售订单零件数据，不触发 MES、WMS、U9，也不自动修改销售订单主流程状态。

## 3. 范围与非范围

### 3.1 本次范围

1. 在 U9 同步页面的“销售订单零件”区域支持行内编辑和批量保存。
2. 支持通过 Excel 对当前销售订单零件行做表格数据替换，先预览差异，确认后统一保存。
3. 后端新增针对销售订单 U9 同步场景的保存服务、Excel 解析服务、预览 DTO 和确认 DTO。
4. 保存后刷新 U9 同步预览，使页面显示值、后端预览值和即将发送给 U9 的值保持一致。
5. 后端保留最终权限边界、状态边界、数据范围边界和操作日志。
6. 更新权限、日志和 U9 同步相关文档口径。

## 4. 行内编辑设计

### 4.1 可编辑字段

| 前端字段 | 后端 DTO 字段 | 数据库字段 | 类型 | 保存规则 |
| --- | --- | --- | --- | --- |
| 数量 | `qty` | `qty` | integer | 必须为正整数；不得小于已提数量或已出货数量。 |
| 客户交期 | `customerDeliveryDate` | `customer_delivery_date` | date | 允许为空；格式 `yyyy-MM-dd`。 |
| 内部交期 | `internalDeliveryDate` | `internal_delivery_date` | date | 允许为空；格式 `yyyy-MM-dd`。 |
| U9未税单价 | `untaxedUnitPrice` | `untaxed_unit_price` | decimal | 必须大于等于 0；不允许科学计数法落库。 |
| 客户订单号 | `customerOrderNo` | `customer_order_no` | string | 最长 120；允许清空。 |
| 客户项目号 | `customerProjectNo` | `customer_project_no` | string | 最长 120；允许清空。 |
| 内部项目号 | `internalProjectNo` | `internal_project_no` | string | 最长 120；允许清空。 |
| 备注 | `remark` | `remark` | string | 最长 500；允许清空。 |

### 4.2 清空与空值规则

行内保存使用 PATCH 语义：

- 字段未出现在请求中：不修改该字段。
- 文本字段出现在请求中且值为 `""` 或 `null`：清空该字段。
- 日期字段出现在请求中且值为 `null`：清空该字段。
- `qty` 和 `untaxedUnitPrice` 出现在请求中时必须是合法非空值；不能通过行内保存清空。

Excel 表格替换不承担清空能力：Excel 单元格为空时一律表示“不覆盖现有值”。如果业务需要清空文本或日期字段，使用行内编辑保存。

### 4.3 数量和金额联动

修改 `qty` 或 `untaxedUnitPrice` 后，后端必须维护同一行的派生金额和剩余数量：

1. `untaxed_total_price = qty * untaxed_unit_price`，当两者均非空时更新。
2. `tax_included_total_price = qty * tax_included_unit_price`，仅当原行已有 `tax_included_unit_price` 时按原含税单价重算；不得根据未税价推导含税价。
3. `remaining_qty = qty - released_qty`，`released_qty` 为空按 0 处理；结果不得小于 0。
4. `unshipped_qty = qty - shipped_qty`，`shipped_qty` 为空按 0 处理；结果不得小于 0。
5. 若新 `qty < released_qty` 或新 `qty < shipped_qty`，保存失败并提示具体行号。

## 5. 后端接口契约

### 5.1 行内批量保存接口

```http
PUT /api/market/u9-sync/orders/{salesOrderId}/items
Content-Type: application/json
Permission: market:u9-sync:submit
```

请求体：

```json
{
  "items": [
    {
      "salesOrderItemId": 251,
      "qty": 2,
      "customerDeliveryDate": "2026-09-30",
      "internalDeliveryDate": "2026-09-25",
      "untaxedUnitPrice": "1344.47",
      "customerOrderNo": "PO-001",
      "customerProjectNo": "CUS-PROJ-001",
      "internalProjectNo": "QPO-PROJ-001",
      "remark": "U9同步前备注"
    }
  ]
}
```

响应体：

```json
{
  "success": true,
  "message": "已保存 1 行零件数据。",
  "salesOrderId": 176,
  "salesOrderNo": "SO-20260817-001",
  "updatedCount": 1,
  "changedFields": ["qty", "customerDeliveryDate", "untaxedUnitPrice"],
  "preview": {
    "salesOrderId": 176,
    "salesOrderNo": "SO-20260817-001",
    "u9SyncStatus": "未同步",
    "lines": []
  }
```

- `preview` 建议直接复用 `SalesOrderU9SyncPreviewResp`，保存成功后前端无需再额外请求一次预览。

- 请求中的 `salesOrderItemId` 必须属于路径上的 `salesOrderId`，否则返回 `400`。

## 6. Excel 表格替换契约

### 6.1 表头

| Excel 表头 | 是否必需 | 目标字段 | 说明 |
| --- | --- | --- | --- |
| `图号` | 是 | 匹配 `sales_order_item.part_no` | 整体作为图号文本，不解析 `-说明`、`_版本-说明` 等旧命名格式。 |
| `版本` | 是 | 匹配 `sales_order_item.version` | 空版本允许匹配空版本，但表头必须存在。 |
| `行号` | 否 | 辅助匹配 `sales_order_item.line_no` | 当前订单内 `图号 + 版本` 不唯一时必须提供。 |
| `数量` / `qty` | 否 | `qty` | 正整数。 |
| `客户交期` | 否 | `customer_delivery_date` | 支持 Excel 日期和常见日期文本。 |
| `内部交期` | 否 | `internal_delivery_date` | 支持 Excel 日期和常见日期文本。 |
| `未税单价` | 否 | `untaxed_unit_price` | 大于等于 0 的 decimal。 |
| `客户订单号` / `客户采购订单号` | 否 | `customer_order_no` | 文本，最长 120。 |
| `客户项目号` | 否 | `customer_project_no` | 文本，最长 120。 |
| `内部项目号` | 否 | `internal_project_no` | 文本，最长 120。 |
| `备注` | 否 | `remark` | 文本，最长 500。 |

至少需要存在一个可替换业务字段，否则预览接口返回 `400`。

### 6.2 图号解析硬规则

图号列必须按用户填写的完整单元格文本处理：

- `LK17.5.1.1-1` 是完整图号，不得被拆成 `LK17.5.1.1` + 说明 `1`。
- `图号-说明` 这种旧格式不再被 U9 同步表格替换支持。
- `图号_版本-说明` 这种旧格式不再被 U9 同步表格替换支持。
- 如 Excel 需要传版本，必须放在独立 `版本` 列。
- 如 Excel 需要说明，U9 同步表格替换不接收说明列；后续如确有需求另行评估字段归属。

### 6.3 匹配规则

1. 匹配范围只限路径上的当前 `salesOrderId`。
2. 默认使用规范化后的 `图号 + 版本` 匹配。
3. 如果当前销售订单内存在多个相同 `图号 + 版本`，Excel 必须提供 `行号` 才能精确匹配；否则该行进入 `ERROR`。
4. 如果 Excel 提供 `行号`，必须同时校验 `行号 + 图号 + 版本` 与目标零件行一致，避免误改。
5. Excel 内重复 `图号 + 版本 + 行号` 的有效业务行整批拒绝确认。
6. 未匹配行进入 `UNMATCHED`，不阻断其他匹配行确认。
7. 空单元格不覆盖现有值。

### 6.4 行状态

| 状态 | 含义 | 是否阻断确认 |
| --- | --- | --- |
| `CHANGED` | 匹配成功且至少一个字段将变化。 | 否 |
| `UNCHANGED` | 匹配成功但导入值与现有值一致。 | 否 |
| `UNMATCHED` | 当前销售订单内没有匹配行。 | 否 |
| `SKIPPED` | 匹配行当前不可编辑，例如 U9 已同步。 | 否 |
| `ERROR` | 表头、字段值、重复键、数量或状态存在错误。 | 是 |

只要存在 `ERROR`，`canConfirm=false`。如果没有任何 `CHANGED` 行，`canConfirm=false`。

   - `已同步`
   - `同步中`
   - `结果待确认`
5. `同步失败`、`未同步` 等可重新整理数据的状态允许编辑，但保存不自动触发同步。
6. 保存过程中使用行锁锁定订单头和本次涉及零件行，避免与 U9 提交并发。

### 7.3 指纹规则

表格替换预览指纹至少包含以下内容：

```text
salesOrderId
excelFileSha256
recognizedFields
matched salesOrderItemId list
each matched item updatedAt
each changed field before/after normalized value
```

确认时重新解析和重新预览后计算指纹，必须与请求 `previewFingerprint` 完全一致才允许保存。

### 7.4 操作日志与文件日志

新增两个操作日志动作：

| action | module | targetType | 触发时机 |
| --- | --- | --- | --- |
| `SALES_ORDER_U9_ITEM_UPDATE` | `MARKET` | `sales_order_header` | 行内保存成功或失败。 |
| `SALES_ORDER_U9_ITEM_DATA_REPLACEMENT` | `MARKET` | `sales_order_header` | 表格替换确认成功或失败。 |

日志摘要只允许记录：

- `salesOrderId`
- `salesOrderNo`
- `updatedCount`
- `changedFields`
- `errorCount`
- `durationMs`
- 失败摘要

日志禁止记录：

- Excel 原始内容或完整解析行。
- U9 完整请求体或响应体。
- token、Authorization header、Cookie、client secret。
- 价格明细值列表、图纸 URL、材料 JSON、工艺路线 JSON、费用 JSON。

## 9. 业务一致性说明

### 9.1 与 U9 同步链路的关系

保存和表格替换完成后，U9 同步继续按现有链路执行：

```text
U9同步页面整理销售订单零件行
    -> 保存 QPO sales_order_item
    -> 刷新 U9 预览
    -> 用户点击同步U9
    -> U9SalesOrderRequestAssembler 使用最新 sales_order_item 值组装请求
    -> 数据中心 / U9 创建销售订单
    -> QPO 回写 U9 状态
```

本次不增加任何绕过预览直接发 U9 的路径。

### 9.2 与 MES 物料号链路的关系

`materialNo` 和 `materialNoStatus` 仍由 MES 物料号获取 / 回写链路维护。本次页面不允许人工改物料号，避免破坏 MES、销售订单主表和 U9 的物料身份一致性。

如果某零件尚未取得已确认物料号，U9 预览仍按现有规则阻断同步；用户可以编辑本次允许的业务字段，但不能通过编辑绕过物料号校验。

### 9.3 与图纸链路的关系

U9 销售订单创建不接收 QPO 图纸文件，也不写 U9 物料档案图号 / 版本 / 图纸字段。因此：

- U9 同步页面不新增图纸上传入口。
- U9 同步表格替换不支持图纸替换。
- 图纸替换仍归属于询价订单、议价提单或销售订单图纸补传等既有图纸链路。

## 10. 阶段开发计划

### 阶段 1：后端行内保存基础

目标：建立 U9 同步前零件行可编辑字段的后端保存能力。

修改范围：

- 新增 `SalesOrderU9ItemUpdateReq`、`SalesOrderU9ItemUpdateLineReq`、`SalesOrderU9ItemUpdateResp`。
- 新增 `SalesOrderU9ItemEditService`。
- 在 `SalesOrderU9SyncController` 新增 `PUT /api/market/u9-sync/orders/{salesOrderId}/items`。
- 复用 `market:u9-sync:submit` 权限。
- 增加数量、金额、日期、文本长度、所属订单和 U9 状态校验。

## 11. 总体验收清单

- U9 同步页面能在同步前编辑并保存 `qty`、`customerDeliveryDate`、`internalDeliveryDate`、`untaxedUnitPrice`、`customerOrderNo`、`customerProjectNo`、`internalProjectNo`、`remark`。

- 同步 U9 时继续使用现有最小已验证 U9 契约，并消费保存后的最新零件行字段。
- 权限继续复用 `market:u9-sync:submit`，不新增菜单或 `common:*` 权限。
- 日志只记录安全摘要，不记录敏感字段、完整请求 / 响应或 Excel 原文。
