# QPO 首页看板模块需求文档

最后更新：2026-08-04

> 文档性质：需求文档。本文只定义首页看板要解决什么问题、展示什么信息、交互应达到什么效果，不包含接口设计、表结构设计、开发阶段拆分或具体实现方案。后续确认需求后，再单独输出开发文档。

## 1. 背景

QPO 当前已经形成询价订单、销售订单、销售匹配、议价提单、已提零件、锁库零件、U9 同步、MES / WMS / 数据中心对接等主链路能力。随着模块增多，用户登录后需要一个统一入口，快速判断当前业务积压在哪里、哪些客户订单需要推进、哪些外部系统动作失败或等待处理。

首页看板的定位不是做复杂 BI，也不是替代各业务模块工作台，而是作为登录后的第一屏，帮助用户用最少点击进入下一步业务处理。

## 2. 需求目标

- 登录后默认进入 `首页看板`，左侧栏顶部显示 `首页看板` 入口。
- 清晰展示询价订单和销售订单两条主链路当前的关键状态。
- 用图表展示订单分布，用表格展示客户维度的状态组合。
- 提供快捷入口，点击后直接进入对应业务模块处理。
- 展示最近需要关注的异常或等待项，避免 MES / WMS / U9 问题被埋在各模块列表里。
- 所有统计结果必须遵循当前登录用户的功能权限和数据权限范围。
- 首页只读，不承载废弃、恢复、同步、下发等写操作。

## 3. 使用对象

| 用户类型 | 主要关注点 |
| --- | --- |
| 管理者 | 看整体订单状态、客户分布、瓶颈和异常数量。 |
| 市场人员 | 看待报价、可提单、销售订单待处理和 U9 同步情况。 |
| 工程人员 | 看未核价询价订单、待核价积压和材料 / 工艺相关后续入口。 |
| 只读或客户范围账号 | 只能看自己权限和数据范围内的统计，不看到无权限模块入口。 |

## 4. 模块位置与入口

- 首页看板应位于左侧栏最顶部，优先于市场、工程、订单、系统等业务分组。
- 用户登录成功或访问系统根路径时，默认进入首页看板。
- 首页看板名称统一为 `首页看板`，不使用 `Dashboard`、`首页`、`数据大屏` 等混合文案。
- 首页看板的快捷入口只做跳转和筛选带入，不直接执行任何业务写入。
- 首页看板应保持 QPO 当前企业后台风格：信息密度高、层级清晰、控件克制，不做营销型大屏或装饰型大图。

## 5. 总体统计口径

### 5.1 权限和数据范围

- 看板统计只包含当前用户有权访问的数据。
- 没有某个业务模块权限时，不显示该模块对应的快捷入口和异常入口。
- 没有某个客户数据权限时，该客户的数据不进入任何图表、表格或待办数量。
- 无数据权限时展示空状态，不用报错，也不能泄露全局数量。

### 5.2 订单数量口径

- 订单统计以订单主表的一条订单为一条数量，不按零件行数量重复计算。
- 询价订单和销售订单分开统计，不互相混用。
- 客户维度展示优先使用客户简称；没有客户简称时使用客户名称；必要时辅助展示客户编码。
- 客户缺失或无法匹配时，归入 `未识别客户`，但仍受数据权限约束。

### 5.3 主图表状态范围

首页主图表只展示以下关键状态：

- `未核价`
- `已核价`
- `已报价`

以下状态不进入首页主图表的订单分布统计：

- `部分已提单`
- `已生成提单`
- `废弃`

说明：`部分已提单` 和 `已生成提单` 属于提单后链路，不作为首页订单主分布展示。第一版首页不单独展示这两类状态的订单数量；如后续需要提单后流程专题看板，应另行确认需求。

## 6. 页面信息架构

首页看板第一版建议由五个区域组成：

1. 顶部概览区：展示当前用户权限范围内的关键待办总量和更新时间。
2. 双图表区：左侧询价订单状态分布，右侧销售订单客户分布。
3. 客户状态交叉表：按客户展示询价订单三状态和销售订单已报价数量。
4. 待办快捷卡片：按业务下一步动作聚合数量，并可点击进入对应模块。
5. 最近异常 / 关注项：展示 MES、WMS、U9、生产下发相关失败或等待状态。

移动端或窄屏下，区域应自然上下排列；桌面端优先保证图表和表格的可读性。

## 7. 图表需求

### 7.1 询价订单状态分布饼图

| 项目 | 需求 |
| --- | --- |
| 图表名称 | `询价订单状态分布` |
| 统计对象 | 询价订单 |
| 分类维度 | 订单状态 |
| 展示状态 | `未核价`、`已核价`、`已报价` |
| 不展示状态 | `部分已提单`、`已生成提单`、`废弃` |
| 展示内容 | 数量、占比、图例 |
| 点击行为 | 点击某状态后进入对应询价链路模块，并带入状态筛选 |

状态含义：

- `未核价`：主要指向工程核价工作。
- `已核价`：主要指向报价处理工作。
- `已报价`：主要指向议价提单工作。

### 7.2 销售订单客户分布饼图

| 项目 | 需求 |
| --- | --- |
| 图表名称 | `销售订单已报价客户分布` |
| 统计对象 | 销售订单 |
| 过滤状态 | 只统计 `已报价` |
| 分类维度 | 客户 |
| 展示内容 | 客户数量、占比、图例 |
| 点击行为 | 点击某客户后进入销售订单模块，并带入客户和 `已报价` 筛选 |

说明：

- 销售订单饼图不按 `未核价 / 已核价 / 已报价` 分类，因为销售订单导入后核心关注点是观察哪些客户仍有已报价销售订单停留，需要查看导入、物料号、U9 或异常治理状态。
- 当客户数量较多时，首页只需要展示主要客户分布，长尾客户可合并为 `其他客户`，具体明细在客户状态交叉表或销售订单模块查看。

## 8. 客户状态交叉表需求

客户状态交叉表用于回答：“每个客户在询价主链路和销售订单主链路分别积压在哪里？”

### 8.1 表格字段

| 字段 | 说明 |
| --- | --- |
| 客户 | 客户简称 / 客户名称，必要时辅助客户编码。 |
| 询价未核价 | 该客户 `未核价` 询价订单数量。 |
| 询价已核价 | 该客户 `已核价` 询价订单数量。 |
| 询价已报价 | 该客户 `已报价` 询价订单数量。 |
| 销售已报价 | 该客户 `已报价` 销售订单数量。 |
| 关注合计 | 上述四项合计，用于排序和识别重点客户。 |

### 8.2 表格行为

- 默认按 `关注合计` 从高到低排序。
- 每个数字应可点击，进入对应模块并带入客户和状态筛选。
- 数量为 0 的单元格弱化展示，避免视觉噪声。
- 客户很多时，首页展示前若干重点客户，并提供进入明细模块的入口。
- 表格不展示 `部分已提单`、`已生成提单`、`废弃` 数量。

## 9. 待办快捷卡片需求

待办快捷卡片用于把“下一步该去哪里处理”直接放在首页。

| 待办卡片 | 统计口径 | 目标模块 |
| --- | --- | --- |
| 待核价询价订单 | 询价订单 `未核价` | 零件核价 / 工程核价入口 |
| 待报价询价订单 | 询价订单 `已核价` | 报价处理 |
| 可提单询价订单 | 询价订单 `已报价` | 议价提单 |
| 可提单销售订单 | 销售订单 `已报价` | 议价提单 |
| 待物料号已提零件 | 已提零件未完成池中缺物料号或待获取物料号的行 | 已提零件 |
| 待锁库已提零件 | 已提零件未完成池中物料号已具备、库存未完成的行 | 已提零件 |
| 待下发 MES 生产 | 待产零件中需要生产且未成功下发 MES 的行 | 待产零件 |
| 待同步 U9 销售订单 | 满足或接近满足 U9 同步条件的销售订单 | U9 同步 |

要求：

- 卡片只展示当前用户有权限进入的模块。
- 点击卡片进入目标模块，并尽量带入业务筛选条件。
- 卡片不提供直接执行按钮，避免首页误触发批量同步、下发或状态变更。
- 数量为 0 时可以弱化展示，但不应造成页面空洞。
- `可提单销售订单` 第一版只统计 `已报价` 销售订单，不把 `部分已提单` 订单作为首页数量展示。

## 10. 最近异常 / 关注项需求

该区域用于集中提醒跨系统链路中的失败、等待和需要人工关注的情况。

| 关注项 | 说明 | 目标模块 |
| --- | --- | --- |
| MES 物料号失败 | 获取物料号失败，需要重试或排查。 | 已提零件 |
| 待 MES 回调 | MES 已接收请求，但物料号等待回调。 | 已提零件 |
| WMS 锁库失败 | 获取库存或锁库分配失败，需要重试或排查。 | 已提零件 |
| U9 同步失败 | 销售订单整单同步 U9 失败，可重试。 | U9 同步 |
| MES 生产下发失败 | 待产零件下发 MES 生产失败。 | 待产零件 |

要求：

- 每个关注项展示当前数量和简短说明。
- 有异常时视觉上需要比普通待办更明显，但不能使用刺眼的大面积红色。
- 点击后进入对应模块，并带入失败或等待状态筛选。
- 不展示 token、完整请求体、接口密钥或外部系统敏感响应内容。
- `待 MES 回调` 不属于失败，但属于需要持续关注的等待状态。

## 11. 快捷入口和跳转联动

首页看板的所有图表、表格数字和快捷卡片都应尽量支持跳转联动：

| 来源 | 点击后行为 |
| --- | --- |
| 询价订单状态饼图 | 进入询价订单 / 工程核价 / 报价处理 / 议价提单相关模块，并带入状态。 |
| 销售订单客户饼图 | 进入销售订单或议价提单入口，并带入客户和 `已报价`。 |
| 客户状态交叉表数字 | 进入对应订单模块，并带入客户和状态。 |
| 待办快捷卡片 | 进入最适合处理该待办的模块，并带入默认筛选。 |
| 异常关注项 | 进入对应模块，并带入失败、待回调或待处理筛选。 |

跳转要求：

- 用户无目标模块权限时，不展示该入口。
- 如果目标模块需要二次选择订单，首页只负责带入可用筛选条件，不绕过目标模块自身权限和业务校验。
- 返回首页后，应保留首页最近一次加载状态或重新加载最新统计，不能出现明显空白闪烁。

## 12. 刷新和时效需求

- 首页进入时自动加载当前统计。
- 页面应展示 `数据更新时间`。
- 用户可以手动刷新看板。
- 第一版不要求 WebSocket 或实时推送。
- 统计允许存在短时间缓存，但用户手动刷新后应尽量看到最新数据库结果。
- 外部系统相关失败和待回调数量应以业务库当前状态为准，不直接实时调用 MES / WMS / U9 / 数据中心。

## 13. 性能需求

- 首页统计必须由后端聚合返回，前端不得为了统计而全量拉取订单、零件或锁库列表。
- 客户交叉表和图表应返回首页需要的聚合结果，不把大订单明细塞进首页。
- 首页首屏应优先加载关键统计，异常明细和长列表可延后或按需跳转到业务模块。
- 大客户、大订单、多零件场景下，首页不能造成明显卡顿或长时间白屏。
- 图表和表格应保留稳定高度，加载时使用统一的加载态或骨架态，避免页面跳动。

## 14. 权限、日志与审计需求

### 14.1 权限

- 首页看板作为登录默认页，应对所有可登录用户可见；如实现为权限点，应默认分配给所有有效业务角色。
- 首页中每个快捷入口、异常入口和可点击跳转都必须按目标模块权限过滤。
- 数据统计必须接入当前系统的数据权限，尤其是客户范围权限。
- 前端隐藏入口只是体验要求，后端统计接口仍需保证数据权限不泄露。

### 14.2 日志

- 首页普通读取、刷新、图表点击不需要写操作日志，避免制造噪声。
- 首页不能记录敏感接口 token、Authorization header、外部系统密钥或完整请求体。
- 如果后续首页新增导出、配置或管理动作，再按对应写操作补充操作日志；第一版不包含这些动作。

## 15. 前端体验需求

- 首页看板视觉应与现有 QPO 页面一致，采用企业后台工作台风格。
- 主内容应先展示最重要的业务判断：订单状态、客户分布、待办、异常。
- 图表不能只靠颜色表达含义，必须有图例、标签或 tooltip。
- 数字、状态和按钮文字要使用中文业务词，不混用英文状态码。
- 小屏下布局自然换行，不出现横向滚动或按钮挤压文字。
- 空状态要清楚说明“当前权限范围内暂无数据”，不要显示技术错误。
- 异常关注项要有可恢复方向，例如进入对应模块重试或查看详情。

## 16. 非目标

第一版首页看板不做以下内容：

- 不做复杂 BI 报表、趋势预测、同比环比分析。
- 不展示 `部分已提单`、`已生成提单`、`废弃` 的主图表分布。
- 不在首页展示完整订单明细、完整零件明细或完整外部接口响应。
- 不在首页直接执行 U9 同步、MES 获取物料号、WMS 锁库或 MES 生产下发。
- 不新增外部系统配置入口；外部系统配置仍在系统配置模块。
- 不展示 token、密钥、完整请求 JSON 或敏感日志。
- 不替代询价订单、销售订单、已提零件、锁库零件、U9 同步等现有模块。

## 17. 验收标准

### 17.1 入口验收

- 登录后默认进入首页看板。
- 左侧栏顶部显示 `首页看板`。
- 原市场、工程、订单、系统模块入口不回退。
- 没有目标模块权限时，首页不展示对应快捷入口。

### 17.2 图表验收

- 询价订单饼图只展示 `未核价`、`已核价`、`已报价`。
- 销售订单饼图只统计 `已报价` 销售订单，并按客户分布展示。
- `部分已提单`、`已生成提单`、`废弃` 不出现在首页主图表分布中。
- 图表为空时有清晰空状态。

### 17.3 客户交叉表验收

- 表格能按客户展示 `询价未核价 / 询价已核价 / 询价已报价 / 销售已报价`。
- 表格不展示 `部分已提单 / 已生成提单 / 废弃` 数量。
- 点击表格数字能进入对应模块并带入客户和状态。
- 数据权限范围外客户不出现在表格中。

### 17.4 待办和异常验收

- 首页展示待核价、待报价、可提单、待物料号、待锁库、待下发 MES 生产、待同步 U9 等快捷待办。
- MES 失败、待 MES 回调、WMS 失败、U9 同步失败、MES 生产下发失败能集中展示。
- 点击待办或异常能进入对应模块并带入筛选。
- 首页不直接执行任何写操作。

### 17.5 性能和安全验收

- 首页统计不通过前端全量拉取业务列表实现。
- 大订单和多零件场景下首页仍能快速加载。
- 首页统计遵循功能权限和客户数据权限。
- 首页不暴露 token、密钥、Authorization header、完整接口请求体或外部系统敏感响应。

## 18. 后续待确认事项

以下事项进入后续开发文档阶段再确认，不影响当前需求口径：

- 首页看板权限点是否单独命名，或作为所有登录用户默认基础入口处理。
- 客户较多时饼图展示 Top N 的具体数量。
- 首页缓存时间和手动刷新后的强制刷新策略。
- 快捷入口跳转到目标模块时，各模块最终支持哪些 URL 查询参数或状态恢复方式。
- 首页第一版是否需要导出截图或导出统计表；当前需求默认不需要。

## 19. 真实接口接入口径

首页看板第一版真实数据统一由后端只读聚合接口提供：

```http
GET /api/dashboard/overview
```

接口口径：

- RFQ 饼图只统计 `未核价 / 已核价 / 已报价`，不统计提单后状态。
- 销售订单饼图只统计 `已报价`，并按客户维度分类展示。
- 客户交叉表不展示 `部分已提单 / 已生成提单 / 废弃`，只展示询价三状态和销售已报价数量。
