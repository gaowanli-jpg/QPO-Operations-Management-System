# QPO 首页看板后端聚合接口接入开发文档

最后更新：2026-08-04

> 本文承接 `28-首页看板模块需求文档.md` 和 `29-首页看板前端原型开发文档.md`。当前首页看板前端原型已经完成，页面、图表、客户交叉表、待办卡片、异常关注项、权限跳转和 mock 数据结构已稳定。本阶段目标是接入真实后端聚合接口，替换 mock 数据，同时保持首页只读、轻量、可快速加载。

## 1. 背景和目标

首页看板当前使用 `dashboardMockData.js` 渲染，已经验证了页面信息架构和视觉方向。接下来需要由后端提供统一聚合接口，让首页展示当前登录用户权限范围内的真实业务统计。

本阶段目标：

- 新增统一后端聚合接口 `GET /api/dashboard/overview`。
- 后端一次性返回首页需要的全部聚合数据，不让前端拉取订单、零件或锁库明细再本地统计。
- 聚合结果遵循当前用户功能权限和数据权限，尤其是客户范围权限。
- 前端用真实接口替换 mock 数据，保留 mock 数据作为测试 fixture / 开发兜底，不作为生产静默兜底。
- 首页仍为只读页面，刷新、图表点击、卡片点击都只做读取或跳转，不触发 MES / WMS / U9 / 数据中心写操作。
- 不新增外部系统调用，不新增业务写入，不记录普通首页读取操作日志。

## 4. 后端接口设计

### 4.1 接口

```http
GET /api/dashboard/overview
```

### 4.2 权限边界

第一版首页看板作为登录默认页处理：

- `/dashboard` 前端路由不新增业务模块权限。
- `GET /api/dashboard/overview` 不新增独立可分配菜单权限，保持“已登录用户可访问”。
- 后端仍必须按当前用户的数据权限过滤所有统计。
- 后端对不同业务域的统计应按目标模块权限进行裁剪：
  - 用户没有 RFQ / 工程 / 报价 / 提单相关权限时，不返回 RFQ 相关图表和待办数量。
  - 用户没有销售订单 / 销售匹配 / U9 同步相关权限时，不返回销售订单相关图表和待办数量。
  - 用户没有已提零件权限时，不返回 MES / WMS 已提零件相关待办和异常数量。
  - 用户没有锁库零件权限时，不返回锁库待生产和 MES 生产下发异常数量。
- 前端仍继续按每个卡片的 `permission` 字段隐藏无权限入口，后端权限裁剪是最终防泄露边界。

如后续需要把首页看板作为独立权限点，可另行新增 `dashboard:view` 并默认分配给所有有效业务角色；本阶段不新增。

### 4.4 空数据规则

- 当前用户没有数据权限时，返回空数组和 0 值，不抛出业务错误。
- 当前用户有权限但暂无数据时，返回空数组和 0 值，由前端展示空状态。
- 后端不得因为某一块统计为空而省略顶层字段。
- 字段为空时使用 `null` 或空字符串，但数组字段必须返回空数组。

## 5. 统计口径

### 5.1 RFQ 询价订单状态分布

| 项目 | 口径 |
| --- | --- |
| 数据表 | `order_rfq` |
| 状态范围 | 仅 `未核价 / 已核价 / 已报价` |
| 排除状态 | `部分已提单 / 已生成提单 / 废弃` 不进入主图表 |
| 数量单位 | 订单数，一张 RFQ 订单算 1 条 |
| 数据权限 | `DataScopeService` 当前订单数据权限 |
| 权限裁剪 | 有 RFQ / 工程 / 报价 / 提单相关查看权限才返回 |

固定返回顺序：

1. `未核价`
2. `已核价`
3. `已报价`

即使某个状态数量为 0，也可以返回该状态，前端弱化显示；如果用户完全没有 RFQ 权限，则返回空数组。

### 5.2 销售订单已报价客户分布

| 项目 | 口径 |
| --- | --- |
| 数据表 | `sales_order_header` |
| 状态范围 | 仅 `已报价` |
| 分类维度 | 客户 |
| 数量单位 | 销售订单数，一张销售订单算 1 条 |
| 数据权限 | `DataScopeService` 当前销售订单数据权限 |
| 权限裁剪 | 有销售订单 / 销售匹配 / 提单 / U9 同步相关查看权限才返回 |

客户显示规则：

1. 优先使用 `customer_short_name`。
2. 没有简称时使用 `customer_name`。
3. 有 `customer_id` 时返回 `customerId`。
4. 没有客户信息时归入 `未识别客户`，但仍必须受数据权限约束。

图表第一版展示 Top 8 客户，其余合并为 `其他客户`；客户交叉表保留 Top 20 客户。

### 5.3 客户状态交叉表

## 8. 后端实现细节

### 8.1 DTO 约定

所有 DTO 使用 Lombok `@Data`，字段名直接对齐前端 mock 数据。

`DashboardOverviewDTO`：

- `updatedAt`
- `summaryCards`
- `rfqStatusDistribution`
- `salesQuotedCustomerDistribution`
- `customerMatrix`
- `todoCards`
- `attentionItems`

`DashboardChartItemDTO` 必须支持：

- `name`
- `value`
- `customerId`
- `customerCode`
- `customerName`
- `customerShortName`
- `targetPath`
- `query`

其中 `query` 使用 `Map<String, Object>`，便于不同卡片带不同筛选参数。

### 8.2 数据权限适配

`DataScopeService` 当前已有：

- `applyOrderScope(QueryWrapper<OrderRfq> query)`
- `applySalesOrderScope(QueryWrapper<SalesOrderHeader> query)`
- `applyDeliveryTicketScope(QueryWrapper<?> query, String ticketAlias)`

聚合 SQL 需要在带别名的 SQL 中使用数据权限，因此建议新增：

```java
public void applyOrderScope(QueryWrapper<?> query, String alias)
public void applySalesOrderScope(QueryWrapper<?> query, String alias)
```

实现上复用现有 private `currentOrderScopeSql(alias)`，不复制权限逻辑。

已提零件和锁库零件继续复用：

```java
dataScopeService.applyDeliveryTicketScope(query, "ticket")
```

### 8.3 功能权限裁剪

`DashboardOverviewService` 需要读取当前用户权限集合，并按以下方法判断：

```java
hasAnyPermission(Set<String> permissions, String... codes)
```

推荐权限分组：

| 分组 | 权限 |
| --- | --- |
| RFQ 统计 | `market:order:view`, `engineer:setup:view`, `engineer:pricing:view`, `market:quote-process:view`, `market:release:view` |
| 销售订单统计 | `market:sales-order:view`, `market:sales-match:view`, `market:release:view`, `market:u9-sync:view` |
| 已提零件统计 | `market:delivered-item:view` |
| 锁库零件统计 | `market:locked-item:view` |
| U9 统计 | `market:u9-sync:view` |

没有对应权限时：

- 不查询该业务域，或查询后不返回该业务域数据。
- `summaryCards / todoCards / attentionItems` 中不放该业务域卡片。
- 图表数组返回空数组。
- 客户交叉表对应列为 0 或不合并该业务域数据；如用户 RFQ 和销售订单权限都没有，则交叉表为空。

### 8.4 聚合 Mapper 设计

建议 `DashboardAggregationMapper` 使用 MyBatis 注解 SQL，并使用 `QueryWrapper` 的 `${ew.customSqlSegment}` 接收数据权限条件。

建议方法：

```java
List<DashboardStatusCountRow> countRfqByStatus(@Param(Constants.WRAPPER) Wrapper<?> query);
List<DashboardCustomerCountRow> countRfqByCustomerAndStatus(@Param(Constants.WRAPPER) Wrapper<?> query);
List<DashboardCustomerCountRow> countSalesQuotedByCustomer(@Param(Constants.WRAPPER) Wrapper<?> query);
long countDeliveredActive(@Param(Constants.WRAPPER) Wrapper<?> query);
long countDeliveredNeedMaterial(@Param(Constants.WRAPPER) Wrapper<?> query);
long countDeliveredNeedWms(@Param(Constants.WRAPPER) Wrapper<?> query);
long countDeliveredMesCallbackPending(@Param(Constants.WRAPPER) Wrapper<?> query);
long countDeliveredMesFailed(@Param(Constants.WRAPPER) Wrapper<?> query);
long countDeliveredWmsFailed(@Param(Constants.WRAPPER) Wrapper<?> query);
long countLockedProductionTodo(@Param(Constants.WRAPPER) Wrapper<?> query);
long countLockedMesProductionFailed(@Param(Constants.WRAPPER) Wrapper<?> query);
long countSalesMatchTodo(@Param(Constants.WRAPPER) Wrapper<?> query);
long countU9Ready(@Param(Constants.WRAPPER) Wrapper<?> query);
long countU9Failed(@Param(Constants.WRAPPER) Wrapper<?> query);
```

说明：

- 内部 row DTO 可以放在 `dto/dashboard` 包，例如 `DashboardStatusCountRow`、`DashboardCustomerCountRow`。
- 订单表统计必须按订单主表计数，不能按零件明细重复计数。
- 已提零件 / 锁库零件按行计数，因为页面关注对象就是零件行或锁库 allocation 行。
- U9 ready 的判断口径必须复用 `SalesOrderU9SyncService` 当前“已生成提单 + 物料号全部确认 + U9 未成功”的业务含义，不调用 U9。

### 8.5 首页聚合索引

优先检查现有索引。如果实施时 `EXPLAIN` 显示状态和客户聚合无法有效利用索引，可新增迁移：

```sql
CREATE INDEX IF NOT EXISTS idx_order_rfq_dashboard_status_customer
    ON order_rfq (status, customer_name);

CREATE INDEX IF NOT EXISTS idx_sales_order_header_dashboard_status_customer
    ON sales_order_header (status, customer_name);

CREATE INDEX IF NOT EXISTS idx_delivery_ticket_dashboard_mes_wms_customer
    ON order_delivery_ticket (mes_sync_status, wms_allocate_status, customer_name);

CREATE INDEX IF NOT EXISTS idx_delivery_allocation_dashboard_type_mes_customer
    ON order_delivery_ticket_allocation (allocation_type, mes_production_status, customer_name);
```

注意：

- 使用 `IF NOT EXISTS`，避免破坏已有环境。
- 如果当前已有等价索引，不重复新增。
- 不新增表，不迁移业务数据。

## 10. 日志、安全和性能

### 10.1 日志

- 首页普通读取和刷新不写操作日志。
- 不新增高频文件日志。
- 后端可保留必要 debug 级聚合耗时日志，但默认 info 不刷屏。
- 不记录 token、Authorization header、外部接口请求体或响应体。

### 10.2 安全

- 接口必须走登录态认证。
- 统计数据必须受数据权限限制。
- 没有目标模块权限时，不返回对应模块数量，避免无权限用户通过首页看见业务规模。
- 首页接口不调用外部系统，不返回数据中心 token 或配置。

### 10.3 性能

- 使用数据库聚合，不在 Java 里加载大列表后统计。
- 每类统计只取 count / group by 结果，不取订单明细。
- 销售订单客户饼图 Top 8，其余合并。
- 客户交叉表 Top 20。
- 首页接口第一版不做应用缓存；如后续数据量变大，可增加 30-60 秒用户级缓存，但手动刷新必须可绕过缓存。
- 大数据量下应检查关键 SQL 的 `EXPLAIN`，必要时补充索引迁移。

## 12. 风险和处理

| 风险 | 处理 |
| --- | --- |
| 首页统计和业务模块筛选口径不一致 | 聚合口径复用 `DeliveredItemService`、`SalesOrderU9SyncService` 等现有业务含义，文档固定筛选参数 |
| 无权限用户通过数量看到业务规模 | 后端按业务域权限裁剪，不仅依赖前端隐藏 |
| 聚合 SQL 慢 | 只做 count / group by，不取明细；必要时补索引并 EXPLAIN |
| 前端失败后误显示 mock 数据 | 生产不静默回退 mock，失败时明确提示 |
| 首页逐渐变成复杂 BI | 第一版只保留主链路概览、待办和异常入口，不做趋势、同比、导出 |
| 状态中文硬编码分散 | 后端使用 `QuoteStatusWorkflow` 常量，前端只消费接口返回文案 |
