# 35-销售订单导入订单级默认信息与零件级覆盖开发文档

> 2026-08-08 两级工艺主数据阶段 15 收口：本文的订单级默认信息和零件级覆盖只影响销售订单业务字段。工艺路线仍来自自动异常治理匹配或 RFQ 派生提单快照，统一使用 `processDetailId / processCode / categoryName / detailName / hourlyRate / unitWorkHours / lineCost / sortNo` 标准字段，不从 Excel 订单默认信息中派生。

> 2026-10-08 当前导入口径更新：步骤 2 上层一行展示必填的单据类型编码、下单日期和订单类型；下层展示可选的客户订单号、客户项目号、客户下单抬头和内部项目号。客户订单号、内部项目号页面默认值可为空，但解析 Excel 并应用页面默认值后，任一销售订单缺少其中一个编号时，整次导入必须拒绝，提示“编号有缺失，请补齐内部项目号或客户订单号。”；若 Excel 行提供了完整编号，仍可不填写页面默认值。本文早期阶段中“客户订单号 / 内部项目号页面必填”由此口径覆盖。

## 1. 背景

当前销售订单导入页面只在步骤 1 选择客户、步骤 2 填写单据类型编码，订单级业务字段主要从 Excel 行中读取。

现有销售订单 Excel 表头里有 6 个字段同时具备订单级和零件级含义：

```text
下单日期、客户订单号、客户项目号、客户下单抬头、订单类型、内部项目号
```

当前后端会按 Excel 行里的 `客户订单号 + 内部项目号` 分组生成 `sales_order_header`，并要求同一组内 `下单日期 / 客户项目号 / 客户下单抬头 / 订单类型` 一致。这导致页面无法直接表达“当前导入的是哪张销售订单”，也要求 Excel 每行重复填写订单级信息。

新口径改为：

1. 销售订单导入页面新增订单级默认信息矩阵。
2. 订单主表字段统一使用页面矩阵填写的订单级值。
3. 零件主表字段优先使用 Excel 每行值；如果 Excel 行为空，则回退使用页面订单级默认值。
4. `下单日期` 和 `客户下单抬头` 也要有零件级字段，一次把数据模型补齐。

## 2. 设计结论

### 2.1 页面输入结论

销售订单导入页面步骤 2 从“单据类型编码”升级为“单据类型与订单信息”。

在现有 `单据类型编码` 输入框下方新增一个矩阵式订单信息区，字段为：

| 字段 | 组件 | 必填 | 说明 |
| --- | --- | --- | --- |
| 下单日期 | `el-date-picker` | 是 | 保存为订单头下单日期，也作为零件行空值 fallback。 |
| 客户订单号 | `el-input` | 否 | 保存为订单头客户订单号，也作为零件行空值 fallback。 |
| 客户项目号 | `el-input` | 否 | 保存为订单头客户项目号，也作为零件行空值 fallback。 |
| 客户下单抬头 | `el-input` | 否 | 保存为订单头客户下单抬头，也作为零件行空值 fallback。 |
| 订单类型 | `el-select` | 是 | 复用议价提单模块选项：`预测订单 / 备货订单 / 正式订单`。 |
| 内部项目号 | `el-input` | 否 | 保存为订单头内部项目号，也作为零件行空值 fallback。 |

展示要求：

- 必填的 `单据类型编码 / 下单日期 / 订单类型` 在上层三列同行。
- 可选的 `客户订单号 / 客户项目号 / 客户下单抬头 / 内部项目号` 在下层两列排布；窄屏逐步收为单列。
- 视觉上仍放在同一个步骤卡片 / 面板中，不新增独立步骤。
- 字段标签短而直观，不在页面内写大段说明。
- 沿用现有权限 `market:rfq:import-sales-order` 和重复点击保护。

### 2.2 导入语义结论

一次销售订单导入只生成一个 `sales_order_header`，订单头字段来自页面矩阵，不再按 Excel 的客户订单号 / 内部项目号拆多个销售订单头。

Excel 中这 6 列变为零件行覆盖字段：

- Excel 有值：写入对应 `sales_order_item` 行。
- Excel 为空或列不存在：使用页面矩阵订单级默认值写入 `sales_order_item` 行。

这样形成明确的两层数据：

```text
sales_order_header：页面订单级默认信息
sales_order_item：Excel 行级信息；空值继承页面订单级默认信息
```

## 4. 数据库变更

新增迁移：

```text
quote-backend/src/main/resources/db/migration/V88__sales_order_item_order_defaults.sql
```

迁移内容：

```sql
ALTER TABLE sales_order_item
    ADD COLUMN IF NOT EXISTS sales_order_date DATE,
    ADD COLUMN IF NOT EXISTS customer_order_title VARCHAR(255);

UPDATE sales_order_item item
SET sales_order_date = header.sales_order_date,
    customer_order_title = header.customer_order_title
FROM sales_order_header header
WHERE item.sales_order_id = header.id
  AND (item.sales_order_date IS NULL OR item.customer_order_title IS NULL);
```

说明：

- 当前本地没有正式销售订单数据，迁移主要用于模型补齐。
- 即使未来已有少量测试数据，迁移也能从订单头回填，风险低。
- 不删除现有零件表冗余字段：`order_type / customer_order_no / customer_project_no / internal_project_no`。

改造重点：


### 5.4 Import Service

- `quote-backend/src/main/java/com/machining/quote/service/SalesOrderQpoImportService.java`

### 5.5 自动提单

修改文件：

- `quote-backend/src/main/java/com/machining/quote/service/DeliveryService.java`

当前销售订单自动提单使用订单头的：

```text
orderType、salesOrderDate、internalProjectNo、customerOrderNo、customerProjectNo
```

改为零件优先、订单头兜底：

```text
ticket.orderType = item.orderType ?: header.orderType ?: "正式订单"
ticket.startDate = item.salesOrderDate ?: header.salesOrderDate ?: LocalDate.now()
ticket.internalProjectNo = item.internalProjectNo ?: header.internalProjectNo
ticket.customerOrderNo = item.customerOrderNo ?: header.customerOrderNo
ticket.customerProjectNo = item.customerProjectNo ?: header.customerProjectNo
```

`internalProjectNo` 和 `customerOrderNo` 仍需最终非空，否则拒绝生成提单。

- 自动提单使用行级有效字段；Excel 行值可覆盖页面默认值，空单元格继承页面默认值。
- 应用行值和页面默认值后，任一订单行缺少客户订单号或内部项目号时，拒绝整次导入且不创建导入批次、销售订单或提单。
- 缺失编号的错误提示为“编号有缺失，请补齐内部项目号或客户订单号。”；页面默认值可以为空，只要 Excel 能补齐全部有效编号。
- 操作日志不包含完整 Excel / multipart / 图纸内容。

## 9. 回归风险

| 风险 | 处理 |
| --- | --- |
| 旧模板仍把 6 个字段作为必填 | 后端改为可选，模板保留可选列，页面说明明确继承规则。 |
| 之前一次 Excel 导入多个销售订单 | 新口径改为一次导入一个订单头；如果未来需要批量多订单，需要单独做批量导入模式。 |
| 自动提单仍使用 header 字段 | 阶段 4 明确改为 item 优先、header 兜底。 |
| 下单日期没有 item 字段 | 阶段 1 新增 `sales_order_item.sales_order_date`。 |
| 客户下单抬头没有 item 字段 | 阶段 1 新增 `sales_order_item.customer_order_title`。 |

## 10. 最终验收

1. 销售订单导入步骤 2 在单据类型编码下方展示订单默认信息矩阵。
2. 页面填写的 6 个字段保存到 `sales_order_header`。
3. Excel 行内对应字段保存到 `sales_order_item`。
4. Excel 行内字段为空时，`sales_order_item` 使用页面默认值。
5. `sales_order_item` 包含 `sales_order_date / customer_order_title`。
6. 自动生成提单时使用零件行级有效字段。
7. 销售订单模板说明改为 6 个字段可选且可继承页面默认值。
8. 权限和日志保持现有销售订单导入口径。

### 阶段 8 收口补充

本文件的订单级默认值和零件级覆盖规则同样适用于 RFQ 议价提单派生销售订单的销售订单零件落库，但 RFQ 零件主表的六个属性仍由独立保存接口维护。生成批次时只使用已保存的 RFQ 零件值，空值才由左侧订单默认值兜底。

派生订单进入 U9 前继续校验已确认物料号和含税单价；本次不新增权限，读取、跳转和预览不记操作日志。
