# QPO 首页看板前端原型开发文档

最后更新：2026-08-04

> 本文承接 `28-首页看板模块需求文档.md`。本阶段目标是先做一个高质量、可交互、可评审的首页看板前端原型，使用 mock / 占位数据验证页面结构、视觉语言、图表表达和跳转体验；不开发后端聚合接口，不改数据库，不接真实业务统计。

## 1. 背景和目标

首页看板是 QPO 登录后的默认第一屏，需要给用户一个现代、清晰、可信的业务工作台，而不是后期再补美化的临时页面。

本阶段采用“前端体验先定稿”的节奏：

1. 先用 mock 数据做出接近最终效果的 `/dashboard` 页面。
2. 让用户提前确认信息层级、图表比例、快捷入口和异常关注区。
3. 后续后端只需要按 mock 数据结构提供真实聚合结果，前端不大改。

## 2. 参考观察

本阶段只借鉴成熟 Vue 后台看板的结构方法，不直接复制模板、不引入整套 UI 框架。

| 参考项目 | 可借鉴点 | QPO 采用方式 |
| --- | --- | --- |
| `vue-element-plus-admin` | `Dashboard/Analysis.vue` 使用面板组 + 图表卡 + skeleton；图表封装为独立组件。 | 首页拆出指标卡、图表卡、表格和待办组件，图表也封装，避免堆在一个大文件。 |
| `vue-pure-admin` | `welcome/data.ts` 将展示数据单独维护，便于 mock 和真实接口切换。 | 新增 `dashboardMockData.js`，后续替换成 API 返回时不推翻页面。 |
| `vue-vben-admin` / `art-design-pro` | 工作台类页面强调首屏总览、快捷入口和任务流。 | QPO 首页定位为业务工作台，不做营销大屏或装饰型图表。 |

QPO 前端仍使用当前技术栈：Vue 3、Vue Router、Pinia、Element Plus、Element Plus Icons、Vite、Vitest。

## 3. 本阶段范围

### 3.1 包含

- 新增 `/dashboard` 首页看板前端页面。
- 将系统根路径 `/` 默认跳转到 `/dashboard`。
- 左侧栏顶部新增 `首页看板` 入口。
- 首页数据使用 mock / 占位数据。
- 新增 ECharts 作为图表库，并封装轻量图表组件。
- 页面展示：
  - 顶部概览与更新时间。
  - 关键指标卡。
  - 询价订单状态分布饼图。
  - 待同步 U9 客户分布饼图。
  - 客户状态交叉表。
  - 待办快捷卡片。
  - 最近异常 / 关注项。
- 快捷入口支持跳转到已有模块，筛选参数先预留。
- 权限体验先按现有前端权限集合隐藏无权限快捷入口。
- 补前端源码测试和构建验证。

### 3.2 不包含

- 不新增后端 Controller / Service / Mapper。
- 不新增数据库表或迁移。
- 不实现真实聚合统计接口。
- 不从前端全量拉取订单、零件或锁库数据做统计。
- 不在首页执行 U9 同步、MES 获取物料号、WMS 锁库、MES 生产下发等写操作。
- 不新增新的角色授权页面逻辑。
- 不引入整套第三方后台模板。

## 4. 视觉和交互原则

首页看板第一版必须是“可上线视觉标准”的原型，而不是丑临时页。

### 4.1 视觉方向

- 保持 QPO 当前企业后台风格：白色 / 浅灰内容面、深色左侧导航、蓝色主色、红橙色仅用于异常强调。
- 页面信息密度高但不拥挤，避免大面积渐变、玻璃拟态、营销型 hero、大装饰图。
- 图表颜色要克制，状态色语义清楚：
  - 未核价：蓝灰 / 信息色。
  - 已核价：琥珀 / 待推进色。
  - 已报价：蓝色 / 主流程色。
  - 异常失败：红色点状或轻背景提示。
  - 等待回调：琥珀提示，不等同失败。

### 4.2 页面布局

桌面端建议布局：

```text
------------------------------------------------------+
| 页面标题 / 说明 / 更新时间 / 刷新按钮                  |
+------------------------------------------------------+
| 指标卡 1 | 指标卡 2 | 指标卡 3 | 指标卡 4              |
+--------------------------+---------------------------+
| 询价订单状态分布饼图       | 待同步 U9 客户分布饼图       |
+--------------------------+---------------------------+
| 客户状态交叉表             | 待办快捷卡片 + 异常关注项     |
+------------------------------------------------------+
```

窄屏下从上到下自然排列：

```text
标题
指标卡
询价饼图
销售饼图
待办快捷卡片
异常关注项
客户状态交叉表
```

### 4.3 交互要求

- 所有卡片、表格数字、图表扇区可点击项必须有 hover / focus / active 反馈。
- 点击只做跳转，不做写操作。
- 图表必须有 tooltip 和 legend，不能只靠颜色理解。
- 页面刷新按钮只刷新 mock 数据状态和更新时间，不请求真实后端。
- 空状态文案使用业务语言：`当前权限范围内暂无待处理数据`。
- 异常关注项点击进入目标模块后，参数可以先带在 URL query 中，后续再由目标模块消费。

## 7. 开发阶段

### 阶段 1：图表依赖和页面入口骨架

目标：系统有 `/dashboard` 页面入口，但页面先只放稳定骨架。

修改：

- `quote-frontend/package.json` 增加 `echarts`。
- `quote-frontend/src/router/index.js`：
  - 新增 `DashboardHome` 懒加载。
  - 新增 `/dashboard` 路由。
  - `/` redirect 从 `/market` 改为 `/dashboard`。
  - `/dashboard` 第一版不设置业务模块权限，作为登录默认页。
- `quote-frontend/src/App.vue`：
  - 左侧栏顶部新增单独分组或置顶入口 `首页看板`。
  - `menuMetaByPath` 新增 `/dashboard`。
  - `shellMetaByPath` 新增首页标题和说明。
  - `visibleMenuGroups` 需要在后端菜单未包含 `/dashboard` 时仍显示首页入口；后续后端权限阶段再收口。
- 新增 `DashboardHome.vue` 空壳页面，带标题、更新时间、刷新按钮、占位区域。

验收：

- 登录后访问 `/` 会进入 `/dashboard`。
- 左侧栏顶部可以看到 `首页看板`。
- 原有 `/market` 新单导入仍可访问。
- 首页页面不是空白，也不显示后端错误。

### 阶段 2：mock 数据和导航辅助

目标：首页原型拥有稳定数据结构，后续可直接替换成后端聚合接口。

修改：

- 新增 `dashboardMockData.js`，包含：
  - `summaryCards`
  - `rfqStatusDistribution`
  - `u9ReadyCustomerDistribution`
  - `customerMatrix`
  - `todoCards`
  - `attentionItems`
- 新增 `dashboardNavigation.js`：
  - `canShowDashboardAction(item, authStore)`：按 `permission` 判断入口是否显示。
  - `goDashboardTarget(router, item)`：统一处理 `path + query` 跳转。
  - `formatDashboardNumber(value)`：统一数字展示。
- mock 数据必须严格遵循 28 号需求：
  - 询价饼图只含 `未核价 / 已核价 / 已报价`。
  - 待同步 U9 饼图只统计整单物料号已确认且尚未同步 U9 的销售订单，分类是客户。
  - 客户交叉表不含 `部分已提单 / 已生成提单 / 废弃` 字段。

验收：

- 页面所有区域都能由 mock 数据渲染。
- mock 数据中不出现真实 token、真实接口地址、真实客户敏感数据。
- 前端没有从订单、零件或锁库列表接口拉全量数据。

### 阶段 3：高质量首页主体页面

目标：完成可评审的现代首页工作台视觉。

修改：

- `DashboardHome.vue` 组合以下区域：
  - 页面头部：标题 `首页看板`、说明、数据更新时间、刷新按钮。
  - 顶部指标区：4 个关键指标卡。
  - 双饼图区：询价订单状态分布、待同步 U9 客户分布。
  - 客户状态交叉表。
  - 待办快捷卡片。
  - 最近异常 / 关注项。
- 使用 Element Plus 组件和现有 QPO 样式基调。
- 自定义 CSS 类建议：
  - `.dashboard-home`
  - `.dashboard-hero`
  - `.dashboard-summary-grid`
  - `.dashboard-chart-grid`
  - `.dashboard-workbench-grid`
  - `.dashboard-surface`
  - `.dashboard-muted`
- 使用 CSS Grid / Flex，保证小屏自然换行。
- 指标卡和快捷卡支持 hover，但不产生布局位移。

验收：

- 页面第一眼能看出这是 QPO 首页工作台。
- 不像模板直接搬运，也不和现有 QPO 风格割裂。
- 图表、表格、待办、异常区层级清楚。
- 页面没有大面积渐变背景、装饰图或营销 hero。

### 阶段 4：ECharts 饼图卡片封装

目标：图表看起来接近最终效果，且后续可复用真实数据。

修改：

- 新增 `DashboardChartCard.vue`。
- 使用 ECharts 初始化和销毁：
  - `onMounted` 初始化。
  - `watch` 数据变化后重新 setOption。
  - `onBeforeUnmount` dispose。
  - 监听窗口 resize，避免图表尺寸错乱。
- 支持 props：
  - `title`
  - `description`
  - `data`
  - `emptyText`
  - `palette`
- 饼图配置要求：
  - donut 样式，中心留白展示合计。
  - legend 放底部或右侧，窄屏改到底部。
  - tooltip 展示 `名称 / 数量 / 占比`。
  - 空数据展示业务空状态，不渲染假图。
- 点击扇区时触发 `select` 事件，由页面统一跳转。

验收：

- 询价订单饼图展示 `未核价 / 已核价 / 已报价`。
- 待同步 U9 饼图展示客户分布。
- resize 后图表不压缩错位。
- 空数据状态清晰。

### 阶段 5：待办、异常和客户交叉表交互

目标：首页从“展示页”变成“可进入业务模块的工作台”。

修改：

- `DashboardSummaryCard.vue`：
  - 展示标题、数字、单位、说明、趋势文案。
  - 有权限时可点击，无权限时不展示。
- `DashboardTodoCard.vue`：
  - 展示待办名称、数量、目标模块说明。
  - 点击跳转目标模块。
- `DashboardAttentionList.vue`：
  - 展示失败 / 等待关注项。
  - `danger`、`warning`、`info` 三种视觉语义。
  - `待 MES 回调` 使用等待语义，不使用失败红色。
- `DashboardCustomerMatrix.vue`：
  - 展示客户、询价未核价、询价已核价、询价已报价、待同步 U9、关注合计。
  - 数字为 0 时弱化。
  - 数字点击跳转目标模块并带 query。

验收：

- 无目标模块权限时，对应快捷入口不展示。
- 点击待办和异常只跳转，不触发写操作。
- 客户交叉表不展示提单后状态数量。
- 长客户名不挤压数字列。

### 阶段 6：前端测试和构建验证

目标：保证首页原型不破坏现有前端。

修改：

- 新增 `dashboardPrototype.test.js`，至少覆盖：
  - 路由包含 `/dashboard`。
  - `/` redirect 到 `/dashboard`。
  - App 菜单包含 `首页看板`。
  - mock 询价状态只包含 `未核价 / 已核价 / 已报价`。
  - mock 待同步 U9 饼图按客户分布且只表达 `materialReadyStatus=READY`。
  - 首页源码不包含 `部分已提单`、`已生成提单` 作为主图表数据项。
  - 首页没有调用 U9 / MES / WMS 写操作 API。
  - 首页引入 ECharts 图表组件。
- 更新已有路由懒加载测试，加入 `DashboardHome`。
- 执行：

```powershell
cd D:\QPO-Operations-Management-System\quote-frontend
npm install
npm test
npm run build
```

验收：

- `npm test` 通过。
- `npm run build` 通过。
- package lock 文件与新增依赖一致。
- 没有引入除 `echarts` 外的新 UI 库。

### 阶段 7：浏览器视觉走查

目标：确认首页看板不是“能运行但不好看”的页面。

修改：

- 启动前端：

```powershell
cd D:\QPO-Operations-Management-System\quote-frontend
npm run dev
```

- 浏览器检查：
  - 桌面宽屏：首页信息层级是否清楚。
  - 1366 宽度：双图表和表格是否拥挤。
  - 小屏宽度：指标卡、图表、表格是否自然换行。
  - 图表 tooltip 是否正常。
  - hover / focus 反馈是否明显但不跳动。
  - 页面是否出现横向滚动。

验收：

- 首页看板首屏现代、干净、可信。
- 图表和表格不遮挡、不压缩、不重叠。
- 视觉上和文件存储、出站接口、已提零件、锁库零件优化后的风格一致。
- 用户能一眼理解“哪里有订单、哪里有待办、哪里有异常”。

## 8. 后续真实后端阶段预留

前端原型确认后，再进入后端聚合接口开发。后端阶段应尽量返回与 `dashboardMockData.js` 一致的数据结构：

- `GET /api/dashboard/overview` 或同等聚合接口。
- 后端完成数据权限过滤。
- 后端聚合询价订单、销售订单、已提零件、锁库零件、U9 同步状态。
- 前端将 mock 数据替换为 API 数据，并保留 mock 作为本地 fallback 或测试 fixture。

本阶段不得为了首页原型提前写临时后端接口，避免接口口径未定导致返工。

## 9. 风险和控制

| 风险 | 控制方式 |
| --- | --- |
| 首页做成模板感太重 | 使用 QPO 业务文案、现有页面密度和克制颜色，不搬运模板布局。 |
| 图表库引入后包体变大 | 只引入 `echarts`，不引入整套图表 UI 框架；后续可按需优化懒加载。 |
| mock 数据和后端接口脱节 | mock 数据结构在文档中固定，后端阶段以该结构为契约起点。 |
| 首页入口和权限菜单冲突 | 第一版首页作为登录默认基础入口；业务快捷入口继续按现有权限隐藏。 |
