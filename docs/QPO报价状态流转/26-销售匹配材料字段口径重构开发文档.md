# QPO 销售匹配材料字段口径重构开发文档

> 2026-08-06 阶段 7 收口：销售订单导入自动补全沿用只补空缺生产快照规则，不提供人工覆盖字段确认。`/sales-match` 页面已改为异常治理，只作为历史销售订单或自动补全异常的兜底入口。

## 1. 背景

销售匹配模块当前用于选择销售订单，并按 `图号 + 版本` 命中历史已提单 RFQ 零件快照，然后把历史生产快照补全到 `sales_order_item`。

现有实现里，销售订单导入模板中的 `材料` 和 `表面处理` 会写入 `sales_order_item.material_name`、`sales_order_item.surface_treatment`。销售匹配命中历史快照后，当前代码仍存在以下行为：

- `material_name` 在当前为空时会从历史 RFQ 补入；勾选覆盖模板材料时会覆盖。
- `surface_treatment` 在当前为空时会从历史 RFQ 补入；勾选覆盖模板材料时会覆盖。
- `drawing_url` 在当前为空时会从历史 RFQ 补入。

新的业务口径要求把销售订单导入事实和历史核价生产快照彻底分开：

- 销售订单导入的 `材料` 是 **导入材料 / 模板材料**，不得被销售匹配覆盖。
- 销售订单导入的 `表面处理` 是销售订单自身事实字段，销售匹配不得覆盖。
- 销售订单已绑定 / 未绑定图纸都不由销售匹配覆盖或补历史图纸。
- 历史匹配命中后，只补销售订单导入时不存在的生产核价快照和真实材料字段。
- 销售匹配是固定规则的信息补全动作，不再提供任何“是否覆盖某字段”的人工选择。

## 2. 目标

1. 明确销售订单导入字段、销售匹配补全字段和后续传输字段的含义。
2. 销售匹配不再覆盖或补写 `material_name`、`surface_treatment`、`drawing_url`。
3. 销售匹配命中历史 RFQ 后，补写真实材料 / 核价材料字段：
   - `engineering_material_name`
   - `material_shape`
   - `material_data`
   - `material_gross_weight`
   - `part_net_weight`
   - `quote_mode`
   - `item_type`
   - `assembly_fee`
   - `base_cost`
   - `process_route`
   - `fee_data`
   - `matched_rfq_id`
   - `matched_item_id`
   - `match_status`
   - `match_message`
   - `assembly_relation_status`
4. 后续提单、锁库、MES 生产下发等生产链路需要展示或传输“材料”时，统一采用：
   - 优先 `engineering_material_name`
   - 其次 `material_data.name`
   - 最后降级 `material_name`
5. 匹配补全采用固定后端规则：只补空缺生产快照字段，已有字段不覆盖，不需要用户二次判断是否覆盖。
6. RFQ 主链路不回退，销售订单主链路不写入 `order_rfq` / `item_quote_version`。

## 3. 字段口径

### 3.1 销售订单字段

| 字段 | 中文显示建议 | 来源 | 是否允许销售匹配写入 | 说明 |
| --- | --- | --- | --- | --- |
| `material_name` | 导入材料 | 销售订单模板 `材料` | 否 | 销售订单原始导入事实。即使为空，销售匹配也不补历史 RFQ 的导入材料。 |
| `surface_treatment` | 表面处理 | 销售订单模板 `表面处理` | 否 | 销售订单原始导入事实。即使为空，销售匹配也不补历史 RFQ 的表面处理。 |
| `drawing_url` | 图纸 | 销售订单导入绑定 / 补传图纸 | 否 | 销售匹配不补历史图纸，也不覆盖已有图纸。 |
| `engineering_material_name` | 真实材料 / 核价材料 | 历史 RFQ 核价快照 | 是 | 从历史 `engineering_material_name` 取值；为空时可从 `material_data.name` 降级解析。 |
| `material_shape` | 材料形态 | 历史 RFQ 核价快照 | 是 | 如 `板材 / 棒材 / 管材`，从历史 `material_shape` 或 `material_data.shape` 解析。 |
| `material_data` | 材料核价快照 | 历史 RFQ 核价快照 | 是 | 保存真实材料、形态、重量、成本、密度、单价等核价材料数据。 |
| `process_route` | 工艺路线快照 | 历史 RFQ 核价快照 | 是 | 生产和成本计算使用的工艺路线。 |
| `fee_data` | 费用快照 | 历史 RFQ 核价快照 | 是 | 加价、费用结构等核价结果。 |
| `material_gross_weight` | 材料毛重 | 历史 RFQ 核价快照 | 是 | 后续提单 / MES / 锁库传输使用。 |
| `part_net_weight` | 零件净重 | 历史 RFQ 核价快照 | 是 | 后续提单 / MES / 锁库传输使用。 |
| `quote_mode` | 核价模式 | 历史 RFQ 核价快照 | 是 | `NORMAL` / `ASSEMBLY`。 |
| `item_type` | 零件类型 | 历史 RFQ 核价快照 | 是 | 普通件 / 组合件。 |
| `assembly_relation_status` | 父子关系状态 | 销售匹配组合件关系判断 | 是 | 普通件为 `不适用`，组合件关系完整为 `已指定父子关系`，否则为 `未指定父子关系`。 |
| `matched_rfq_id` | 匹配来源 RFQ ID | 历史 RFQ 快照 | 是 | 用于追溯，不代表销售订单进入 RFQ 主表。 |
| `matched_item_id` | 匹配来源零件 ID | 历史 RFQ 快照 | 是 | 用于追溯历史 `item_quote_version.id`。 |
| `match_status` | 匹配状态 | 销售匹配结果 | 是 | `待匹配 / 已匹配 / 未匹配 / 跳过`。 |
| `match_message` | 匹配说明 | 销售匹配结果 | 是 | 展示命中、未命中或跳过原因。 |

## 4. RFQ 材料口径对齐

RFQ 现有材料链路是本次销售订单口径的参考：

1. RFQ 导入时，模板 `材料名称` 写入 `item_quote_version.material_name`，这是市场导入材料。
2. 工程核价时，真实材料写入 `item_quote_version.material_data.name`，并沉淀到 `item_quote_version.engineering_material_name`。
3. 材料形态写入 `item_quote_version.material_data.shape`，并沉淀到 `item_quote_version.material_shape`。
4. 提单和后续生产链路需要真实材料时，优先取 `engineering_material_name`，为空时从 `material_data.name` 解析。

销售订单应采用同样含义：

- `sales_order_item.material_name` = 导入材料。
- `sales_order_item.engineering_material_name` = 真实材料 / 核价材料。
- `sales_order_item.material_shape` = 材料形态。
- `sales_order_item.material_data` = 材料核价快照。

## 5. 设计方案

### 5.1 推荐方案

采用 **保留现有字段、调整字段含义和写入规则** 的方案。

原因：

- 不新增数据库字段，避免迁移复杂度。
- 与 RFQ 已有 `material_name / engineering_material_name / material_data` 口径一致。
- 销售订单历史数据可继续使用，不需要搬表或重算。
- 后续生产链路只需要统一材料解析规则即可。

不采用的方案：

1. 新增 `import_material_name` 字段保存导入材料，再把 `material_name` 改成真实材料。该方案会影响大量已有页面、提单、锁库、MES 生产下发字段，迁移成本高。
2. 销售匹配继续允许覆盖任意字段，靠前端提示规避误操作。该方案无法保证后端安全边界，也不符合“补空缺信息”的模块定位。

### 5.2 后端改造

#### 5.2.1 `SalesOrderMatchService.applyProductionSnapshot(...)`

调整写入规则：

- 删除 / 禁止写入 `item.setMaterialName(...)`。
- 删除 / 禁止写入 `item.setSurfaceTreatment(...)`。
- 删除 / 禁止写入 `item.setDrawingUrl(...)` 和 `item.setHasDrawing(...)`。
- 保留补空写入。以下字段只有当前为空、空对象或空数组时才从历史快照补入；当前已有值时不覆盖：
  - `engineeringMaterialName`
  - `materialShape`
  - `materialGrossWeight`
  - `partNetWeight`
  - `quoteMode`
  - `assemblyFee`
  - `baseCost`
  - `itemType`
  - `materialData`
  - `processRoute`
  - `feeData`
  - `assemblyRelationStatus`
- 保留匹配结果写入。以下字段用于记录本次匹配结果和来源追溯，不属于覆盖销售订单导入事实：
  - `matchedRfqId`
  - `matchedItemId`
  - `matchStatus`
  - `matchMessage`

真实材料取值规则：

```text
source.engineering_material_name
  -> source.material_data.name
  -> 空
```

材料形态取值规则：

```text
source.material_shape
  -> source.material_data.shape
  -> 空
```

#### 5.2.2 `changedFields(...)`

预览摘要中：

- 不再把 `materialName` 作为可补全字段。
- 不再把 `surfaceTreatment` 作为可补全字段。
- 不再把 `drawingUrl` 作为可补全字段。
- 增加或保留：
  - `engineeringMaterialName`：真实材料 / 核价材料。
  - `materialShape`：材料形态。
  - `materialSnapshotAvailable`：材料核价快照是否存在。
  - `processSnapshotAvailable`：工艺路线是否存在。
  - `feeSnapshotAvailable`：费用快照是否存在。

#### 5.2.3 `protectedFields(...)`

保护摘要中必须稳定展示：

- `materialName`：导入材料，销售匹配不覆盖。
- `surfaceTreatment`：表面处理，销售匹配不覆盖。
- `drawingUrl`：销售订单图纸，销售匹配不覆盖。
- `materialNo`：MES/U9 物料号，销售匹配不覆盖。
- `description`：销售订单导入描述，语义对应 RFQ 物料描述，销售匹配不覆盖。
- `qty`、价格、客户订单号、客户项目号、内部项目号、交期等原有保护字段。

#### 5.2.4 `SalesOrderMatchApplyReq`

移除覆盖类参数。

实施要求：

- 移除或忽略 `overwriteTemplateMaterial`，不得通过该参数覆盖导入材料和表面处理。
- 移除或忽略 `overwriteExistingProductionSnapshot`，不得通过该参数覆盖已有生产快照。
- 后端即使收到旧前端传入的覆盖参数，也按“只补空缺信息”执行。
- 前端不展示任何覆盖选项。
- 接口文档说明销售匹配无覆盖语义，只有补空缺语义。

#### 5.2.5 统一材料解析工具

新增或扩展材料解析方法，用于销售订单：

```text
effectiveEngineeringMaterialName(salesOrderItem)
  -> engineering_material_name
  -> material_data.name
  -> material_name
```

含义：

- 展示“真实材料”或传输生产材料时，用该规则。
- 展示“导入材料”时，只展示 `material_name`。

### 5.3 提单和后续链路改造

#### 5.3.1 销售订单提单

`order_delivery_ticket` 继续保存两类材料：

| 目标字段 | 来源 | 含义 |
| --- | --- | --- |
| `material_name` | `sales_order_item.material_name` | 导入材料快照。 |
| `engineering_material_name` | `effectiveEngineeringMaterialName(sales_order_item)` | 真实材料 / 核价材料快照。 |
| `material_shape` | `sales_order_item.material_shape -> sales_order_item.material_data.shape` | 材料形态快照。 |
| `material_data` | `sales_order_item.material_data` | 材料核价快照。 |
| `surface_treatment` | `sales_order_item.surface_treatment` | 销售订单导入表面处理。 |
| `drawing_url` | `sales_order_item.drawing_url` | 销售订单图纸。 |

#### 5.3.2 已提零件 / 锁库零件 / MES 生产下发

页面可同时保留：

- `导入材料`：`material_name`
- `真实材料`：`engineering_material_name`，为空时前端可显示 `-`
- `材料形态`：`material_shape`

对 MES 生产下发等外部接口：

- 保留现有 `materialName` 字段时，建议传 `effectiveEngineeringMaterialName` 的结果。
- 如接口需要同时区分，可传：
  - `importMaterialName`
  - `engineeringMaterialName`
  - `materialName` = `engineeringMaterialName -> materialData.name -> materialName`

第一版为降低对接风险，建议不改外部字段名，只更新字段说明：

- `materialName`：生产侧有效材料名称，优先真实材料，缺失时降级导入材料。
- `engineeringMaterialName`：真实材料 / 核价材料。
- `materialData`：材料核价快照。

## 6. 前端改造

### 6.1 `SalesMatch.vue`

页面形态已进一步收口为订单级工作台：用户通过共享订单选择弹窗选择一张 `已报价` 销售订单，页面自动执行整单预览，再由用户点击 `补全生产快照` 完成整单补全。核心路径固定为 `选择销售订单 -> 整单预览 -> 补全生产快照`。

页面文案调整：

- 零件表 `材料` 改为 `导入材料`。
- 预览表 `历史材料` 改为 `历史真实材料` 或 `可补真实材料`。
- 删除 `覆盖模板材料/表面处理` 复选框。
- 保护字段摘要中展示：
  - 导入材料已保护
  - 表面处理已保护
  - 销售订单图纸已保护
- 预览结果中不再显示“可补导入材料 / 可补表面处理 / 可补图纸”。

交互规则：

- 用户选择一张 `已报价` 销售订单后，页面自动调用订单级预览；点击 `补全生产快照` 后，后端直接按固定规则补空缺并返回结果。
- 不再提供零件级勾选，补全生产快照只补空缺信息。
- 预览如保留，仅用于让用户提前看到命中情况和可补字段摘要，不承担覆盖选择。
- 不再提供任何覆盖导入材料、表面处理、图纸或已有生产快照的操作入口。
- 不再提供任何覆盖字段确认，也不再弹出“是否覆盖某某字段”的确认项。
- 如保留执行确认弹窗，弹窗只确认是否执行补全动作，不出现字段覆盖选项，文案改为：

```text
确认补全销售订单零件的空缺生产快照？
系统只补空缺信息；导入材料、表面处理、图纸、价格、数量、交期、客户字段、物料号和已有生产快照均不会被覆盖。
```

### 6.2 其他页面显示

如后续页面同时展示导入材料和真实材料，建议统一命名：

| 页面显示 | 字段 |
| --- | --- |
| 导入材料 | `material_name` |
| 真实材料 | `engineering_material_name` |
| 材料形态 | `material_shape` |
| 表面处理 | `surface_treatment` |

## 7. 测试方案

### 7.1 后端测试

新增或更新销售匹配测试：

1. 销售订单 `material_name` 为空时，匹配成功也不写历史 `material_name`。
2. 销售订单 `material_name` 有值时，匹配成功不覆盖。
3. 销售订单 `surface_treatment` 为空时，匹配成功也不写历史 `surface_treatment`。
4. 销售订单 `surface_treatment` 有值时，匹配成功不覆盖。
5. 销售订单 `drawing_url` 为空时，匹配成功也不写历史 `drawing_url`。
6. 销售订单 `drawing_url` 有值时，匹配成功不覆盖。
7. 销售订单 `description` 为空时，匹配成功也不写历史 RFQ `description`。
