# QPO 客户主数据模块开发文档

最后更新：2026-08-11

## 1. 当前口径

客户资料模块已经从“QPO 本地维护客户”改造为“U9 客户只读缓存”。

现行原则：

- U9 是客户主数据唯一来源，QPO 不允许新增、编辑或删除客户。
- QPO 本地只保存同步缓存，用于全系统客户选择、数据权限选择和销售订单 U9 同步。
- 客户稳定身份使用 `customer_code`，客户名称和简称只作为展示、搜索和历史快照字段。
- 销售订单、询价订单等业务单据保存客户编码和名称快照，避免 U9 主数据后续变化影响历史单据。
- 不新增可分配 `common:*` 客户权限。

## 2. 目标

- 客户资料页面只能查看、筛选、刷新和手动同步 U9 客户缓存。
- 所有客户选项来自 `customer_master` 的 U9 同步结果。
- 构造 `POST / PUT / DELETE /api/system/customers` 不能新增、编辑或删除客户。
- 客户资料展示客户编码、客户简称、客户名称、有效状态、最近同步时间和来源。
- U9 同步失败时保留上一轮成功缓存，并只记录脱敏错误摘要。

## 3. 非目标

- 不建设 QPO 本地客户维护能力。
- 不允许业务用户在 QPO 中修正客户编码、简称或名称。
- 不提供客户导入、批量编辑、批量删除或停用入口。
- 不把 U9 组织作为页面筛选条件暴露给业务用户；当前 U9 同步固定使用配置组织。
- 不新增销售部门/销售员左侧管理页面；销售订单 U9 同步页只使用本地缓存选项。

## 4. 数据模型

`customer_master` 是 U9 客户缓存表，核心字段如下：

| 字段 | 说明 |
| --- | --- |
| `customer_code` | U9 客户编码，QPO 客户稳定身份，销售订单同步时作为 U9 OrderBy。 |
| `customer_short_name` | U9 客户简称，用于展示和搜索。 |
| `customer_name` | U9 客户名称，用于展示、搜索和业务快照。 |
| `u9_org_code` | 同步来源组织，当前配置为 U9 组织 `101`。 |
| `u9_customer_id` | U9 返回的客户主数据标识，仅用于排查和同步去重。 |
| `enabled` | U9 有效状态；新业务选择只允许有效客户。 |
| `last_synced_at` | 最近一次成功同步写入时间。 |
| `created_at` / `updated_at` | QPO 缓存记录时间。 |

同步约束：

- `customer_code` 是主要去重键。
- 客户名称不作为唯一身份，允许 U9 存在同名客户。
- 本轮 U9 未返回但本地已存在的客户不物理删除，只标记 `enabled=false`。

## 5. 权限设计

| 授权能力 | 权限编码 | 类型 | 默认角色 | 说明 |
| --- | --- | --- | --- | --- |
| 客户资料 | `system:customer:view` | `MENU` | `SUPER_ADMIN`, `MARKET_MANAGER` | 控制客户资料入口、分页查询和客户选项读取。 |
| 同步 U9 客户 | `system:customer:sync` | `BUTTON` | `SUPER_ADMIN` | 手动触发 U9 客户同步，只记录同步批次安全摘要。 |

已下线权限：

| 权限编码 | 处理方式 |
| --- | --- |
| `system:customer:create` | 从默认角色移除，数据库标记停用或不可分配。 |
| `system:customer:update` | 从默认角色移除，数据库标记停用或不可分配。 |
| `system:customer:delete` | 从默认角色移除，数据库标记停用或不可分配。 |

后端权限仍是最终边界，前端隐藏按钮不能替代后端校验。

## 6. 日志设计

普通客户列表查询、客户选项查询和客户选择弹窗不写操作日志，也不增加业务 INFO 文件日志。

手动同步 U9 客户写入操作日志：

| 动作编码 | 中文动作 | 模块 | targetType |
| --- | --- | --- | --- |
| `U9_CUSTOMER_SYNC` | 同步 U9 客户主数据 | `SYSTEM` | `u9_master_data_sync_run` |

日志摘要只允许包含：

- `syncRunId`
- `syncType`
- `status`
- `fetchedCount`
- `upsertedCount`
- `disabledCount`
- 脱敏后的 `safeMessage`

不得记录完整 U9 请求、响应、token、Authorization header、Cookie、账号密码或完整业务体。

## 7. 后端 API

路径前缀：`/api/system/customers`

| 方法 | 路径 | 权限 | 行为 |
| --- | --- | --- | --- |
| `GET` | `/api/system/customers` | `system:customer:view` | 分页查询 U9 客户缓存。 |
| `GET` | `/api/system/customers/options` | `system:customer:view` | 查询有效客户选项。 |
| `POST` | `/api/system/customers/sync` | `system:customer:sync` | 手动同步 U9 客户缓存。 |
| `POST` | `/api/system/customers` | 无业务入口 | 不提供映射，构造请求返回 405 或 404。 |
| `PUT` | `/api/system/customers/{id}` | 无业务入口 | 不提供映射，构造请求返回 405 或 404。 |
| `DELETE` | `/api/system/customers/{id}` | 无业务入口 | 不提供映射，构造请求返回 405 或 404。 |

分页查询参数：

- `field`：`all` / `code` / `shortName` / `name`
- `keyword`
- `page`
- `pageSize`

客户 DTO：

- `id`
- `u9OrgCode`
- `u9CustomerId`
- `customerCode`
- `customerShortName`
- `customerName`
- `enabled`
- `lastSyncedAt`
- `createdAt`
- `updatedAt`

## 8. 后端实现

当前核心类：

- `CustomerMaster.java`：U9 客户缓存实体。
- `CustomerMasterMapper.java`：只保留查询和同步缓存写入所需能力，不提供人工删除校验能力。
- `CustomerMasterDTO.java`：页面展示 DTO。
- `CustomerOptionDTO.java`：客户选择 DTO。
- `CustomerMasterService.java`：只提供分页、选项、名称列表等只读能力。
- `CustomerMasterController.java`：只提供查询、选项和手动同步入口。
- `U9MasterDataSyncService.java`：负责分页拉取 U9 客户、去重、upsert、停用标记和同步批次记录。

已移除或不再使用：

- `CustomerMasterSaveReq`
- `CustomerMasterService.saveCustomer`
- `CustomerMasterService.deleteCustomer`
- 客户新增、编辑、删除 Controller 映射
- 前端客户保存和删除 API

## 9. 前端设计

`CustomerManage.vue` 为只读页面：

- 页面标题：`客户资料`。
- 页面描述：来自 U9 的只读客户主数据，供 QPO 全系统客户选择和数据权限使用。
- 工具栏：筛选字段、关键词、查询、重置、刷新。
- 手动同步：`同步 U9 客户`，受 `system:customer:sync` 控制。
- 表格列：客户编码、客户简称、客户名称、有效状态、最近同步时间、来源。
- 不展示新增、编辑、删除按钮。
- 不保留新增/编辑弹窗。
- 表格内部允许横向滚动，小屏不能出现页面级横向溢出。

`customerApi.js` 只导出：

- `listCustomers`
- `listCustomerOptions`
- `syncCustomers`

不再导出 `createCustomer`、`updateCustomer`、`deleteCustomer`。

## 10. 全系统客户选择

客户选择能力继续复用模块自有权限，不新增 `common:customer:*`。

典型模块级客户选择权限包括：

- `market:rfq:customer-select`
- `market:quote-process:customer-select`
- `market:release:customer-select`
- `market:delivery-document:customer-select`
- `market:order:customer-select`
- `market:history-order:customer-select`
- `market:delivered-item:customer-select`
- `market:locked-item:customer-select`
- `engineer:setup:customer-select`

选择接口返回客户对象，调用方按业务需要保存客户编码和名称快照。

## 11. 数据兼容

本轮开发允许清空询价订单和销售订单做不兼容改造，但客户模块本身仍遵循以下兼容口径：

- 历史业务表中已保存的客户名称仍视为历史快照。
- 新业务应优先保存 `customer_code` 作为稳定身份。
- 数据权限指定客户改为客户编码口径时，应读取 U9 客户缓存选项。
- 客户名称变化不反向覆盖历史单据。

## 12. 验收标准

- 客户资料页面只能查看、筛选、刷新和同步。
- 构造请求无法新增、编辑或删除客户。
- 页面展示客户编码、客户名称、有效状态和同步时间。
- 无 `system:customer:view` 不能读取客户资料。
- 无 `system:customer:sync` 不能手动同步客户缓存。
- 客户查询和选项读取不产生操作日志噪声。
- 手动同步日志不包含完整 U9 请求、响应、token、Authorization header、Cookie、账号密码或完整业务体。
- 不新增可分配 `common:*` 权限。
