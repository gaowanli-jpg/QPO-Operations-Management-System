# QPO 客户主数据模块开发文档

最后更新：2026-09-05

> 2026-09-05 补充：客户资料仍以 U9 客户缓存为主数据来源，但新增 QPO 本地字段 `supplierCode`（数据库字段 `supplier_code`）用于维护客户对应供应商代码；该字段可为空，只能在客户资料模块维护，U9 客户同步不得覆盖。

> 2026-08-12 补充：客户定时同步策略由 `u9_customer_sync_schedule_config` 单行配置表和客户资料页“定时同步策略”弹窗维护，实际运行以数据库策略为准；`erp.env` / `application.yaml` 中的 `ERP_U9_CUSTOMER_SYNC_*` 仅作为配置缺失时的兜底默认值。策略入口位于“同步 U9 客户”左侧，复用 `system:customer:sync`，不新增 `common:*` 或客户写权限。

> 2026-08-11 阶段 8 权限、日志、文档和全量回归收口：客户只来自 U9 客户缓存，不存在可用客户本地新增、编辑、删除接口，不存在独立销售部门/销售员管理模块。本次同步更新权限、日志、清库脚本文档和部署顺序；后端权限仍是最终边界，普通查询不写操作日志，手动同步只记录安全摘要，不新增可分配 `common:*` 权限。

## 1. 当前口径

客户资料模块已经从“QPO 本地维护客户”改造为“U9 客户缓存 + QPO 本地供应商代码”。

现行原则：

- U9 是客户编码、简称、名称和启停状态的唯一来源，QPO 不允许新增、编辑或删除客户。
- `supplierCode` 是 QPO 本地维护的可选属性，U9 同步不得覆盖。
- QPO 本地只保存同步缓存，用于全系统客户选择、数据权限选择和销售订单 U9 同步。
- 客户稳定身份使用 `customer_code`，客户名称和简称只作为展示、搜索和历史快照字段。
- 销售订单、询价订单等业务单据保存客户编码和名称快照，避免 U9 主数据后续变化影响历史单据。
- 不新增可分配 `common:*` 客户权限。

## 2. 目标

- 客户资料页面可以查看、筛选、刷新、手动同步 U9 客户缓存、维护 U9 客户定时同步策略，并维护 QPO 本地字段 `supplierCode`。
- 所有客户选项来自 `customer_master` 的 U9 同步结果。
- 构造 `POST / PUT / DELETE /api/system/customers` 不能新增、编辑或删除客户；只允许通过专用接口修改 `supplierCode`。
- 客户资料展示客户编码、客户简称、客户名称、供应商代码、有效状态、最近同步时间和来源。
- U9 同步失败时保留上一轮成功缓存，并只记录脱敏错误摘要。

## 3. 非目标

- 不建设 QPO 本地客户完整维护能力。
- 不允许业务用户在 QPO 中修正客户编码、简称或名称。
- 不提供客户导入、批量编辑、批量删除或停用入口。
- 不把 U9 组织作为页面筛选条件暴露给业务用户；当前 U9 同步固定使用配置组织。
- 不新增销售部门/销售员左侧管理页面；销售订单 U9 同步页只使用本地缓存选项。

## 4. 数据模型

`customer_master` 是 U9 客户缓存表，核心字段如下：

| 字段 | 说明 |
| --- | --- |
| `customer_code` | U9 客户编码，QPO 客户稳定身份，销售订单同步时作为 U9 OrderBy。 |
| `customer_short_name` | U9 客户简称，用于展示和搜索。 |
| `customer_name` | U9 客户名称，用于展示、搜索和业务快照。 |
| `supplier_code` | QPO 本地维护的供应商代码，可为空；U9 同步不得覆盖。 |
| `u9_org_code` | 同步来源组织，当前配置为 U9 组织 `101`。 |
| `u9_customer_id` | U9 返回的客户主数据标识，仅用于排查和同步去重。 |
| `enabled` | U9 有效状态；新业务选择只允许有效客户。 |
| `last_synced_at` | 最近一次成功同步写入时间。 |
| `created_at` / `updated_at` | QPO 缓存记录时间。 |

同步约束：

- `customer_code` 是主要去重键。
- 客户名称不作为唯一身份，允许 U9 存在同名客户。
- 本轮 U9 未返回但本地已存在的客户不物理删除，只标记 `enabled=false`。
- `supplier_code` 不参与 U9 去重，不从 U9 读取；同步新增客户时为空，更新客户时保留本地原值。

## 5. 权限设计

| 授权能力 | 权限编码 | 类型 | 默认角色 | 说明 |
| --- | --- | --- | --- | --- |
| 客户资料 | `system:customer:view` | `MENU` | `SUPER_ADMIN`, `MARKET_MANAGER` | 控制客户资料入口、分页查询和客户选项读取。 |
| 同步 U9 客户 / 定时同步策略 | `system:customer:sync` | `BUTTON` | `SUPER_ADMIN` | 手动触发 U9 客户同步，或维护客户定时同步策略；写操作只记录安全摘要。 |
| 维护客户供应商代码 | `system:customer:supplier-code-update` | `BUTTON` | `SUPER_ADMIN`, `MARKET_MANAGER` | 仅允许维护 QPO 本地字段 `supplierCode`，不允许修改 U9 客户编码、简称、名称或启停状态。 |

已下线权限：

| 权限编码 | 处理方式 |
| --- | --- |
| `system:customer:create` | 从默认角色移除，数据库标记停用或不可分配。 |
| `system:customer:update` | 从默认角色移除，数据库标记停用或不可分配。 |
| `system:customer:delete` | 从默认角色移除，数据库标记停用或不可分配。 |

后端权限仍是最终边界，前端隐藏按钮不能替代后端校验。

## 6. 日志设计

普通客户列表查询、客户选项查询和客户选择弹窗不写操作日志，也不增加业务 INFO 文件日志。

手动同步 U9 客户写入操作日志：

| 动作编码 | 中文动作 | 模块 | targetType |
| --- | --- | --- | --- |
| `U9_CUSTOMER_SYNC` | 同步 U9 客户主数据 | `SYSTEM` | `u9_master_data_sync_run` |
| `U9_CUSTOMER_SYNC_SCHEDULE_UPDATE` | 更新 U9 客户定时同步策略 | `SYSTEM` | `u9_customer_sync_schedule_config` |
| `CUSTOMER_SUPPLIER_CODE_UPDATE` | 维护客户供应商代码 | `SYSTEM` | `customer_master` |

U9 同步日志摘要只允许包含：

- `syncRunId`
- `syncType`
- `status`
- `fetchedCount`
- `upsertedCount`
- `disabledCount`
- 脱敏后的 `safeMessage`

定时同步策略保存只允许记录 `enabled`、`startupDelayMs`、`fixedDelayMs`、`lastScheduledStatus` 等安全摘要；读取策略、定时巡检和普通查询不写操作日志。

供应商代码保存只记录客户 ID、客户编码、客户名称和变更前后 `supplierCode`；不记录完整客户对象、U9 原始响应或认证信息。

不得记录完整 U9 请求、响应、token、Authorization header、Cookie、账号密码或完整业务体。

## 7. 后端 API

路径前缀：`/api/system/customers`

| 方法 | 路径 | 权限 | 行为 |
| --- | --- | --- | --- |
| `GET` | `/api/system/customers` | `system:customer:view` | 分页查询 U9 客户缓存。 |
| `GET` | `/api/system/customers/options` | `system:customer:view` | 查询有效客户选项。 |
| `PUT` | `/api/system/customers/{id}/supplier-code` | `system:customer:supplier-code-update` | 维护客户 QPO 本地字段 `supplierCode`，可传空值清空。 |
| `POST` | `/api/system/customers/sync` | `system:customer:sync` | 手动同步 U9 客户缓存。 |
| `GET` | `/api/system/customers/sync-schedule` | `system:customer:sync` | 读取 U9 客户定时同步策略。 |
| `PUT` | `/api/system/customers/sync-schedule` | `system:customer:sync` | 保存 U9 客户定时同步策略。 |
| `POST` | `/api/system/customers` | 无业务入口 | 不提供映射，构造请求返回 405 或 404。 |
| `PUT` | `/api/system/customers/{id}` | 无业务入口 | 不提供映射，构造请求返回 405 或 404。 |
| `DELETE` | `/api/system/customers/{id}` | 无业务入口 | 不提供映射，构造请求返回 405 或 404。 |

分页查询参数：

- `field`：`all` / `code` / `shortName` / `name` / `supplierCode`
- `keyword`
- `page`
- `pageSize`

客户 DTO：

- `id`
- `u9OrgCode`
- `u9CustomerId`
- `customerCode`
- `customerShortName`
- `customerName`
- `supplierCode`
- `enabled`
- `lastSyncedAt`
- `createdAt`
- `updatedAt`

## 8. 后端实现

当前核心类：

- `CustomerMaster.java`：U9 客户缓存实体。
- `CustomerMasterMapper.java`：只保留查询和同步缓存写入所需能力，不提供人工删除校验能力。
- `CustomerMasterDTO.java`：页面展示 DTO。
- `CustomerOptionDTO.java`：客户选择 DTO。
- `CustomerMasterService.java`：提供分页、选项、名称列表等读取能力，以及 `supplierCode` 专用保存能力。
- `CustomerMasterController.java`：提供查询、选项、`supplierCode` 专用保存和手动同步入口。
- `U9MasterDataSyncService.java`：负责分页拉取 U9 客户、去重、upsert、停用标记和同步批次记录。
- `U9CustomerSyncScheduleConfigService.java`：负责读取/保存定时同步策略，缺失配置时才回退环境默认值，并按启动延迟和完成后间隔判断是否到点。

已移除或不再使用：

- `CustomerMasterSaveReq`
- `CustomerMasterService.saveCustomer`
- `CustomerMasterService.deleteCustomer`
- 客户新增、编辑、删除 Controller 映射
- 前端客户保存和删除 API

## 9. 前端设计

`CustomerManage.vue` 为 U9 字段只读、`supplierCode` 可维护页面：

- 页面标题：`客户资料`。
- 页面描述：来自 U9 的客户主数据；供应商代码为 QPO 本地维护字段。
- 工具栏：筛选字段、关键词、查询、重置、刷新。
- 定时策略：`定时同步策略`，位于 `同步 U9 客户` 左侧，受 `system:customer:sync` 控制。
- 手动同步：`同步 U9 客户`，受 `system:customer:sync` 控制。
- 表格列：客户编码、客户简称、客户名称、供应商代码、有效状态、最近同步时间、来源。
- 供应商代码：行内编辑保存，受 `system:customer:supplier-code-update` 控制；空值保存表示清空。
- 不展示新增、编辑、删除按钮。
- 不保留新增/编辑弹窗。
- 表格内部允许横向滚动，小屏不能出现页面级横向溢出。

`customerApi.js` 只导出：

- `listCustomers`
- `listCustomerOptions`
- `updateCustomerSupplierCode`
- `syncCustomers`
- `getCustomerSyncSchedule`
- `saveCustomerSyncSchedule`

不再导出 `createCustomer`、`updateCustomer`、`deleteCustomer`。

## 10. 全系统客户选择

客户选择能力继续复用模块自有权限，不新增 `common:customer:*`。

典型模块级客户选择权限包括：

- `market:rfq:customer-select`
- `market:quote-process:customer-select`
- `market:release:customer-select`
- `market:delivery-document:customer-select`
- `market:order:customer-select`
- `market:history-order:customer-select`
- `market:delivered-item:customer-select`
- `market:locked-item:customer-select`
- `engineer:setup:customer-select`

选择接口返回客户对象，调用方按业务需要保存客户编码和名称快照。

## 11. 数据兼容

本轮开发允许清空询价订单和销售订单做不兼容改造，但客户模块本身仍遵循以下兼容口径：

- 历史业务表中已保存的客户名称仍视为历史快照。
- 新业务应优先保存 `customer_code` 作为稳定身份。
- 数据权限指定客户改为客户编码口径时，应读取 U9 客户缓存选项。
- 客户名称变化不反向覆盖历史单据。

## 12. 验收标准

- 客户资料页面可以查看、筛选、刷新、同步和维护供应商代码。
- 构造请求无法新增、编辑或删除客户。
- 构造请求只能通过专用接口修改 `supplierCode`，不能修改客户编码、简称、名称或启停状态。
- 页面展示客户编码、客户名称、有效状态和同步时间。
- 页面展示并可保存供应商代码；供应商代码允许为空。
- 无 `system:customer:view` 不能读取客户资料。
- 无 `system:customer:sync` 不能手动同步客户缓存。
- 无 `system:customer:supplier-code-update` 不能保存供应商代码，前端按钮隐藏且后端接口拦截。
- 无 `system:customer:sync` 不能查看或保存定时同步策略，前端按钮隐藏且后端接口拦截。
- 定时同步实际运行以数据库策略为准，环境变量只作为缺失配置兜底。
- 策略保存日志不包含完整 U9 请求、响应、token、Authorization header、Cookie、client secret 或凭据。
- 客户查询和选项读取不产生操作日志噪声。
- 手动同步日志不包含完整 U9 请求、响应、token、Authorization header、Cookie、账号密码或完整业务体。
- 供应商代码保存日志不包含完整客户对象、完整 U9 响应、token、Authorization header、Cookie、账号密码或完整业务体。
- 不新增可分配 `common:*` 权限。

## 13. 清库脚本和部署顺序

订单链路客户编码切换允许清空询价订单、销售订单及其依赖业务数据，但客户缓存、权限、用户、系统配置和日志不随订单一起清空。

部署顺序：

1. 先备份数据库。
2. 在目标环境确认后，执行 `docs/ops/sql/clear_order_business_data_before_u9_customer_cutover.sql`，并在同一 SQL 会话设置 `SET qpo.confirm_clear_order_business_data = 'YES'`。
3. 部署后端并执行 Flyway V6/V7。
4. 同步 U9 客户缓存和 U9 同步选项缓存。
5. 按 U9 客户编码重新配置角色数据范围。
6. 部署前端，再执行全量回归。

清库脚本不得进入 Flyway 自动迁移；脚本不清空 `customer_master`、`u9_sync_seller_option_cache`、`u9_sync_department_option_cache`、`u9_master_data_sync_run`、用户、角色、权限、系统配置或日志。
