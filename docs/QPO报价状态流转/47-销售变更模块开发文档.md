# 销售变更模块开发文档

> 编写日期：2026-08-24
> 适用范围：QPO 销售订单已同步 U9 后的本地数据校正。
> 核心边界：本模块只修改 QPO 本地销售订单零件数据，不调用 U9 / MES / WMS，不创建 U9 变更单，不删除或重建 U9 销售订单。

## 1. 背景

当前 QPO 的 U9 同步链路采用“同步前可维护、同步后锁定”的设计：销售订单同步到 U9 后，`u9_sync_status = 已同步` 的订单不能再通过 U9 同步页修改零件行，也不能再次执行创建型 U9 同步。

实际业务中，销售订单同步到 U9 后，操作员可能在 U9 中人工调整了销售订单相关数据。此时 QPO 需要提供一个受控入口，让操作员把 QPO 本地销售订单零件数据调整为与 U9 一致，避免两边数据长期对不上。

本次不处理 U9 侧自动变更，因为 U9 销售订单可能存在开立、审核、后续单据、变更单、删除 / 作废等复杂状态。第一版只做 QPO 可把握的本地校正能力。

## 2. 目标

- 新增左侧一级模块 **变更**，位于 **订单** 与 **系统** 之间。
- 在 **变更** 下新增页面 **销售变更**。
- 销售变更只允许选择 `u9_sync_status = 已同步` 的销售订单。
- 支持对已同步 U9 销售订单的零件行进行本地修改，字段范围完全复用当前 U9 同步页已支持的零件字段。
- 支持表格数据替换：上传 Excel 后先预览差异，再确认落库。
- 保存和确认替换时必须填写 **变更原因**。
- 保存成功后保留销售订单 `u9_sync_status = 已同步`，不得改成未同步、同步失败或结果待确认。
- 任何操作不得触发 U9 / MES / WMS 外部接口，也不得改变 U9 单号、U9 同步尝试号或原创建结果。
- 操作日志和变更记录能够追踪：谁、什么时候、因为什么原因、修改了哪张销售订单、多少行、哪些字段。

## 3. 非目标

- 不调用 U9 修改接口。
- 不创建 U9 销售订单变更单。
- 不删除、作废或重建 U9 原销售订单。
- 不做二次同步 U9。
- 不开放订单头字段修改。
- 不修改图纸、物料号、图号、版本、行号。
- 不绕过已有销售订单数据权限。
- 不新增可分配 `common:*` 权限。

## 4. 业务口径

### 4.1 模块定位

**销售变更** 是“U9 已人工处理后的 QPO 本地追平工具”，不是 U9 同步工具。

页面必须显著提示：

```text
本功能仅修改 QPO 本地销售订单零件数据，不会同步到 U9。请确认 U9 已完成对应调整后再保存。
```

### 4.2 可操作订单

只允许选择满足以下条件的销售订单：

- 订单存在于 `sales_order_header`。
- `u9_sync_status = 已同步`。
- 通过当前用户数据权限校验。

以下订单不得进入变更保存：

- `未同步`：应回到 U9 同步页同步前维护。
- `同步失败`：应回到 U9 同步页修正后重试。
- `同步中`：需要等待或核对 U9 结果。
- `结果待确认`：必须先在 U9 同步页核对。

### 4.3 可修改字段

第一版只允许修改当前 U9 同步页已经支持的 8 个零件字段：

| 字段 | 来源列 | 说明 |
| --- | --- | --- |
| `qty` | `sales_order_item.qty` | 销售数量，必须为正整数，且不得小于已提数量、已出货数量。 |
| `customerDeliveryDate` | `sales_order_item.customer_delivery_date` | 客户交期。 |
| `internalDeliveryDate` | `sales_order_item.internal_delivery_date` | 内部交期。 |
| `untaxedUnitPrice` | `sales_order_item.untaxed_unit_price` | 未税单价，必须大于等于 0。 |
| `customerOrderNo` | `sales_order_item.customer_order_no` | 零件级客户订单号。 |
| `customerProjectNo` | `sales_order_item.customer_project_no` | 零件级客户项目号。 |
| `internalProjectNo` | `sales_order_item.internal_project_no` | 零件级内部项目号。 |
| `remark` | `sales_order_item.remark` | 零件级备注。 |

以下字段只展示，不允许修改：

- 销售订单号。
- U9 单号 / U9 编码。
- 图号。
- 版本。
- 行号。
- 物料号。
- 物料号状态。
- 已提数量。
- 已出货数量。
- 图纸。
- 工艺路线。
- 材料 / 费用 JSON。

### 4.4 变更原因

保存和确认表格替换时必须填写变更原因。

原因规则：

- 必填。
- 去除首尾空格后长度 5 到 500 字符。
- 用于说明 U9 侧已发生的人工调整或业务确认依据。
- 写入销售变更记录和操作日志摘要。
- 不允许记录 token、密码、Authorization、完整外部请求体、完整 U9 响应或图纸 URL。

推荐前端占位文案：

```text
请填写变更原因，例如：U9 已人工调整交期，QPO 本地同步校正。
```

## 5. 权限设计

新增一级业务域：`change`。

| 能力 | 权限编码 | 类型 | 默认角色 | 说明 |
| --- | --- | --- | --- | --- |
| 查看销售变更 | `change:sales-order:view` | `MENU` | SUPER_ADMIN, MARKET_MANAGER, MARKET_USER, READONLY | 控制左侧“变更 > 销售变更”入口、路由和只读页面。 |
| 销售变更选择客户 | `change:sales-order:customer-select` | `API` | SUPER_ADMIN, MARKET_MANAGER, MARKET_USER, READONLY | 控制销售变更页客户筛选 / 选择能力。 |
| 销售变更选择订单 | `change:sales-order:order-select` | `API` | SUPER_ADMIN, MARKET_MANAGER, MARKET_USER, READONLY | 控制已同步销售订单列表和订单选择。 |
| 保存销售变更 | `change:sales-order:update` | `BUTTON` | SUPER_ADMIN, MARKET_MANAGER, MARKET_USER | 控制行内保存和表格替换确认。READONLY 不授予。 |

说明：

- 后端接口必须使用 `@RequirePermission` 做最终权限校验。
- 前端隐藏按钮不能替代后端权限。
- 不复用 `market:u9-sync:submit`，避免管理员误认为销售变更会同步 U9。
- 不新增任何 `common:*` 权限。

## 7. 页面设计

页面整体参考 `SalesOrderU9Sync.vue`，但移除所有 U9 同步动作。

### 7.1 顶部操作区

- 标题：销售变更。
- 说明：校正已同步 U9 后的 QPO 本地销售订单零件数据。
- 按钮：选择销售订单、刷新。
- 不展示：同步 U9、核对 U9 结果、刷新 U9 选项、保存 Seller / SaleDepartment。

### 7.2 左侧订单信息区

展示当前选中订单：

- 销售订单号。
- 客户。
- 下单日期。
- 订单类型。
- 内部项目号。
- 当前 U9 状态：固定要求为 `已同步`。
- U9 编码 / U9 单号。
- 订单状态。

展示提示：

```text
本页面只做 QPO 本地校正，不会调用 U9。请确认 U9 已经完成对应人工调整。
```

### 7.3 主表格区

表格列参考 U9 同步页零件表，保留：

- 图号。
- 行号。
- 版本。
- 物料号。
- 物料号状态。
- 数量。
- 未税单价。
- 未税金额。
- 客户交期。
- 内部交期。
- 客户订单号。
- 客户项目号。
- 内部项目号。
- 备注。
- 已提数量。
- 已出货数量。

可编辑控件只出现在 8 个允许字段上。

### 7.4 保存交互

行内修改后：

- 页面显示“已修改 N 行”。
- 点击“保存修改”时弹出确认框或抽屉，要求填写变更原因。
- 变更原因通过校验后提交。
- 保存成功后刷新预览，清空脏状态。

### 7.5 表格数据替换

新增“表格数据替换”按钮，复用 U9 同步页表格替换体验：

- 上传 Excel。
- 后端解析。
- 按 `图号 + 版本 + 可选行号` 匹配当前销售订单零件。
- 展示识别字段、差异、错误行、未匹配行。
- 空单元格不覆盖现有值。
- 错误行存在时不能确认。
- 确认替换时必须填写变更原因。
- 确认成功后刷新页面数据。

继续固化图号整体解析规则：不支持 `图号-说明` 和 `图号_版本-说明`，例如 `LK17.5.1.1-1` 必须整体识别为图号。

基础路径：


| `page` | number | 否 | 默认 1。 |

固定条件：

```sql

```

不得通过请求参数覆盖该条件。

### 8.2 订单预览

```http
GET /api/change/sales-orders/{salesOrderId}/preview
```

权限：

```text
change:sales-order:view
```

返回内容可复用 U9 同步预览 DTO 的主要订单和零件字段，但应移除“是否可同步 U9”的语义，新增本地变更语义：

```json
{
  "salesOrderId": 1,
  "salesOrderNo": "SO-001",
  "u9SyncStatus": "已同步",
  "u9OrderCode": "U9-SO-001",
  "changeEditable": true,
  "changeBlockedReason": null,
  "lines": []
}
```

### 8.3 行内保存

```http
PUT /api/change/sales-orders/{salesOrderId}/items
```

权限：

```text
change:sales-order:update
```

请求体：

```json
{
  "reason": "U9 已人工调整交期，QPO 本地同步校正",
  "items": [
    {
      "salesOrderItemId": 1001,
      "qty": 10,
      "customerDeliveryDate": "2026-09-10",
      "internalDeliveryDate": "2026-09-08",
      "untaxedUnitPrice": "12.50",
      "customerOrderNo": "PO-001",
      "customerProjectNo": "CP-001",
      "internalProjectNo": "IP-001",
      "remark": "U9 已调整"
    }
  ]
}
```

校验规则：

- `reason` 必填。
- 销售订单必须存在且 `u9_sync_status = 已同步`。
- 当前用户必须具备订单数据权限。
- `items` 不为空。
- `salesOrderItemId` 必须属于当前销售订单。
- 同一请求内不得重复提交同一个 `salesOrderItemId`。
- 至少包含一个可编辑字段。
- `qty` 必须为正整数，且不得小于 `released_qty`、`shipped_qty`。
- `untaxedUnitPrice` 必须大于等于 0。
- 文本字段长度沿用 U9 同步页保存限制。

保存规则：

- 更新 `sales_order_item` 的 8 个允许字段。
- 重算 `untaxed_total_price`。
- 如存在 `tax_included_unit_price`，同步重算 `tax_included_total_price`。
- 重算 `remaining_qty = max(0, qty - released_qty)`。
- 重算 `unshipped_qty = max(0, qty - shipped_qty)`。
- 更新 `sales_order_item.updated_at`。
- 不修改 `u9_sync_status`。
- 不修改 `u9_order_id`、`u9_order_code`、`u9_sync_attempt_id`。
- 不调用外部系统。

### 8.4 表格替换预览

```http
POST /api/change/sales-orders/{salesOrderId}/item-data-replacement/preview
Content-Type: multipart/form-data
```

权限：

```text
change:sales-order:update
```

表单字段：

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `excelFile` | file | 是 | `.xlsx` 或 `.xls`。 |

预览不写数据库，不写操作日志。

### 8.5 表格替换确认

```http
POST /api/change/sales-orders/{salesOrderId}/item-data-replacement/confirm
Content-Type: multipart/form-data
```

权限：

```text
change:sales-order:update
```

表单字段：

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `excelFile` | file | 是 | 与预览文件一致。 |
| `previewFingerprint` | string | 是 | 预览指纹。 |
| `reason` | string | 是 | 变更原因。 |

确认规则：

- 重新解析 Excel。
- 加锁订单头和零件行。
- 重新生成预览。
- 校验 `previewFingerprint`，防止旧预览确认。
- 错误行存在时拒绝确认。
- 未匹配行不阻断确认，但不落库。
- 任一落库异常导致整批回滚。
- 不调用外部系统。

## 9. 后端服务设计

建议新增服务：

```text
SalesOrderChangeService
SalesOrderChangeItemEditService
SalesOrderChangeItemDataReplacementService
```

### 9.1 复用策略

当前 U9 同步模块已经有：

- `SalesOrderU9ItemEditService`
- `SalesOrderU9ItemDataReplacementService`
- `SalesOrderU9ItemDataReplacementExcelParser`
- `SalesOrderU9ItemDataReplacementField`
- U9 同步预览 DTO 和行 DTO

销售变更第一版可以复用以下能力：

- Excel 字段识别。
- 图号 + 版本 + 可选行号匹配。
- 空单元格不覆盖。
- 数量、价格、日期、文本长度校验。
- 金额和剩余数量重算逻辑。
- 预览指纹机制。

但必须改造状态策略：

| 场景 | U9 同步页 | 销售变更页 |
| --- | --- | --- |
| `未同步` | 可编辑 | 不可编辑 |
| `同步失败` | 可编辑 | 不可编辑 |
| `同步中` | 不可编辑 | 不可编辑 |
| `结果待确认` | 不可编辑 | 不可编辑 |
| `已同步` | 不可编辑 | 可编辑 |

建议抽出共享 helper，避免复制大量逻辑：

```text
SalesOrderItemEditableFieldSupport
SalesOrderItemDataReplacementSupport
```

如果第一阶段为降低风险选择复制服务，也必须用测试锁定两个模块的状态差异，避免后续维护时互相串逻辑。

## 10. 数据库设计

### 10.1 变更批次表

建议新增 `sales_order_change_record`，用于记录每次本地校正批次。

```sql
CREATE TABLE IF NOT EXISTS sales_order_change_record (
    id BIGSERIAL PRIMARY KEY,
    sales_order_id BIGINT NOT NULL,
    sales_order_no VARCHAR(100) NOT NULL,
    change_type VARCHAR(40) NOT NULL,
    reason VARCHAR(500) NOT NULL,
    updated_count INTEGER NOT NULL DEFAULT 0,
    changed_fields_json TEXT,
    created_by BIGINT,
    created_by_name VARCHAR(100),
    created_at TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP
);

CREATE INDEX IF NOT EXISTS idx_sales_order_change_record_order
    ON sales_order_change_record(sales_order_id, created_at DESC);
```

`change_type` 建议值：

- `INLINE_UPDATE`
- `DATA_REPLACEMENT`

### 10.2 变更明细表

建议新增 `sales_order_change_record_item`，用于记录发生变化的零件行快照。

```sql
CREATE TABLE IF NOT EXISTS sales_order_change_record_item (
    id BIGSERIAL PRIMARY KEY,
    change_record_id BIGINT NOT NULL,
    sales_order_item_id BIGINT NOT NULL,
    line_no INTEGER,
    part_no VARCHAR(200),
    version VARCHAR(80),
    changed_fields_json TEXT,
    before_snapshot_json TEXT,
    after_snapshot_json TEXT,
    created_at TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP
);

CREATE INDEX IF NOT EXISTS idx_sales_order_change_record_item_record
    ON sales_order_change_record_item(change_record_id);

CREATE INDEX IF NOT EXISTS idx_sales_order_change_record_item_item
    ON sales_order_change_record_item(sales_order_item_id);
```

说明：

- 变更记录表用于业务追溯，不替代 `audit_log`。
- `audit_log` 记录低噪声摘要；变更记录保存本次修改前后快照。
- 快照只包含允许修改的 8 个字段及行身份字段，不保存图纸 URL、材料 JSON、工艺路线、完整价格明细或外部响应。

| action | module | targetType | 触发时机 |

安全摘要字段：

| 字段 | 说明 |
| --- | --- |
| `salesOrderId` | 销售订单 ID。 |
| `salesOrderNo` | 销售订单号。 |
| `changeRecordId` | 变更记录 ID。 |
| `reason` | 变更原因，最长 500 字符。 |
| `updatedCount` | 实际更新行数。 |
| `changedFields` | 字段编码集合。 |
| `importedCount` | 表格替换导入行数，仅替换动作记录。 |
| `matchedCount` | 表格替换匹配行数，仅替换动作记录。 |
| `unmatchedCount` | 表格替换未匹配行数，仅替换动作记录。 |
| `errorCount` | 表格替换错误行数，仅替换动作记录。 |
| `durationMs` | 耗时。 |

禁止写入：

- Excel 原文。
- 完整解析行。
- 完整 before / after 明细。
- 完整价格明细。
- 图纸 URL。
- U9 请求 / 响应。
- token。
- Authorization header。
- Cookie。

## 12. 数据一致性影响

### 12.1 销售订单状态

保存后：

- `sales_order_header.u9_sync_status` 保持 `已同步`。
- `sales_order_header.u9_order_id` 保持不变。
- `sales_order_header.u9_order_code` 保持不变。
- `sales_order_header.u9_sync_request_hash` 保持原同步请求 hash，不作为本地变更后的最新 hash 使用。

### 12.2 下游接口

销售变更只修改销售订单本地数据，因此会影响所有读取 `sales_order_item` 当前值的 QPO 页面或只读接口。

必须确认：

- 不触发 MES 物料号获取。
- 不触发 WMS 锁库。
- 不触发 MES 生产下发。
- 不触发 U9 同步。
- 不自动改变已提零件、待产零件、锁库零件历史任务结果。

如外部销售订单同步接口按 `sales_order_item.updated_at` 计算 `changedAt`，本地变更后应正常进入增量同步水位，这是预期行为。

## 18. 风险与注意事项

- 销售变更是本地校正，不代表 U9 已被 QPO 修改。页面文案必须持续强调这一点。
- 如果 U9 人工调整后的数量小于 QPO 已提数量或已出货数量，第一版不允许直接保存，应先做业务治理，否则会破坏 QPO 本地库存 / 交付数量约束。
- `u9_sync_request_hash` 是当时创建 U9 的请求 hash，本地校正后不应拿它代表当前最新本地数据。
- 表格替换确认必须使用预览指纹，避免多人同时修改导致旧预览覆盖新数据。
- 变更原因属于业务审计信息，可以记录，但仍需避免填写认证信息、外部完整报文或图纸 URL。
