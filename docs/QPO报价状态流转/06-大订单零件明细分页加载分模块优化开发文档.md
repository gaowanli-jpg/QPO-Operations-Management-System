# QPO 大订单零件明细分页加载分模块优化开发文档

## 1. 背景

当前 QPO 的订单选择链路已经具备服务端分页：

```text
选择客户
  -> 选择订单状态
  -> 服务端分页选择 RFQ 订单
  -> 选中订单后加载订单零件明细
```

真正的大单性能风险不在“订单选择弹窗”，而在“选中订单后加载零件明细”。目前多个模块仍会一次性返回整单 `itemList`，前端再用 `paginateRows()` 做前端分页。订单零件几十到几百条时体验正常；如果单个订单达到几千到上万零件，会出现接口响应慢、JSON 过大、浏览器内存占用高、保存后刷新慢、跨页勾选不稳定等问题。

本优化目标是按实际模块分开处理：

- 订单选择列表继续使用现有服务端分页。
- 全局设定页继续只做前 10 个零件预览。
- 需要逐件操作的页面改为服务端分页。
- 需要跨页批量操作的页面改为“分页展示 + 选中 ID 集合 + 后端全量动作”。
- 导出、整单核价、重复件复用、提单生成等全量业务动作继续放在后端按订单全量处理，不受页面分页影响。

## 2. 当前使用点盘点

| 模块 | 当前接口 / 代码位置 | 当前行为 | 风险判断 | 优化策略 |
| --- | --- | --- | --- | --- |
| 订单选择弹窗 | `OrderPickerDialog.vue` + `OrderManagementService.listOrders()` | 服务端分页订单 | 低 | 保持现状 |
| 全局设定页 | `/api/engineer/setup/summary/{rfqId}` | 只返回前 10 个零件预览 | 低 | 保持现状，补测试护栏 |
| 逐件核价页 | `/api/engineer/pricing/summary/{rfqId}` | 一次返回整单 `itemList`，前端分页 | 高 | 拆为摘要 + 零件服务端分页 |
| 报价处理页 | `/api/market/quote-process/{rfqId}` | 一次返回整单 `itemList`，前端分页 | 高 | 拆为摘要 + 零件服务端分页，批量交期按 ID 操作 |
| 议价提单页 | `/api/market/release/summary/{rfqId}` + `/internal-target-lead-time/{rfqId}/items` | 加载整单零件、提单、工艺表，前端分页 | 很高 | 零件、提单、工艺表均分页；跨页选择用 ID 集合 |
| 订单管理详情 | `/api/order-management/orders/{rfqId}` | 一次返回零件、提单、工艺表 | 中高 | 详情拆标签分页，补图纸动作后只刷新摘要和当前页 |
| 历史订单详情 | 复用订单管理详情接口 | 一次返回零件、提单、工艺表 | 中高 | 复用订单详情分页接口，只读展示 |
| 报价单 / 核价单 / 提单导出 | `ExcelExportService`、`QuoteTemplateExportService` | 后端全量导出 | 合理 | 保持全量，必要时异步化另开专项 |
| 重复件复用 / 刷新核价 / 完成整单核价 | `EngineerService`、`SystemTaskService` | 后端按整单处理 | 合理 | 保持后端全量，不依赖页面当前页 |

## 3. 总体设计

### 3.1 通用分页口径

新增统一分页请求和返回结构，供各模块复用：

```text
page       默认 1，最小 1
pageSize   默认 50，最大 100
keyword    可选，匹配图号 / 版本 / 描述
status     可选，模块允许时使用
partNo     可选，精确或模糊按模块决定
version    可选，精确匹配
```

建议新增 DTO：

```text
quote-backend/src/main/java/com/machining/quote/dto/OrderItemPageReq.java
quote-backend/src/main/java/com/machining/quote/dto/OrderItemPageDTO.java
quote-backend/src/main/java/com/machining/quote/dto/OrderItemSummaryDTO.java
```

分页返回统一包含：

```json
{
  "records": [],
  "total": 0,
  "page": 1,
  "pageSize": 50,
  "summary": {
    "itemCount": 0,
    "pricedCount": 0,
    "quotedCount": 0,
    "releasedCount": 0,
    "missingDrawingCount": 0
  }
}
```

### 3.2 通用后端服务

新增共享查询服务：

```text
quote-backend/src/main/java/com/machining/quote/service/OrderItemPageService.java
```

职责：

- 校验订单存在。
- 接入 `DataScopeService.assertCanAccessOrder(order)`。
- 按 `rfq_id` 查询分页零件。
- 提供模块所需 summary 统计。
- 提供基础行 DTO，再由模块服务补充模块字段。

不建议把所有模块字段都塞进一个超大 DTO。基础字段由共享服务提供，模块字段在各自 Service 中补齐。

### 3.3 数据库索引

当前大部分大单查询都围绕 `rfq_id` 加排序、状态、图号版本筛选。建议新增或确认以下索引：

```sql
CREATE INDEX IF NOT EXISTS idx_item_quote_version_rfq_id_id
    ON item_quote_version(rfq_id, id);

CREATE INDEX IF NOT EXISTS idx_item_quote_version_rfq_status_id
    ON item_quote_version(rfq_id, status, id);

CREATE INDEX IF NOT EXISTS idx_item_quote_version_rfq_part_version_id
    ON item_quote_version(rfq_id, part_no, version, id);

CREATE INDEX IF NOT EXISTS idx_order_delivery_ticket_rfq_id_id
    ON order_delivery_ticket(rfq_id, id);

CREATE INDEX IF NOT EXISTS idx_order_delivery_ticket_rfq_item_id
    ON order_delivery_ticket(rfq_id, item_id);
```

说明：

- `rfq_id, id` 支撑按订单取零件当前页。
- `rfq_id, status, id` 支撑按订单状态统计和筛选。
- `rfq_id, part_no, version, id` 支撑订单内图号版本定位、组合件候选、补图纸匹配。
- 提单表索引用于议价提单页剩余数量、提单列表、工艺表快照查询。
- 不新增客户索引解决单订单零件分页，因为客户过滤发生在订单列表，不发生在单订单零件页。

## 4. 分模块优化方案

### 4.1 订单选择弹窗

涉及文件：

```text
quote-frontend/src/components/OrderPickerDialog.vue
quote-backend/src/main/java/com/machining/quote/service/OrderManagementService.java
```

当前已经是服务端分页订单列表，保留现状。

验收：

- 选择客户、状态后只加载当前页订单。
- 搜索 RFQ 号仍触发服务端分页查询。
- 不因为本次大单零件优化改动订单选择权限或数据范围。

### 4.2 全局设定页

涉及文件：

```text
quote-backend/src/main/java/com/machining/quote/controller/EngineerController.java
quote-frontend/src/components/GlobalSetup.vue
quote-backend/src/test/java/com/machining/quote/EngineerSetupPreviewTest.java
quote-frontend/src/engineeringSetupStage5.test.js
```

当前 `/api/engineer/setup/summary/{rfqId}` 已经只返回前 10 个零件预览和 `itemCount`。该页面职责是帮助工程师快速看订单概况、保存全局默认设定，不承担全量逐件核价。

优化策略：

- 保持 `SETUP_PREVIEW_LIMIT = 10`。
- 保持 `itemList` / `previewItemList` 只返回前 10 条。
- 增加测试护栏，防止后续又改回全量加载。

验收：

- 订单有 5000 个零件时，全局设定页仍只加载 10 条预览。
- 页面显示总零件数，不显示全量零件表。

### 4.3 逐件核价页

涉及文件：

```text
quote-backend/src/main/java/com/machining/quote/controller/EngineerController.java
quote-backend/src/main/java/com/machining/quote/service/EngineerService.java
quote-backend/src/main/java/com/machining/quote/service/OrderItemPageService.java
quote-frontend/src/services/engineerApi.js
quote-frontend/src/components/ItemPricing.vue
quote-frontend/src/itemPricingRepeatQuote.test.js
```

当前风险：

- `/api/engineer/pricing/summary/{rfqId}` 一次返回整单 `itemList`。
- 前端指标 `零件总数 / 已核价 / 重复件` 基于全量数组计算。
- 当前页分页是前端分页。
- 组合件核价弹窗的子件候选来自全量 `itemList`。

目标接口：

```text
GET /api/engineer/pricing/summary/{rfqId}
GET /api/engineer/pricing/items/{rfqId}?page=1&pageSize=50&keyword=&status=
GET /api/engineer/pricing/assembly-child-candidates/{rfqId}?parentItemId=1&page=1&pageSize=50&keyword=
```

接口口径：

- `pricing/summary` 只返回订单信息、统计数、全局配置，不返回全量 `itemList`。
- `pricing/items` 返回当前页核价零件。
- `assembly-child-candidates` 专门用于组合件弹窗选择子件，避免依赖当前页或全量数组。
- `applyRepeatQuotes(rfqId)`、`refreshOrderQuotes(rfqId)`、`completeOrderQuote(rfqId)` 继续由后端全量处理，完成后前端刷新 summary 和当前页。

前端改造：

- `quoteData.itemList` 改为当前页数据，不再代表全量。
- 指标区改用后端 summary。
- 表格分页改为服务端分页。
- 保存单个零件后只刷新当前页该行或当前页。
- 自动重复件复用仍在首次进入逐件核价页后触发一次，但不依赖全量前端 `itemList`。

验收：

- 进入 5000 零件订单时，逐件核价页只请求第一页零件。
- 翻页时请求后端分页接口。
- 保存单个零件不重新拉取整单零件。
- 组合件子件选择可搜索并分页，不受当前页限制。
- 完成整单核价仍按整单校验，不只校验当前页。

### 4.4 报价处理页

涉及文件：

```text
quote-backend/src/main/java/com/machining/quote/controller/QuoteProcessController.java
quote-backend/src/main/java/com/machining/quote/service/QuoteProcessService.java
quote-frontend/src/services/marketApi.js
quote-frontend/src/components/QuoteProcess.vue
quote-frontend/src/quoteProcess*.test.js
```

当前风险：

- `getQuoteProcess(rfqId)` 一次返回整单报价零件。
- 前端批量调整报价交期依赖已加载全量 `itemList`。
- 保存报价单后返回整单 `itemList`。

目标接口：

```text
GET /api/market/quote-process/{rfqId}/summary
GET /api/market/quote-process/{rfqId}/items?page=1&pageSize=50&keyword=&status=
POST /api/market/quote-process/lead-time/shift
POST /api/market/quote-process/lead-time/set
POST /api/market/quote-process/lead-time/update
POST /api/market/quote-process/{rfqId}/save-quote
```

接口口径：

- `summary` 返回订单信息、零件总数、缺报价交期数量、已报价数量。
- `items` 返回当前页报价处理行。
- 批量交期接口继续按 `itemIds` 更新，不要求前端持有全量行。
- 保存报价单继续后端整单处理；返回保存摘要，不返回整单 `itemList`。

前端改造：

- 批量选择改为跨页 `selectedItemIds` 集合。
- 当前页表格选择变化只影响当前页 ID。
- 批量交期成功后刷新 summary 和当前页。
- 保存报价单成功后刷新 summary 和当前页。

验收：

- 5000 零件订单报价处理页首屏只加载当前页。
- 跨页勾选后批量调整只提交选中 ID。
- 保存报价单不返回整单零件。
- 导出报价单仍导出整单。

### 4.5 议价提单页

涉及文件：

```text
quote-backend/src/main/java/com/machining/quote/controller/MarketController.java
quote-backend/src/main/java/com/machining/quote/controller/InternalTargetLeadTimeController.java
quote-backend/src/main/java/com/machining/quote/service/InternalTargetLeadTimeService.java
quote-backend/src/main/java/com/machining/quote/service/DeliveryService.java
quote-frontend/src/services/marketApi.js
quote-frontend/src/components/MarketRelease.vue
quote-frontend/src/workflowPolish.test.js
```

当前风险最高：

- 页面加载订单后会拉取整单零件、提单列表、工艺表列表。
- 剩余可提数量在前端基于整单 `itemList` 和提单数据计算。
- 跨页选择、Excel 导入选择都依赖前端持有整单零件。

目标接口：

```text
GET /api/market/release/summary/{rfqId}
GET /api/market/release/items/{rfqId}?page=1&pageSize=50&keyword=&status=&remainingOnly=true
GET /api/market/tickets/{rfqId}?page=1&pageSize=50
GET /api/market/process-sheets/{rfqId}?page=1&pageSize=50
POST /api/market/release/parse-part-selection/{rfqId}
POST /api/market/release/generate
```

接口口径：

- `release/summary` 只返回订单信息、零件总数、可提数量统计、已提数量统计。
- `release/items` 返回当前页可提单零件，并由后端计算：
  - `ticketedQty`
  - `remainingQty`
  - `canSelect`
  - `releaseBlockedReason`
- `tickets` 和 `process-sheets` 改为服务端分页。
- `parse-part-selection/{rfqId}` 由后端解析 Excel 后在整单范围匹配图号版本，返回匹配到的 `itemIds`、不可选原因和摘要。
- `generate` 继续按选中 `itemIds` 和数量生成提单，不依赖前端全量零件。

前端改造：

- `itemList` 改为当前页。
- 新增 `selectedItemIdMap`，保存跨页选中项和本次提单数量。
- 翻页后根据当前页 ID 恢复勾选状态。
- Excel 选取订单零件不再前端遍历整单，改为后端返回 `itemIds` 后写入 `selectedItemIdMap`。
- 生成提单成功后刷新 summary、当前页、提单当前页、工艺表当前页。

验收：

- 已报价、部分已提单、已生成提单订单都可进入页面查看。
- 5000 零件订单首屏只加载当前页。
- 跨页选择多个零件后能一次生成提单。
- Excel 导入选择能匹配整单零件，不要求前端加载全量。
- 已提单零件仍不可选择改变参数。
- 提单列表和工艺表列表也分页加载。

### 4.6 订单管理详情与历史订单详情

涉及文件：

```text
quote-backend/src/main/java/com/machining/quote/controller/OrderManagementController.java
quote-backend/src/main/java/com/machining/quote/service/OrderManagementService.java
quote-frontend/src/services/orderApi.js
quote-frontend/src/components/OrderManage.vue
quote-frontend/src/components/HistoryOrderManage.vue
```

当前风险：

- `getOrderDetail(rfqId)` 一次返回 `itemList`、`ticketList`、`processSheetList`。
- 补录图纸后刷新整个订单详情。
- 缺图纸统计依赖前端全量 `itemList`。

目标接口：

```text
GET /api/order-management/orders/{rfqId}
GET /api/order-management/orders/{rfqId}/items?page=1&pageSize=50&keyword=&status=
GET /api/order-management/orders/{rfqId}/tickets?page=1&pageSize=50
GET /api/order-management/orders/{rfqId}/process-sheets?page=1&pageSize=50
GET /api/order-management/orders/{rfqId}/drawing-summary
POST /api/order-management/orders/{rfqId}/supplement-drawings
```

接口口径：

- `orders/{rfqId}` 只返回订单基础信息、summary、fileRoot，不返回三张明细全量。
- `items`、`tickets`、`process-sheets` 分标签分页加载。
- `drawing-summary` 返回缺图数量、已绑定数量、图纸目录校验摘要。
- `supplement-drawings` 后端仍可按整单图号匹配图纸文件；返回绑定摘要和受影响 itemIds，不返回整单 `itemList`。

前端改造：

- 订单详情打开后先显示基础信息，再按当前 tab 加载对应分页。
- 补图纸成功后刷新 `drawing-summary` 和零件当前页。
- 历史订单详情复用同一组只读分页接口。

验收：

- 订单管理打开 5000 零件订单详情不一次加载所有零件。
- 补录图纸仍支持多文件拖入。
- 补录后订单状态不被零件状态回写影响。
- 历史订单详情只读分页可用。

### 4.7 后端全量动作

这些动作本质上就是整单业务处理，不应被页面分页切碎：

```text
EngineerService.applyRepeatQuotes(rfqId)
EngineerService.refreshOrderQuotes(rfqId)
EngineerService.completeOrderQuote(rfqId)
QuoteProcessService.saveQuoteSheet(rfqId)
DeliveryService.generateTickets(req)
ExcelExportService.*
QuoteTemplateExportService.*
```

优化策略：

- 保持后端整单处理。
- 前端只展示任务结果摘要。
- 如果未来单订单零件达到数万且导出或刷新耗时明显，再单独升级为异步任务。

验收：

- 页面分页不会导致整单动作只处理当前页。
- 整单动作完成后刷新 summary 和当前页。

## 5. 分阶段实施

### 阶段 0：测试护栏与口径冻结

目标：先锁定哪些地方不能再全量加载，哪些地方必须保持整单处理。

后端：

- 新增 `LargeOrderItemPagingTest`。
- 验证全局设定页仍只返回 10 条预览。
- 验证逐件核价、报价处理、议价提单、订单详情都有分页接口。
- 验证整单动作不受分页影响。

前端：

- 新增 `largeOrderItemPaging.test.js`。
- 冻结 `OrderPickerDialog.vue` 仍使用服务端订单分页。
- 冻结 `ItemPricing.vue`、`QuoteProcess.vue`、`MarketRelease.vue` 不再用全量 `itemList.length` 作为服务端总数。
- 冻结 `GlobalSetup.vue` 仍使用预览口径。

验收：

```powershell
cd D:\QPO-Operations-Management-System\quote-backend
.\mvnw.cmd test -Dtest=LargeOrderItemPagingTest,EngineerSetupPreviewTest

cd D:\QPO-Operations-Management-System\quote-frontend
npm test -- largeOrderItemPaging.test.js engineeringSetupStage5.test.js
```

### 阶段 1：通用分页底座与索引

目标：提供所有模块共享的分页能力。

修改：

- 新增 `OrderItemPageReq`、`OrderItemPageDTO`、`OrderItemSummaryDTO`。
- 新增 `OrderItemPageService`。
- 新增 Flyway 索引迁移，例如 `V56__large_order_item_paging_indexes.sql`。
- 更新 `schema.sql`。

验收：

- 按 `rfqId` 可分页查询零件。
- Summary 统计不依赖前端全量数组。
- 索引存在且不新增无关客户索引。

### 阶段 2：逐件核价页分页

目标：逐件核价首屏不再加载整单零件。

修改：

- `EngineerController` 拆分 `pricing/summary` 和 `pricing/items`。
- `ItemPricing.vue` 改服务端分页。
- 组合件子件候选新增分页搜索接口。

验收：

- 翻页触发后端请求。
- 保存单个零件只刷新当前页。
- 完成整单核价仍校验整单。

### 阶段 3：报价处理页分页

目标：报价处理页不再持有整单 `itemList`。

修改：

- `QuoteProcessController` / `QuoteProcessService` 拆分 summary 和 items。
- `QuoteProcess.vue` 改服务端分页和跨页选择 ID 集合。
- 批量交期接口返回摘要，不返回整单 `itemList`。

验收：

- 批量调整跨页选中项可用。
- 保存报价单仍处理整单。
- 导出报价单仍导出整单。

### 阶段 4：议价提单页分页

目标：提单页支持大订单跨页选件。

修改：

- `MarketController` 拆分 `release/summary` 和 `release/items`。
- `InternalTargetLeadTimeService` 提供分页行，并在行内返回剩余可提数量。
- `DeliveryService` 提供提单列表和工艺表分页查询。
- `MarketRelease.vue` 改跨页选中 ID/数量集合。
- Excel 选择零件改为后端整单匹配。

验收：

- 当前页可提数量由后端返回。
