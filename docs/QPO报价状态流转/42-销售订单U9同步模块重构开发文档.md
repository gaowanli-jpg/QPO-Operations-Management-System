## 1. 背景与最终结论

现有 **U9同步** 模块已经完成页面、权限、销售订单整单预览、已确认物料号校验、数据中心调用和 U9 结果回填，但最初实现依据接口大 DTO 推测字段含义，没有经过逐字段的 U9 实际创建和回查验证。当前请求同时发送客户料号、客户品名、版本、项目、单位、换算率、订单价、价格来源、普通备注等字段，并且把含税单价作为 `FinallyPriceTC`，与本轮组织 `101` 的真实测试结果不一致。

本轮已经通过数据中心和 U9 测试账套完成多组受控创建与通用实体回查，确认重构方向为 **最小已验证契约**：

1. QPO 只发送业务明确要求且已经在 U9 创建、查询中验证生效的字段。
2. U9 销售订单使用 **未税单价**：`IsPriceIncludeTax = false`，`FinallyPriceTC = sales_order_item.untaxed_unit_price`。
3. 税组合、税率、未税金额、税额、价税合计、币种、单位、换算率、客户站点、供应组织等由 U9 主数据和销售订单逻辑自动生成。
4. `Seller` 和 `SaleDepartment` 都允许为空；U9同步页面提供实时 U9 选项，选择销售员时自动带出所属部门，但部门仍可修改或清空。
5. 客户项目号、客户采购订单号、内部项目号、客户交期、内部交期、未税价格和销售备注写入 U9 销售订单行的已确认私有字段。
6. 客户料号不发送、不展示；图号和版本号不随销售订单创建请求发送。图号和版本属于 U9 物料档案私有字段，由正式物料号关联。
7. U9 请求中的两个 `ItemCode` 是同一个正式物料号分别出现在订单行和计划行，不代表 QPO 存在两个物料号。
8. QPO 必须使用稳定、唯一、非空的 `DocNo` 进行提交前查重和超时后对账；`OtherID` 只用于创建响应关联，不能作为 U9 持久化查询依据。
9. 外部 U9 调用不得处于数据库长事务内。同步改为短事务预约、事务外查重/创建、短事务回填。
10. 网络超时或响应不明时不得直接重发；必须先按 `DocNo` 对账，不能确认时进入“结果待确认”。
11. 本次不新增用户权限，不新增 `common:*`，继续复用 `market:u9-sync:*`。
12. 第 43 号文档已承接 U9 客户只读缓存和 U9 同步选项持久化缓存；U9 同步继续只消费销售订单客户、Seller、SaleDepartment 快照，不建设独立销售部门/销售员管理模块，不改变 MES、WMS、待产、锁库和提单表据链路。

本文是本轮 U9 销售订单创建字段和同步行为的最新开发依据。实施时必须同步修正 `16-销售订单U9同步模块开发文档.md`、`37-RFQ议价提单派生销售订单并接入U9开发文档.md` 中与含税价格、宽 DTO 和幂等方式冲突的旧口径。

创建响应会返回 `m_otherID`，当前 QPO 依靠它把批量响应关联回请求订单。但是通过 `UFIDA.U9.SM.SO.SO` 回查上述订单时，实体字段 `OtherID` 为 `null`，而 `DocNo` 能稳定查询到订单。

因此：

- `OtherID` 继续发送，用于本次创建响应关联。
- `OtherID` 不作为重试幂等或 U9 持久化对账依据。
- `DocNo` 必须由 QPO 在创建前生成、稳定保存并保证唯一。
- U9 返回的 `m_code` 只写入 `u9_order_code`，不得覆盖 QPO `document_no`。

## 3. 目标与非目标

### 3.1 开发目标

- 把 U9 创建请求收窄为精确、可测试的字段白名单。
- 将同步价格统一为未税单价。
- 写入 U9 已确认的订单行私有字段。
- Seller / SaleDepartment 选项来自本地持久化缓存，并提供销售员和销售部门选择与 QPO 快照保存。
- 同步提交前校验客户、Seller、SaleDepartment 的当前有效状态。
- 保证刷新、切单和同步失败后选择不丢失。
- 保证成功同步后选择只读。
- 用稳定 `DocNo` 完成创建前查重、超时回查和历史状态修复。
- 拆除外部调用上的数据库长事务。
- 在不增加用户权限的前提下保留后端最终权限和数据范围边界。
- 让预览、实际请求、自动化测试和文档使用同一字段契约。
- 不让完整请求、响应、token 或业务体进入操作日志和文件日志。

### 3.2 明确非目标

- 不建设独立“销售部门”或“销售员”管理模块；第 43 号文档只落地 U9 同步页专用选项缓存。
- U9 客户资料同步由第 43 号文档作为客户只读缓存模块落地，本模块不允许在同步页维护客户档案。
- 销售员或部门只作为第 43 号文档定义的同步页选项缓存和销售订单快照使用，不提供人工 CRUD 页面。
- 不创建、修改或补全 U9 客户档案。
- 不创建、修改或补全 U9 物料档案。
- 不发送客户料号。
- 不通过销售订单创建请求覆盖 U9 物料档案的图号和版本。
- 不由 QPO 计算税率、税额或价税合计。
- 不自动审核 U9 销售订单；本次只负责创建，U9 状态“开立”是正确结果。
- 不改变 MES 物料号、WMS、待产、锁库、生产下发和提单表据职责。
- 不把 U9 同步重新并入销售订单导入事务。
- 不新增 `common:*` 或其他用户权限。

## 4. 最小已验证 U9 创建契约

### 4.1 契约分类

本文把 U9 字段分为四类：

| 分类 | 含义 | QPO 行为 |
| --- | --- | --- |
| QPO 必须发送 | 创建、关联或业务正确性必需 | 缺失时预览和提交都阻断 |
| QPO 可选发送 | U9 接受且 QPO 有明确业务来源 | 有值才发送，空值不序列化 |
| U9 自动生成 | 已通过最小请求验证可由 U9 主数据/业务逻辑带出 | QPO 不发送、不计算 |
| 禁止发送 | 无业务用途、属于其他主数据、已验证无效或可能覆盖 U9 默认逻辑 | DTO 中删除并用 JSON 契约测试锁定 |

### 4.2 订单头字段

| U9 字段 | 分类 | QPO 来源 | 校验与说明 |
| --- | --- | --- | --- |
| `OtherID` | 必须发送 | `sales_order_header.sales_order_no` | 非空；用于创建响应关联。 |
| `DocNo` | 必须发送 | `sales_order_header.document_no` | 非空、稳定、全局唯一；用于 U9 查重和对账。 |
| `BusinessDate` | 必须发送 | `sales_order_header.sales_order_date` | 格式 `yyyy-MM-dd`；不得用当前日期静默兜底。 |
| `OrderBy` | 必须发送 | `sales_order_header.customer_code` | 非空；当前来自 QPO 客户编码快照。 |
| `Seller` | 可选发送 | `sales_order_header.u9_seller_code` | 只发送编码；空值不发送。 |
| `SaleDepartment` | 可选发送 | `sales_order_header.u9_sale_department_code` | 只发送编码；空值不发送。 |
| `DocumentType` | 必须发送 | `sales_order_header.document_type_code` | 非空；现有默认值 `SO06`。 |
| `IsPriceIncludeTax` | 必须发送 | 固定 `false` | 表示 `FinallyPriceTC` 为未税单价。 |
| `SOLineDTOList` | 必须发送 | 当前销售订单全部零件 | 至少一行；整单原子创建。 |

订单头 DTO 不再保留 `TC`、`AC`、客户站点、付款客户、付款站点和普通 `Memo`。

### 4.3 销售订单行字段

| U9 字段 | 分类 | QPO 来源 | 校验与说明 |
| --- | --- | --- | --- |
| `DocLineNo` | 必须发送 | `sales_order_item.line_no`，无效时按稳定顺序生成 | 必须为正数且整单唯一。 |
| `ItemCode` | 必须发送 | `sales_order_item.material_no` | 必须非空且 `material_no_status = 已确认`。 |
| `OrderByQtyTU` | 必须发送 | `sales_order_item.qty` | 正整数。 |
| `OrderByQtyPU` | 必须发送 | 同一 `qty` | 与 TU 数量相同，不做换算。 |
| `FinallyPriceTC` | 必须发送 | `sales_order_item.untaxed_unit_price` | 非空；不得降级到含税单价。 |
| `FreeType` | 必须发送 | 固定 `-1` | 沿用已成功创建的普通销售行口径。 |
| `ShipTogetherFlag` | 必须发送 | 固定 `-1` | 沿用已成功创建的口径。 |
| `DescFlexField` | 可选容器 | 本文 4.4 的私有字段 | 只序列化有值字段。 |
| `SOShiplineDTOList` | 必须发送 | 每个订单行一个计划行 | 不拆分同一 QPO 行。 |

数量口径：QPO 和 U9 都使用 `PCS` 所代表的件数，不进行单位换算。请求只发送 TU/PU 两个数量，不发送单位编码和换算率；U9 根据物料档案自动得到 `PCS / PCS / 1`。

| `PrivateDescSeg2` | 客户采购订单号 | `sales_order_item.customer_order_no`，兜底订单头 | 空值不发送。 |

- 客户交期：`SOShiplineDTOList.RequireDate` + `PrivateDescSeg4`。
- 内部交期：`SOShiplineDTOList.DeliveryDate` + `PrivateDescSeg5`。

### 5.2 新订单写入规则

- RFQ 派生销售订单继续使用 `SalesOrderNumberService.forRfqRelease(...)` 生成 `sales_order_no` 和 `document_no`。
- 直接导入销售订单在创建订单头时设置 `document_no = sales_order_no`。
- 其他后续销售订单来源也必须在插入订单头时生成稳定 `document_no`，不能等到 U9 同步时临时生成。
- `document_no` 一旦写入不得因同步成功、失败或重试改变。
- U9 `m_iD` 写入 `u9_order_id`；`m_code` 写入 `u9_order_code`。

### 5.3 销售员和部门快照规则

- 编码和名称一起保存，避免 U9 选项暂时不可用时页面只显示编码。
- 前端只提交编码；后端根据 U9 主数据解析名称。
- 销售员为空时，销售员编码和名称都置空。
- 部门为空时，部门编码和名称都置空。
- 清空销售员不自动清空部门。
- 重新选择销售员时，前端默认把该销售员所属部门写入部门选择；用户可以随后覆盖或清空。
- `同步中`、`结果待确认`、`已同步` 状态禁止修改销售员和部门。

### 5.4 同步尝试字段

| 字段 | 用途 |
| --- | --- |
| `u9_sync_attempt_id` | 标识一次提交/对账尝试，最终回填时做条件校验。 |
| `u9_sync_request_hash` | 对精确最小 JSON 做 SHA-256，用于判断回填是否对应同一业务快照；不保存完整请求。 |
| `u9_sync_started_at` | 记录本次尝试开始时间，并作为结果待确认保护期起点。 |
| `u9_sync_finished_at` | 记录成功、明确失败或本次核对结束时间。 |

不得新增保存完整 U9 请求或完整 U9 响应的数据库字段。

请求指纹必须基于稳定排序后的订单行和固定字段顺序序列化结果计算。同一业务快照重复预览和提交必须得到相同 SHA-256；不得对属性顺序不稳定的任意 `Map` 直接计算指纹。

## 6. 后端架构设计

### 6.1 职责拆分

当前 `SalesOrderU9SyncService` 同时承担查询、验证、DTO 组装、事务、外部调用、状态机、日志和审计。重构后拆分为：

| 组件 | 主要职责 |
| --- | --- |
| `U9SalesOrderContractValidator` | 校验订单状态、必填头字段、物料号、数量、未税单价、行号和选择快照。 |
| `U9SalesOrderRequestAssembler` | 从 `sales_order_header / sales_order_item` 组装精确 U9 DTO。 |
| `U9CommonEntityClient` | 通过数据中心调用 U9 通用实体查询，只返回受控 DTO。 |
| `U9MasterDataService` | 查询、过滤和缓存组织 `101` 的销售员、部门。 |
| `U9SalesOrderReconciliationService` | 按 `DocNo` 查询并核对 U9 订单头、订单行。 |
| `SalesOrderU9SyncStateService` | 在独立短事务中预约、回填成功、回填失败、标记待确认。 |
| `SalesOrderU9SyncService` | 编排列表、预览、选择保存、同步和结果核对。自身不持有跨网络事务。 |
| `U9SalesOrderClient` | 只负责创建销售订单并解析受控创建结果。 |

组件之间使用明确 DTO，不传递 U9 原始 `Map` 到控制器、操作日志或文件日志。

### 6.3 验证器规则

整单阻断条件：

- 销售订单不存在或不在当前用户数据范围。
- 订单状态不是 `已生成提单`。
- `u9_sync_status = 已同步` 且已经有 U9 ID/编码。
- `u9_sync_status = 同步中` 或 `结果待确认` 时再次执行创建。
- `sales_order_no`、`document_no`、`sales_order_date`、`customer_code`、`document_type_code` 任一为空。
- 没有销售订单零件。
- 任一零件没有全部生成提单。
- 任一零件 `material_no` 为空或状态不是 `已确认`。
- 任一零件数量为空、非正数或不是整数。
- 任一零件 `untaxed_unit_price` 为空。
- 最终生成的 `DocLineNo` 为空、非正数或重复。
- 已保存销售员/部门在成功获取的最新 U9 主数据中属于其他组织、失效或类型不正确。

非阻断警告：

- 客户交期为空。
- 内部交期为空。
- 客户项目号、客户采购订单号、内部项目号或销售备注为空。
- U9 主数据读取暂时失败但已有可用缓存。

预览和提交必须调用同一个验证器和同一个请求组装器。不得在提交路径额外使用另一套字段兜底。

### 6.4 行号生成规则

销售订单零件按以下稳定顺序排列：

1. `line_no` 非空的行按 `line_no` 升序。
2. `line_no` 相同或为空时按 `sales_order_item.id` 升序。

`DocLineNo` 规则：

- 原始 `line_no` 为正数且整单唯一时沿用。
- 原始行号为空、非正数或重复时，整单统一按稳定排序生成 `10、20、30...`，不能只修复个别重复行。

`DocSubLineNo` 每个订单行固定传 `1`；U9 可以在持久化时规范化为自身行号，不影响 QPO 请求关联。

### 6.5 U9 主数据查询

在 `DataCenterEndpointRegistry` 增加：

```text
U9_COMMON_ENTITY_QUERY
```

默认数据中心 path：

```text
/api/v1/u9/CommonEntity/Query
```

增加配置 fallback：


现有 `ERP_U9_ORG_CODE` 在数据中心模式下同时作为 QPO 预期 U9 组织编码，本项目配置为 `101`。数据中心自身用于登录 U9 的组织也必须为 `101`；查询返回任何其他组织数据时，后端必须过滤并记录安全摘要。

销售员查询请求：

```json

  "ReturnFields": [
```

部门查询使用实体 `UFIDA.U9.CBO.HR.Department.Department`，返回编码、名称、组织、父部门、有效状态和树路径。查询按页执行，直到返回行数小于 `PageSize`，不能假设主数据永远少于单页上限。

销售员过滤：

- `Org.Code = 101`。
- `Effective.IsEffective = true`。
- `OperatorLine` 至少存在一行 `OperatorType = 销售业务员`。

部门选项取并集：

- 有效的 `2002 / 销售部` 及其所有有效下级部门。
- 有效销售业务员实际所属的有效部门，即使该部门不在 `2002` 树下。

缓存规则：

- 成功结果缓存 5 分钟。
- 缓存 key 至少包含预期组织编码。
- U9 查询失败且存在旧缓存时返回旧缓存，并设置 `stale=true`、`refreshedAt` 和安全提示。
- 没有任何缓存时返回服务不可用，不返回部分原始数据。
- 不把完整 U9 主数据响应写入日志或数据库。

### 6.6 数据中心错误安全边界

本轮实测发现：U9 通用实体查询发生元数据或 OQL 错误时，数据中心错误对象的 `Data.Headers` 可能包含完整 U9 token。因此 `U9CommonEntityClient` 必须：

- 成功时只映射白名单字段。
- `Success=false` 或 `ResCode!=0` 时丢弃整个 `Data`。
- 只保留清洗后的 `ResCode` 和限定长度的 `ResMsg`。
- 不把原始响应作为异常 message。
- 不把包含原始响应的异常对象作为日志 cause 直接输出。
- 对 `token`、`Authorization`、`client_secret`、`password`、`cookie` 做二次脱敏。

创建接口客户端遵循相同原则：只解析 `m_isSucess`、`m_otherID`、`m_iD`、`m_code` 和安全错误摘要。

```json
    "Status"
  ],
  "Filters": [
    {
      "Field": "DocNo",
      "Operator": "eq",
      "Value": "目标DocNo",
      "Logic": "And"
    }
  ]
}
```

找到唯一订单头后，再按唯一 `SO.ID` 查询 `UFIDA.U9.SM.SO.SOLine`，返回：

- `ID`、`SO.ID`、`DocLineNo`。
- `ItemInfo.ItemID.Code`。
- `OrderByQtyTU`、`OrderByQtyPU`。
- `FinallyPriceTC`。
- `DescFlexField.PrivateDescSeg1/2/3/4/5/9`、`DescFlexField.PubDescSeg2`，仅作为冲突警告信息。

订单行按 `DocLineNo` 一一匹配，不按列表位置猜测。数量和价格使用 `BigDecimal.compareTo(...) == 0` 比较，忽略无意义的小数位差异，不使用 `double` 或字符串比较。查询结果中的组织、客户、单据类型、销售员和部门在 QPO 本地校验，不能依靠多个 U9 Filters 拼接完成安全边界。

```http

```

- `FOUND_AND_MATCHED`：找到且业务字段一致，已修复为“已同步”。
- `FOUND_CONFLICT`：找到但字段不一致，保持“结果待确认”。
- `MULTIPLE_FOUND`：同一 `DocNo` 多单，保持“结果待确认”。
- `NOT_FOUND_WAIT`：仍在保护期或查询不稳定，保持“结果待确认”。
- `NOT_FOUND_CONFIRMED`：超过保护期且查询成功明确无单，转为“同步失败”。
- `QUERY_FAILED`：查询失败，保持“结果待确认”。

核对操作不自动创建新订单。

## 8. 同步状态机与事务设计

### 8.1 状态定义

| 状态 | 含义 | 页面允许操作 |
| --- | --- | --- |
| `未同步` | 尚未提交 | 修改选择、预览、同步。 |
| `同步中` | 已预约并正在外部调用 | 只读、刷新。 |
| `已同步` | U9 已确认存在且字段匹配 | 只读，不允许重复创建。 |
| `同步失败` | 明确校验失败、U9 业务拒绝或保护期后确认未创建 | 修复数据/选择后重试。 |
| `结果待确认` | 创建结果存在网络或数据冲突歧义 | 只允许核对，不允许直接创建。 |

### 8.2 短事务预约

`SalesOrderU9SyncStateService.reserve(...)` 使用独立事务：

1. `SELECT ... FOR UPDATE` 锁定订单头。
2. 执行数据权限和完整契约校验。
3. 拒绝“同步中”“结果待确认”“已同步”。
4. 重新读取零件并组装精确 JSON。
5. 计算 SHA-256 请求指纹。
6. 生成随机 `attemptId`。
7. 写入“同步中”、尝试号、指纹、开始时间和安全摘要。
8. 提交事务并返回不可变 `PreparedOrder`。

事务提交后才能调用数据中心/U9。

### 8.3 创建前查重

对每个 `PreparedOrder` 先按 `DocNo` 查询 `UFIDA.U9.SM.SO.SO`：

- 未找到：允许调用创建。
- 找到一单：继续查询订单行并执行字段核对。
- 找到多单：进入“结果待确认”，不调用创建。

创建前查重必须执行实时查询，不能用销售员/部门的五分钟缓存代替。实时查询失败发生在创建调用之前，因此能够确定本次尚未调用 U9 创建：该尝试写入“同步失败”和“创建前查重失败”的安全摘要，允许用户稍后重试；重试时仍先查重。

核对字段至少包括：

- U9 组织 = 预期组织 `101`。
- 客户编码 = `OrderBy`。
- 单据类型编码一致。
- 订单行数量一致。
- 每行物料号、销售数量、计价数量和最终未税单价一致。

销售员或销售部门为空时不要求 U9 自动补值；有值时必须一致。私有字段差异不用于自动认领历史单，但必须作为核对警告返回，便于人工判断。

### 8.4 创建结果处理

| 场景 | 最终处理 |
| --- | --- |
| U9 返回 `ResCode=0` 且对应行 `m_isSucess=true` | 写“已同步”、U9 ID/编码。 |
| U9 返回明确业务错误 | 写“同步失败”和安全错误摘要。 |
| 返回缺少对应 `m_otherID` | 立即按 `DocNo` 对账；无法确认则“结果待确认”。 |
| 网络超时、连接中断、响应解析失败 | 立即按 `DocNo` 对账；无法确认则“结果待确认”。 |
| 对账找到且匹配 | 写“已同步”。 |
| 对账找到但冲突或多单 | 写“结果待确认”。 |

最终状态更新必须带 `WHERE id = ? AND u9_sync_attempt_id = ?` 语义。旧请求不能覆盖已经由新核对操作修复的状态。

### 8.5 结果待确认保护期

- 默认保护期 `120s`，新增配置 `erp.u9.reconciliation-grace-seconds`。
- 保护期从 `u9_sync_started_at` 计算。
- 保护期内查询无单只返回 `NOT_FOUND_WAIT`。
- 保护期后，只有“通用实体查询成功且明确返回零行”才能转为“同步失败”。
- 查询失败、响应异常或同一单号多单始终不能自动转为可重试状态。
- 从“同步失败”重新提交时仍先执行创建前查重。

### 8.6 历史同步中恢复

页面加载到长时间停留在“同步中”的订单时，不自动创建。后端把超过保护期的历史“同步中”按待核对语义处理：

- 找到 U9 单据并匹配：修复成功。
- 找不到且查询成功：转同步失败。
- 查询失败或冲突：转结果待确认。
