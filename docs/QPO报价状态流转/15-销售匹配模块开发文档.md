# QPO 销售匹配手工模块退役说明

> 2026-08-10 收口：原销售匹配 / 异常治理手工模块已删除。QPO 不再提供独立左侧入口、前端页面、手工预览、手工确认、客户选择或订单选择 API。销售订单导入自动快照补全继续保留为导入事务内部能力。

## 1. 退役范围

以下内容不再作为运行时能力存在：

- 手工选择销售订单后进行预览和确认补全的页面。
- 手工销售匹配相关前端路由、菜单项、页面组件和 `marketApi` helper。
- 手工销售匹配 Controller、预览 DTO、确认 DTO 和对外 API。
- 首页看板中的手工治理待办卡片。
- 独立销售匹配权限点、角色映射和授权树节点。

已安装环境通过后续迁移删除旧菜单和角色授权记录；新建环境不得重新授出旧入口。

## 2. 保留能力

销售订单导入仍会在导入事务内自动执行历史生产快照补全：

1. 根据销售订单零件 `图号 + 版本` 查找最新已提 RFQ 历史快照。
2. 只补齐销售订单零件缺失的生产快照、工程材料身份、材料形态、重量、费用快照和标准工艺路线快照。
3. 保留销售订单 Excel 导入事实字段，不覆盖 `material_name`、`description`、`surface_treatment`、图纸绑定、价格、数量或交期。
4. 复用已确认 MES 物料号时只补空缺或一致值；目标已有不同物料号时记录冲突，不覆盖。
5. 组合件来源完整时写入 `sales_order_item_assembly_relation`；来源不完整时仅标记组合件关系状态。
6. 未命中历史快照不阻断导入和自动提单，导入结果返回匹配 / 未匹配统计。

价格字段继续使用 `tax_included_unit_price`、`tax_included_total_price`、`untaxed_unit_price` 和 `untaxed_total_price`；自动补全不写价格，也不提供价格覆盖入口。

自动补全的实现入口是后端 `SalesOrderAutoSnapshotCompletionService.completeImportedOrder`，仅由 `SalesOrderQpoImportService` 在销售订单导入链路中调用。

## 3. 权限与日志

- 自动快照补全继续由销售订单导入权限 `market:rfq:import-sales-order` 覆盖，不新增可分配 `common:*` 权限。
- 后端销售订单导入权限和数据范围仍是最终边界；前端隐藏不作为安全边界。
- 自动补全不产生独立操作日志动作，统一纳入销售订单导入摘要。
- 文件日志只记录订单数、零件数、匹配数、未匹配数、跳过数、物料号复用统计和耗时，不记录完整 Excel、token、Authorization header、完整请求体或响应体。

## 4. 回归验收

- 销售订单导入后仍自动补全可命中的历史生产快照。
- 未匹配行不阻断导入和自动提单。
- 已提单或无剩余数量的销售订单零件跳过补全。
- 销售订单管理、U9 同步、提单表据、已提零件、MES、WMS、待产和锁库链路继续消费确认后的销售订单零件快照。
- 前端菜单、路由和 API 不再暴露手工销售匹配入口。
- 后端不再暴露手工销售匹配 Controller、DTO 或权限点。
