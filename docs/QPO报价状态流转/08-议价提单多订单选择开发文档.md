# QPO 议价提单多订单选择开发文档

## 1. 背景

当前 `议价提单` 页面一次只能选择一个订单，候选零件表、内部目标交期调整、Excel 导入选件和正式提单生成都围绕单个 `rfqId` 工作。

新需求是：用户可以多次点击 `选择订单`，把多个订单加入当前议价提单工作台；这些订单下可提单零件统一展示在右侧候选零件表，用户可统一勾选、统一维护提单参数、统一生成正式提单。

已确认业务口径：

- `订单类型`、`开工日期`、`安排类型`、`内部项目号`、`客户订单号`、`客户项目号` 共用一套。
- Excel 导入批量选件需要在所有已选订单的候选零件范围内匹配并选中。
- 继续遵守现有权限、日志和大订单分页规范。

## 2. 目标

- `MarketRelease.vue` 支持多订单选择、移除单订单状态依赖。
- 候选零件表展示所有已选订单的可提零件。
- Excel 导入选件支持跨已选订单匹配。
- 生成正式提单时按 `rfqId` 分组提交，每个订单仍走现有提单生成规则。
- 保留并继续使用后端分页，避免多订单大数据量时前端全量拉取。

## 3. 非目标

- 不新增可分配 `common:*` 权限。
- 不改变正式提单生成的不可逆规则、剩余可提数量规则和订单状态流转规则。
- 不改变 `提单表据`、`已提零件`、`锁库零件` 页面职责。
- 不把多个订单合并成一个后端事务；本阶段采用按订单分组生成。
- 不新增零件类型、客户、订单状态等筛选框；只保留当前议价提单已有筛选/分页能力。

## 4. 核心方案

采用 **前端多订单聚合 + 后端批量分页查询 + 跨订单导入匹配 + 按订单分组调用现有生成接口**。

### 4.1 多订单选择

- `OrderPickerDialog.vue` 增加可选的多选模式，供 `MarketRelease.vue` 使用。
- 用户可多次打开弹窗追加订单。
- 首个订单选中后锁定客户；后续选择订单默认沿用同一客户，避免多个客户共用同一套客户订单号和客户项目号造成歧义。
- 页面左侧显示已选订单标签列表，包含 `RFQ号 / 状态`，支持移除单个订单。
- 移除最后一个订单时清空候选零件、选中零件、导入选择结果和单据参数中的订单上下文。

### 4.2 候选零件聚合展示

- 右侧候选零件表改为按 `selectedOrders` 聚合展示。
- 表格新增展示列：
  - `RFQ号`
  - `客户`
  - `订单状态`
- 保留现有零件列、剩余可提数量、内部目标交期、通过数量、选择状态。
- `row-key` 继续使用零件 `id`；零件主键全局唯一，因此跨订单选择不会冲突。

### 4.3 共用提单参数

左侧提单参数保持一套：

- `订单类型`
- `开工日期`
- `安排类型`
- `内部项目号`
- `客户订单号`
- `客户项目号`

`RFQ号 / 项目号` 不再固定显示单个订单 RFQ；提交时每个订单的 `projectNo` 传空或不传，由后端按该订单自身 RFQ 默认解析。

### 4.4 生成正式提单

提交前端逻辑：

1. 校验至少选择一个订单。
2. 校验至少选择一个可提零件。
3. 校验共用提单参数完整。
4. 按 `row.rfqId` 对已选零件分组。
5. 对每个 `rfqId` 调用现有 `generateTicket(payload)`。
6. 每组 payload 使用同一套共用参数，只更换 `rfqId` 和该订单下的 `items`。
7. 生成结束后刷新所有已选订单的候选零件分页数据和订单状态摘要。

结果提示：

- 全部成功：提示成功订单数和提单行数。
- 部分失败：提示成功订单、失败订单及后端返回原因；已成功订单不回滚。
- 全部失败：展示失败原因汇总。

## 5. 分页设计

### 5.1 结论

分页工作仍然保留，而且必须继续起作用。

不能为了多订单聚合而把所有订单零件一次性拉到前端再分页。这样会绕开阶段 6 的大订单后端分页优化，在大订单场景下会重新变慢。

### 5.2 推荐实现

新增一个多订单候选零件服务端分页接口：

```text
POST /api/market/release/items/batch
Permission: market:release:view
Content-Type: application/json
```

请求：

```json
{
  "rfqIds": [101, 102, 103],
  "page": 1,
  "pageSize": 20,
  "keyword": "",
  "status": "",
  "remainingOnly": false
}
```

响应沿用现有 `PageResult<Map<String,Object>>`：

```json
{
  "records": [],
  "total": 128,
  "page": 1,
  "pageSize": 20
}
```

后端分页排序建议：

```text
order_rfq.id ASC, item_quote_version.id ASC
```

这样分页稳定，用户翻页不会跳行。

### 5.3 前端分页如何继续工作

`MarketRelease.vue` 继续保留：

```js
const releaseItemPagination = reactive({ page: 1, pageSize: DEFAULT_CLIENT_PAGE_SIZE })
```

但数据加载从：

```js
listReleaseItems(rfqId, { page, pageSize })
```

改为：

```js
listReleaseItemsBatch({
  rfqIds: selectedOrders.value.map(order => order.id),
  page: releaseItemPagination.page,
  pageSize: releaseItemPagination.pageSize,
  keyword,
  status,
  remainingOnly
})
```

分页控件仍使用后端返回的 `total / page / pageSize`。

### 5.4 跨页选中如何继续工作

继续保留当前 `selectedItemIdMap` 思路：

- 当前页展示的是后端分页返回的 `records`。
- 用户跨页勾选的行保存在 `selectedItemIdMap`。
- 翻页后通过 `row.id` 恢复当前页已选状态。
- 生成时使用 `selectedItemIdMap` 中保存的完整行数据，不依赖当前页。

因此，前端跨页选择能力仍然可用。

## 6. Excel 导入选件设计

### 6.1 新增批量导入匹配接口

新增接口：

```text
POST /api/market/release/parse-part-selection/batch
Permission: market:release:create
Content-Type: multipart/form-data
```

参数：

- `excelFile`: 上传的 Excel 文件。
- `rfqIds`: JSON 字符串，例如 `[101,102,103]`。

返回：

```json
{
  "success": true,
  "importedCount": 30,
  "matchedCount": 28,
  "selectedCount": 26,
  "skippedCount": 2,
  "data": []
}
```

### 6.2 匹配规则

基础匹配：

- 默认按 `图号 + 版本` 在所有已选订单候选零件中匹配。
- 如果同一 `图号 + 版本` 在多个已选订单中存在，默认全部匹配并选中。
- 不可提、已提完、剩余数量为 0 的零件进入 `skippedRows`，不选中。

增强匹配：

- 如果 Excel 中存在 `RFQ号` 列，则优先按 `RFQ号 + 图号 + 版本` 精确匹配。
- 如果 Excel 中没有 `RFQ号` 列，则退回到所有已选订单范围内匹配。

### 6.3 导入后的选中状态

- 导入接口返回的 `data` 是完整候选行，包含 `rfqId`、`rfqNo`、`partNo`、`version`、`remainingQty`。
- 前端把返回行写入 `selectedItemIdMap`。
- 如果导入选中的零件不在当前分页页码，也照样保留选中；用户翻到对应页时恢复勾选。

### 7.2 Controller

修改：

```text

```

新增：

```java
@PostMapping("/release/items/batch")

```

新增：

```java
@PostMapping("/release/parse-part-selection/batch")
@RequirePermission("market:release:create")
public Map<String, Object> parsePartSelectionForOrders(
        @RequestParam("excelFile") MultipartFile excelFile,
        @RequestParam("rfqIds") String rfqIdsJson)
```

保留现有单订单接口：

```text
GET  /api/market/release/items/{rfqId}
POST /api/market/release/parse-part-selection/{rfqId}
```

用于兼容现有测试和单订单逻辑。

### 7.3 Service

修改：

```text
quote-backend/src/main/java/com/machining/quote/service/InternalTargetLeadTimeService.java
quote-backend/src/main/java/com/machining/quote/service/OrderItemPageService.java
```

新增能力：

- `pageItemRowsBatch(ReleaseItemBatchQueryReq req)`
- `matchPartSelectionBatch(List<Integer> rfqIds, List<Map<String,String>> importedItems)`

安全要求：

- 每个 `rfqId` 都必须执行数据权限校验。
- 无数据权限的订单不得出现在结果中。
- 如果所有订单都不可见，返回空 `PageResult`。
- 不新增读操作日志；分页和导入匹配仍属于页面辅助读取/解析能力。

### 7.4 SQL / Mapper

优先在现有大订单分页查询基础上扩展 `rfq_id IN (...)`，不要在 Java 内存中合并全量零件后再分页。

查询必须支持：

- `rfq_id IN selectedIds`
- `keyword`
- `status`
- `LIMIT / OFFSET`
- 稳定排序：`rfq_id ASC, id ASC`

如现有 Mapper 不方便扩展，可新增专用 Mapper 方法，但不要新增索引，先复用阶段 6 已有分页索引。

### 8.3 MarketRelease

修改：

```text
quote-frontend/src/components/MarketRelease.vue
```

状态调整：

- `selectedRfqId` 改为 `selectedOrders`
- `orderInfo` 改为 `selectedOrderSummary`
- `selectedOrderLabel` 改为多订单数量摘要
- `fetchReleaseItems(rfqId)` 改为 `fetchReleaseItemsBatch()`

主要方法：

- `handleOrderSelected(order)`：追加订单。
- `removeSelectedOrder(orderId)`：移除订单并清理该订单下已选零件。
- `fetchReleaseItemsBatch()`：调用后端批量分页接口。
- `handleSelectionExcelChange()`：调用批量导入匹配接口。
- `submitTicket()`：按 `rfqId` 分组，多次调用现有 `generateTicket()`。

### 8.4 内部目标交期操作

当前接口仍按单订单工作，因此多订单场景下前端按订单分组调用：

- 批量增加/减少内部目标交期：按 `rfqId` 分组调用现有 `shiftInternalTargetLeadTime`。
- 批量指定内部目标交期：按 `rfqId` 分组调用现有 `setInternalTargetLeadTime`。
- 行内保存内部目标交期：使用该行自己的 `row.rfqId` 调用现有 `updateInternalTargetLeadTime`。

这样不用新增内部目标交期后端权限和日志。

## 9. 权限与日志

### 9.1 权限

沿用现有议价提单权限：

- 查看候选零件：`market:release:view`
- 选择订单：`market:release:order-select`
- 导入选件、调整内部目标交期、生成提单：`market:release:create`

不新增权限点，不复用 `common:*`。

### 9.2 日志

不新增分页、选择订单、导入匹配的操作日志。

正式生成仍由现有 `DeliveryService.generateTickets()` 记录：

- 文件日志：`Delivery ticket generation started/completed/failed`
- 操作日志：`DELIVERY_TICKET_GENERATE`

多订单生成时会按订单产生多条生成日志，符合现有单订单生成审计边界。

## 11. 分阶段实施

### 阶段 1：后端批量分页接口

目标：多订单候选零件仍使用后端分页。

修改：

- 新增 `ReleaseItemBatchQueryReq.java`。
- `MarketController.java` 新增 `/release/items/batch`。
- `InternalTargetLeadTimeService` / `OrderItemPageService` 支持 `rfqIds` 批量分页。
- 补后端分页测试。

验收：

- `rfqIds=[A,B]` 返回两个订单的聚合分页。
- `page/pageSize/total` 正确。
- 不全量拉取后在前端分页。

### 阶段 2：前端多订单状态与分页接入

目标：议价提单页面能选择多个订单并分页展示候选零件。

修改：

- `OrderPickerDialog.vue` 支持多选追加模式。
- `MarketRelease.vue` 引入 `selectedOrders`。
- `marketApi.js` 新增 `listReleaseItemsBatch()`。
- 候选零件表新增 `RFQ号 / 客户 / 订单状态` 列。

验收：

- 多次选择订单后，候选零件表展示聚合结果。
- 翻页仍请求后端批量分页接口。
- 移除订单会移除对应候选和已选零件。

### 阶段 3：跨订单导入选件

目标：Excel 导入可在所有已选订单里匹配零件。

修改：

- 后端新增 `/release/parse-part-selection/batch`。
- 前端导入时上传 `rfqIds + excelFile`。
- 导入结果写入 `selectedItemIdMap`。

验收：

- Excel 无 `RFQ号` 时按所有已选订单匹配。
- Excel 有 `RFQ号` 时按指定订单精确匹配。
- 跨页选中仍保留。

### 阶段 4：统一生成与状态刷新

目标：共用参数，按订单分组生成正式提单。

修改：

- `submitTicket()` 按 `rfqId` 分组。
- 每组调用现有 `generateTicket()`。
- 成功后刷新所有已选订单状态和候选零件分页。
- 成功提示引导到 `提单表据` 查看导出。

验收：

- 多订单同一套参数可批量生成。
- 部分订单失败时能显示失败明细。
- 现有单订单生成行为不回退。

### 阶段 5：回归与文档

目标：确保权限、分页、日志和现有流程不受影响。

修改：

- 更新相关测试。
- 如权限文档需要说明多订单仍沿用 `market:release:*`，补充说明。

验收：

- `mvnw.cmd test` 通过。
- `npm test` 通过。
- `npm run build` 通过。
- 权限、日志不新增噪声。
