# 40-议价提单表格数据批量替换开发文档

> 文档版本：V1.0
>
> 文档日期：2026-08-10
>
> 文档状态：待按阶段实施。本文用于指导 QPO 在议价提单工作台新增“表格数据替换”能力，通过 Excel 中的图号和版本匹配当前已选 RFQ 零件，先由后端生成差异预览，用户确认后再原子保存零件字段；Excel 中的“通过数量”只更新本次议价提单页面草稿，不写入 RFQ 零件主表。

## 1. 文档目的

当前议价提单工作台已经支持：

- 同一客户选择多个 RFQ 询价订单。
- 在右侧零件表逐行维护内部目标交期、物料描述、表面处理、备注和六个零件级订单属性。
- 导入表格按图号和版本批量勾选零件。
- 导入 PDF 批量替换零件图纸。
- 一批生成一张派生销售订单和对应 RFQ 来源提单行。

但当前多个零件的业务字段仍需要逐行编辑和保存。客户已经在外部表格中维护这些信息时，用户必须再次手工录入，效率低且容易发生漏填或错填。

本次新增“表格数据替换”能力，目标是：

1. 用户上传包含 `图号 / 版本` 和任意可替换业务列的 Excel。
2. 系统只在议价提单当前已选择的 RFQ 范围内匹配零件。
3. 系统先预览匹配结果和字段差异，不立即写数据库。
4. 用户确认后，后端重新解析、重新校验、锁定数据并在一个事务中批量保存。
5. Excel 缺少的列和空单元格不覆盖现有值。
6. Excel 中的“通过数量”只作用于当前页面的本次提单数量草稿，正式提单时才写入 `order_delivery_ticket.qty`。

目标链路：

```text
当前已选 RFQ
    -> 上传 Excel
    -> 后端解析表头和数据
    -> 图号 + 版本匹配当前 RFQ 零件
    -> 权限、状态、字段和数量校验
    -> 返回原值 -> 新值预览
    -> 用户确认
    -> 后端重新解析并锁行校验
    -> item_quote_version 原子批量更新
    -> 前端刷新受影响字段
    -> 有“通过数量”的行更新本次勾选和数量草稿
    -> 用户继续生成正式提单
```

## 2. 当前实现分析

### 2.1 当前页面入口

`quote-frontend/src/components/MarketRelease.vue` 右侧“通过零件选择”表头当前包含：

- `导入替换图纸`
- `导入表格选定`

本次在 `导入替换图纸` 左侧新增：

```text
表格数据替换 | 导入替换图纸 | 导入表格选定
```

三个入口职责保持独立：

| 入口 | 职责 |
| --- | --- |
| 表格数据替换 | 按图号和版本批量预览并保存零件业务字段，可同时设置本次通过数量。 |
| 导入替换图纸 | 按图号或图号加版本替换 PDF 图纸。 |
| 导入表格选定 | 只根据表格图号和版本批量勾选可提零件，不保存业务字段。 |

本次不合并或删除原有两个入口，避免改变已经稳定的操作习惯。

### 2.2 当前逐行保存能力

当前字段分别通过以下接口保存：

| 字段 | 当前接口 | 当前保存方式 |
| --- | --- | --- |
| 内部目标交期 | `/api/market/internal-target-lead-time/update` | 单行保存。 |
| 物料描述、表面处理、备注 | `/api/market/release/items/{itemId}/fields` | 三字段一次保存。 |
| 六个零件级订单属性 | `/api/market/release/items/{itemId}/order-fields` | 前端单列按钮触发，后端一次保存六字段。 |

这些接口已经具备部分字段校验、RFQ 数据权限、全部提单后禁止修改和操作日志能力，但不适合由前端循环调用来完成 Excel 批量替换，原因包括：

- 前端循环调用不能保证整批事务原子性。
- 中途失败会形成部分零件已更新、部分零件未更新。
- 多次请求会产生大量零散操作日志。
- 无法在保存前统一展示原值和新值差异。
- 通过数量不是数据库主表字段，不能混入现有保存接口。

因此本次必须新增后端批量预览和确认服务，不使用前端逐行循环保存。

### 2.3 当前通过数量口径

当前页面使用：

```javascript
acceptedQtyMap[rowKey(row)]
```

保存本次议价提单的通过数量。该数量当前只存在于页面状态中，生成正式提单时作为 `DeliveryGenerateReq.items[].acceptedQty` 提交，随后写入不可逆的 `order_delivery_ticket.qty`。

`item_quote_version` 不存在也不应新增“通过数量”字段。本次 Excel 中的“通过数量”必须遵循同一口径：

- 预览时只进行校验和展示。
- 确认成功后才写入前端 `acceptedQtyMap`。
- 自动勾选对应零件。
- 不更新 `item_quote_version.qty`。
- 不更新历史 ticket。
- 页面刷新后数量草稿可以丢失，正式提单前仍以当前页面值为准。

### 2.4 当前匹配和分页边界

议价提单支持多 RFQ 和后端分页。批量替换不能只匹配当前页面已加载行，必须根据当前已选 RFQ ID 从数据库查询全部候选零件。

当前 `PartSelectionImportService` 已提供图号和版本表头识别，但它会直接去重并只返回少量字符串字段，不足以支撑：

- 区分“没有表头”和“有表头但单元格为空”。
- 返回 Excel 原始行号。
- 报告重复图号和版本所在的全部行号。
- 解析日期、数量和多种业务字段。
- 生成字段级原值和新值差异。

因此本次新增专用解析器，不修改原有“导入表格选定”解析行为。

## 3. 范围和不变项

### 3.1 本次范围

- 议价提单页面新增“表格数据替换”按钮和预览确认弹窗。
- 支持 `.xlsx` 和 `.xls`。
- 按 `图号 + 版本` 匹配当前已选 RFQ 零件。
- 支持任意顺序、任意子集的可替换业务表头。
- 支持先预览、后确认的两阶段接口。
- 支持字段级差异、未匹配、跳过和错误结果展示。
- 确认阶段使用单一事务和行锁。
- 支持并发状态指纹，预览后数据变化时拒绝旧预览确认。
- 保存后更新当前页面零件数据，并应用有效的通过数量草稿。
- 更新权限、操作日志、文件日志、测试和相关文档。

### 3.2 不在本次范围

- 不修改 RFQ 导入模板。
- 不修改销售订单 Excel 导入。
- 不修改核价、报价、重复件匹配和派生销售订单规则。
- 不新增 `item_quote_version` 字段。
- 不新增数据库迁移或临时预览表。
- 不把“通过数量”持久化到 RFQ 零件主表。
- 不修改已经生成的 `order_delivery_ticket` 历史快照。
- 不自动生成正式提单。
- 不调用 MES、WMS、U9 或数据中心。
- 不支持销售订单来源；议价提单继续只处理 RFQ。
- 不新增菜单、页面路由或用户权限编码。

### 3.3 已确认业务规则

1. Excel 必须包含 `图号` 和 `版本` 表头。
2. Excel 至少还要包含一个可替换业务表头。
3. 表头顺序不限。
4. Excel 有哪个业务表头，就只处理哪个业务字段。
5. 有表头但当前行单元格为空时保留原值，不执行清空。
6. 未提供的表头完全不影响对应字段。
7. Excel 中相同 `图号 + 版本` 出现多行时整批拒绝，并返回重复行号。
8. 当前 RFQ 范围内数据库存在多个相同 `图号 + 版本` 时整批拒绝。
9. 未匹配行跳过并展示，不阻断其他匹配行。
10. 已全部提单、不可编辑的零件跳过并展示，不阻断其他匹配行。
11. 部分已提单但仍有剩余数量的零件允许修改；历史 ticket 不变化。
12. 已匹配行存在日期、数量、长度或订单类型错误时，整批不能确认。
13. 确认阶段任何持久化异常导致全部数据库更新回滚。
14. “通过数量”只更新当前页面的本次提单数量草稿。
15. 没有“通过数量”表头或单元格为空时，不改变现有勾选和数量。
16. 有有效“通过数量”的行在确认成功后自动勾选。
17. 不清空其他已经勾选的零件。

## 4. Excel 契约

### 4.1 表头和字段映射

| Excel 表头 | 是否必需 | 解析类型 | 目标字段 / 作用 | 空单元格规则 |
| --- | --- | --- | --- | --- |
| 图号 | 是 | 文本 | 匹配 `item_quote_version.part_no`，不修改 | 有业务数据的行为空时报错。 |
| 版本 | 是 | 文本 | 匹配 `item_quote_version.version`，不修改 | 有业务数据的行为空时报错。 |
| 内部目标交期 | 否 | 日期 | `item_quote_version.internal_target_lead_time` | 保留原值。 |
| 通过数量 | 否 | 正整数 | 当前页面 `acceptedQtyMap`，不写数据库 | 保留现有数量和勾选。 |
| 物料描述 | 否 | 文本 | `item_quote_version.description` | 保留原值。 |
| 表面处理 | 否 | 文本 | `item_quote_version.surface_treatment` | 保留原值。 |
| 备注 | 否 | 文本 | `item_quote_version.remark` | 保留原值。 |
| 下单日期 | 否 | 日期 | `item_quote_version.sales_order_date` | 保留原值。 |
| 客户订单号 | 否 | 文本 | `item_quote_version.customer_order_no` | 保留原值。 |
| 客户项目号 | 否 | 文本 | `item_quote_version.customer_project_no` | 保留原值。 |
| 客户下单抬头 | 否 | 文本 | `item_quote_version.customer_order_title` | 保留原值。 |
| 订单类型 | 否 | 枚举文本 | `item_quote_version.order_type` | 保留原值。 |
| 内部项目号 | 否 | 文本 | `item_quote_version.internal_project_no` | 保留原值。 |

### 4.2 表头识别规则

- 只读取第一个工作表。
- 在前 20 行中寻找同时包含 `图号` 和 `版本` 的表头行。
- 表头比较前去除首尾空格、换行和所有空白字符。
- 表头顺序不限。
- 未识别的额外表头忽略，不报错。
- 同一个标准表头在表头行重复出现时整批拒绝，并报告重复列。
- 没有任何可替换业务表头时拒绝预览。

本阶段只支持上表中的正式中文表头，不增加大量模糊别名，避免把客户自由文本误识别成可写字段。后续如果确有稳定模板别名，再在解析器中显式增加。

### 4.3 数据行规则

- 完全空白行忽略。
- 只要任意可识别业务列存在非空值，该行就属于有效业务行。
- 有业务值但图号或版本为空时，该行进入 `ERROR`。
- 图号使用 `DrawingPartNoResolver.normalizePartNo(...)` 统一规范化。
- 版本去除首尾空格并转为大写后参与匹配。
- 原始图号和版本仍在预览中展示，便于用户定位 Excel 行。
- 同一规范化 `图号 + 版本` 重复时整批预览不可确认。
- 有公式的单元格使用 POI `FormulaEvaluator` 读取计算值。

### 4.4 日期规则

`内部目标交期` 和 `下单日期` 复用销售订单导入日期口径，支持：

- Excel 日期单元格。
- Excel 日期序列号。
- `yyyy-MM-dd`。
- `yyyy-M-d`。
- `yyyy/MM/dd`。
- `yyyy/M/d`。
- `yyyy.MM.dd`。
- `yyyy.M.d`。
- `yyyy年M月d日`。

保存口径：

- `sales_order_date` 使用 `LocalDate`。
- `internal_target_lead_time` 统一保存为 `yyyy-MM-dd` 文本，继续兼容当前提单交期解析服务。
- 非法日期返回 Excel 行号和字段名，不静默猜测。

### 4.5 文本和枚举规则

| 字段 | 最大长度 / 取值 |
| --- | --- |
| 物料描述 | 500 个字符。 |
| 表面处理 | 200 个字符。 |
| 备注 | 500 个字符。 |
| 客户订单号 | 120 个字符。 |
| 客户项目号 | 120 个字符。 |
| 客户下单抬头 | 255 个字符。 |
| 内部项目号 | 120 个字符。 |
| 订单类型 | 只能是 `预测订单 / 备货订单 / 正式订单`。 |

所有文本在校验前执行 trim。空字符串按“本行不替换该字段”处理，不执行数据库清空。

### 4.6 通过数量规则

- 必须是正整数。
- 不能包含小数。
- 不能大于当前剩余可提数量。
- 零、负数、非数字和超出剩余数量都属于行错误。
- 零件必须满足当前议价提单可选规则。
- 预览只返回拟应用数量，不修改页面。
- 确认成功后前端写入 `acceptedQtyMap` 并勾选该行。
- 通过数量不会写入 `item_quote_version.qty / released_qty / remaining_qty`。
- 用户最终点击“生成正式提单”时，现有提单接口仍会再次校验数量。

## 5. 匹配范围和状态规则

### 5.1 匹配范围

请求必须携带当前议价提单已选择的 RFQ 来源：

```json
[
  { "sourceType": "RFQ", "sourceOrderId": 101 },
  { "sourceType": "RFQ", "sourceOrderId": 102 }
]
```

后端必须：

1. 拒绝空来源列表。
2. 拒绝 `SALES_ORDER` 或未知来源类型。
3. 对每个 RFQ 执行数据权限校验。
4. 校验 RFQ 状态仍允许进入议价提单工作台。
5. 校验 RFQ 仍属于同一客户。
6. 从数据库查询全部选中 RFQ 零件，不受当前前端分页影响。
7. 只在该集合中按规范化 `图号 + 版本` 匹配。

不得把 Excel 行拿到全库匹配，否则会跨越用户当前选择和客户数据范围。

### 5.2 匹配结果

逐行状态定义：

| 状态 | 含义 | 是否阻断确认 |
| --- | --- | --- |
| `CHANGED` | 匹配成功，至少一个持久字段将发生变化。 | 否 |
| `QUANTITY_ONLY` | 匹配成功，只设置本次通过数量。 | 否 |
| `UNCHANGED` | 匹配成功，但非空导入值与现有值相同。 | 否 |
| `UNMATCHED` | 当前 RFQ 范围内没有对应零件。 | 否 |
| `SKIPPED` | 零件已全部提单或当前不可编辑。 | 否 |
| `ERROR` | Excel、字段、数量、重复键或系统匹配存在错误。 | 是 |

当所有行都是 `UNCHANGED / UNMATCHED / SKIPPED` 且没有可应用通过数量时，`canConfirm = false`。

### 5.3 已提单状态

- 零件剩余可提数量大于 0 时仍可替换主表字段。
- 部分已提单零件只修改 RFQ 主表，既有 ticket 快照保持不变。
- 剩余可提数量为 0 或零件已处于全部提单状态时标记 `SKIPPED`。
- 跳过原因明确展示为“已全部提单，不能修改”。
- 本次不新增修改历史 ticket 的入口。

## 6. 总体架构

### 6.1 新增后端组件

建议新增：

| 组件 | 职责 |
| --- | --- |
| `ReleaseItemDataReplacementController` | 提供预览和确认接口，执行权限注解和 multipart 参数接收。 |
| `ReleaseItemDataReplacementExcelParser` | 读取 Excel、识别表头、保留字段存在性、解析行号、日期、数量和文本。 |
| `ReleaseItemDataReplacementService` | 校验来源、查询匹配范围、生成差异、计算指纹、确认事务和结果摘要。 |
| `ReleaseItemMutationPolicy` | 统一计算 RFQ 零件是否仍可修改及阻断原因，供现有单行保存和新批量替换复用。 |
| `ReleaseItemDataReplacementPreviewDTO` | 预览级响应。 |
| `ReleaseItemDataReplacementRowDTO` | 行级匹配、差异和错误。 |
| `ReleaseItemDataReplacementChangeDTO` | 字段级原值和新值。 |
| `ReleaseItemDataReplacementConfirmDTO` | 确认成功后的更新行和数量草稿指令。 |

不建议继续把完整功能堆入已经较大的 `MarketController` 或 `InternalTargetLeadTimeService`。新 Controller 仍使用 `/api/market/release/...` 路径，不增加前端路由或菜单。

### 6.2 复用和隔离原则

- 图号规范化复用 `DrawingPartNoResolver`。
- 日期解析口径与 `SalesOrderQpoExcelParser` 保持一致，可抽取共享日期解析帮助类，禁止复制后形成两套格式规则。
- RFQ 状态判断复用 `QuoteStatusWorkflow`。
- 数据权限复用 `DataScopeService`。
- 零件可修改规则抽取为 `ReleaseItemMutationPolicy`，现有单行保存行为不变化。
- 原有 `PartSelectionImportService` 保持不变，避免影响报价处理和“导入表格选定”。
- 新解析器使用项目已有 Apache POI，不向前端引入 Excel 解析依赖。

## 7. 两阶段接口契约

### 7.1 预览接口

```http
POST /api/market/release/item-data-replacement/preview
Content-Type: multipart/form-data
Permission: market:release:create
```

参数：

| 参数 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `sources` | JSON string | 是 | 当前已选 RFQ 来源数组。 |
| `excelFile` | file | 是 | `.xlsx` 或 `.xls`。 |

预览响应结构：

```json
{
  "success": true,
  "canConfirm": true,
  "previewFingerprint": "sha256摘要",
  "recognizedFields": ["internalTargetLeadTime", "description", "acceptedQty"],
  "summary": {
    "importedCount": 12,
    "matchedCount": 10,
    "changedCount": 7,
    "quantityOnlyCount": 1,
    "unchangedCount": 2,
    "unmatchedCount": 1,
    "skippedCount": 1,
    "errorCount": 0
  },
  "rows": []
}
```

预览接口：

- 不写数据库。
- 不修改当前页面状态。
- 不保存 Excel 到磁盘、数据库或 MinIO。
- 不创建操作日志。
- 结构性错误返回 `400`。
- 行级错误尽量一次返回全部行，并令 `canConfirm = false`。

### 7.2 行级预览 DTO

```json
{
  "excelRowNumber": 5,
  "partNo": "PART-001",
  "version": "A",
  "rfqId": 101,
  "rfqNo": "RFQ-EXAMPLE",
  "itemId": 2001,
  "status": "CHANGED",
  "changes": [
    {
      "field": "description",
      "label": "物料描述",
      "beforeValue": "原描述",
      "afterValue": "新描述"
    }
  ],
  "acceptedQty": 3,
  "reason": ""
}
```

示例只表示 DTO 结构，运行日志不得输出完整 `rows / changes`。

### 7.3 确认接口

```http
POST /api/market/release/item-data-replacement/confirm
Content-Type: multipart/form-data
Permission: market:release:create
```

参数：

| 参数 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `sources` | JSON string | 是 | 必须与预览范围一致。 |
| `excelFile` | file | 是 | 前端保留并重新提交同一原始文件。 |
| `previewFingerprint` | string | 是 | 预览返回的并发状态指纹。 |

确认响应结构：

```json
{
  "success": true,
  "summary": {
    "updatedItemCount": 7,
    "quantityAppliedCount": 2,
    "unchangedCount": 2,
    "unmatchedCount": 1,
    "skippedCount": 1
  },
  "affectedRows": [],
  "acceptedQtyUpdates": [
    {
      "releaseItemKey": "RFQ:2001",
      "itemId": 2001,
      "acceptedQty": 3
    }
  ]
}
```

`affectedRows` 返回所有 `CHANGED / QUANTITY_ONLY` 零件的完整议价提单行结构。即使某行只设置通过数量、没有持久字段更新，前端也能使用后端返回的完整行对象完成跨分页勾选。前端不能根据 Excel 自己拼装数据库结果。

### 7.4 HTTP 错误口径

| 状态 | 场景 |
| --- | --- |
| `400` | 文件类型、表头、重复列、有效行上限等结构性错误；或绕过预览直接确认非法数据。 |
| `403` | 缺少权限或 RFQ 数据权限。 |
| `409` | 预览后来源、零件字段、状态或剩余数量发生变化。 |
| `413` | 超过系统文件大小限制。 |
| `500` | Excel 读取、数据库或其他未预期异常。 |

业务错误返回安全、可操作的中文提示；数据权限错误不得泄露用户无权查看的 RFQ 或零件详情。

预览阶段的重复数据键、字段格式和数量错误使用正常预览响应一次返回全部 `ERROR` 行，并设置 `canConfirm = false`，便于用户集中修正。确认接口不接受带错误的预览；如果客户端绕过前端直接提交非法数据，则返回 `400`。

## 8. 预览指纹和并发保护

### 8.1 不使用临时预览表

本次不新增服务器临时表、缓存表或 Excel 临时文件。前端在弹窗打开期间保留原始 `File`，确认时重新上传。

优点：

- 不需要清理过期预览数据。
- 应用重启不会留下业务临时记录。
- 不保存客户 Excel 内容。
- 不引入多实例缓存一致性问题。

### 8.2 指纹内容

`previewFingerprint` 使用稳定顺序序列化后计算 SHA-256，至少包含：

- 当前用户 ID。
- 规范化并排序后的 RFQ 来源 ID。
- 已识别业务字段集合。
- 每条 Excel 行的规范化图号、版本和非空替换值。
- 图号和版本到 RFQ 零件的匹配结果。
- 匹配零件当前将被替换的相关字段值。
- RFQ 当前状态。
- 零件当前状态。
- 零件询价数量、已提单数量和剩余可提数量。

只把 Excel 实际涉及的目标字段纳入状态指纹，避免无关字段变化造成不必要的预览失效；但可编辑状态和剩余数量必须始终纳入。

该指纹是并发一致性令牌，不替代权限校验。即使客户端伪造请求，确认接口仍必须重新执行全部权限、来源、字段和业务校验。

### 8.3 确认阶段

确认接口必须：

1. 重新解析同一文件。
2. 重新规范化来源列表。
3. 按固定 ID 顺序锁定 RFQ。
4. 查询并按固定 ID 顺序锁定匹配零件。
5. 重新计算 ticket 已提数量和剩余数量。
6. 重新生成完整预览模型和指纹。
7. 使用常量时间或标准安全比较方法比较指纹。
8. 不一致时返回 `409`，不执行任何更新。
9. 一致后再进行批量保存。

## 9. 确认事务算法

### 9.1 事务边界

`ReleaseItemDataReplacementService.confirm(...)` 使用 `@Transactional`，事务覆盖：

- RFQ 锁定和状态校验。
- 零件锁定和可修改校验。
- ticket 数量读取。
- 指纹重算。
- 所有 `item_quote_version` 更新。
- 批次操作日志写入。

任何数据库更新或操作日志异常都回滚全部持久字段修改。

### 9.2 更新算法

对每个 `CHANGED` 行：

1. 从锁定后的 `ItemQuoteVersion` 复制当前实体。
2. 只应用 Excel 表头存在且当前单元格非空的字段。
3. 对日期、订单类型和长度再次校验。
4. 计算实际 `changedFields`。
5. 相同值不加入 SQL 更新字段。
6. 一个零件最多执行一次 `updateById(...)`。
7. 保存后重新构造完整议价提单行 DTO。

通过数量不参与实体更新，只在事务成功响应中返回 `acceptedQtyUpdates`。

### 9.3 原子性边界

以下情况确认接口在更新前失败：

- Excel 内容与预览不同。
- 来源 RFQ 范围与预览不同。
- 预览后零件目标字段被修改。
- 预览后新增或删除了同图号版本匹配项。
- 预览后零件被全部提单或剩余数量变化。
- 预览后 RFQ 状态不再允许修改。
- 任何已匹配行出现字段错误。

`UNMATCHED` 和确认前已经明确的 `SKIPPED` 行允许存在，但它们必须参与指纹，状态变化时要求重新预览。

4. 把这些数量行加入 `selectedItemIdMap` 并同步表格勾选。
5. 不清空其他已选零件。
6. 不改变没有“通过数量”的行的选择和数量。

- 预览失败不改变当前列表、勾选和数量。

- 普通字段错误保留文件和预览结果，方便用户查看，但确认按钮保持禁用。
- 更换文件时清理旧预览和指纹。
- 关闭弹窗时清理文件、预览、指纹和 loading 状态。

## 17. 最终验收标准

### 17.1 Excel 和预览

- 支持 `.xlsx / .xls`。
- 图号和版本为必需匹配键。
- 业务表头可以任意排序和任意缺省。
- 缺失列和空单元格不覆盖现有字段。
- 预览能显示字段级原值和新值。
- 重复 Excel 键或系统重复匹配会阻断确认。
- 未匹配和不可编辑行能明确展示。

### 17.2 保存和并发

- 确认时重新解析、重新授权、重新校验并锁行。
- 预览后数据变化时旧预览不能继续保存。
- 所有持久字段在一个事务中提交。
- 任一更新异常时全部回滚。
- 一个零件只执行一次数据库更新。
- 不新增数据库表或字段。

### 17.3 通过数量

- 有“通过数量”的行确认后自动勾选并设置数量。
- 没有该表头或单元格为空的行保持原选择和数量。
- 其他已选零件不被清空。
- 通过数量不写入 `item_quote_version`。
- 正式提单时由现有接口再次校验并写入 ticket。

### 17.4 权限和日志

- 复用 `market:release:create`。
- 前端隐藏和后端强制校验一致。
- 每个 RFQ 都执行数据权限校验。
- 预览不写操作日志。
- 确认持久更新只写一条批次操作日志。
- 日志不包含完整 Excel、完整逐行差异或认证信息。

### 17.5 回归

- RFQ 导入、核价、报价和议价提单不回退。
- 一批生成一张派生销售订单不回退。
- 已提零件、MES 物料号、WMS、待产、锁库和 U9 链路不回退。
- 后端测试、前端测试和前端构建全部通过。

## 18. 风险和处理原则

| 风险 | 处理原则 |
| --- | --- |
| Excel 空白误清空数据 | 空单元格永远表示“不替换”，本阶段不提供批量清空语义。 |
| Excel 重复行值互相覆盖 | 重复规范化图号和版本整批拒绝。 |
| 多 RFQ 中系统存在重复零件 | 不自行选择第一条，整批拒绝并提示系统重复匹配。 |
| 预览后其他用户修改数据 | 确认时锁行重算指纹，不一致返回 `409`。 |
| 前端循环保存形成部分成功 | 所有持久字段由单一后端事务保存。 |
| 通过数量被误写成询价数量 | 通过数量只返回前端草稿指令，不修改 `item_quote_version.qty`。 |
| 部分提单后修改历史事实 | 只修改 RFQ 主表，既有 ticket 保持不可变。 |
| 大 Excel 占用过多资源 | 服从文件大小限制，并限制 10,000 条有效行。 |
| 操作日志泄露客户表格 | 日志只记录 RFQ ID 和数量汇总，不记录逐行值。 |
| 页面组件继续膨胀 | 预览弹窗拆为独立组件，页面只负责工作台状态协调。 |

## 19. 交付结果

完成后，议价提单批量维护口径统一为：

```text
匹配身份：图号 + 版本
处理范围：当前已选、同客户、具有数据权限的 RFQ
字段语义：有表头且单元格非空才替换
保存方式：后端预览 -> 用户确认 -> 锁行重校验 -> 单事务保存
数量语义：通过数量只属于本次页面提单草稿
历史语义：既有 ticket 不修改
权限语义：复用 market:release:create
日志语义：预览不审计，确认只记录批次安全摘要
```

该能力完成后，用户可以直接使用客户或内部整理的表格批量维护议价提单零件信息，同时保留 QPO 对权限、数据范围、并发、历史提单和后续派生销售订单链路的控制，不需要再逐行重复录入。
