# 百分比费用分类与乘法加权价格公式开发文档

> 编写日期：2026-08-27
> 适用范围：零件核价、组合件核价、材料工艺模块百分比费用维护、报价导出和价格快照。
> 核心结论：百分比费用从“按名称识别税费 + 加法叠加”升级为“明确分类 + 适用范围 + 分类内加总 + 分类间乘法加权”。

## 1. 背景

当前 QPO 的百分比费用有两套配置：

- 普通件百分比费用：`dict_markup_fee`。
- 组装件百分比费用：`dict_assembly_markup_fee`。

当前核价保存时，普通件和组装件都按“基础金额 × 每条费率”计算每条费用，再把费用金额相加。税费通过费用名称包含 `税 / tax / vat` 判断，并用“含税单价 - 税费金额”得到未税单价。

这个实现能满足早期固定费用项，但现在存在三个问题：

1. 税率身份依赖名称，后续改名、多税率或新增类似名称时容易误判。
2. 运输费、管理费、利润、客户权重、税率在业务含义上不是同一层级，不适合继续混在同一页里靠名称区分。
3. 新需求要求百分比费用可扩展，并且价格公式改为同一分类内部费率先加总、不同分类加权因子连续相乘，而不是跨分类把所有百分比直接相加。

## 2. 目标

- 新增统一百分比费用表，使用 `pricingScope = NORMAL / ASSEMBLY` 区分普通件和组装件。
- 新增明确分类字段 `feeCategory`：
  - `BASIC_PERCENT`：基础百分比费用，例如运输费、管理费、利润。
  - `TAX`：税率。
  - `CUSTOMER_WEIGHT`：客户权重。
- 普通件核价改为乘法加权公式：
  - 未税单价 = `基础成本 * 客户权重因子 * 基础百分比费用因子`
  - 含税单价 = `基础成本 * 客户权重因子 * 基础百分比费用因子 * 税率因子`
- 组合件继续保持“子件价格由子件带入，组装件百分比费用只作用于组装费”的口径。
- 材料工艺模块中，百分比费用维护拆为三个子页面：基础百分比费用、税率、客户权重。
- 税率和客户权重身份分别由 `feeCategory = TAX / CUSTOMER_WEIGHT` 决定，不再靠名称判断；系统默认税率和系统默认客户权重不可删除，只能停用或修改百分率。
- 前端实时预估、后端保存核价、导出快照保持同一公式口径。
- 本功能采用硬切换：新版本只使用统一百分比费用模型，旧两套费用运行逻辑从代码中移除。
- 不新增权限点，继续复用材料工艺模块现有费用维护权限。

## 3. 非目标

- 不按客户主数据做自动差异化定价；第一版客户权重是按适用范围维护的全局系统加权项，不绑定具体客户。
- 不修改材料费、工艺小时价格、非工时固定费用的取数规则。
- 不重新计算历史已保存核价单价、历史提单、历史销售订单价格。
- 不修改销售订单导入、U9 同步、MES、WMS 的接口字段口径。
- 不保留旧两套百分比费用运行逻辑；升级后不再让代码读取或维护 `dict_markup_fee`、`dict_assembly_markup_fee`。
- 不以清空业务数据作为上线前提；历史报价、历史提单、历史销售订单继续保留已保存价格和快照。仅本地测试环境需要重新验证时，可以按现有清库脚本清空业务数据。
- 不编辑 `V1__qpo_baseline_schema.sql`、`V2__qpo_baseline_seed_data.sql` 或任何已执行迁移。

## 4. 业务口径

### 4.1 百分比费用分类

| 分类 | 编码 | 用途 | 是否进入未税价 | 是否进入含税价 |
| --- | --- | --- | --- | --- |
| 基础百分比费用 | `BASIC_PERCENT` | 运输费、管理费、利润等基础加成 | 是 | 是 |
| 税率 | `TAX` | 增值税或后续其他税率 | 否 | 是 |
| 客户权重 | `CUSTOMER_WEIGHT` | 对客户、项目或商务策略的全局权重加成 | 是 | 是 |

所有分类都可以有多条启用费用。每个分类内部按 `sortNo ASC, id ASC` 保留展示和快照顺序，计算时先把该分类所有启用 `ratePercent` 加总，再组成一个分类因子：

```text
分类因子 = 1 + Σ(ratePercent) / 100
```

当某个分类没有启用项时，该分类因子默认为 `1.0`。

### 4.2 普通件公式

普通件基础成本沿用现有后端权威口径：

```text
材料费用 = 毛坯重量 * 材料单价
工艺费用 = Σ(工时 * 具体工艺有效小时价格) + Σ(非工时固定费用)
基础成本 = 材料费用 + 工艺费用
```

新增乘法加权公式：

```text
客户权重因子 = 1 + Σ(CUSTOMER_WEIGHT.ratePercent) / 100
基础百分比费用因子 = 1 + Σ(BASIC_PERCENT.ratePercent) / 100
税率因子 = 1 + Σ(TAX.ratePercent) / 100

未税单价 = 基础成本 * 客户权重因子 * 基础百分比费用因子
含税单价 = 基础成本 * 客户权重因子 * 基础百分比费用因子 * 税率因子
未税金额 = 未税单价 * 数量
含税金额 = 含税单价 * 数量
```

示例：

```text
基础成本 = 100
客户权重 = 10%
运输费 = 5%，管理费 = 5%，利润 = 15%
税率 = 13%

客户权重因子 = 1.10
基础百分比费用因子 = 1 + 5% + 5% + 15% = 1.25
税率因子 = 1.13

未税单价 = 100 * 1.10 * 1.25 = 137.5
含税单价 = 137.5 * 1.13 = 155.375
```

这与跨分类全部直接相加不同。新公式把每类百分比费用作为独立加权层处理：同分类内部先加总，不同分类之间再相乘。

### 4.3 组合件公式

组合件继续保持现有原则：子件价格由子件核价结果带入，不在父件核价时重新按当前字典价计算子件。

第一版只替换组装费部分的百分比计算：

```text
子件汇总 = Σ(子件含税单价 * 每父件用量)
组装费 = 用户录入的组装费

组装费未税价 = 组装费 * 客户权重因子 * 基础百分比费用因子
组装费含税价 = 组装费 * 客户权重因子 * 基础百分比费用因子 * 税率因子

父件未税单价 = 子件汇总 + 组装费未税价
父件含税单价 = 子件汇总 + 组装费含税价
```

说明：

- `pricingScope = ASSEMBLY` 的费用只作用于组装费。
- 子件沿用自身已保存价格快照，不重新读取当前材料价、工艺价或百分比费用。
- 本阶段不做“子件未税汇总 + 组装费未税”的深度重构，避免改变既有组合件报价口径。

### 4.4 税率和客户权重系统项规则

税率不再通过费用名称识别，而是由 `feeCategory = TAX` 决定。客户权重不再作为普通可删除费用项，而是由 `feeCategory = CUSTOMER_WEIGHT` 决定。

默认税率行和默认客户权重行都需要设置为系统必需项：

- 不允许删除。
- 允许修改百分率。
- 允许启用 / 停用。
- 名称建议固定展示为“税率”和“客户权重”，第一版不开放改名，避免系统项身份被业务误解。
- 删除接口遇到系统必需税率行或系统必需客户权重行时返回业务错误，不做物理删除。

### 4.5 客户权重第一版口径

客户权重第一版作为按适用范围维护的全局系统加权项，不绑定客户主数据，不按 RFQ 客户自动筛选。

每个 `pricingScope` 默认保留一条系统客户权重：

```text
NORMAL / CUSTOMER_WEIGHT / 客户权重 / 0%
ASSEMBLY / CUSTOMER_WEIGHT / 客户权重 / 0%
```

默认客户权重可以停用，也可以把百分率从 0% 改为业务需要的权重；但不能删除，也不建议新增多个客户权重行。这样既保留后续配置弹性，又避免客户权重像普通费用一样被误删或重复叠加。

如果未来要支持“不同客户不同权重”，应另起客户价格策略设计，例如新增客户-权重关系表，并明确普通件、组装件、销售订单导入、报价模板导出的继承规则。本次不提前做复杂客户绑定，避免超出当前需求。

## 5. 数据模型设计

### 5.1 新统一表

新增表建议命名：

```text
dict_pricing_markup_fee
```

字段设计：

| 字段 | 类型建议 | 说明 |
| --- | --- | --- |
| `id` | `BIGSERIAL` 或沿用项目整数主键风格 | 主键。 |
| `pricing_scope` | `VARCHAR(20)` | `NORMAL` 或 `ASSEMBLY`。 |
| `fee_category` | `VARCHAR(32)` | `BASIC_PERCENT`、`TAX`、`CUSTOMER_WEIGHT`。 |
| `fee_name` | `VARCHAR(100)` | 页面显示名称。 |
| `rate_percent` | `NUMERIC(12,4)` | 百分比费率，允许 0。 |
| `sort_no` | `INTEGER` | 排序。 |
| `enabled` | `BOOLEAN` | 是否启用。 |
| `system_required` | `BOOLEAN` | 系统必需项，第一版用于默认税率和默认客户权重不可删除。 |
| `created_at` | `TIMESTAMP` | 创建时间，按项目已有风格决定是否由数据库默认。 |
| `updated_at` | `TIMESTAMP` | 更新时间，按项目已有风格决定是否自动维护。 |

建议约束：

```text
pricing_scope in ('NORMAL', 'ASSEMBLY')
fee_category in ('BASIC_PERCENT', 'TAX', 'CUSTOMER_WEIGHT')
rate_percent >= 0
unique(pricing_scope, fee_category, fee_name)
```

### 5.2 迁移策略

当前最新迁移为 `V22__data_center_sso_login_config.sql`，本功能新增迁移应使用下一个版本：

```text
quote-backend/src/main/resources/db/migration/V23__pricing_markup_fee_category_scope.sql
```

迁移规则：

- 从 `dict_markup_fee` 迁移为 `pricing_scope = NORMAL`。
- 从 `dict_assembly_markup_fee` 迁移为 `pricing_scope = ASSEMBLY`。
- 迁移时仅使用旧名称做一次性分类：名称包含 `税 / tax / vat` 的旧费用迁为 `TAX`，其他旧费用迁为 `BASIC_PERCENT`。
- 默认税率行设置 `system_required = true`。
- 每个 `pricingScope` 插入一条默认客户权重行，`fee_category = CUSTOMER_WEIGHT`、`rate_percent = 0`、`system_required = true`、`enabled = false`。
- 数据迁移完成后删除旧表 `dict_markup_fee` 和 `dict_assembly_markup_fee`，让数据库结构与新代码保持一致。
- 新代码只读取和维护 `dict_pricing_markup_fee`，不保留旧接口和旧 Mapper 作为运行路径。
- 没有启用客户权重时因子为 `1.0`；默认客户权重行即使保留在表中，停用时也不参与计算。

上线方式要求：

- 本功能必须以后端、前端、数据库迁移一起发布，不支持“旧前端 + 新后端”或“新前端 + 旧后端”的滚动兼容组合。
- 本地测试环境如需要绝对干净的数据，可以先清空业务数据再开发验证；生产或正式服务器版本更新不得以清空业务数据为前提。
- 旧表删除不影响历史报价，因为历史报价的权威数据是 `item_quote_version`、`order_delivery_ticket`、`sales_order_item` 中已保存的价格字段和快照。

## 6. 后端接口设计

### 6.1 新费用维护接口

建议在 `DictController` 或拆出的字典服务中新增统一接口：

```text
GET    /api/dict/pricing-markup-fees?pricingScope=NORMAL&feeCategory=BASIC_PERCENT
POST   /api/dict/pricing-markup-fees
PUT    /api/dict/pricing-markup-fees/{id}
DELETE /api/dict/pricing-markup-fees/{id}
```

请求 / 响应 DTO 建议字段：

```json
{
  "id": 1,
  "pricingScope": "NORMAL",
  "feeCategory": "BASIC_PERCENT",
  "feeName": "利润",
  "ratePercent": 15.0,
  "sortNo": 3,
  "enabled": true,
  "systemRequired": false
}
```

校验规则：

- `pricingScope` 必须是 `NORMAL / ASSEMBLY`。
- `feeCategory` 必须是 `BASIC_PERCENT / TAX / CUSTOMER_WEIGHT`。
- `feeName` 必填，去首尾空格后不能为空。
- `ratePercent` 为空时按 `0` 保存，不允许负数。
- `sortNo` 为空时按 `0` 保存。
- `enabled` 为空时按 `true` 保存。
- 删除 `systemRequired = true` 的税率行或客户权重行时拒绝并返回明确提示。
- `feeCategory = TAX / CUSTOMER_WEIGHT` 的系统项第一版不开放普通新增，维护动作聚焦为修改百分率和启停。

### 6.2 旧接口下线

以下旧接口随本次重构下线，不再作为兼容入口保留：

```text
/api/dict/markup-fees
/api/dict/assembly-markup-fees
```

下线口径：

- 删除旧接口对应的 Controller 方法、实体、Mapper 和前端 API 封装。
- 所有字典维护和核价计算只使用 `/api/dict/pricing-markup-fees`。
- 测试不再断言旧接口存在；改为断言旧接口路径没有被前端引用，后端代码没有旧 Mapper 注入。
- 如果部署后仍有旧前端访问旧接口，应视为版本包未同步更新，而不是后端兼容问题。

## 7. 后端价格计算设计

### 7.1 新计算边界

建议新增独立计算服务，避免继续让 `EngineerService` 承担所有细节：

```text
quote-backend/src/main/java/com/machining/quote/service/PricingMarkupFeeService.java
quote-backend/src/main/java/com/machining/quote/service/PricingFeeCalculator.java
```

职责划分：

- `PricingMarkupFeeService`：按 `pricingScope` 加载启用费用、维护 CRUD、做字段校验和系统项删除保护。
- `PricingFeeCalculator`：接收基础金额和费用列表，输出分类因子、逐行增量金额、未税价、含税价。
- `EngineerService`：继续负责材料、工艺、组合件关系和状态保存，只调用计算服务获取价格结果。

### 7.2 快照结构

`item_quote_version.fee_data` 继续作为费用快照来源，但每行需要增加分类、范围和分类内加总过程字段，示例：

```json
{
  "feeName": "利润",
  "pricingScope": "NORMAL",
  "feeCategory": "BASIC_PERCENT",
  "ratePercent": 15.0,
  "factor": 1.15,
  "baseAmount": 110.0,
  "cost": 16.5,
  "amountAfter": 137.5,
  "includedInUntaxedPrice": true,
  "includedInTaxIncludedPrice": true
}
```

字段口径：

- `factor`：当前费用行的费率因子。
- `baseAmount`：当前费用分类应用前的金额，同一分类内多条费用使用相同基数。
- `cost`：当前费用行增量金额，即 `baseAmount * ratePercent / 100`。
- `amountAfter`：当前分类内按费用顺序累计到当前行后的金额。
- `feeCategory`：导出和未税 / 含税识别必须依赖该字段，不再依赖 `feeName`。
- `pricingScope`：标记该快照来自普通件还是组装件费用配置。

为了保持当前报价模板导出字段稳定，`cost` 字段继续保留；“百分比费用合计”建议使用 `taxIncludedUnitPrice - baseCost` 或快照行 `cost` 求和，两者应在四舍五入允许范围内一致。

### 7.3 历史快照只读规则

历史 `feeData` 可能只有：

```json
{
  "feeName": "税费",
  "ratePercent": 13.0,
  "cost": 13.0
}
```

只读规则：

- 导出历史订单时继续按历史快照中的 `feeName / ratePercent / cost` 展示，不实时查当前字典价。
- 新核价保存生成的新快照必须带 `feeCategory / pricingScope / factor / baseAmount / amountAfter`。
- 不批量回填历史 `feeData`，避免改变历史报价追溯结果。

## 8. 前端设计

### 8.1 材料工艺模块

页面位置不变：

```text
quote-frontend/src/components/MaterialProcessManage.vue
```

建议把当前两个页签：

```text
百分比费用类
组装件百分比费用类
```

调整为一个统一维护区：

```text
百分比费用
```

维护区内部使用两个层级控制：

```text
适用范围：普通件 / 组装件
费用分类：基础百分比费用 / 税率 / 客户权重
```

表格列：

| 列 | 说明 |
| --- | --- |
| 序号 | `sortNo`。 |
| 费用名称 | `feeName`。 |
| 费率 | `ratePercent`，显示为百分比。 |
| 分类 | 展示中文分类，可放在筛选后表格中保留用于确认。 |
| 适用范围 | 展示普通件 / 组装件。 |
| 启用 | `enabled`。 |
| 系统项 | `systemRequired`，税率和客户权重默认行展示“系统项”。 |
| 操作 | 编辑、删除；系统项禁用删除按钮。 |

交互要求：

- 基础百分比费用页允许新增、编辑、删除。
- 税率页和客户权重页不显示新增按钮，默认系统行只能修改百分率和启停。
- 用户不能在表单里靠手输文字决定税率或客户权重身份。
- 删除系统必需税率行或客户权重行时前端禁用按钮；后端仍做最终保护。
- 搜索、分页沿用材料工艺模块现有风格，数据量不大时保持前端分页即可。

### 8.2 字典缓存

`dictionaryStore` 新增统一缓存：

```js
pricingMarkupFees: []
```

旧缓存字段同步删除：

```js
markupFees
assemblyMarkupFees
```

所有前端消费者通过统一 helper 读取费用：

```js
getPricingMarkupFees(pricingScope, feeCategory)
```

这样可以让代码里不再出现“普通百分比费用一套、组装件百分比费用一套”的旧模型。普通件和组装件差异只由 `pricingScope` 参数表达。

### 8.3 零件核价实时预估

页面位置：

```text
quote-frontend/src/components/ItemPricing.vue
```

实时预估应与后端保存公式一致：

- 普通件：用 `pricingScope = NORMAL` 的启用费用计算。
- 组合件：用 `pricingScope = ASSEMBLY` 的启用费用，仅作用于组装费。
- 税率识别依赖 `feeCategory = TAX`，删除前端 `isTaxFeeName` 这类名称判断。
- 用户修改材料、工艺、非工时费用、组装费后，预估价格实时刷新。
- 保存核价时仍以后端重算结果为准，前端预估不作为可信入库价格。

## 9. 权限设计

本功能不新增权限点。

| 能力 | 复用权限 |
| --- | --- |
| 查看百分比费用 | `engineer:dict:view` |
| 新增 / 编辑 / 删除基础百分比费用，编辑 / 启停税率和客户权重 | `engineer:dict:fee-manage` |
| 普通件核价保存 | `engineer:pricing:save-item` |
| 组合件核价保存 | `engineer:pricing:save-item` |

说明：

- 前端隐藏按钮只改善体验，后端 `@RequirePermission` 仍是最终边界。
- 不新增 `common:*` 权限。
- 不给税率、客户权重单独加新权限，避免材料工艺模块权限碎片化。

## 10. 日志设计

字典维护属于低频写操作，必须进入操作日志；核价保存继续沿用已有核价保存日志。

建议新增统一动作编码：

| 动作 | 编码 | targetType |
| --- | --- | --- |
| 新增百分比费用 | `DICT_PRICING_MARKUP_FEE_CREATE` | `dict_pricing_markup_fee` |
| 更新百分比费用 | `DICT_PRICING_MARKUP_FEE_UPDATE` | `dict_pricing_markup_fee` |
| 删除百分比费用 | `DICT_PRICING_MARKUP_FEE_DELETE` | `dict_pricing_markup_fee` |

日志摘要允许记录：

- `pricingScope`
- `feeCategory`
- `feeName`
- `ratePercent`
- `enabled`
- `systemRequired`

日志摘要不得记录：

- 完整报价快照。
- 完整 Excel 内容。
- token、Authorization、Cookie。
- 外部系统密钥。

普通读取、核价页实时预估和字典下拉加载不写操作日志，也不增加高频业务 INFO。

## 11. 导出和外部链路影响

报价模板导出、报价处理、议价提单、销售订单派生和 U9 同步继续读取已保存价格字段和快照：

- `baseCost`
- `feeData`
- `untaxedUnitPrice`
- `untaxedTotalPrice`
- `taxIncludedUnitPrice`
- `taxIncludedTotalPrice`

不允许导出或外部同步时重新读取当前百分比费用字典来重算历史报价，否则会破坏历史报价可追溯性。

销售订单导入自带价格的场景不受本公式影响；只有工程在零件核价模块保存普通件或组合件核价时才使用新公式。

## 12. 验收标准

- 材料工艺模块只保留一个统一百分比费用维护入口，并能按普通件 / 组装件、基础百分比费用 / 税率 / 客户权重维护数据。
- 税率身份来自 `feeCategory = TAX`，不再靠名称包含 `税 / tax / vat` 判断。
- 默认税率和默认客户权重可以修改百分率、启停，但不能删除。
- 后端不再暴露 `/api/dict/markup-fees` 和 `/api/dict/assembly-markup-fees`，前端不再引用 `markupFees / assemblyMarkupFees` 旧缓存字段。
- 普通件核价保存使用新公式：`含税 = 基础成本 * 客户权重因子 * 基础百分比费用因子 * 税率因子`。
- 普通件未税价不包含 `TAX` 因子。
- 组合件只对组装费应用 `ASSEMBLY` 范围下的乘法因子，子件价格快照不被重算。
- 前端实时预估与后端保存结果在相同输入下保持一致。
- 新保存的 `feeData` 快照包含 `pricingScope / feeCategory / factor / baseAmount / amountAfter`。
- 历史订单导出继续读取历史快照，不因当前费用字典变化而重算。
- 不新增权限点，不记录高频读取日志，不泄露完整快照、token 或密钥。
- `git diff --check` 无空白错误，后端和前端目标测试通过。

## 14. 风险和处理

| 风险 | 处理 |
| --- | --- |
| 新旧公式导致报价结果变化 | 这是本需求的目标变化；测试中必须用明确样例锁住新旧差异。 |
| 税率名称不再决定税费 | 迁移时一次性按旧名称分类；运行时全部依赖 `feeCategory`。 |
| 前端和后端公式漂移 | 公式测试分别覆盖前端预估和后端保存，并使用同一组数字样例。 |
| 历史导出被当前字典影响 | 导出继续读取保存快照，不实时查字典。 |
| 旧接口和新接口并存造成混乱 | 本次采用硬切换，删除旧接口、旧实体、旧 Mapper 和旧前端缓存字段。 |
| 部署包前后端版本不一致 | 后端、前端、数据库迁移必须同版本发布；本功能不支持滚动兼容。 |
| 客户权重被误解为按客户自动匹配 | 第一版文档明确为全局加权项；客户差异化策略后续单独设计。 |
