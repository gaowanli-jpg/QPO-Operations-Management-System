# 已提零件筛选区优化开发文档
最后更新：2026-08-02

## 1. 背景

当前 **已提零件** 模块已经被重构为 MES/WMS 未完成工作池：

- 默认只展示尚未完成物料号获取和锁库流程的 `order_delivery_ticket` 行。
- 获取物料号和获取库存信息已经收口为勾选行后点击顶部批量按钮。
- 完成锁库后的结果进入 **锁库零件** 模块查看，原始提单行不删除、不搬表。
- 已提零件页面仍保留客户、RFQ号、图号、版本、内部项目号、客户订单号、客户项目号、MES状态、WMS状态、交货日期等筛选条件。

现有筛选区把所有查询字段平铺在一行或多行中，视觉拥挤，且与“未完成工作池”的实际使用场景不匹配。用户更关心当前零件卡在哪个处理阶段，而不是每次都面对大量订单追溯字段。

## 2. 当前问题

### 2.1 视觉问题

- 筛选控件数量过多，客户、单号、图号、版本、状态、日期和操作按钮全部挤在同一工具栏区域。
- 控件宽度和信息密度不均衡，页面顶部显得杂乱。
- `搜索`、`刷新`、`批量获取物料号`、`批量获取库存数据` 与筛选输入混排，主操作不够突出。
- 小屏或较窄窗口下换行后控件顺序不稳定，用户扫视成本较高。

### 2.2 业务语义问题

- 已提零件默认是“未完成工作池”，用户核心任务是处理卡住的行：
  - 缺物料号。
  - 等 MES 回调。
  - MES 获取失败。
  - 已有物料号但未获取库存。
  - WMS 处理中或失败。
- 现有 `MES状态` + `WMS状态` 两个下拉是技术状态，用户需要组合理解，例如 `MES=SUCCESS + WMS=PENDING` 才能表示“待获取库存”。
- `RFQ号` 对销售订单来源提单不够通用，销售订单来源行可能没有 RFQ 号，继续放在主筛选区会弱化销售订单链路体验。
- 内部项目号、客户订单号、客户项目号、交货日期更多是追溯筛选，不应默认占据首屏主筛选空间。

## 3. 目标

### 3.1 用户目标

- 让已提零件页面更像一个“待处理工作台”，而不是一个全字段查询表单。
- 用户进入页面后优先按客户、图号、版本和流程阶段定位待处理行。
- 用户能一眼理解“当前卡在哪一步”，不用手动组合 MES/WMS 技术状态。
- 追溯类字段仍然可用，但默认收起，不占用主操作区。
- 批量获取物料号和批量获取库存数据保持顶部主操作入口。

### 3.2 技术目标

- 第一版优先前端优化，不改数据库。
- 尽量复用现有 `DeliveredItemQueryReq` 查询参数。
- 不做前端全量拉取后本地过滤，仍使用后端分页查询。
- 不新增用户权限。
- 不改变 MES 获取、MES 回调、同图号版本去重、WMS 锁库和锁库零件结果池逻辑。
- 保持 RFQ 来源和销售订单来源已提零件都可正常展示和筛选。

## 4. 非目标

- 不新增左侧菜单模块。
- 不新增新的业务表。
- 不改变 `order_delivery_ticket` / `order_delivery_ticket_allocation` 数据边界。
- 不恢复行内“获取物料号 / 获取库存数据”按钮。
- 不在已提零件页展示已完成流程行。
- 不新增高频查询日志。
- 不把已提零件页面做成报表中心或历史总账。

## 5. 推荐方案

采用 **主筛选 + 流程阶段 + 高级筛选折叠 + 操作区分离** 的方案。

页面顶部拆成三块：

```text
主筛选区
  客户 / 图号 / 版本 / 流程状态 / 搜索 / 重置 / 高级筛选

批量操作区
  批量获取物料号 / 批量获取库存数据

高级筛选区（默认收起）
  来源单号 / 内部项目号 / 客户订单号 / 客户项目号 / 交货日期 / MES状态 / WMS状态
```

核心变化：

- 主筛选区只保留最高频字段。
- `MES状态` 和 `WMS状态` 默认不直接暴露，改为主筛选 `流程状态`。
- 追溯类字段进入高级筛选。
- 搜索、重置、展开高级筛选是查询动作。
- 批量获取物料号、批量获取库存数据是业务处理动作，视觉上和查询动作分组。

## 6. 筛选字段分层

### 6.1 主筛选字段

| 字段 | 控件 | 默认展示 | 说明 |
| --- | --- | --- | --- |
| 客户 | 客户选择按钮 | 是 | 复用现有 `CustomerPickerDialog`，权限仍为 `market:delivered-item:customer-select`。 |
| 图号 | 输入框 | 是 | 高频定位字段，传 `partNo`。 |
| 版本 | 输入框 | 是 | 与图号配套使用，传 `version`。 |
| 流程状态 | 下拉框 | 是 | 新增前端语义字段 `flowStage`，映射到现有查询参数。 |
| 搜索 | 按钮 | 是 | 执行 `handleSearch()`。 |
| 重置 | 按钮 | 是 | 清空筛选并重新加载第一页。 |
| 高级筛选 | 文本按钮 / 次级按钮 | 是 | 展开或收起追溯类字段。 |

### 6.2 高级筛选字段

| 字段 | 控件 | 默认展示 | 说明 |
| --- | --- | --- | --- |
| 来源单号 | 输入框 | 否 | 第一版可继续绑定 `rfqNo`；文案从 `RFQ号` 改为 `来源单号/RFQ号` 或 `来源单号`。 |
| 内部项目号 | 输入框 | 否 | 传 `internalProjectNo`。 |
| 客户订单号 | 输入框 | 否 | 传 `customerOrderNo`。 |
| 客户项目号 | 输入框 | 否 | 传 `customerProjectNo`。 |
| 交货日期 | 日期范围 | 否 | 传 `dateFrom` / `dateTo`。 |
| MES状态 | 下拉框 | 否 | 保留给排查用，传 `mesSyncStatus`。 |
| WMS状态 | 下拉框 | 否 | 保留给排查用，传 `wmsAllocateStatus`。 |

### 6.3 不建议进入主筛选的字段

- `internalProjectNo`：主要用于订单追溯，不是处理工作池的第一定位方式。
- `customerOrderNo` / `customerProjectNo`：更偏订单追溯，适合高级筛选。
- `rfqNo`：RFQ 来源可用，但销售订单来源不通用，建议弱化成高级筛选。
- `dateRange`：交货期有价值，但不是处理状态第一入口，放高级筛选更清爽。

## 7. 流程状态设计

### 7.1 新增前端字段

在 `DeliveredItemManage.vue` 中新增前端本地字段：

```js
flowStage: ''
```

该字段不一定直接传给后端。第一版建议在 `buildParams()` 中转换成现有 `mesSyncStatus` / `wmsAllocateStatus` 参数。

### 7.2 流程状态选项

| 选项文案 | value | 查询口径 | 用途 |
| --- | --- | --- | --- |
| 全部未完成 | 空值 | 不额外传状态，使用后端默认 ACTIVE 未完成池 | 默认视图。 |
| 待获取物料号 | `NEED_MATERIAL` | 需要后端支持组合条件，或第一版暂不开放 | 物料号为空或 MES 未处理。 |
| 待MES回调 | `MES_CALLBACK_PENDING` | `mesSyncStatus=CALLBACK_PENDING` | 看 MES 长任务等待行。 |
| 物料号处理中 | `MES_PROCESSING` | `mesSyncStatus=PROCESSING` | 看已提交 MES 但未完成行。 |
| 物料号失败 | `MES_FAILED` | `mesSyncStatus=FAILED` | 看可重试 MES 行。 |
| 待获取库存 | `NEED_WMS` | 推荐后端新增组合条件，或第一版通过高级筛选手动组合 | 物料号已成功但 WMS 未处理。 |
| 库存处理中 | `WMS_PROCESSING` | `wmsAllocateStatus=PROCESSING` | 看 WMS 处理中行。 |
| 库存失败 | `WMS_FAILED` | `wmsAllocateStatus=FAILED` | 看可重试 WMS 行。 |

### 7.3 第一版推荐取舍

为了避免后端大改，第一版分两级实现：

**第一批可直接落地的流程状态：**

| value | 映射 |
| --- | --- |
| `MES_CALLBACK_PENDING` | `mesSyncStatus=CALLBACK_PENDING` |
| `MES_PROCESSING` | `mesSyncStatus=PROCESSING` |
| `MES_FAILED` | `mesSyncStatus=FAILED` |
| `WMS_PROCESSING` | `wmsAllocateStatus=PROCESSING` |
| `WMS_FAILED` | `wmsAllocateStatus=FAILED` |

**需要后端补 `flowStage` 才能精准落地的流程状态：**

| value | 原因 |
| --- | --- |
| `NEED_MATERIAL` | 需要判断 `material_no` 为空或 MES 未成功，当前单一参数无法完整表达。 |
| `NEED_WMS` | 需要判断物料号已确认 / MES 成功 / WMS 未成功，当前单一参数无法完整表达。 |

建议第二阶段后端新增 `flowStage` 查询参数，统一处理组合条件。这样前端语义更自然，用户不需要理解 MES/WMS 技术状态。

## 8. 后端接口设计

### 8.1 第一阶段：不改接口

第一阶段只改前端显示和参数映射：

- `flowStage=MES_CALLBACK_PENDING` -> `mesSyncStatus=CALLBACK_PENDING`
- `flowStage=MES_PROCESSING` -> `mesSyncStatus=PROCESSING`
- `flowStage=MES_FAILED` -> `mesSyncStatus=FAILED`
- `flowStage=WMS_PROCESSING` -> `wmsAllocateStatus=PROCESSING`
- `flowStage=WMS_FAILED` -> `wmsAllocateStatus=FAILED`
- 高级筛选中如果用户手动选择 MES状态或 WMS状态，则以高级筛选为准，或清空流程状态。

第一阶段不新增后端参数，因此风险低、回归范围小。

### 8.2 第二阶段：新增 `flowStage`

为了精确支持“待获取物料号”和“待获取库存”，建议在后端新增：

```java
private String flowStage;
```

位置：

- `quote-backend/src/main/java/com/machining/quote/dto/DeliveredItemQueryReq.java`
- `quote-backend/src/main/java/com/machining/quote/service/DeliveredItemService.java`

后端映射：

| flowStage | SQL口径 |
| --- | --- |
| `NEED_MATERIAL` | `NULLIF(BTRIM(ticket.material_no), '') IS NULL OR COALESCE(ticket.mes_sync_status, 'PENDING') IN ('PENDING', 'FAILED')` |
| `MES_PROCESSING` | `ticket.mes_sync_status = 'PROCESSING'` |
| `MES_CALLBACK_PENDING` | `ticket.mes_sync_status = 'CALLBACK_PENDING'` |
| `MES_FAILED` | `ticket.mes_sync_status = 'FAILED'` |
| `NEED_WMS` | `NULLIF(BTRIM(ticket.material_no), '') IS NOT NULL AND ticket.mes_sync_status = 'SUCCESS' AND COALESCE(ticket.wms_allocate_status, 'PENDING') IN ('PENDING', 'FAILED')` |
| `WMS_PROCESSING` | `ticket.wms_allocate_status = 'PROCESSING'` |
| `WMS_FAILED` | `ticket.wms_allocate_status = 'FAILED'` |

约束：

- `flowStage` 与 `mesSyncStatus` / `wmsAllocateStatus` 同时存在时，建议 `flowStage` 优先。
- `flowStage` 只在 `flowScope=ACTIVE` 或默认未完成池中使用。
- 非法 `flowStage` 不报错，按未传处理，避免旧链接或手工调用失败。

## 10. 参数映射设计

### 10.1 前端 filters 结构

建议调整为：

```js
const filters = reactive({
  customerName: '',
  partNo: '',
  version: '',
  flowStage: '',
  rfqNo: '',
  internalProjectNo: '',
  customerOrderNo: '',
  customerProjectNo: '',
  mesSyncStatus: '',
  wmsAllocateStatus: '',
  dateRange: []
})
```

说明：

- `flowStage` 是前端业务语义字段。
- `rfqNo` 暂时保留字段名，避免第一版改后端和接口。
- 页面展示文案改成 `来源单号`。

### 10.2 buildParams 第一阶段逻辑

第一阶段不新增后端 `flowStage` 时：

```js
const flowStageStatusMap = {
  MES_PROCESSING: { mesSyncStatus: 'PROCESSING' },
  MES_CALLBACK_PENDING: { mesSyncStatus: 'CALLBACK_PENDING' },
  MES_FAILED: { mesSyncStatus: 'FAILED' },
  WMS_PROCESSING: { wmsAllocateStatus: 'PROCESSING' },
  WMS_FAILED: { wmsAllocateStatus: 'FAILED' }
}
```

规则：

- 主筛选 `flowStage` 映射到 `mesSyncStatus` 或 `wmsAllocateStatus`。
- 高级筛选中用户直接选择 `mesSyncStatus` / `wmsAllocateStatus` 时，应清空 `flowStage`，避免产生冲突。
- 或者在 `buildParams()` 中明确优先级：高级状态优先，流程状态次之。
- `NEED_MATERIAL` / `NEED_WMS` 如果第一阶段无法精确查询，则不要先展示，避免误导。

### 10.3 buildParams 第二阶段逻辑

第二阶段后端支持 `flowStage` 后：

```js
if (filters.flowStage) {
  params.flowStage = filters.flowStage
}
```

此时可以开放完整流程状态：

- `NEED_MATERIAL`
- `MES_PROCESSING`
- `MES_CALLBACK_PENDING`
- `MES_FAILED`
- `NEED_WMS`
- `WMS_PROCESSING`
- `WMS_FAILED`

- `flowStage=MES_CALLBACK_PENDING` 返回待 MES 回调行。
- `flowStage=MES_FAILED` 返回 MES 失败行。
- `flowStage=NEED_WMS` 返回已有物料号且待 WMS 的行。
- `flowStage=WMS_FAILED` 返回 WMS 失败行。
- 非法 `flowStage` 按未传处理。
- `flowStage` 不破坏默认 `ACTIVE` 未完成池过滤。
- 数据权限仍生效。

## 14. 风险与处理

### 14.1 流程状态与高级状态冲突

风险：

- 用户选择了 `流程状态=待MES回调`，又在高级筛选选择 `MES状态=失败`。

处理：

- 第一版建议高级技术状态选择时清空 `flowStage`。
- 或在 UI 上提示“流程状态和 MES/WMS 状态不可同时使用”。
- 推荐实现：`flowStage` 与高级 MES/WMS 状态互斥，交互最清楚。

### 14.2 销售订单来源没有 RFQ号

风险：

- 主筛选继续展示 `RFQ号` 会让用户误以为销售订单来源不可筛。

处理：

- 主筛选移除 RFQ号。
- 高级筛选改文案为 `来源单号`。
- 第一版字段仍传 `rfqNo`，后续如需要更精准，可后端扩展 `sourceOrderNo`。

### 14.3 过早新增后端组合状态

风险：

- 一次性改前后端会扩大回归面。

处理：

- 分两阶段。
- 阶段 1 和阶段 2 只做前端布局与现有状态映射。
- 阶段 3 再加后端 `flowStage`，补精准组合状态。

### 14.4 用户找不到高级字段

风险：

- 把追溯字段收起后，老用户可能一开始找不到内部项目号、客户订单号等字段。

处理：

- 按钮文案使用 `高级筛选`。
- 展开后字段保持原有顺序：来源单号、内部项目号、客户订单号、客户项目号、交货日期、MES状态、WMS状态。
- 如果存在活跃高级筛选，即使区域收起，也显示 `已启用高级筛选` 标签或让按钮高亮。
