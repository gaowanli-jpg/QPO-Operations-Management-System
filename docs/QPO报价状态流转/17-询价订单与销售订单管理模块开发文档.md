# QPO 询价订单与销售订单管理模块开发文档

最后更新：2026-08-01

## 1. 背景与结论

当前系统左侧存在 **订单管理** 和 **历史订单** 两个模块。

- **订单管理** 实际管理的是 RFQ / 询价单主链路，名称过于泛化，容易和销售订单混淆。
- **历史订单** 的原业务定位已经不再成立，因为系统不允许用户物理删除订单或零件信息，也不应提供“删除后再历史查询”的管理口径。
- 销售订单独立主表链路已经建立，销售订单应拥有独立的管理入口，用于查看、废弃、恢复、补传图纸和查看下游提单 / 工艺信息。

因此本次调整分为三件事：

1. **改名一个模块**：将原 **订单管理** 改名为 **询价订单**，继续管理 RFQ / 询价单。
2. **实现一个模块**：将原 **历史订单** 前端基础能力改造成 **销售订单** 模块，管理 `sales_order_header` / `sales_order_item`。
3. **清理一个模块**：废弃“历史订单”语义，移除销售订单管理中的物理删除能力。

最终业务边界：

```text
询价订单：RFQ 主链路，使用 order_rfq / item_quote_version
销售订单：销售订单主链路，使用 sales_order_header / sales_order_item

两条主链路在议价提单前不互相污染。
议价提单、U9同步、提单表据、已提零件、锁库零件等共享下游通过 source_type 区分来源。
```

## 2. 目标

- 左侧菜单中原 **订单管理** 显示为 **询价订单**。
- 左侧菜单中原 **历史订单** 显示为 **销售订单**。
- 销售订单模块按客户查看销售订单。
- 销售订单模块只读取销售订单独立表，不读取 RFQ 主表作为主数据。
- 销售订单详情支持查看订单信息、零件明细、提单行、工艺表行。
- 销售订单详情支持补传图纸，并绑定到销售订单零件。
- 销售订单支持废弃与恢复：
  - 仅 `已报价` 可以废弃。
  - 仅 `废弃` 可以恢复为 `已报价`。
  - `部分已提单`、`已生成提单` 不允许废弃。
- 销售订单不允许删除订单或删除零件。
- 权限清单、管理员说明、日志说明同步更新。

## 3. 非目标

- 不把销售订单写入 `order_rfq`。
- 不把销售订单零件写入 `item_quote_version`。
- 不在销售订单模块实现报价处理。
- 不在销售订单模块实现议价提单生成；提单仍由议价提单模块处理。
- 不在销售订单模块实现 U9 同步；U9 同步仍由独立 U9同步模块处理。
- 不保留历史订单物理删除入口。
- 不做 RFQ 权限码大迁移，除非后续单独立项。

## 4. 模块职责

### 4.1 询价订单模块

原 **订单管理** 改名为 **询价订单**。

职责：

- 管理 RFQ / 询价订单。
- 查看 RFQ 订单列表。
- 查看 RFQ 零件明细。
- 查看 RFQ 来源提单行和工艺表行。
- 支持原 RFQ 状态管理能力：
  - 已报价退回已核价。
  - 已核价退回未核价。
  - 废弃。
  - 恢复。
- 支持 RFQ 零件补传图纸。

数据源：

| 数据 | 表 |
| --- | --- |
| 询价订单头 | `order_rfq` |
| 询价订单零件 | `item_quote_version` |
| 提单行 | `order_delivery_ticket`，RFQ 来源 |
| 工艺表行 | 既有 RFQ 工艺表查询链路 |

兼容策略：

- 路由 `/orders` 可保持不变。
- 组件 `OrderManage.vue` 可保持文件名不变。
- 权限码 `market:order:*` 暂时保留，文档中说明其当前业务含义为“询价订单”。

### 4.2 销售订单模块

原 **历史订单** 改造为 **销售订单**。

职责：

- 按客户选择并查看销售订单。
- 查看销售订单头表信息。
- 查看销售订单零件明细。
- 查看销售订单来源提单行。
- 查看销售订单来源工艺表行。
- 支持销售订单零件补传图纸。
- 支持销售订单废弃和恢复。
- 禁止删除订单和零件。

数据源：

| 数据 | 表 |
| --- | --- |
| 销售订单头 | `sales_order_header` |
| 销售订单零件 | `sales_order_item` |
| 提单行 | `order_delivery_ticket`，`source_type = 'SALES_ORDER'` |
| 工艺表行 | 销售订单来源提单行关联的工艺数据 |

状态规则：

| 当前状态 | 允许操作 | 目标状态 | 说明 |
| --- | --- | --- | --- |
| `已报价` | 废弃 | `废弃` | 订单尚未进入提单，可停止继续流转。 |
| `废弃` | 恢复 | `已报价` | 恢复后继续作为销售订单参与销售匹配、议价提单等流程。 |
| `部分已提单` | 不允许废弃 | - | 已进入下游，不允许废弃。 |
| `已生成提单` | 不允许废弃 | - | 已完成提单生成，不允许废弃。 |

### 4.3 历史订单模块

历史订单作为业务模块废弃。

处理方式：

- 前端不再显示 **历史订单** 菜单文案。
- 旧历史订单页面能力改造为销售订单页面。
- 删除按钮、删除确认弹窗、删除接口调用全部移除。
- `market:history-order:*` 标记为历史兼容权限，不再作为新销售订单模块权限。
- 如保留 `/history-orders`，只作为兼容入口跳转到 `/sales-orders`，不再承载独立历史订单页面。

## 5. 权限设计

### 5.1 询价订单权限

继续沿用现有权限码：

| 权限码 | 当前业务含义 |
| --- | --- |
| `market:order:view` | 查看询价订单 |
| `market:order:customer-select` | 询价订单选择客户 |
| `market:order:file-preview` | 询价订单预览文件 |
| `market:order:supplement-drawing` | 询价订单补传图纸 |
| `market:order:rollback-quoted` | 已报价退回已核价 |
| `market:order:rollback-priced` | 已核价退回未核价 |
| `market:order:discard` | 废弃询价订单 |
| `market:order:restore` | 恢复废弃询价订单 |

说明：

- 权限码保持不变是为了避免影响现有角色授权。
- 文档和页面文案需要明确这些权限当前属于 **询价订单**。

### 5.2 销售订单权限

新增销售订单模块权限：

| 权限码 | 类型 | 名称 |
| --- | --- | --- |
| `market:sales-order:view` | `MENU` | 查看销售订单 |
| `market:sales-order:customer-select` | `API` | 销售订单选择客户 |
| `market:sales-order:file-preview` | `API` | 销售订单预览文件 |
| `market:sales-order:supplement-drawing` | `BUTTON` / `API` | 销售订单补传图纸 |
| `market:sales-order:discard` | `BUTTON` / `API` | 废弃销售订单 |
| `market:sales-order:restore` | `BUTTON` / `API` | 恢复销售订单 |

权限要求：

- 左侧销售订单入口由 `market:sales-order:view` 控制。
- 客户选择接口由 `market:sales-order:customer-select` 控制。
- 文件预览接口由 `market:sales-order:file-preview` 控制。
- 补传图纸接口由 `market:sales-order:supplement-drawing` 控制。
- 废弃接口由 `market:sales-order:discard` 控制。
- 恢复接口由 `market:sales-order:restore` 控制。
- 后端权限校验是最终安全边界，前端隐藏按钮不能替代后端校验。

### 5.3 历史订单权限清理

旧权限：

| 权限码 | 处理方式 |
| --- | --- |
| `market:history-order:view` | 标记废弃，不再控制新销售订单页面。 |
| `market:history-order:customer-select` | 标记废弃，不再控制新销售订单客户选择。 |
| `market:history-order:file-preview` | 标记废弃，不再控制新销售订单文件预览。 |

如果为了角色平滑迁移需要兼容，可在迁移中将已拥有 `market:history-order:view` 的角色同步授予 `market:sales-order:view`，但新代码不再依赖 `market:history-order:*`。

## 7. 后端接口设计

### 7.1 新增控制器与服务

新增：

- `SalesOrderManageController`
- `SalesOrderManageService`

可按现有 `OrderManagementController` / `OrderManagementService` 的结构实现，但数据源必须切换为销售订单独立表。

### 7.2 接口清单

#### 7.2.1 客户列表

```http
GET /api/market/sales-order-management/customers
```

用途：

- 获取当前用户可访问的客户。
- 用于销售订单页面第一步选择客户。

权限：

- `market:sales-order:customer-select`

要求：

- 接入数据权限。
- 无客户数据范围时返回空列表，不泄露客户数据。

#### 7.2.2 销售订单列表

```http
GET /api/market/sales-order-management/orders
```

查询参数：

| 参数 | 说明 |
| --- | --- |
| `customerId` | 客户 ID，必选或按现有页面规则处理。 |
| `status` | 状态筛选，可选。 |
| `keyword` | 订单号、客户订单号、内部项目号等关键字。 |
| `page` | 页码。 |
| `size` | 每页条数。 |

返回字段建议：

| 字段 | 说明 |
| --- | --- |
| `id` | 销售订单头 ID。 |
| `salesOrderNo` | 销售订单号。 |
| `customerId` | 客户 ID。 |
| `customerCode` | 客户编码。 |
| `customerName` | 客户名称。 |
| `customerShortName` | 客户简称。 |
| `documentTypeCode` | 单据类型编码。 |
| `customerOrderNo` | 客户订单号。 |
| `customerProjectNo` | 客户项目号。 |
| `internalProjectNo` | 内部项目号。 |
| `status` | 销售订单状态。 |
| `itemCount` | 零件数。 |
| `releasedQuantity` | 已提数量。 |
| `totalQuantity` | 总数量。 |
| `drawingMissingCount` | 缺图零件数。 |
| `u9SyncStatus` | U9 同步状态。 |
| `updatedAt` | 更新时间。 |

权限：

- `market:sales-order:view`

要求：

- 数据源为 `sales_order_header`。
- 不查询 `order_rfq` 作为主数据。
- 接入数据权限。
- 后端分页，不全量返回大订单。

#### 7.2.3 销售订单详情

```http
GET /api/market/sales-order-management/orders/{salesOrderId}
```

用途：

- 获取销售订单头表详情。

权限：

- `market:sales-order:view`

要求：

- 数据源为 `sales_order_header`。
- 校验当前用户是否有该销售订单客户的数据权限。

#### 7.2.4 销售订单零件分页

```http
GET /api/market/sales-order-management/orders/{salesOrderId}/items
```

用途：

- 分页获取销售订单零件明细。

返回字段建议：

| 字段 | 说明 |
| --- | --- |
| `id` | 销售订单零件 ID。 |
| `lineNo` | 行号。 |
| `partNo` | 图号。 |
| `version` | 版本。 |
| `materialNo` | 物料号。 |
| `materialNoStatus` | 物料号状态。 |
| `quantity` | 数量。 |
| `unitPriceWithoutTax` | 未税单价。 |
| `unitPriceWithTax` | 含税单价。 |
| `totalAmountWithoutTax` | 未税总价。 |
| `totalAmountWithTax` | 含税总价。 |
| `deliveryDate` | 交期。 |
| `status` | 行状态。 |
| `drawingStatus` | 图纸状态。 |
| `assemblyRelationStatus` | 组合件父子关系状态。 |

权限：

- `market:sales-order:view`

要求：

- 数据源为 `sales_order_item`。
- 不查询 `item_quote_version` 作为主数据。
- 支持后端分页。

#### 7.2.5 销售订单提单行

```http
GET /api/market/sales-order-management/orders/{salesOrderId}/tickets
```

用途：

- 查看销售订单进入议价提单后生成的提单行。

查询规则：

```sql
source_type = 'SALES_ORDER'
AND source_order_id = :salesOrderId
```

权限：

- `market:sales-order:view`

要求：

- 不通过 RFQ 零件回查。
- 支持分页。

#### 7.2.6 销售订单工艺表行

```http
GET /api/market/sales-order-management/orders/{salesOrderId}/process-sheets
```

用途：

- 查看销售订单来源提单行关联的工艺表行。

查询规则：

- 先定位销售订单来源提单行：

```sql
order_delivery_ticket.source_type = 'SALES_ORDER'
AND order_delivery_ticket.source_order_id = :salesOrderId
```

- 再按现有工艺表关联规则查询工艺表行。

权限：

- `market:sales-order:view`

要求：

- 不强依赖 `item_quote_version`。
- 销售订单没有提单行时返回空分页，不报错。

#### 7.2.7 废弃销售订单

```http
POST /api/market/sales-order-management/orders/{salesOrderId}/discard
```

权限：

- `market:sales-order:discard`

规则：

- 仅允许 `sales_order_header.status = '已报价'`。
- 不允许 `部分已提单` 废弃。
- 不允许 `已生成提单` 废弃。
- 不允许已存在销售订单来源提单行的订单废弃。
- 更新头表状态为 `废弃`。
- 同步更新未提单销售订单行状态为 `废弃`。
- 不清空价格、数量、交期、客户、图纸、物料号、匹配快照、提单历史。

失败提示：

- `只有已报价且未生成提单的销售订单可以废弃。`

#### 7.2.8 恢复销售订单

```http
POST /api/market/sales-order-management/orders/{salesOrderId}/restore
```

权限：

- `market:sales-order:restore`

规则：

- 仅允许 `sales_order_header.status = '废弃'`。
- 恢复头表状态为 `已报价`。
- 同步恢复相关销售订单行状态为 `已报价` 或系统已有的可流转状态。
- 不清空任何业务字段。

失败提示：

- `只有废弃状态的销售订单可以恢复。`

#### 7.2.9 补传销售订单图纸

```http
POST /api/market/sales-order-management/items/{itemId}/drawings
```

权限：

- `market:sales-order:supplement-drawing`

要求：

- 复用现有图纸上传能力。
- 绑定对象为 `sales_order_item.id`。
- 不绑定到 `item_quote_version.id`。
- 支持文件预览权限 `market:sales-order:file-preview`。

## 8. 前端页面设计

### 8.1 询价订单页面

文件：

- `quote-frontend/src/components/OrderManage.vue`

修改：

- 页面标题改为 `询价订单`。
- 页面说明、按钮、弹窗中的泛化“订单管理”改为“询价订单”。
- RFQ 业务中的“订单”可以按上下文调整为“询价订单”或“询价单”。
- 保留原有 RFQ 状态按钮。
- 保留原有 RFQ 图纸补传能力。
- 保留原有 RFQ 详情结构。

不修改：

- 不切换数据源。
- 不改变 `/orders` 路由。
- 不改变 `market:order:*` 权限码。
- 不改变 RFQ 状态流转规则。

### 8.2 销售订单页面

文件：

- 推荐新增或重命名为 `quote-frontend/src/components/SalesOrderManage.vue`
- 原 `HistoryOrderManage.vue` 可删除、保留兼容导出，或改为薄包装组件。

页面标题：

```text
销售订单
```

基础流程：

```text
选择客户
  -> 按状态 / 关键字筛选销售订单
  -> 查看销售订单列表
  -> 打开详情
  -> 查看订单信息 / 零件明细 / 提单行 / 工艺表行
  -> 必要时补传图纸
  -> 对已报价订单执行废弃
  -> 对废弃订单执行恢复
```

状态筛选：

| 选项 | 说明 |
| --- | --- |
| 全部 | 展示可访问的全部销售订单。 |
| 已报价 | 可继续销售匹配、议价提单，也可废弃。 |
| 部分已提单 | 只能查看，不允许废弃。 |
| 已生成提单 | 只能查看，不允许废弃。 |
| 废弃 | 可恢复为已报价。 |

订单列表列建议：

| 列 | 说明 |
| --- | --- |
| 销售订单号 | `sales_order_header.sales_order_no` |
| 客户订单号 | `sales_order_header.customer_order_no` 或头表对应字段 |
| 客户项目号 | `sales_order_header.customer_project_no` |
| 内部项目号 | `sales_order_header.internal_project_no` |
| 单据类型编码 | `sales_order_header.document_type_code` |
| 状态 | `sales_order_header.status` |
| 零件数 | 后端汇总 |
| 已提数量 / 总数量 | 后端汇总 |
| 缺图数 | 后端汇总 |
| U9同步状态 | `sales_order_header.u9_sync_status` |
| 更新时间 | `sales_order_header.updated_at` |
| 操作 | 详情、废弃、恢复 |

按钮规则：

| 按钮 | 展示条件 |
| --- | --- |
| 详情 | 有 `market:sales-order:view`。 |
| 废弃 | 状态为 `已报价` 且有 `market:sales-order:discard`。 |
| 恢复 | 状态为 `废弃` 且有 `market:sales-order:restore`。 |
| 补传图纸 | 详情零件行内展示，有 `market:sales-order:supplement-drawing`。 |

禁止展示：

- 删除。
- 退回已核价。
- 退回未核价。
- RFQ 号作为销售订单主标识。

### 8.3 销售订单详情

详情结构参考询价订单详情：

```text
订单信息
零件明细
提单行
工艺表行
```

订单信息展示：

| 字段 | 来源 |
| --- | --- |
| 客户 | `sales_order_header.customer_id` 关联客户主数据 |
| 客户编码 | 客户主数据 `customer_code` |
| 客户简称 | 客户主数据 `customer_short_name` |
| 客户名称 | 客户主数据 `customer_name` |
| 单据类型编码 | `sales_order_header.document_type_code` |
| 销售订单号 | `sales_order_header.sales_order_no` |
| 客户订单号 | `sales_order_header.customer_order_no` |
| 客户项目号 | `sales_order_header.customer_project_no` |
| 内部项目号 | `sales_order_header.internal_project_no` |
| 状态 | `sales_order_header.status` |
| U9同步状态 | `sales_order_header.u9_sync_status` |

零件明细：

- 使用后端分页。
- 展示销售订单导入模板中的核心字段。
- 固定前置字段建议：
  - 图号
  - 行号
  - 版本
  - 物料号
  - 物料号状态
  - 数量
  - 状态
  - 图纸状态
  - 阻断原因或警告
- 后续字段按销售订单导入模板顺序展示，去掉前置字段中已经出现的重复列。

提单行：

- 只展示 `source_type = SALES_ORDER` 且 `source_order_id = 当前销售订单ID` 的提单行。
- 不展示其他 RFQ 来源提单行。

工艺表行：

- 通过销售订单来源提单行关联查询。
- 没有关联数据时显示空状态。

图纸补传：

- 复用询价订单现有补传图纸组件或能力。
- 上传完成后绑定到 `sales_order_item`。
- 文件预览走销售订单文件预览权限。

## 9. 数据权限

所有销售订单查询必须接入数据权限：

- 客户列表按当前用户数据范围过滤。
- 销售订单列表按客户数据范围过滤。
- 销售订单详情必须校验当前用户可访问该销售订单所属客户。
- 销售订单零件、提单行、工艺表行必须先校验销售订单头访问权限。
- 无数据范围时返回空列表，不泄露订单数量或客户名称。

## 10. 日志与审计

### 10.1 操作日志

销售订单关键写操作需要写操作日志：

| 操作 | 操作类型 |
| --- | --- |
| 废弃销售订单 | `SALES_ORDER_DISCARD` |
| 恢复销售订单 | `SALES_ORDER_RESTORE` |
| 补传销售订单图纸 | 可复用现有图纸上传日志类型或新增 `SALES_ORDER_DRAWING_SUPPLEMENT` |

日志内容：

- 销售订单 ID。
- 销售订单号。
- 客户 ID / 客户名称。
- 原状态。
- 新状态。
- 操作人。
- 操作时间。

### 10.2 文件日志

文件日志只记录低噪声摘要：

- 废弃成功 / 失败。
- 恢复成功 / 失败。
- 补传图纸成功 / 失败。

不记录：

- token。
- 密钥。
- 完整请求体。
- 完整文件内容。
- 高频列表查询。

## 11. 数据库与迁移

### 11.1 权限迁移

```sql
market:sales-order:view
market:sales-order:customer-select
market:sales-order:file-preview
market:sales-order:supplement-drawing
market:sales-order:discard

```

迁移要求：

- 授权树中销售订单挂在订单相关分组下。

### 11.2 业务表

本模块优先使用既有销售订单独立表：

- `sales_order_header`
- `sales_order_item`
- `order_delivery_ticket`

如缺少状态更新时间、废弃原因等字段，可另行评估是否补充；第一版不强制新增业务字段。

## 12. 实施阶段

### 阶段 1：询价订单改名

目标：原订单管理改名为询价订单，RFQ 功能不变。

修改：

- 更新 `App.vue` 菜单标题。
- 更新 `OrderManage.vue` 页面标题和业务文案。
- 更新路由标题或测试快照中的显示文案。
- 更新权限清单和日志说明中的模块名称。

验收：

- `/orders` 仍可访问。
- 原 RFQ 订单管理能力不回退。
- 销售订单不出现在询价订单页面。

### 阶段 2：销售订单权限、菜单和路由

目标：将历史订单入口改造成销售订单入口。

修改：

- 新增 `/sales-orders` 路由。
- 新增或重命名 `SalesOrderManage.vue`。
- `App.vue` 菜单显示 `销售订单`。
- 新增 `market:sales-order:*` 权限迁移。
- 更新 `PermissionService.defaultPermissions()`。
- 旧 `/history-orders` 做兼容重定向或移除入口。

验收：

- 有 `market:sales-order:view` 可见销售订单入口。
- 无权限入口隐藏，直接访问被拦截。
- 页面不再显示历史订单名称。
- 旧历史订单权限不控制销售订单新页面。

### 阶段 3：后端销售订单管理接口

目标：销售订单页面从独立销售订单表读取数据。

修改：

- 新增 `SalesOrderManageController`。
- 新增 `SalesOrderManageService`。
- 新增客户列表、订单列表、订单详情、零件分页、提单行分页、工艺表行分页接口。
- 接入数据权限。
- 接入后端权限注解。

验收：

- 销售订单列表不查询 `order_rfq`。
- 销售订单零件不查询 `item_quote_version`。
- 提单行按 `source_type = SALES_ORDER` 查询。
- 大订单明细后端分页。

### 阶段 4：销售订单废弃、恢复和图纸补传

目标：销售订单可治理，但不可删除。

修改：

- 新增废弃接口。
- 新增恢复接口。
- 新增或复用销售订单图纸补传接口。
- 写操作日志和低噪声文件日志。
- 前端接入废弃 / 恢复 / 补传图纸按钮。
- 移除删除按钮和删除调用。

验收：

- `已报价` 销售订单可废弃。
- `部分已提单` 销售订单不可废弃。
- `已生成提单` 销售订单不可废弃。
- `废弃` 销售订单可恢复为 `已报价`。
- 销售订单页面无删除按钮。
- 补传图纸绑定到 `sales_order_item`。

### 阶段 5：历史订单清理

目标：彻底清理历史订单旧语义。

修改：

- 删除或废弃历史订单页面文案。
- 删除前端历史订单删除逻辑。
- 删除销售订单页面对 `market:order:delete` 的依赖。
- 更新权限清单、管理员说明、日志说明。
- 如后端仍保留旧删除接口，标记 deprecated，并确保新页面不调用。

实施口径：

- 删除 `HistoryOrderManage.vue`，`/history-orders` 仅保留路由兼容重定向到 `/sales-orders`。
- 删除前端 `orderApi.deleteOrder` 与 `history-order` 客户范围映射，销售订单页面不再存在物理删除入口。
- 后端 `OrderManagementController` 旧历史客户接口和旧 DELETE 接口保留为 `@Deprecated` 兼容入口。
- 新增 V72 迁移，将 `market:history-order:*` 和 `market:order:delete` 标记为不可分配兼容权限。

验收：

- 销售订单模块不依赖 `market:history-order:*`。

## 13. 最终验收标准

- 原 **订单管理** 已改名为 **询价订单**。
- 原 **历史订单** 已改造成 **销售订单**。
- 销售订单模块使用 `sales_order_header` / `sales_order_item`。
- 销售订单模块不读取 `order_rfq` / `item_quote_version` 作为主数据。
- 销售订单可按客户查看。
- 销售订单可查看订单信息、零件明细、提单行、工艺表行。
- 销售订单可补传图纸。
- `已报价` 销售订单可废弃。
- `部分已提单` 和 `已生成提单` 销售订单不可废弃。
- `废弃` 销售订单可恢复为 `已报价`。
- 销售订单不能删除订单或零件。
- 历史订单页面已删除，旧 `/history-orders` 仅跳转到销售订单模块；旧 `market:history-order:*` 与 `market:order:delete` 不再作为新授权项。
- RFQ / 询价订单原流程不回退。
- 议价提单、U9同步、提单表据、已提零件、锁库零件继续通过来源字段处理 RFQ 和销售订单。
