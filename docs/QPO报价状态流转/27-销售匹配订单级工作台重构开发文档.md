# QPO 销售匹配订单级工作台重构开发文档

> 2026-08-06 阶段 7 收口：订单级工作台已降级为异常治理兜底页面，保留 `/sales-match` 路由和 `market:sales-match:*` 权限 code。新销售订单导入后不需要手动进入该页面，系统已在导入事务内自动补全生产快照并自动生成已提零件。

## 1. 背景

当前销售匹配模块已经完成“材料字段口径重构”：销售匹配只补真实材料和空缺生产快照，不覆盖销售订单导入事实。现有页面仍保留了早期工作台式交互：

- 页面顶部有客户、订单关键字、订单状态、匹配状态等筛选。
- 页面中部同时展示销售订单列表和销售订单零件列表。
- 用户可以勾选订单，也可以勾选零件。
- 预览和补全请求同时支持 `salesOrderIds` 和 `salesOrderItemIds`。

这种设计能力较强，但对当前业务来说显得复杂。销售匹配的真实业务定位已经变成：

> 对一张“已报价”的销售订单，按 `图号 + 版本` 命中历史已提单 RFQ 生产快照，并整单补全空缺生产快照。

因此，页面应对齐 `U9同步` 模块的交互方式：右上角选择销售订单，选中后显示订单信息和整单零件预览，再按订单级执行补全。这样市场模块的设计语言和操作方法会更统一。

## 2. 目标

1. 销售匹配页面改为订单级工作台，不再让用户在页面内维护订单列表、零件列表和零件级勾选。
2. 销售匹配只能选择 `已报价` 状态的销售订单。
3. 选中销售订单后自动预览整单匹配结果。
4. 执行补全时固定按整单执行，不提供零件级局部匹配入口。
5. 补全语义继续保持第 26 号文档口径：只补空缺生产快照，不覆盖销售订单导入材料、表面处理、图纸、价格、数量、交期、客户字段、物料号和已有生产快照。
6. 权限、数据权限和操作日志不回退。
7. RFQ 主链路和销售订单主链路继续隔离，销售订单数据不写入 `order_rfq` / `item_quote_version`。

## 3. 非目标

- 不新增数据库表。
- 不新增菜单权限点。
- 不改变历史匹配算法，仍按 `part_no + version` 命中历史已提单最新零件。
- 不改变第 26 号文档已确定的材料字段保护口径。
- 不恢复任何“覆盖字段”选项。
- 不支持销售匹配页面选择 `部分已提单` 或 `已生成提单` 销售订单。
- 不支持销售匹配页面手工选择部分零件执行补全。

## 4. 现状问题

### 4.1 页面操作路径复杂

当前 `SalesMatch.vue` 有两层可选对象：

1. 销售订单列表。
2. 销售订单零件列表。

用户需要理解“选订单”和“选零件”的差异，才能判断预览和补全作用范围。实际业务中，销售匹配应在销售订单导入后、议价提单前完成，天然是订单级动作，不应让用户选择部分零件局部补全。

### 4.2 和 U9 同步设计语言不一致

`U9同步` 页面已经采用统一模式：

```text
页面头部操作：选择销售订单 / 刷新 / 执行动作
左侧：已选订单、条件、订单信息、执行结果
右侧：订单零件明细
```

销售匹配也属于销售订单主链路中的订单级操作，应该采用同一套交互语言。

### 4.3 状态限制需要后端兜底

前端可以通过选择器只展示 `已报价` 销售订单，但仍必须在后端兜底：

- 列表接口只返回可销售匹配的 `已报价` 销售订单。
- 预览接口遇到非 `已报价` 销售订单时拒绝。
- 补全接口遇到非 `已报价` 销售订单时拒绝。

这样即使绕过前端直接调用接口，也不会对已提单或部分已提单订单执行销售匹配。

## 5. 业务口径

### 5.1 可选择订单

销售匹配只能选择：

| 条件 | 要求 |
| --- | --- |
| 来源 | 独立销售订单主表 `sales_order_header` |
| 订单状态 | `已报价` |
| 数据权限 | 当前用户可访问的销售订单客户 / 数据范围 |
| 废弃状态 | 不包含 `废弃` |
| RFQ 订单 | 不允许出现 |

### 5.2 不可选择订单

以下销售订单不能在销售匹配模块选择或执行：

| 状态 | 处理 |
| --- | --- |
| `部分已提单` | 不展示；直接调用预览 / 补全接口时拒绝 |
| `已生成提单` | 不展示；直接调用预览 / 补全接口时拒绝 |
| `废弃` | 不展示；直接调用预览 / 补全接口时拒绝 |
| 空状态 / 异常状态 | 不展示；直接调用预览 / 补全接口时拒绝 |

### 5.3 预览口径

选中一张销售订单后，系统自动预览整单零件：

- 查询该销售订单下全部有效 `sales_order_item`。
- 按 `part_no + version` 命中历史已提单最新 RFQ 零件快照。
- 展示每行是否命中、可补全空缺生产快照摘要、保护字段摘要、父子关系状态和警告。
- 预览不修改数据库。
- 预览结果不包含完整 JSON 大对象，例如完整 `material_data` / `process_route` / `fee_data` 原始内容。

### 5.4 补全口径

点击 `补全生产快照` 后，系统按订单级执行：

```json
{
  "salesOrderIds": [123],
  "salesOrderItemIds": [],
  "applyAllMatchedInSelectedOrders": false
}
```

执行规则：

- 对整单零件进行匹配补全。
- 未匹配零件不阻断整单执行。
- 已有生产快照字段不覆盖。
- 保护字段永不覆盖。
- 组合件父子关系仍按既有规则处理：
  - 历史组合件快照命中且子件完整时，重建 `sales_order_item_assembly_relation`。
  - 历史组合件快照命中但子件不完整时，不写不完整关系，只更新父件 `assembly_relation_status = 未指定父子关系`。
- 写 `SALES_ORDER_MATCH_APPLY` 操作日志和低噪声文件日志。

### 5.5 字段保护口径

继续遵循第 26 号文档：

| 字段 | 销售匹配处理 |
| --- | --- |
| `material_name` / 导入材料 | 不写入，不覆盖 |
| `surface_treatment` / 表面处理 | 不写入，不覆盖 |
| `drawing_url` / 图纸 | 不写入，不覆盖 |
| `description` / 描述 | 不写入，不覆盖 |
| 价格、数量、交期、客户字段 | 不写入，不覆盖 |
| `material_no` / 物料号 | 不写入，不覆盖 |
| 已有 `engineering_material_name` | 不覆盖 |
| 已有 `material_shape` | 不覆盖 |
| 已有 `material_data` | 不覆盖 |
| 已有 `process_route` | 不覆盖 |
| 已有 `fee_data` | 不覆盖 |

## 6. 设计方案

### 6.1 推荐方案

采用 **复用 U9 同步页面结构 + 后端订单状态兜底 + 保留兼容接口** 的方案。

原因：

- 与 `U9同步`、`提单表据` 等订单级页面交互一致。
- 不需要重做历史匹配算法。
- 不需要数据库迁移。
- 可以继续复用 `SalesOrderMatchService.preview(...)` 和 `SalesOrderMatchService.apply(...)` 的核心逻辑。
- 保留旧 `POST /api/market/sales-match/preview` 和 `POST /api/market/sales-match/apply` 可降低联调风险，但前端不再使用零件级 payload。

### 6.2 页面结构

重构后的 `SalesMatch.vue` 页面结构：

```text
Page Header
  - 标题：销售匹配
  - 描述：选择已报价销售订单，预览历史生产快照并补全空缺生产信息
  - 按钮：选择销售订单 / 刷新 / 补全生产快照

Order-Level Workspace
  Left Panel
    - 已选销售订单小表
    - 匹配条件
    - 订单信息
    - 补全结果

  Right Panel
    - 销售订单零件预览表
    - 命中状态、真实材料、材料形态、空缺生产快照、保护字段摘要、父子关系、警告

OrderPickerDialog
  - 客户选择
  - 状态选择：仅 已报价
  - 销售订单选择
```

### 6.3 前端状态模型

`SalesMatch.vue` 保留以下核心状态：

```js
const previewLoading = ref(false)
```

移除或不再使用：

```js

selectedItemIds
filters
itemFilters
matchOptions.onlyUnmatched
orderPagination
```

说明：

- 销售匹配页面不再自己实现客户筛选、订单筛选和分页列表。
- 客户选择、状态选择和订单分页交给 `OrderPickerDialog`。
- 零件明细来自订单级预览结果，不再单独调用零件分页接口。

### 6.4 后端接口设计

保留现有兼容接口：

| 接口 | 状态 |
| --- | --- |
| `POST /api/market/sales-match/preview` | 兼容保留 |
| `POST /api/market/sales-match/apply` | 兼容保留 |
| `GET /api/market/sales-match/orders/{salesOrderId}/items` | 兼容保留，前端新页面不使用 |

新增订单级语义接口：

| 接口 | 权限 | 说明 |
| --- | --- | --- |
| `GET /api/market/sales-match/orders/{salesOrderId}/preview` | `market:sales-match:view` | 预览单张销售订单整单匹配结果 |
| `POST /api/market/sales-match/orders/{salesOrderId}/apply` | `market:sales-match:apply` | 对单张销售订单执行整单补全 |

新增接口内部可以直接包装现有 DTO：

```java
SalesOrderMatchPreviewReq req = new SalesOrderMatchPreviewReq();
req.setSalesOrderIds(List.of(salesOrderId));
req.setSalesOrderItemIds(List.of());
req.setOnlyUnmatched(false);
return salesOrderMatchService.preview(req);
```

```java
SalesOrderMatchApplyReq req = new SalesOrderMatchApplyReq();
req.setSalesOrderIds(List.of(salesOrderId));
req.setSalesOrderItemIds(List.of());
req.setApplyAllMatchedInSelectedOrders(false);
return salesOrderMatchService.apply(req);
```

### 6.5 订单状态兜底

`SalesOrderMatchService` 增加订单可匹配校验：

```text
requireMatchableSalesOrder(salesOrderId)
  - salesOrderId 非空
  - sales_order_header 存在
  - 数据权限可访问
  - status = 已报价
```

使用位置：

- `listOrders(...)`：销售匹配订单选择列表只返回 `已报价`。
- `preview(...)`：按订单 ID 加载预览前校验所有订单均为 `已报价`。
- `apply(...)`：事务内锁定订单后再次校验状态为 `已报价`。
- 新增订单级 `preview/apply` 接口：入口处也应调用该校验或通过 service 统一校验。

错误提示：

```text
异常治理只能处理已报价销售订单，请确认订单状态后重试。
```

### 6.7 前端按钮权限

继续使用现有权限：

| 操作 | 权限 |
| --- | --- |
| 访问页面 | `market:sales-match:view` |
| 选择客户 | `market:sales-match:customer-select` |
| 选择销售订单 | `market:sales-match:order-select` |
| 补全生产快照 | `market:sales-match:apply` |

不新增 `common:*` 权限。

### 6.8 补全按钮禁用规则

`补全生产快照` 按钮：

- 无 `market:sales-match:apply` 权限时隐藏。
- 未选择订单时禁用。
- 预览加载中时禁用。
- 当前订单不是 `已报价` 时禁用。
- 当前预览未加载时禁用，并提示先选择销售订单。
- 正在提交时禁用。

建议禁用原因：

```text
请先选择已报价销售订单
正在加载异常治理预览
异常治理只能处理已报价销售订单
异常治理补全正在提交，请稍候
```

### 6.9 预览表列建议

右侧预览表建议列：

| 列 | 来源 |
| --- | --- |
| 图号 | `partNo` |
| 行号 | `lineNo`，如预览 DTO 当前缺失则补充 |
| 版本 | `version` |
| 数量 | `qty` |
| 当前状态 | `currentMatchStatus` |
| 命中 | `matched` |
| 历史来源 | `sourceRfqId / sourceItemId` |
| 导入材料 | `materialName`，展示销售订单导入事实或保护字段摘要 |
| 真实材料 | `engineeringMaterialName` |
| 材料形态 | `changedFields.materialShape.source` 或新增 `materialShape` |
| 空缺生产快照 | `changedFields` 格式化 |
| 保护字段摘要 | `protectedFields` 格式化 |
| 父子关系 | `assemblyRelationStatus` |
| 警告 | `warningMessage` |

如果当前 `SalesOrderMatchPreviewRow` 缺少 `lineNo`、`materialShape`，建议补齐轻量字段，避免前端从 `changedFields` 结构里猜。

## 9. 分阶段实施

### 阶段 1：后端订单级接口和状态兜底

  - `applyOrder(...)`
