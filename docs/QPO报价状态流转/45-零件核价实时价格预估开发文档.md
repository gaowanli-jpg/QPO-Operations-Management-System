# 零件核价实时价格预估开发文档

> 更新日期：2026-08-27
> 当前口径：实时预估、后端保存和导出快照统一使用“分类百分比费用 + 乘法加权”公式。前端预估只是页面即时展示，最终入库价格仍以后端保存核价结果为准。

## 1. 背景

零件核价模块的普通件核价弹窗已经能根据材料、毛坯形状、尺寸、密度和材料单价实时展示材料相关指标。随着百分比费用改造为统一费用表，实时价格预估也需要从旧的“所有百分比费用加总、再按名称扣税”切换为“同分类费用先加总形成分类因子，客户权重、基础百分比费用、税率三个分类因子依次相乘”。

本次收口覆盖普通件和组合件的页面预估：

- 普通件：基础成本为材料费用 + 工艺费用。
- 组合件：子件价格继续读取已保存快照，统一百分比费用只作用于组装费。
- 税率身份来自 `feeCategory = TAX`，不再通过费用名称包含 `税 / tax / vat` 判断税率。

## 2. 展示目标

在核价弹窗中继续展示以下四个实时价格结果，视觉上沿用材料摘要区的紧凑表格风格：

| 展示项 | 口径 |
| --- | --- |
| 未税单价 | 当前零件单件未税价格 |
| 含税单价 | 当前零件单件含税价格 |
| 未税金额 | 未税单价 × 当前零件数量 |
| 含税金额 | 含税单价 × 当前零件数量 |

实时计算需要响应以下输入变化：

- 材料选择变化。
- 毛坯形状、尺寸、密度、重量、材料单价变化。
- 工艺路线增删、工时输入变化。
- 非工时固定费用输入变化。
- 统一百分比费用配置缓存变化。
- 当前零件数量变化。
- 组合件组装费变化。

## 3. 公式口径

### 3.1 分类因子

统一百分比费用来自 `dict_pricing_markup_fee`，前后端都按 `pricingScope` 与 `feeCategory` 读取已启用费用。每个分类内部按 `sortNo ASC, id ASC` 保留费用展示和快照顺序，计算时先汇总该分类全部启用 `ratePercent`，再形成一个分类因子；某分类无启用项时，该分类因子为 `1.0`。

```text
客户权重因子 = 1 + Σ(CUSTOMER_WEIGHT.ratePercent) / 100
基础百分比费用因子 = 1 + Σ(BASIC_PERCENT.ratePercent) / 100
税率因子 = 1 + Σ(TAX.ratePercent) / 100
```

### 3.2 普通件

普通件基础成本沿用后端权威口径：

```text
材料费用 = 毛坯重量 * 材料单价
工艺费用 = Σ(工时 * 具体工艺有效小时价格) + Σ(非工时固定费用)
基础成本 = 材料费用 + 工艺费用

未税单价 = 基础成本 * 客户权重因子 * 基础百分比费用因子
含税单价 = 基础成本 * 客户权重因子 * 基础百分比费用因子 * 税率因子
未税金额 = 未税单价 * 数量
含税金额 = 含税单价 * 数量
```

### 3.3 组合件

组合件继续保持“子件价格由子件已保存结果带入”的原则，不在父件核价时按当前字典重算子件材料、工艺或百分比费用。统一百分比费用只对组装费生效，并且使用 `pricingScope = ASSEMBLY` 的费用配置。

```text
子件汇总 = Σ(子件含税单价 * 每父件用量)
组装费 = 用户录入的组装费

组装费未税价 = 组装费 * 客户权重因子 * 基础百分比费用因子
组装费含税价 = 组装费 * 客户权重因子 * 基础百分比费用因子 * 税率因子

父件未税单价 = 子件汇总 + 组装费未税价
父件含税单价 = 子件汇总 + 组装费含税价
```

## 4. 前端缓存设计

前端继续使用 Pinia 字典缓存，核价页只加载当前会话所需字典，不增加后端缓存、Redis 或自动轮询。

主要缓存字段：

- `dictionaryStore.materials`
- `dictionaryStore.processDetails`
- `dictionaryStore.extraFeeItems`
- `dictionaryStore.pricingMarkupFees`

进入零件核价页面时调用费用字典加载逻辑，确保 `pricingMarkupFees` 中包含 NORMAL / ASSEMBLY 与三类费用：

```js
await dictionaryStore.loadPricingFeeDicts()
```

打开同一订单内下一个零件核价弹窗时，优先复用当前 Pinia 内存缓存。若另一个用户在此期间修改材料、工艺或百分比费用，当前页面实时预估仍使用已加载缓存；保存核价时，后端会按数据库最新主数据重新计算并落库。

## 5. 前端计算设计

### 5.1 费用分组

前端不再通过费用名称识别税率，只使用 `feeCategory`：

```js
const CUSTOMER_WEIGHT = 'CUSTOMER_WEIGHT'
const BASIC_PERCENT = 'BASIC_PERCENT'
const TAX = 'TAX'

const UNTAXED_PRICING_FEE_SEQUENCE = [CUSTOMER_WEIGHT, BASIC_PERCENT]
const TAX_INCLUDED_PRICING_FEE_SEQUENCE = [CUSTOMER_WEIGHT, BASIC_PERCENT, TAX]

const markupFeeOptions = computed(() => dictionaryStore.getPricingMarkupFees('NORMAL'))
const assemblyMarkupFeeOptions = computed(() => dictionaryStore.getPricingMarkupFees('ASSEMBLY'))
```

### 5.2 普通件预估

普通件预估以当前页面材料和工艺输入得到 `normalBaseCostPreview`，再依次应用 NORMAL 范围下的客户权重、基础百分比费用和税率。

```js
const normalUntaxedUnitPricePreview = computed(() =>
  applyPricingFeeCategories(normalBaseCostPreview.value, markupFeeOptions.value, UNTAXED_PRICING_FEE_SEQUENCE)
)

const normalTaxIncludedUnitPricePreview = computed(() =>
  applyPricingFeeCategories(normalBaseCostPreview.value, markupFeeOptions.value, TAX_INCLUDED_PRICING_FEE_SEQUENCE)
)
```

说明：

- 工时工艺按 `inputVal * hourlyRate` 预估。
- 非工时费用按 `inputVal` 直接进入工艺费。
- 百分比费用基数为 `材料费 + 工艺费`。
- `0%` 是有效费率，停用费用不参与计算。

### 5.3 组合件预估

组合件预估只把 ASSEMBLY 范围的费用作用于组装费：

```js
const assemblyFeeUntaxedPreview = computed(() =>
  applyPricingFeeCategories(assemblyFee.value, assemblyMarkupFeeOptions.value, UNTAXED_PRICING_FEE_SEQUENCE)
)

const assemblyFeeTaxIncludedPreview = computed(() =>
  applyPricingFeeCategories(assemblyFee.value, assemblyMarkupFeeOptions.value, TAX_INCLUDED_PRICING_FEE_SEQUENCE)
)
```

## 6. 后端一致性

后端保存仍是最终权威。`EngineerService` 保存普通件和组合件时调用统一计算服务读取 `dict_pricing_markup_fee`，并把费用行、分类、适用范围和分类内加总过程写入 `feeData` 快照。

新快照行建议保留以下字段：

```json
{
  "feeName": "利润",
  "pricingScope": "NORMAL",
  "feeCategory": "BASIC_PERCENT",
  "ratePercent": 15.0,
  "factor": 1.15,
  "baseAmount": 110.0,
  "cost": 16.5,
  "amountAfter": 137.5,
  "includedInUntaxedPrice": true,
  "includedInTaxIncludedPrice": true
}
```

导出历史报价时继续读取已保存价格字段和 `feeData` 快照，不实时查询当前费用字典，不重算历史价格。

## 7. 非目标

- 不新增数据库字段；统一费用表由 `49-百分比费用分类与乘法加权价格公式开发文档.md` 管理。
- 不让前端实时预估值直接作为最终入库价格。
- 不改变 U9、销售订单导入、提单、已提零件链路的价格字段口径。
- 不新增权限点和操作日志；实时预估是只读展示，不写高频日志。
- 不批量回填历史 `feeData`，避免改变历史报价追溯结果。

## 8. 测试要求

前端测试应覆盖：

1. 普通件核价弹窗包含 `未税单价 / 含税单价 / 未税金额 / 含税金额` 文案。
2. 普通件预估使用 `CUSTOMER_WEIGHT * BASIC_PERCENT * TAX` 乘法公式。
3. 组合件组装费预估使用 `pricingScope = ASSEMBLY` 的分类费用，并且只作用于组装费。
4. 前端代码不再通过费用名称包含 `税 / tax / vat` 来判断税率。
5. 保存核价后页面以后端返回价格为准。

后端测试应覆盖：

1. 普通件保存按 NORMAL 分类费用计算未税价和含税价。
2. 组合件保存按 ASSEMBLY 分类费用只计算组装费部分。
3. 税率和客户权重系统项不可删除，只能启停或修改百分率。
4. 历史导出继续读取保存快照，不因当前费用字典变更而重算。

## 9. 验收标准

- 普通件实时预估与后端保存使用同一组乘法公式。
- 组合件组装费实时预估与后端保存使用同一组乘法公式。
- 税率和客户权重身份由 `feeCategory` 决定，不依赖费用名称。
- 历史报价导出读取快照值，不实时重算。
- 权限继续复用 `engineer:dict:view`、`engineer:dict:fee-manage` 和 `engineer:pricing:save-item`。
- 统一百分比费用 CRUD 使用 `DICT_PRICING_MARKUP_FEE_*` 审计动作，读取和实时预估不记高频日志。
