# 零件核价实时价格预估开发文档

## 1. 背景

零件核价模块的普通件核价弹窗目前已经可以根据材料、毛坯形状、尺寸、密度和材料单价实时展示：

- 毛坯体积
- 毛坯重量
- 材料单价
- 预测本件材料费

实际核价时，工程师还需要在输入材料参数、工艺工时、非工时固定费用时，立即看到当前零件的最终价格影响。现有页面需要保存后才在列表或后续流程中看到 `未税单价 / 含税单价 / 未税金额 / 含税金额`，不利于边调参数边判断报价结果。

本次优化只针对 **普通件 NORMAL 核价弹窗展示**，不调整组合件 ASSEMBLY 核价展示，不改变后端最终保存价格的权威计算规则。

## 2. 目标

在普通件核价弹窗的材料价格四格下方，新增四个实时计算格。视觉上保持当前材料摘要区的紧凑表格风格；如果沿用现有 `th + td + th + td` 结构，可展示为两行两列指标。

| 展示项 | 口径 |
| --- | --- |
| 未税单价 | 当前普通件单个零件的未税价格 |
| 含税单价 | 当前普通件单个零件的含税价格 |
| 未税金额 | 未税单价 × 当前零件数量 |
| 含税金额 | 含税单价 × 当前零件数量 |

统一百分比费用分类收口后，普通件实时预估公式为：

```text
未税单价 = 基础成本 * 客户权重因子 * 基础百分比费用因子
含税单价 = 基础成本 * 客户权重因子 * 基础百分比费用因子 * 税率因子
```

税率身份来自 `feeCategory = TAX`，不再通过费用名称包含 `税 / tax / vat` 判断税率。

实时计算需要响应以下输入变化：

- 材料选择变化。
- 毛坯形状、尺寸、密度、重量、材料单价变化。
- 工艺路线增删、工时输入变化。
- 非工时固定费用输入变化。
- 百分比费用配置缓存变化。
- 当前零件数量变化。

## 3. 非目标

- 不新增数据库字段。
- 不新增后端缓存、Redis 或定时刷新机制。
- 不改变 `submitQuote` 保存接口入参。
- 不让前端计算结果直接作为最终入库价格。
- 不调整组合件核价页展示。
- 不改变 U9、销售订单导入、提单、已提零件链路的价格字段口径。
- 不新增权限点和操作日志；本次仅增加读态实时展示，不新增关键业务写操作。

## 4. 当前实现依据

### 4.1 前端现状

普通件核价弹窗位于：

- `quote-frontend/src/components/ItemPricing.vue`

当前前端已经存在以下实时材料计算：

- `currentMatInfo`
- `currentUnitPrice`
- `currentDensity`
- `calculatedVolume`
- `calculatedWeight`
- `calculatedMaterialCost`

基础字典缓存来自：

- `quote-frontend/src/stores/dictionaryStore.js`

`ItemPricing.vue` 进入页面时调用：

```js
await dictionaryStore.loadBaseDicts({ includeMarkupFees: true })
```

`dictionaryStore.loadBaseDicts(...)` 已有 `loadedAt` 和 `includeMarkupFees` 判定：同一页面会话内，如果缓存已满足当前需求，不会重复向后端加载材料、工艺、费用字典。

### 4.2 后端权威保存口径

后端权威计算位于：

- `quote-backend/src/main/java/com/machining/quote/service/EngineerService.java`

普通件保存核心方法：

- `saveCalculatedQuote(...)`

现有保存公式：

```text
材料费 = 毛坯重量 × 材料单价
工艺费 = Σ(工时 × 工艺小时费率) + Σ(非工时固定费用)
基础成本 = 材料费 + 工艺费
百分比费用 = 基础成本 × 费用比例
含税单价 = 基础成本 + 百分比费用
未税单价 = 含税单价 - 税费类费用
含税金额 = 含税单价 × qty
未税金额 = 未税单价 × qty
```

后端保存时会按材料编码、工艺 ID、费用主数据重新读取数据库并计算，所以前端实时金额只是“当前页面缓存下的预估展示”，最终入库仍以后端计算为准。

## 5. 缓存设计

### 5.1 缓存位置

沿用现有前端 Pinia 缓存：

- `dictionaryStore.materials`
- `dictionaryStore.processDetails`
- `dictionaryStore.extraFeeItems`
- `dictionaryStore.markupFees`

不新增后端缓存。

### 5.2 加载时机

进入零件核价页面时，`ItemPricing.vue` 调用：

```js
dictionaryStore.loadBaseDicts({ includeMarkupFees: true })
```

打开同一订单内下一个零件核价弹窗时，不重新加载字典，只复用当前 Pinia 内存缓存。

### 5.3 数据新鲜度边界

如果用户打开核价页面期间，另一个用户修改了材料价格、工艺费率或百分比费用：

- 当前页面实时预估仍使用已加载缓存。
- 保存核价时后端用数据库最新主数据重新计算并落库。
- 本次不增加前端“刷新价格缓存”按钮，也不增加自动轮询。

## 6. 前端实时计算设计

### 6.1 新增 computed

在 `ItemPricing.vue` 普通件计算区新增以下 computed，命名建议：

```js
const markupFeeOptions = computed(() => dictionaryStore.markupFees)

const currentItemQty = computed(() => numberOrZero(currentRow.value?.qty))

const normalProcessCostPreview = computed(() => {
  return processRoute.value.reduce((sum, proc) => {
    const inputVal = numberOrZero(proc.inputVal)
    if (inputVal <= 0) return sum
    if (isSelectableProcessRoute(proc)) {
      const option = findProcessOption(proc)
      const hourlyRate = numberOrZero(option?.hourlyRate ?? proc.hourlyRate ?? proc.unitRate)
      return sum + inputVal * hourlyRate
    }
    return sum + inputVal
  }, 0)
})

const normalBaseCostPreview = computed(() => calculatedMaterialCost.value + normalProcessCostPreview.value)

const normalMarkupFeeRowsPreview = computed(() => markupFeeOptions.value
  .filter(fee => fee.enabled !== false)
  .map(fee => {
    const ratePercent = numberOrZero(fee.ratePercent)
    const cost = normalBaseCostPreview.value * ratePercent / 100
    return {
      feeName: fee.feeName,
      ratePercent,
      cost
    }
  }))

const normalMarkupCostPreview = computed(() => normalMarkupFeeRowsPreview.value
  .reduce((sum, row) => sum + numberOrZero(row.cost), 0))

const isTaxFeeName = (feeName) => {
  const text = String(feeName || '').toLowerCase()
  return text.includes('税') || text.includes('tax') || text.includes('vat')
}

const normalTaxFeeCostPreview = computed(() => normalMarkupFeeRowsPreview.value
  .filter(row => isTaxFeeName(row.feeName))
  .reduce((sum, row) => sum + numberOrZero(row.cost), 0))

const normalTaxIncludedUnitPricePreview = computed(() => normalBaseCostPreview.value + normalMarkupCostPreview.value)

const normalUntaxedUnitPricePreview = computed(() => Math.max(
  0,
  normalTaxIncludedUnitPricePreview.value - normalTaxFeeCostPreview.value
))

const normalTaxIncludedTotalPricePreview = computed(() => normalTaxIncludedUnitPricePreview.value * currentItemQty.value)

const normalUntaxedTotalPricePreview = computed(() => normalUntaxedUnitPricePreview.value * currentItemQty.value)
```

说明：

- 工时工艺按 `inputVal × hourlyRate` 预估。
- 非工时费用按 `inputVal` 直接进入工艺费。
- 百分比费用基数为 `材料费 + 工艺费`，与后端普通件保存一致。
- 税费识别规则与后端 `isTaxFeeRow(...)` 对齐：费用名称包含 `税`、`tax`、`vat` 即作为税费，从含税单价中扣除得到未税单价。

### 6.2 模板展示

在现有 `.material-summary-table` 的材料费行下方追加价格预估展示，保持原表格 `th + td + th + td` 语义结构：

```vue
<tr v-if="quoteMode === 'NORMAL'">
  <th scope="row" title="未税单价">未税单价</th>
  <td :title="`¥ ${normalUntaxedUnitPricePreview.toFixed(2)}`">¥ {{ normalUntaxedUnitPricePreview.toFixed(2) }}</td>
  <th scope="row" title="含税单价">含税单价</th>
  <td :title="`¥ ${normalTaxIncludedUnitPricePreview.toFixed(2)}`">¥ {{ normalTaxIncludedUnitPricePreview.toFixed(2) }}</td>
</tr>
<tr v-if="quoteMode === 'NORMAL'">
  <th scope="row" title="未税金额">未税金额</th>
  <td :title="`¥ ${normalUntaxedTotalPricePreview.toFixed(2)}`">¥ {{ normalUntaxedTotalPricePreview.toFixed(2) }}</td>
  <th scope="row" title="含税金额">含税金额</th>
  <td :title="`¥ ${normalTaxIncludedTotalPricePreview.toFixed(2)}`">¥ {{ normalTaxIncludedTotalPricePreview.toFixed(2) }}</td>
</tr>
```

这两行对应四个业务指标：未税单价、含税单价、未税金额、含税金额。不要改成组合件共用展示。

## 7. 后端一致性设计

本次不要求后端新增接口，但建议补一个纯 Java 单元测试，锁定前后端需要对齐的普通件公式口径。

若后续希望彻底避免前后端公式漂移，可以再将普通件价格公式抽成独立后端服务，例如：

- `QuotePriceCalculationService`

但本次不建议重构，因为当前需求只需要前端实时展示，后端已有保存重算兜底。

## 9. 测试要求

### 9.1 前端测试

新增或补充测试应覆盖：

1. 普通件核价弹窗包含 `未税单价 / 含税单价 / 未税金额 / 含税金额` 文案。
2. 新增金额展示只出现在普通件 `NORMAL` 逻辑中，不影响组合件展示。
3. `dictionaryStore.loadBaseDicts({ includeMarkupFees: true })` 仍是页面进入时加载，不在保存单个零件后强制刷新字典。
4. 前端公式包含：
   - `calculatedMaterialCost`
   - `processRoute` 工艺费汇总
   - `markupFeeOptions` 百分比费用
   - `currentRow.qty` 数量乘数
   - `税 / tax / vat` 税费扣除规则

### 9.2 后端测试

如补充后端测试，建议覆盖：

1. 普通件保存时仍由后端根据数据库材料、工艺、费用配置计算价格。
2. `untaxedUnitPrice = taxIncludedUnitPrice - 税费类费用`。
3. `untaxedTotalPrice / taxIncludedTotalPrice` 按 `qty` 计算。

## 10. 验收标准

- 普通件核价弹窗材料摘要区展示新增四项价格结果。
- 修改材料尺寸、形状、材料、工艺工时、非工时固定费用后，四项价格立即变化。
- 未税/含税单价按单件展示。
- 未税/含税金额按当前零件数量展示。
- 核价下一个零件时不重新请求材料/工艺/费用字典。
- 保存核价后最终列表价格以后端保存结果为准。
- 组合件核价区不出现本次新增四格，不改变组合件现有展示。
- 不新增权限，不新增操作日志，不增加高频接口请求。

## 11. 实施建议

建议按以下顺序开发：

1. 先写前端测试，冻结新增展示文案和普通件限定范围。
2. 在 `ItemPricing.vue` 新增 computed 公式。
3. 修改材料摘要表格模板，沿用现有 `.material-summary-table` 样式。
4. 运行前端测试。
5. 如需增强后端公式保护，再补后端单元测试；没有公式变更则不改后端生产代码。
6. 手工验证：打开普通件核价弹窗，分别调整材料尺寸、工时、固定费用，观察四项金额实时变化。
