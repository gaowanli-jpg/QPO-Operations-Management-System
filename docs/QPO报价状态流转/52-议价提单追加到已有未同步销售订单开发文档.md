# 议价提单追加到已有未同步销售订单开发文档

## 1. 背景与目标

议价提单原有出口是把选中的 RFQ 零件生成一张新的销售订单，并生成对应 `order_delivery_ticket`。新增需求是在同一客户下，允许把本次选中的议价提单零件追加到一张尚未同步 U9 的既有销售订单中，形成新的销售订单行和提单行。

第一版目标只解决可控场景：目标销售订单必须仍处于 QPO 本地可修改、未同步 U9 的阶段；追加动作只写 QPO 本地数据，不调用 U9 / MES / WMS。追加完成后，后续已提零件、获取 MES 物料号、WMS 锁库、待产下发 MES、锁库零件展示和 U9 同步都继续沿用既有销售订单与提单行链路。

## 2. 业务口径

- 追加入口放在 **市场 > 议价提单** 页面，与“生成正式提单”并列，按钮文案为“追加销售提单”。
- 追加目标只能选择同一客户的销售订单，订单状态为 `已生成提单`，且 `u9_sync_status` 为空、`未同步` 或 `同步失败`。
- 目标订单为 `已同步`、`同步中`、`结果待确认` 时禁止追加。
- 追加销售提单不读取页面左侧“订单默认信息”。左侧 `单据类型`、`下单日期`、`客户订单号`、`订单类型`、`内部项目号` 等必填项只用于“生成正式提单”；追加时不参与按钮启用、弹窗打开、请求参数或后端生成逻辑，即使用户填写了这些字段也视为未使用。
- 追加时订单头字段以目标销售订单当前字段为准；新销售订单行沿用已选 RFQ 零件的已报价快照、图号版本、材料、工艺、交期、数量等行级数据。
- 追加后如果目标订单原本是 `同步失败`，重置为 `未同步` 并清空旧 U9 同步失败摘要，便于重新预览和同步。

## 3. 数据落库

追加成功后需要新增或更新以下数据：

- `order_delivery_ticket`：为本次追加的每个 RFQ 零件生成新的不可逆提单行，`source_type = RFQ`。
- `sales_order_item`：在目标 `sales_order_header` 下追加新的销售订单行，`source_ticket_id` 指向新提单行。
- `sales_order_source_rfq`：如果目标销售订单尚未记录本次 RFQ 来源，则补充来源关系。
- `sales_order_item_assembly_relation`：当本次选中组合件父子行时，复制对应父子关系到销售订单行关系表。
- `sales_order_header.total_item_count / updated_at / u9_sync_status`：刷新目标销售订单头汇总和 U9 状态。
- `sales_order_append_batch`：记录追加批次幂等键、请求 hash、来源 RFQ ID、提单 ID 和销售订单行 ID。

## 4. 接口契约

### 4.1 追加目标销售订单列表

```http
GET /api/market/release/append-target-sales-orders
```

权限：`market:release:order-select`。

查询参数沿用订单选择器：

| 参数 | 说明 |
| --- | --- |
| `customerCode` | 客户编码，追加入口前端锁定为当前已选 RFQ 客户。 |
| `customerName` | 客户名称兜底。 |
| `keyword` | 销售订单号、单据号、客户订单号、内部项目号、客户项目号关键词。 |
| `status` | 固定只允许 `已生成提单`。 |
| `page/pageSize` | 分页参数。 |

返回复用 U9 同步订单行 DTO，供选择器展示销售订单号、客户、来源、状态、U9 状态和创建时间。

### 4.2 追加提交

```http
POST /api/market/release/append-to-sales-order
```

权限：`market:release:create`。

请求体：

```json
{
  "targetSalesOrderId": 1001,
  "appendBatchKey": "uuid-or-client-generated-key",
  "rfqIds": [18, 19],
  "items": [
    {
      "sourceType": "RFQ",
      "sourceOrderId": 18,
      "sourceItemId": 501,
      "itemId": 501,
      "acceptedQty": 3
    }
  ]
}
```

请求体不得包含 `documentTypeCode`、`salesOrderDate`、`customerOrderNo`、`customerProjectNo`、`customerOrderTitle`、`orderType`、`internalProjectNo`、`arrangeType` 等左侧订单默认信息字段。

响应复用 `DeliveryBatchResultDTO`，追加成功时 `salesOrderId` 指向目标销售订单，`ticketIds` 为本次新生成的提单行。

## 5. 校验规则

- 必须至少选择一个 RFQ 订单和一个已报价可提单零件。
- 只支持 `sourceType = RFQ` 的议价提单零件。
- 所有 RFQ 必须属于同一客户，且目标销售订单客户必须一致。
- 目标销售订单必须存在、当前用户有销售订单数据权限、状态为 `已生成提单`。
- 目标销售订单 U9 状态仅允许空、`未同步`、`同步失败`。
- 同一 `appendBatchKey` 首次成功后可幂等重放；同 key 但请求 hash 不一致必须拒绝。
- 不允许绕过 RFQ 数据权限、销售订单数据权限或既有可提单规则。

## 6. 前端交互

- 页面左侧“订单默认信息”提示改为：`仅用于生成正式提单：一批生成一张销售订单，零件值优先，空值继承订单默认信息；追加销售提单以目标销售订单头为准，左侧必填项不参与。`
- “生成正式提单”继续要求左侧必填项完整。
- “追加销售提单”不以左侧必填项为空作为禁用条件；左侧默认信息已填写时也不带入追加请求。
- “追加销售提单”只受已选零件、行级订单字段草稿、来源类型、提交中和表格替换中等追加链路自身条件限制。
- 点击“追加销售提单”后，打开销售订单选择器；选择器锁定当前 RFQ 客户，订单状态默认 `已生成提单`。
- 确认追加后，结果卡片标题展示“已追加到销售订单”，并可继续跳转销售订单、U9 同步或已提零件页面。

## 7. 下游链路影响

- 已提零件：通过新生成的 `order_delivery_ticket` 展示本次追加零件。
- MES 物料号：继续通过 `source_ticket_id` 同步回写 RFQ 零件和销售订单行。
- WMS 锁库：继续读取提单行和销售订单行快照，不需要新增分支。
- 待产零件 / 锁库零件：继续沿用 ticket / allocation 链路。
- U9 同步：目标销售订单重新预览时会读取追加后的全部销售订单行。
- 追加动作本身不调用 U9 / MES / WMS，不修改历史提单行。

## 8. 权限与日志

- 不新增权限点，不新增 `common:*`。
- 目标销售订单选择复用 `market:release:order-select`。
- 追加提交复用 `market:release:create`。
- 操作日志复用 `DELIVERY_TICKET_GENERATE`，摘要增加 `mode = APPEND_TO_EXISTING_SALES_ORDER`、目标销售订单 ID/编号、RFQ 数量、提单行数量、MES 已确认 / 待获取数量、追加批次短摘要和耗时。
- 日志不得记录左侧默认信息表单快照、完整请求体、完整响应体、完整价格明细、图纸 URL、Authorization、token、Cookie 或外部系统密钥。

## 9. 分阶段计划

### 阶段 1：后端追加基础

- 新增追加请求 DTO、追加批次表、实体和 mapper。
- 新增追加 service，校验目标销售订单、客户一致性、U9 状态和 RFQ 可提单规则。
- 追加生成 ticket、sales order item、来源 RFQ 关系和组合件关系。
- 验证幂等重放、参数冲突、跨客户和已同步目标拒绝。

### 阶段 2：前端追加入口

- 议价提单页新增“追加销售提单”按钮。
- 复用订单选择器，新增 `release-append-sales-order` scope。
- 追加路径 payload 只包含目标销售订单 ID、批次键、RFQ ID 和已选零件身份。
- 明确追加不读取左侧订单默认信息。

### 阶段 3：文档、权限日志和回归

- 更新权限文档，确认复用议价提单权限。
- 更新日志文档，确认 `DELIVERY_TICKET_GENERATE` 的追加模式摘要。
- 回归议价提单生成、已提零件、MES 物料号、WMS、U9 同步预览和同步前编辑。

## 10. 验收标准

- 左侧订单默认信息为空时，只要已选零件满足追加条件，仍可点击“追加销售提单”。
- 左侧订单默认信息已填写时，追加仍以目标销售订单头为准，不读取、不校验、不覆盖这些字段。
- 追加提交请求不包含左侧订单默认信息字段。
- 只能选择同一客户、已生成提单、未同步或同步失败的销售订单作为目标。
- 追加成功后目标销售订单新增销售订单行，新提单行进入已提零件。
- U9 同步页重新预览能看到追加后的销售订单行。
- 追加不调用 MES / WMS / U9。
- 操作日志和文件日志不出现敏感信息或完整业务体。
