# 零件核价材料工艺远程分页选择重构开发文档

> 编写日期：2026-08-27
> 适用范围：零件核价全局设定页、逐件核价页、材料选择弹窗、工艺选择弹窗、核价实时价格预估。
> 核心结论：材料和工艺主数据不再在核价页面全量缓存；选择材料 / 工艺时改为后端分页搜索，选中后继续在前端实时预估价格，保存核价时仍以后端数据库最新主数据重新核算并落库。

## 1. 背景

当前零件核价链路为了保证工程师在单个零件核价时输入尺寸、重量、工时、非工时费用后能实时看到价格变化，前端会在进入页面时通过 `dictionaryStore.loadBaseDicts(...)` 一次性加载材料、工艺、费用类字典，再在浏览器内完成实时预估。

这个模式在主数据较少时体验很好，但材料和具体工艺来自 MES / 数据中心后，数据量会持续增大，继续把全部材料和全部工艺加载到前端会带来几个问题：

- 首次进入核价页变慢。
- 浏览器内存和表单搜索压力变大。
- 材料 / 工艺选择弹窗需要在大数组中本地过滤，数据越多越不稳定。
- 核价页实际只需要“当前被选中的材料 / 工艺”，不需要整库主数据。

同时，核价实时预估本身不能取消。工程师调整材料物理参数、工时、固定费用时，页面仍应即时展示未税单价、含税单价、未税金额、含税金额，不能每次输入都等待后端响应。

因此本次重构要解决的是 **选项来源全量缓存问题**，不是把 **参数输入后的实时计算** 改成每次查库。

## 2. 目标

- 材料选择不再依赖前端全量 `dictionaryStore.materials`。
- 工艺选择不再依赖前端全量 `dictionaryStore.processDetails / processes`。
- 材料选择弹窗支持后端分页、关键词搜索、翻页和 loading 状态。
- 工艺选择弹窗支持后端分页、关键词搜索、翻页和 loading 状态，并保留具体工艺与非工时费用两类可选项。
- 选中材料后，把材料编码、名称、类型、分类、密度、单价等快照写入当前核价表单。
- 选中工艺后，把具体工艺 ID、大类信息、小时价格、费用类型等快照写入当前工艺行。
- 工程师修改尺寸、重量、工时、非工时费用时，继续前端实时预估价格。
- 保存核价时，后端继续按 `materialCode / processDetailId / feeCategory` 从数据库读取最新主数据并重新核算，最终落库以后端为准。
- 不改变 MES / WMS / U9 / 销售订单 / 提单链路。

## 3. 非目标

- 不改核价最终保存公式。
- 不让前端预估金额成为最终入库金额。
- 不做每次输入参数都请求后端重新计算。
- 不新增 Redis、浏览器持久化缓存或定时轮询。
- 不新增材料 / 工艺维护权限点。
- 不新增普通读接口操作日志。
- 不重新计算历史已核价订单、已提单订单或销售订单价格。
- 不改材料工艺管理页的维护方式；材料工艺管理页已经有独立后端分页，继续保持管理口径。

## 4. 当前系统现状

### 4.1 前端现状

逐件核价页：

- `quote-frontend/src/components/ItemPricing.vue`

当前进入页面时会调用：

```js
await dictionaryStore.loadBaseDicts({ includeMarkupFees: true })
```

该调用会加载：

- 材料类型
- 材料主数据
- 工艺大类
- 具体工艺
- 非工时费用
- 普通件百分比费用
- 组装件百分比费用

然后页面通过以下 computed 使用前端缓存：

```js
const materialOptions = computed(() => dictionaryStore.materials)
const processOptions = computed(() => dictionaryStore.processes)
const extraFeeOptions = computed(() => dictionaryStore.extraFeeItems)
const markupFeeOptions = computed(() => dictionaryStore.markupFees)
const assemblyMarkupFeeOptions = computed(() => dictionaryStore.assemblyMarkupFees)
const combinedProcessOptions = computed(() => dictionaryStore.combinedProcessOptions)
```

材料 / 工艺弹窗：

- `quote-frontend/src/components/EngineeringOptionPickerDialog.vue`

当前弹窗只接收 `items` 数组，在前端本地根据关键词过滤：

```js
const filteredItems = computed(() => {
  const text = keyword.value.trim().toLowerCase()
  if (!text) return props.items
  return props.items.filter(item => searchTextOf(item).includes(text))
})
```

### 4.2 后端现状

核价保存接口：

- `POST /api/engineer/submit-quote`
- `EngineerController.submitQuote(...)`
- `EngineerService.calculateAndSaveQuote(...)`

普通件保存时后端会重新执行：

```text
材料费用 = 材料重量 × 当前数据库材料单价
工艺费用 = Σ(工时 × 当前数据库有效小时价格) + Σ(非工时费用)
基础成本 = 材料费用 + 工艺费用
未税 / 含税价格 = 基础成本 × 当前费用规则
```

也就是说，当前前端缓存只用于选择和预估，最终保存价格已经是后端权威计算。

### 4.3 已有可复用分页能力

材料工艺管理页已经具备后端分页接口：

- `GET /api/dict/materials/page`
- `GET /api/dict/process-categories/page`
- `GET /api/dict/process-details/page`

这些接口适合材料工艺维护页面使用。本次零件核价页建议新增核价场景专用只读选项接口，内部可以复用已有 service 查询能力，但权限和返回字段按核价页面收窄。

## 5. 总体方案

采用三层分工：

| 层级 | 职责 | 是否查数据库 |
| --- | --- | --- |
| 选项搜索 | 材料 / 工艺弹窗输入关键词、翻页、选中行 | 是，后端分页查询 |
| 实时预估 | 修改尺寸、重量、工时、非工时费用、组装费后即时算价 | 否，使用当前表单快照 |
| 保存核价 | 点击保存核价，落库前重新计算最终价格 | 是，后端按最新主数据重算 |

这个方案避免“每输入一个数字就打接口”，也避免“打开页面一次性加载全部主数据”。

## 6. 后端设计

### 6.1 新增核价选项接口

建议新增在 `EngineerController` 下，复用 `engineer:pricing:view` 权限，不新增权限点：

```http
GET /api/engineer/pricing/options/materials
GET /api/engineer/pricing/options/processes
```

原因：

- 这是逐件核价页的只读选择能力，不是材料工艺维护能力。
- 核价用户访问逐件核价页时天然需要选材料 / 工艺。
- 不让逐件核价页继续直接绑定材料工艺管理接口语义。
- 后端仍然是最终权限边界，不能只靠前端隐藏按钮。

### 6.2 材料选项接口

请求：

```http
GET /api/engineer/pricing/options/materials?keyword=45&page=1&pageSize=10
```

参数：

| 参数 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `keyword` | string | 否 | 搜索材料编码、材料名称、材料类型、材质分类、备注。 |
| `page` | integer | 否 | 页码，默认 1。 |
| `pageSize` | integer | 否 | 每页数量，只允许 10 / 20 / 50 / 100，默认 10。 |

返回：

```json
{
  "records": [
    {
      "id": 1,
      "materialCode": "MAT-000001",
      "materialName": "45#",
      "materialTypeId": 10,
      "materialTypeCode": "RAW_MATERIAL",
      "materialTypeName": "原材料",
      "materialCategory": "钢材",
      "density": 7850,
      "mesDensityRaw": "7850",
      "platePrice": 7.1,
      "barPrice": 10,
      "tubePrice": 10,
      "remarks": ""
    }
  ],
  "total": 1,
  "page": 1,
  "pageSize": 10
}
```

过滤规则：

- 只返回 `enabled = true` 的材料。
- 按 `material_type_id ASC, sort_no ASC, id ASC` 排序。
- 关键词为空时返回第一页启用材料。
- 关键词不为空时按材料编码、材料名称、材料类型、材质分类、备注模糊搜索。

### 6.3 工艺选项接口

请求：

```http
GET /api/engineer/pricing/options/processes?keyword=CNC&page=1&pageSize=10
```

参数：

| 参数 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `keyword` | string | 否 | 搜索具体工艺、大类编码、大类名称、非工时费用名称。 |
| `page` | integer | 否 | 页码，默认 1。 |
| `pageSize` | integer | 否 | 每页数量，只允许 10 / 20 / 50 / 100，默认 10。 |

返回：

```json
{
  "records": [
    {
      "optionKey": "process:1001",
      "sourceType": "process",
      "processDetailId": 1001,
      "processCategoryId": 101,
      "processCode": "CNC",
      "categoryName": "数控加工",
      "detailName": "CNC 精加工",
      "processName": "CNC 精加工",
      "label": "CNC 精加工（CNC / 数控加工 / 80.00元/小时）",
      "calcType": "工时",
      "detailHourlyRate": 80,
      "categoryHourlyRate": 60,
      "effectiveHourlyRate": 80,
      "hourlyRate": 80
    },
    {
      "optionKey": "extra:12",
      "sourceType": "extra",
      "feeItemId": 12,
      "feeName": "喷砂",
      "processName": "喷砂",
      "label": "喷砂（非工时费用）",
      "calcType": "非工时费用"
    }
  ],
  "total": 2,
  "page": 1,
  "pageSize": 10
}
```

过滤规则：

- 具体工艺只返回 `detail.enabled = true` 且所属大类 `category.enabled = true` 的有效工艺。
- 非工时费用只返回启用项。
- 关键词为空时返回第一页可选项。
- 关键词不为空时同时搜索具体工艺、大类编码、大类名称、非工时费用名称。
- 排序保持稳定：具体工艺按大类排序和明细排序；非工时费用按 `sort_no ASC, id ASC`。如果采用同一结果集，建议先具体工艺后非工时费用，避免固定费用挤占常用工时工艺。

### 6.4 DTO 建议

新增 DTO：

```text
PricingMaterialOptionDTO
PricingProcessOptionDTO
PricingOptionPageReq
```

返回分页结构继续使用已有：

```text
PageResult<T>
```

### 6.5 Service 建议

新增：

```text
EngineeringPricingOptionService
```

职责：

- 提供材料分页选项查询。
- 提供工艺分页选项查询。
- 统一校验 `pageSize`。
- 统一做启用状态过滤。
- 不写审计日志。
- 不暴露材料工艺维护专用字段。

材料查询可以复用 `MaterialMasterService.pageMaterials(true, keyword, page, pageSize)` 的 DTO 转换逻辑；工艺查询建议单独封装为核价可选项，因为它需要合并“具体工艺”和“非工时费用”。

## 7. 前端设计

### 7.1 API helper

在 `quote-frontend/src/services/engineerApi.js` 新增：

```js
export const pagePricingMaterialOptions = ({ keyword, page, pageSize } = {}) => request(
  `/api/engineer/pricing/options/materials${buildQuery({ keyword, page, pageSize })}`
)

export const pagePricingProcessOptions = ({ keyword, page, pageSize } = {}) => request(
  `/api/engineer/pricing/options/processes${buildQuery({ keyword, page, pageSize })}`
)
```

如果 `engineerApi.js` 当前没有公共 `buildQuery`，可以抽到共享工具，或按现有文件风格在本文件内补一个小函数。

### 7.2 弹窗组件改造

改造 `EngineeringOptionPickerDialog.vue`，仅保留远程分页模式，调用方可按场景配置分页选项和默认页大小。

新增 props 建议：

```js
const props = defineProps({
  remoteLoader: { type: Function, default: null },
  pageSizeOptions: { type: Array, default: () => [20, 50, 100] },
  defaultPageSize: { type: Number, default: 20 }
})
```

逐件核价页的材料 / 工艺弹窗单独传入：

```vue
<EngineeringOptionPickerDialog
  :remote-loader="pagePricingMaterialOptions"
  :page-size-options="[10, 20, 50, 100]"
  :default-page-size="10"
/>
```

远程模式行为：

- 弹窗打开时请求第一页。
- 输入关键词后 300ms 防抖请求第一页。
- 翻页和修改 pageSize 请求后端。
- loading 时禁用确认按钮或保持当前已选项可确认。
- 请求失败时展示错误提示，并保留已选项不丢失。
- 老请求晚于新请求返回时丢弃老响应，避免搜索结果乱序覆盖。

本地模式行为：

- 保留当前 `items + filteredItems + pagedItems` 逻辑，避免影响其他已有使用方。

### 7.3 逐件核价页改造

改造 `ItemPricing.vue`：

- 页面初始化不再通过 `dictionaryStore.loadBaseDicts({ includeMarkupFees: true })` 拉取全量材料和全量工艺。
- 新增只加载费用类字典的方法，例如 `dictionaryStore.loadPricingFeeDicts()` 或 `ItemPricing.vue` 直接调用费用类 API。
- 材料弹窗使用 `remote=true` 和 `pagePricingMaterialOptions`。
- 工艺弹窗使用 `remote=true` 和 `pagePricingProcessOptions`。
- `selectMaterial(...)` 仍把选中材料快照写入 `matForm`。
- `selectProcess(...)` 仍把选中工艺快照写入当前 `processRoute` 行。
- `currentMatInfo` 不再依赖全量 `materialOptions` 查找；优先使用当前 `matForm` 已选快照。
- `normalProcessCostPreview` 不再依赖全量 `combinedProcessOptions` 查找；优先使用当前工艺行上的 `hourlyRate / unitRate / calcType / sourceType` 快照。
- 已核价行再次打开时，如果当前材料 / 工艺不在当前远程搜索页，也要能按保存快照正常回显。

### 7.4 全局设定页改造

改造 `GlobalSetup.vue`：

- 默认材料选择改为远程材料选择。
- 通用工艺路线选择改为远程工艺选择。
- 保存全局设定仍保存材料 / 工艺快照。
- 历史推荐配置如果使用旧材料名称或旧工艺名称，仍按现有“请重新选择”提示处理。
- 不再为了全局设定页选择框加载全量材料和全量具体工艺。

说明：如果只改逐件核价页，工程流程中的 `/engineering` 全局设定页仍可能加载全量主数据。为了彻底解决核价流程主数据变大问题，本次重构应同步覆盖 `/engineering` 和 `/pricing` 两个页面。

### 7.5 实时计算保持不变

以下输入变化仍由前端实时计算，不请求后端：

- 毛坯形状。
- 长宽厚、外径、内径。
- 净重。
- 工时。
- 非工时费用金额。
- 组装费。
- 子件用量。

理由：这些变化只依赖当前表单数据和已选项快照，不需要读取数据库。保存时后端会重新按数据库最新字典校验和计算。

## 8. 权限与日志

### 8.1 权限

- 新增核价选项接口不新增权限点。
- 材料 / 工艺远程选项接口复用 `engineer:pricing:view`。
- 材料工艺管理页仍复用 `engineer:dict:view / engineer:dict:*`。
- 保存核价仍复用 `engineer:pricing:save-item`。
- 不新增 `common:*` 权限。

### 8.2 日志

- 材料 / 工艺选项搜索是普通读接口，不写操作日志。
- 不记录完整搜索结果 JSON。
- 不记录材料价格全量列表。
- 保存核价日志保持现有 `ITEM_QUOTE_SAVE` 口径。
- 不新增 MES / WMS / U9 相关日志，因为本次不触发外部系统。

## 9. 边界与异常处理

### 9.1 字典更新时的数据新鲜度

如果用户打开核价页期间，另一个用户修改了材料单价、密度或工艺小时价格：

- 当前页面已选项的实时预估仍基于选中时的快照。
- 再次打开选择弹窗并搜索，会拿到后端最新选项。
- 点击保存核价时，后端按数据库最新主数据重新核算并落库。

### 9.2 已选项不在当前页

远程分页后，当前已选材料 / 工艺可能不在当前搜索结果页中。页面必须继续按当前表单快照展示标签和实时预估，不能因为当前页没有这条选项而显示“未选择”或把价格算成 0。

### 9.3 材料或工艺被停用

如果已选材料 / 工艺在保存前被停用：

- 前端可以继续展示快照。
- 保存时以后端校验为准，后端应返回明确错误，例如“材料已停用，请重新选择材料”或“具体工艺已停用，请重新选择工艺”。

### 9.4 请求乱序

前端远程搜索必须处理请求乱序：

- 用户快速输入 `C`、`CN`、`CNC` 时，只接受最后一次 `CNC` 的响应。
- 早发晚回的旧响应不得覆盖新结果。

## 10. 分阶段开发计划

### 阶段 1：后端核价选项分页接口

目标：建立逐件核价专用材料 / 工艺远程选项查询能力。

修改范围：

- 新增 `PricingOptionPageReq`。
- 新增 `PricingMaterialOptionDTO`。
- 新增 `PricingProcessOptionDTO`。
- 新增 `EngineeringPricingOptionService`。
- `EngineerController` 新增：
  - `GET /api/engineer/pricing/options/materials`
  - `GET /api/engineer/pricing/options/processes`
- 材料选项只返回启用材料。
- 工艺选项返回启用具体工艺和启用非工时费用。
- `pageSize` 只允许 `10 / 20 / 50 / 100`，默认 `10`。
- 不写操作日志。

验收标准：

- 正确 `engineer:pricing:view` 权限用户可以查询材料和工艺选项。
- 无权限用户无法访问接口。
- 材料关键词能命中材料编码、材料名称、材料类型、材质分类、备注。
- 工艺关键词能命中具体工艺、大类编码、大类名称、非工时费用名称。
- 停用材料、停用工艺、停用大类、停用非工时费用不返回。
- 分页顺序稳定，同一关键词连续翻页不漏不重。
- 查询接口不产生操作日志。

### 阶段 2：远程选择弹窗组件

目标：让 `EngineeringOptionPickerDialog.vue` 同时支持本地数组模式和远程分页模式。

修改范围：

- `EngineeringOptionPickerDialog.vue` 新增远程模式 props。
- 新增弹窗内部分页状态：`page / pageSize / total / records / loading / error`。
- 新增关键词防抖查询。
- 新增请求序号或 abort 机制处理乱序响应。
- 保留当前本地 `items` 模式，避免影响旧页面。
- 保持材料和工艺两套列展示不变。

验收标准：

- 本地模式原有测试通过。
- 远程模式打开弹窗会加载第一页。
- 输入关键词后请求第一页。
- 翻页和切换 pageSize 会重新请求。
- 请求失败有可见提示，不清空当前已选项。

## 11. 上线注意事项

- 本功能不需要数据库迁移文件。
- 如果未来材料或工艺数据达到数万级以上，再评估搜索索引优化；第一版先使用现有数据库查询能力。
- 上线前应使用真实材料数量和真实工艺数量做一次核价页打开、弹窗搜索、翻页、保存核价联调。
- 如果保存核价时出现“材料已停用”或“具体工艺已停用”，这是正确保护，应提示工程师重新选择当前有效主数据。
- 如果其他会话正在改费用公式或 `EngineerService`，实现本功能时必须先合并最新主线，避免重复改同一段核价计算逻辑。
