# 销售订单补传图纸体验对齐询价订单开发文档

## 1. 背景

当前 QPO 已同时支持询价订单和销售订单的图纸补传，但两条链路体验不一致：

- 询价订单详情在订单级提供“补传图纸”入口，用户一次上传多个 PDF 或整个图纸文件夹，系统按图号在整张询价订单内自动匹配缺图零件。
- 销售订单详情当前是零件行级“补传图纸”，用户需要先定位具体零件行，再上传图纸；即使选择多个 PDF，也只围绕当前行处理，不能像询价订单一样整单批量匹配。

本阶段目标是将销售订单补传图纸体验改成与询价订单一致：在销售订单详情中按订单级补传，多 PDF / 文件夹上传后按文件名图号自动匹配销售订单下所有缺图零件。

## 2. 范围

### 2.1 本阶段包含

- 销售订单详情补图入口改为订单级按钮，位置和交互对齐询价订单详情。
- 销售订单补图弹窗展示当前销售订单缺图零件列表。
- 支持拖拽多个 PDF、拖拽文件夹、按钮选择多个 PDF、按钮选择文件夹。
- 后端新增销售订单级补图接口，按 `sales_order_id` 下所有零件匹配图号。
- 已有图纸的销售订单零件不覆盖。
- 未匹配图纸、非 PDF 文件、已绑定零件结果展示与询价订单一致。
- 权限沿用 `market:sales-order:supplement-drawing`。
- 操作日志和文件日志更新为订单级摘要，不记录图纸内容或完整请求体。
- 更新前后端测试。

### 2.2 本阶段不包含

- 不迁移历史图纸文件。
- 不改变新单导入图纸绑定逻辑。
- 不改变询价订单补图接口行为。
- 不改变 MES / WMS / U9 下游图纸读取逻辑。
- 不强制删除 `sales_order_item.has_drawing` 字段；但业务判断以 `drawing_url` 为空为准。

## 3. 现状对比

| 模块 | 当前入口 | 当前接口 | 当前行为 |
|---|---|---|---|
| 询价订单详情 | 订单详情顶部“补传图纸” | `POST /api/order-management/orders/{rfqId}/supplement-drawings` | 订单级批量匹配，写 `item_quote_version.drawing_url`，已有图纸跳过 |
| 销售订单详情 | 零件行内“补传图纸” | `POST /api/market/sales-order-management/items/{itemId}/drawings` | 行级绑定，写 `sales_order_item.drawing_url` / `has_drawing`，已有图纸跳过 |

目标状态：

| 模块 | 目标入口 | 目标接口 | 目标行为 |
|---|---|---|---|
| 销售订单详情 | 订单详情顶部“补传图纸” | `POST /api/market/sales-order-management/orders/{salesOrderId}/supplement-drawings` | 订单级批量匹配，写缺图行 `sales_order_item.drawing_url`，同步 `has_drawing=true`，已有图纸跳过 |

## 4. 复用结论

### 4.1 可以复用的能力

- `quote-frontend/src/utils/drawingUpload.js`
  - `collectPdfFilesFromDataTransfer`
  - `mergePdfFiles`
  - `collectPdfFilesFromFileList`
  - 这些已经支持多 PDF、文件夹递归读取、去重。
- 后端图号解析工具：
  - `DrawingPartNoResolver.extractPartNo(...)`
  - `DrawingPartNoResolver.normalizePartNo(...)`
- 询价订单补图结果结构：
  - `boundCount`
  - `alreadyBoundCount`
  - `unmatchedCount`
  - `skippedCount`
  - `boundItems`
  - `alreadyBoundItems`
  - `unmatchedDrawings`
  - `skippedFiles`

### 4.2 建议抽出的前端组件

不建议直接复用 `ImportDrawingUploadPanel.vue`。它是新单导入场景组件，重点是“导入包附件选择”，没有缺图列表、补传结果 tabs、弹窗 footer 和提交状态。

建议从 `OrderManage.vue` 当前补图弹窗抽出新的共享组件：

```text
quote-frontend/src/components/order/SupplementDrawingDialog.vue
```

组件职责：

- 展示订单信息。
- 展示缺图零件列表。
- 负责拖拽 PDF / 文件夹、按钮选择多个 PDF / 文件夹。
- 展示已选文件列表和移除按钮。
- 展示补传结果 tabs。
- 通过事件把提交动作交给父组件。

建议 props：

| Prop | 类型 | 说明 |
|---|---|---|
| `modelValue` | Boolean | 弹窗显示状态 |
| `title` | String | 弹窗标题 |
| `permission` | String | 按钮和上传区权限码 |
| `orderRows` | Array | 订单信息描述行，例如订单号、客户 |
| `missingItems` | Array | 缺图零件列表 |
| `files` | Array | 当前选择的 PDF 文件 |
| `result` | Object | 补传结果 |
| `pending` | Boolean | 提交 loading 状态 |
| `submitText` | String | 默认“上传并匹配” |

建议 emits：

| Event | 说明 |
|---|---|
| `update:modelValue` | 关闭 / 打开弹窗 |
| `update:files` | 文件列表变化 |
| `submit` | 用户点击提交 |

使用方式：

- `OrderManage.vue` 使用该组件，保持现有 RFQ 补图接口不变。
- `SalesOrderManage.vue` 使用同一组件，接入新的销售订单级补图接口。

## 5. 后端设计

### 5.1 新接口

```http
POST /api/market/sales-order-management/orders/{salesOrderId}/supplement-drawings
Content-Type: multipart/form-data

drawings: PDF files[]
```

权限：

```java
@RequirePermission("market:sales-order:supplement-drawing")
```

Controller：

```java
@PostMapping(value = "/orders/{salesOrderId}/supplement-drawings", consumes = MediaType.MULTIPART_FORM_DATA_VALUE)
public Map<String, Object> supplementOrderDrawings(
        @PathVariable Long salesOrderId,
        @RequestParam("drawings") List<MultipartFile> drawings) {
    return salesOrderManageService.supplementOrderDrawings(salesOrderId, drawings);
}
```

### 5.2 服务逻辑

新增：

```java
@Transactional
public Map<String, Object> supplementOrderDrawings(Long salesOrderId, List<MultipartFile> drawings)
```

处理规则：

1. 锁定销售订单头：`salesOrderHeaderMapper.selectByIdForUpdate(salesOrderId)`。
2. 查询该销售订单下所有 `SalesOrderItem`。
3. 使用 `drawing_url` 是否为空判断缺图；`has_drawing` 只作为同步字段，不作为缺图判断源。
4. 按 `part_no` 归一化后构建 `Map<String, List<SalesOrderItem>>`。
5. 对每个上传文件：
   - 非 PDF：进入 `skippedFiles`。
   - PDF：用 `DrawingPartNoResolver.extractPartNo(cleanFileName, itemMap.keySet())` 提取图号。
   - 找不到销售订单零件：进入 `unmatchedDrawings`。
   - 匹配到的所有零件都已有 `drawing_url`：进入 `alreadyBoundItems`。
   - 匹配到缺图零件：保存文件，写入这些缺图行的 `drawing_url`，并同步 `has_drawing=true`。
6. 单个 PDF 匹配同一销售订单内多个同图号零件时，应一次保存文件，并复用同一个 publicPath 更新多个缺图行。
7. 返回结构与询价订单补图一致。

### 5.3 保存路径

沿用销售订单图纸保存能力：

```java
businessFileService.saveSalesOrderImportDrawing(
    order.getCustomerName(),
    orderNo,
    drawing,
    "SALES_ORDER_DRAWING_SUPPLEMENT",
    String.valueOf(salesOrderId)
)
```

`bizId` 建议改为 `salesOrderId`，因为这是订单级补传，不再是单个 `itemId`。

### 5.4 旧行级接口处理

当前行级接口：

```http
POST /api/market/sales-order-management/items/{itemId}/drawings
```

建议处理方式：

- 前端不再调用该接口。
- 若确认无外部调用，可在本阶段同步删除 controller 方法、service 方法和相关测试。
- 若担心兼容，可先保留一版并标记 deprecated，但新文档、页面和测试均以订单级接口为准。

推荐：QPO 内部系统目前由前端统一调用，优先清理旧行级入口，减少后续语义混淆。

## 6. 前端设计

### 6.1 询价订单

`OrderManage.vue`：

- 保留订单详情顶部“补传图纸”按钮。
- 改用 `SupplementDrawingDialog.vue`。
- 提交仍调用：

```js
supplementDrawings(rfqId, formData)
```

### 6.2 销售订单

`SalesOrderManage.vue`：

- 在销售订单详情顶部补充订单级“补传图纸”按钮，位置和禁用规则对齐询价订单：
  - `missingDrawingCount === 0` 时禁用。
  - title 展示“当前缺图零件：N 个”。
- 移除零件行内“补传图纸”按钮，避免用户误以为只能单行补图。
- 弹窗复用 `SupplementDrawingDialog.vue`：
  - 订单描述行展示销售订单号、客户。
  - 缺图列表来自当前销售订单缺图零件。
  - 支持拖拽多个 PDF / 文件夹、选择多个 PDF、选择文件夹。
- 提交调用：

```js
supplementSalesOrderDrawings(salesOrderId, formData)
```

新增 API：

```js
export const supplementSalesOrderDrawings = (salesOrderId, formData) => request(
  `/api/market/sales-order-management/orders/${salesOrderId}/supplement-drawings`,
  {
    method: 'POST',
    data: formData,
    headers: { 'Content-Type': 'multipart/form-data' }
  }
)
```

旧 API `supplementSalesOrderItemDrawings(itemId, formData)` 若后端同步删除，则前端一并删除。

### 6.3 缺图列表

销售订单缺图列表可直接从当前明细表数据过滤：

```js
const missingDrawingItems = computed(() =>
  orderItems.value.filter(item => !item.drawingUrl)
)
```

如果销售订单详情分页只加载部分明细，则必须由后端提供完整缺图列表接口或在详情加载时拉取完整缺图清单。当前实现需确认 `SalesOrderManage.vue` 的明细列表是否完整覆盖该订单所有零件；若存在分页，建议后端 `getSalesOrderDrawingSummary` 扩展返回 `missingItems`，避免只展示当前页缺图。

## 8. 日志与审计

### 8.1 操作日志

动作码沿用：

```text
SALES_ORDER_DRAWING_SUPPLEMENT
```

建议从行级 target 调整为订单级 target：

| 字段 | 值 |
|---|---|
| `module` | `MARKET` |
| `targetType` | `sales_order_header` |
| `targetId` | `salesOrderId` |

summary 只记录安全摘要：

```json
{
  "salesOrderId": 1,
  "salesOrderNo": "SOQPOxxx",
  "uploadCount": 10,
  "boundCount": 8,
  "alreadyBoundCount": 1,
  "unmatchedCount": 1,
  "skippedCount": 0,
  "boundItems": [
    { "itemId": 1, "partNo": "P-001", "fileName": "P-001.pdf", "status": "已绑定" }
  ]
}
```

不得记录：

- PDF 文件内容。
- 完整 multipart 请求体。
- token、cookie、Authorization header。

### 8.2 文件日志

文件日志事件建议：

```text
Sales order drawing supplement completed salesOrderId={} uploadCount={} boundCount={} alreadyBoundCount={} unmatchedCount={} skippedCount={}
Sales order drawing supplement completed with warnings salesOrderId={} unmatchedCount={} skippedCount={}
```

失败时：

```text
Sales order drawing supplement failed salesOrderId={} uploadCount={}
```

## 10. 验收标准

- 销售订单详情补图体验与询价订单详情一致：订单级入口、缺图列表、拖拽上传、多 PDF、文件夹选择、结果 tabs。
- 销售订单补图不再要求用户先点具体零件行。
- 销售订单补图按图号自动匹配整张销售订单下所有缺图零件。
- 已有图纸不覆盖。
- `drawing_url` 是图纸绑定事实来源；`has_drawing` 仅同步状态。
- 权限仍由 `market:sales-order:supplement-drawing` 控制。
- 操作日志和文件日志只记录安全摘要。
- 后端定向测试、前端定向测试和前端 build 通过。

## 11. 推荐实施顺序

1. 抽出 `SupplementDrawingDialog.vue`，先让 `OrderManage.vue` 复用并保持现有询价订单补图测试通过。
2. 新增销售订单级补图 API 和 service 方法，复用 `DrawingPartNoResolver`。
3. 改造 `SalesOrderManage.vue` 为订单级补图入口，删除行级按钮调用。
4. 更新 `orderApi.js`，新增 `supplementSalesOrderDrawings`，移除或停用旧行级 API。
5. 更新权限 / 日志文档和相关测试。
6. 跑后端定向测试、前端测试、前端 build。
