# QPO 权限点清单与现有角色映射

权限清单冻结版本：Stage 0

本文档用于企业级权限用户体系阶段 0。它冻结当前单角色权限入口，并给出迁移到 RBAC + 数据权限后的目标权限编码。后续阶段如果新增、删除或重命名权限点，必须同步更新本文档和阶段 0 测试。

## 1. 当前角色到目标角色映射

| 旧角色 | 目标角色 | 迁移说明 |
| --- | --- | --- |
| `ADMIN` | `SUPER_ADMIN` | 管理员继续拥有全部功能权限，并默认拥有全部数据权限。 |
| `MARKET` | `MARKET_USER` | 市场与工程账号迁移后默认保持现有可访问页面不变；市场账号继续保留新单导入、报价处理、议价提单、订单管理等市场主流程。 |
| `ENGINEER` | `ENGINEER_USER` | 市场与工程账号迁移后默认保持现有可访问页面不变；工程账号继续保留零件核价、逐件核价、材料工艺等工程主流程。 |

## 6. 数据权限迁移基线

| 当前角色 | 迁移后默认数据范围 | 说明 |
| --- | --- | --- |
| ADMIN | ALL | 迁移为 SUPER_ADMIN 后看全部数据。 |
| MARKET | SELF 或 CUSTOMER | 第一阶段为保持现有行为可先临时 ALL，数据权限阶段再收敛到本人或客户范围。 |
| ENGINEER | DEPT 或 CUSTOM | 第一阶段为保持现有行为可先临时 ALL，数据权限阶段再收敛到工程部门或指定订单范围。 |

阶段 6 启用数据权限前，必须先补齐订单归属字段，例如 `created_by`、`owner_user_id`、`owner_dept_id`。

## 7. 阶段 0 验收基线

- 权限编码唯一。
- 每个当前 `@RequireRole` 文件都出现在迁移清单中。
- 前端每个受保护路由都出现在迁移表中。
- 菜单显示快照保持与当前系统一致。
- 登录、强制改密、禁用用户、旧密码升级等现有行为被测试保护。
