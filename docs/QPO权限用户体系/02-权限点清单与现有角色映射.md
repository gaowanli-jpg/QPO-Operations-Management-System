# QPO 权限点清单与现有角色映射

权限清单冻结版本：Stage 8.6 授权树收口版 + 报价状态流转 Stage 6 / 提单表据模块拆分版 + 订单状态管理收口版 + 已提零件基础版 + MES物料号同步收口版 + WMS锁库分配前端页版

2026-08-07 统一价格字段阶段 5 收口：本次不新增用户权限，不修改既有权限 code、默认角色映射或数据范围。价格字段替换只影响数据模型和业务字段口径；核价、提单、异常治理、MES/WMS、待产、锁库和 U9 继续复用现有模块权限。

本文档用于冻结 QPO 企业级 RBAC + 数据权限体系的权限编码、角色映射和授权树口径。后续如果新增、删除或重命名权限点，必须同步更新本文档、权限树开发标准和对应测试。

2026-08-06 销售订单导入即提单阶段 7 收口：阶段 7 不新增权限。销售订单导入后的自动补全和自动提单由 `market:rfq:import-sales-order` 覆盖，不单独要求 `market:sales-match:apply` 或 `market:release:create`；异常治理继续复用 `market:sales-match:*`，仅调整显示名称和页面用途。

## 1. 当前角色到目标角色映射

| 旧角色 | 目标角色 | 迁移说明 |
| --- | --- | --- |
| `ADMIN` | `SUPER_ADMIN` | 管理员继续拥有全部功能权限，并默认拥有全部数据权限。 |
| `MARKET` | `MARKET_USER` | 市场与工程账号迁移后默认保持现有可访问页面不变；市场账号继续保留新单导入、报价处理、议价提单、询价订单等市场主流程。 |
| `ENGINEER` | `ENGINEER_USER` | 市场与工程账号迁移后默认保持现有可访问页面不变；工程账号继续保留零件核价、逐件核价、材料工艺等工程主流程。 |

## 2. 冻结权限编码目录

权限编码采用“模块:资源:动作”格式。下表是当前稳定权限目录，每个编码必须唯一。

### 2.1 授权树展示规则

角色授权页不再按平铺 checkbox 展示权限，而是按“市场 / 订单 / 工程 / 系统”分组，再展开到可点击模块和模块内权限。

| 权限类别 | 管理员看到的位置 | 解决的问题 |
| --- | --- | --- |
| 模块权限 `MENU` | 授权树的模块节点，也是左侧可点击入口 | 决定用户能不能看到并进入某个模块。每个左侧入口必须有独立 `MENU` 权限。 |
| 按钮/动作权限 `BUTTON` / `API` | 挂在对应模块权限下面 | 决定用户进入模块后能不能执行导入、导出、删除、重置、保存等动作。 |
| 模块级基础能力 | 挂在实际使用模块下面，例如“报价处理选择订单” | 选择客户、选择订单、文件预览、查看异步任务等能力不再作为泛用 `common:*` 暴露给管理员，而是按业务场景归属到模块。 |
| 数据权限 | 角色权限的数据范围抽屉 | 决定用户在有功能权限后能看到哪些订单、客户或日志，不进入功能授权树。 |

授权保存规则：

- 勾选模块节点时，系统会勾选该模块下的子权限。
- 取消模块节点时，该模块下按钮、接口和模块级基础能力一并取消。
- 只勾选子权限时，后端保存会自动补齐父级模块 `MENU` 权限，避免“有按钮权限但进不了页面”。
- `common:customer:select`、`common:order:select` 已通过 V38 退役删除；客户/订单选择必须使用模块归属权限。
- `common:file:preview`、`common:task:view` 暂作为历史兼容权限保留，不出现在可分配授权树中。

### 2.2 订单分组独立权限

询价订单、销售订单、已提零件、锁库零件在左侧订单分组下独立授权：

| 左侧入口 | 独立权限 | 说明 |
| --- | --- | --- |
| 询价订单 | `market:order:view` | 查看当前 RFQ 询价订单、图纸、提单和工艺表状态。 |
| 销售订单 | `market:sales-order:view` | 查看独立销售订单、零件明细、提单行和工艺表状态。 |
| 已提零件 | `market:delivered-item:view` | 查看已生成提单的零件需求池和 MES / WMS 基础状态。 |
| 待产零件 | `market:production-item:view` | 查看 WMS 拆分后仍需下发 MES 生产的待产行。 |
| 锁库零件 | `market:locked-item:view` | 查看 WMS 拆分后的已入库库存锁定和在产库存锁定结果。 |
| U9同步 | `market:u9-sync:view` | 查看销售订单整单 U9 同步入口、同步列表和预览结果。 |
| 提单表据 | `market:delivery-document:view` | 查看 RFQ / 销售订单已生成提单行和动态工艺表行，只面向 `部分已提单` / `已生成提单` 订单。 |

首页看板权限收口：`首页看板` 是登录默认页，不新增 `dashboard:view` 或其他首页独立权限点。页面入口对可登录用户可见，但首页中的图表、数字、待办卡片和异常入口仍按目标模块权限裁剪：询价相关入口使用 `market:order:view`、工程 / 报价 / 议价提单相关权限；销售订单相关入口使用 `market:sales-order:view`、`market:sales-match:view`、`market:release:view`、`market:u9-sync:view`；已提零件相关入口使用 `market:delivered-item:view`；待产零件相关入口使用 `market:production-item:view`；锁库零件相关入口使用 `market:locked-item:view`。后端 `GET /api/dashboard/overview` 同样按上述目标模块权限和数据权限裁剪统计数量，不能只依赖前端隐藏。

因此，角色拥有 `market:order:view` 但没有 `market:sales-order:view`、`market:delivered-item:view`、`market:production-item:view` 或 `market:locked-item:view` 时，左侧只显示询价订单；反过来，拥有销售订单、已提零件、待产零件或锁库零件权限但没有订单数据范围时，页面列表为空而不是报错。旧 `market:history-order:*` 仅作为历史兼容权限保留，不再作为可见菜单，也不再控制新的销售订单页面。

RFQ 物料号确认字段收口不新增权限：询价订单详情中的零件物料号和物料号状态展示复用 `market:order:view`，只读展示 `item_quote_version.material_no / material_no_status`；MES 获取物料号仍由已提零件操作权限 `market:delivered-item:mes-sync` 控制。后续 RFQ U9 同步如果拆成独立模块，再按模块入口、订单选择和提交动作单独设计权限，不在本阶段提前新增。

### 2.3 已提零件独立权限

已提零件必须作为订单分组下的独立 `MENU` 权限治理，不得复用询价订单、历史订单或议价提单的查看权限。

| 授权能力 | 权限编码 | 类型 | 说明 |
| --- | --- | --- | --- |
| 查看已提零件 | `market:delivered-item:view` | `MENU` | 控制左侧“已提零件”入口、分页列表和详情查询。 |
| 已提零件选择客户 | `market:delivered-item:customer-select` | `API` | 控制已提零件页面客户选择弹窗，挂在 `market:delivered-item:view` 下。 |
| 已提零件预览图纸 | `market:delivered-item:file-preview` | `API` | 控制已提零件页面图纸预览，挂在 `market:delivered-item:view` 下。 |
| 获取MES物料号 | `market:delivered-item:mes-sync` | `BUTTON` | 控制已提零件页面“获取物料号 / 重试”按钮，触发 `MES_MATERIAL_SYNC` 后台任务，挂在 `market:delivered-item:view` 下。 |
| 提交WMS锁库 | `market:delivered-item:wms-allocate` | `BUTTON` | 控制已提零件页面“提交WMS锁库 / 重试WMS”按钮，触发 `WMS_ALLOCATION` 后台任务，挂在 `market:delivered-item:view` 下。 |
| 查看待产零件 | `market:production-item:view` | `MENU` | 控制左侧“待产零件”入口和待生产工作池查询。 |
| 待产零件选择客户 | `market:production-item:customer-select` | `API` | 控制待产零件页面客户选择弹窗，挂在 `market:production-item:view` 下。 |
| 待产零件下发MES生产 | `market:production-item:mes-production-submit` | `BUTTON` | 控制待产零件页面“下发MES生产”按钮，触发待生产 allocation 行进入 MES 生产流程，挂在 `market:production-item:view` 下。 |
| 查看锁库零件 | `market:locked-item:view` | `MENU` | 控制左侧“锁库零件”入口和 WMS 已锁库存结果查询。 |
| 锁库零件选择客户 | `market:locked-item:customer-select` | `API` | 控制锁库零件页面客户选择弹窗，挂在 `market:locked-item:view` 下。 |
`order_delivery_ticket` 是 MES/WMS 对接需求池。管理员只授予 `market:delivered-item:view` 时，用户可以查看需求池但不能打开图纸，也不能向 MES 获取物料号，也不能向 WMS 提交锁库；同时授予 `market:delivered-item:customer-select` 后，才允许使用已提零件页面的客户选择弹窗；同时授予 `market:delivered-item:file-preview` 后，才允许在该模块预览图纸；同时授予 `market:delivered-item:mes-sync` 后，才允许提交或重试 MES 物料号同步任务；MES 同图号版本去重不新增用户权限，仍由 `market:delivered-item:mes-sync` 控制单条 / 批量获取、失败重试、唯一物料号复用和关联等待处理，不新增任何 MES 去重专用权限或同义权限；同时授予 `market:delivered-item:wms-allocate` 后，才允许提交或重试 WMS 锁库任务。待产零件页面的客户选择弹窗由 `market:production-item:customer-select` 控制，待生产行下发 MES 生产由 `market:production-item:mes-production-submit` 控制；锁库零件页面的客户选择弹窗由 `market:locked-item:customer-select` 控制，锁库零件不再承载生产下发权限。客户选择、文件预览、MES 同步、MES 去重、WMS 锁库和待产生产下发能力均按模块归属展示，不新增可分配 `common:*` 权限。

已提零件未完成池与锁库结果池重构不新增权限。阶段 20 只调整查询口径和页面说明：`market:delivered-item:view` 继续控制已提零件未完成池列表和原始提单行详情，`market:delivered-item:wms-allocate` 继续控制 WMS 锁库提交 / 重试，`market:locked-item:view` 继续控制锁库结果池列表和按 `ticketId` 追溯结果；不新增完成池专用查看权限、锁库追溯专用权限或其他同义权限。

管理员授权建议：

| 角色类型 | 建议授权 | 不建议授权 |
| --- | --- | --- |
| 市场主管 | `market:delivered-item:view`、`market:delivered-item:customer-select`、`market:delivered-item:file-preview`、`market:delivered-item:mes-sync`、`market:delivered-item:wms-allocate`、`market:production-item:view`、`market:production-item:customer-select`、`market:production-item:mes-production-submit`、`market:locked-item:view`、`market:locked-item:customer-select` | 如公司要求外部系统动作集中审批，可只给主管保留 MES/WMS 操作权限。 |
| 市场人员 | 默认可授予已提零件查看、图纸预览、MES 获取物料号、WMS 锁库和锁库零件查看；如果岗位只负责跟单查看，可只授予 `view` 和 `file-preview`。 | 不把 MES/WMS 操作拆到 `common:*`，也不复用询价订单权限。 |
| 只读账号 | `market:delivered-item:view`、`market:delivered-item:customer-select`、`market:delivered-item:file-preview`、`market:production-item:view`、`market:production-item:customer-select`、`market:locked-item:view`、`market:locked-item:customer-select` | 不授予 `market:delivered-item:mes-sync`、`market:delivered-item:wms-allocate`、`market:production-item:mes-production-submit`。 |

### 2.4 订单状态管理权限

询价订单模块新增 4 个状态动作权限，全部挂在 `market:order:view` 下面，不新增独立左侧模块：

| 动作 | 权限编码 | 类型 | 推荐默认角色 | 说明 |
| --- | --- | --- | --- | --- |
| 已报价退回已核价 | `market:order:rollback-quoted` | `BUTTON` | `SUPER_ADMIN`, `MARKET_MANAGER` | 只调整状态，不清空报价交期和核价结果。 |
| 已核价退回未核价 | `market:order:rollback-priced` | `BUTTON` | `SUPER_ADMIN`, `MARKET_MANAGER` | 只调整状态，已录入核价数据保留为草稿。 |
| 废弃订单 | `market:order:discard` | `BUTTON` | `SUPER_ADMIN`, `MARKET_MANAGER` | 允许 `未核价`、`已核价`、`已报价` 订单停止流转但保留数据。 |
| 恢复废弃订单 | `market:order:restore` | `BUTTON` | `SUPER_ADMIN`, `MARKET_MANAGER` | 将 `废弃` 订单恢复为 `已核价`，后续业务校验继续生效。 |

治理口径：

- `部分已提单` / `已生成提单` 不允许废弃或回退；只要存在 `order_delivery_ticket` 提单行，即使订单状态异常也必须拒绝状态动作。
- 状态管理只改订单和非提单零件状态，不清空核价、报价交期、图纸、材料、工艺或提单快照。
- 操作日志动作固定为 `ORDER_STATUS_ROLLBACK_QUOTED`、`ORDER_STATUS_ROLLBACK_PRICED`、`ORDER_DISCARD`、`ORDER_RESTORE`；文件日志事件固定为 `Order status change started/completed/rejected/failed`。

### 2.5 议价提单权限收口

议价提单模块只保留查看、生成和模块级基础能力权限：

- `market:release:view`：进入议价提单生成页面，查看候选零件并维护生成前参数；已生成提单行和动态工艺表行由提单表据模块负责查看和导出。
- `market:release:create`：按剩余可提数量生成新的不可逆提单记录；同时覆盖生成前的单行版本修改和导入替换图纸。
- `market:release:customer-select`、`market:release:order-select`、`market:release:task-view`：议价提单模块内基础能力。

多订单议价提单只是现有生成工作台的能力扩展，批量候选零件分页、跨订单导入匹配、按订单分组生成仍沿用 `market:release:view`、`market:release:order-select`、`market:release:create`。版本修改和导入替换图纸属于生成正式提单前的资料维护动作，也沿用 `market:release:create`。不新增 `market:release:batch-*`、`market:release:update-version`、`market:release:replace-drawing`，不新增可分配 `common:*`，也不把提单表据的查看/导出权限反向用于生成动作。

`market:release:reset` 已废弃，不得出现在可分配权限目录、默认角色映射、授权树或新增代码中。提单记录一旦生成，不再提供删除提单行、删除工艺表行或订单重置提单/工艺的权限点。

数据职责边界：`order_delivery_ticket` 是不可逆发布记录，也是 MES/WMS 对接需求池和工艺快照来源；QPO 内部工艺表展示/导出从 `order_delivery_ticket` 动态生成，`order_process_sheet` 已通过 V36 回填后删除。议价提单权限只控制候选零件查看和正式提单生成；生成后的表据查看和导出由提单表据权限单独控制，不提供发布后回退授权。

### 2.6 提单表据独立权限

提单表据是 `议价提单` 生成后的只读表据工作台，作为市场分组下的独立 `MENU` 权限治理，不复用 `market:release:view`、询价订单或已提零件权限。订单选择返回来源对象，`sourceType = RFQ` 时读取 `order_rfq`，`sourceType = SALES_ORDER` 时读取 `sales_order_header`；两类来源统一从 `order_delivery_ticket` 的来源字段分页展示和导出。

| 授权能力 | 权限编码 | 类型 | 推荐默认角色 | 说明 |
| --- | --- | --- | --- | --- |
| 提单表据 | `market:delivery-document:view` | `MENU` | `SUPER_ADMIN`, `MARKET_USER`, `MARKET_MANAGER`, `READONLY` | 控制左侧入口、页面进入、RFQ / 销售订单摘要、提单行分页和工艺表行分页。 |
| 提单表据选择客户 | `market:delivery-document:customer-select` | `API` | `SUPER_ADMIN`, `MARKET_USER`, `MARKET_MANAGER`, `READONLY` | 控制新页面客户选择弹窗，挂在 `market:delivery-document:view` 下。 |
| 提单表据选择订单 | `market:delivery-document:order-select` | `API` | `SUPER_ADMIN`, `MARKET_USER`, `MARKET_MANAGER`, `READONLY` | 控制新页面订单选择弹窗，后端仅返回 RFQ / 销售订单中 `部分已提单` / `已生成提单` 订单，并返回 `sourceType`、`sourceOrderId`、`sourceOrderNo`。 |
| 导出提单表据 | `market:delivery-document:export` | `BUTTON` | `SUPER_ADMIN`, `MARKET_USER`, `MARKET_MANAGER` | 控制导出提单 Excel 和导出工艺表 Excel；只读账号默认不授予。 |

### 2.7 组织档案授权

组织档案是系统治理能力，不是订单数据范围能力。它用于维护用户的组织身份字典，并给用户管理提供部门、岗位选项。

| 授权节点 | 权限编码 | 类型 | 说明 |
| --- | --- | --- | --- |
| 组织档案 | `system:org:view` | `MENU` | 左侧四字入口；没有该权限时不可进入组织档案页。 |
| 部门管理 | `system:dept:view` | `MENU` | 组织档案内的部门管理标签或子节点可见。 |
| 维护部门 | `system:dept:manage` | `BUTTON` | 新增、编辑、启停、删除部门。 |
| 岗位管理 | `system:post:view` | `MENU` | 组织档案内的岗位管理标签或子节点可见。 |
| 维护岗位 | `system:post:manage` | `BUTTON` | 新增、编辑、启停、删除岗位。 |

治理口径：

- `system:dept:*`、`system:post:*` 只管理用户身份属性，不参与订单数据范围。
- 给管理员创建“只能维护用户组织资料”的角色时，只授予 `system:org:view`、`system:dept:view`、`system:dept:manage`、`system:post:view`、`system:post:manage`，数据范围建议选择 `NONE`。
- 默认 `SUPER_ADMIN` 拥有组织档案全部权限；其他角色按实际治理职责单独授权。

### 2.8 客户资料授权

客户资料是系统主数据能力，用于维护客户编码、客户简称、客户名称三字段，作为后续客户选择和 U9 销售订单客户编码来源。

| 授权节点 | 权限编码 | 类型 | 推荐默认角色 | 说明 |
| --- | --- | --- | --- | --- |

### 2.9 系统配置授权

系统配置是系统治理能力，当前承载文件存储配置、出站接口/数据中心配置和入站接口配置：文件存储用于维护本地存储和 MinIO 存储策略，出站接口/数据中心配置用于维护 QPO 调用数据中心的连接配置、功能接口配置，以及旧 U9、MES、WMS 直连 fallback 配置，入站接口用于维护数据中心调用 QPO 回调接口的入口地址和机器 token 状态。该模块只建议授予超级管理员；如后续需要“只管系统配置、不看业务订单”的运维账号，应配合数据范围 `NONE` 使用。

| 授权节点 | 权限编码 | 类型 | 推荐默认角色 | 说明 |
| --- | --- | --- | --- | --- |
| 系统配置 | `system:config:view` | `MENU` | `SUPER_ADMIN` | 控制左侧系统分组中的系统配置入口和配置查询。 |
| 维护文件存储配置 | `system:config:storage:update` | `BUTTON` | `SUPER_ADMIN` | 新增、编辑、停用本地或 MinIO 文件存储配置。 |
| 测试文件存储配置 | `system:config:storage:test` | `BUTTON` | `SUPER_ADMIN` | 测试本地目录或 MinIO bucket 的上传、读取、删除能力。 |
| 激活文件存储配置 | `system:config:storage:activate` | `BUTTON` | `SUPER_ADMIN` | 切换新上传文件使用的存储策略。 |
| 维护出站接口/数据中心配置 | `system:config:integration:update` | `BUTTON` | `SUPER_ADMIN` | 新增、编辑、停用数据中心连接配置、功能接口配置和旧 U9、MES、WMS 直连 fallback 配置。 |
| 测试出站接口/数据中心配置 | `system:config:integration:test` | `BUTTON` | `SUPER_ADMIN` | 测试数据中心 token、功能接口配置，以及旧 U9、MES、WMS fallback 地址、认证和超时配置。 |
| 激活出站接口/数据中心配置 | `system:config:integration:activate` | `BUTTON` | `SUPER_ADMIN` | 激活某套数据中心连接配置；旧直连 fallback 仍按系统维度保留激活能力。 |
| 维护入站接口配置 | `system:config:inbound:update` | `BUTTON` | `SUPER_ADMIN` | 保存 MES 回调入站接口配置、启停 token 校验、配置 publicBaseUrl。 |
| 轮换入站回调Token | `system:config:inbound:token-rotate` | `BUTTON` | `SUPER_ADMIN` | 生成或轮换 MES 回调机器 token；明文只允许返回一次。 |

治理口径：

- 系统配置不新增 `common:*` 权限。
- 文件存储配置写操作必须由后端 `@RequirePermission` 校验，前端隐藏按钮不能作为安全边界。
- 出站接口/数据中心配置写操作必须由后端 `@RequirePermission` 校验，前端隐藏按钮不能作为安全边界。
- `system:config:integration:*` 只授权页面维护、测试、激活、停用数据中心连接配置、功能接口配置和旧直连 fallback 配置；不授予 MES/WMS/U9 业务操作权限，业务入口仍使用各自模块权限。
- 入站接口配置写操作必须由后端 `@RequirePermission("system:config:inbound:update")` 校验；生成或轮换 MES 回调 token 必须由 `@RequirePermission("system:config:inbound:token-rotate")` 校验。
- MES 回调业务接口本身不走用户权限树，使用机器 token 校验；入站接口配置权限只负责治理 token、启停和可对外提供的回调 URL。
- MES/WMS/U9 运行时优先读取页面激活的 DB 配置；没有 active DB 配置时才回退到 `erp.env` 中的 `ERP_MES_*`、`ERP_WMS_*`、`ERP_U9_*`。
- 页面激活配置互斥按系统维度生效，同一系统同一时间只允许一条 active 配置；变更页面配置不需要重启 backend。
- U9、MES、WMS 的 token、secret、认证参数和完整外部请求体不得进入权限文档、操作日志、文件日志或前端缓存。
- 数据中心配置使用 `system_data_center_config` 保存连接配置，使用 `system_data_center_endpoint_config` 保存功能接口配置；默认功能编码包含 `MES_MATERIAL_RESOLVE`、`WMS_INVENTORY_ALLOCATE`、`U9_SALES_ORDER_SYNC` 和 `MES_PRODUCTION_DISPATCH`，且继续复用 `system:config:integration:*` 权限，不新增 `common:*` 或数据中心专用权限。
- MinIO access secret、token、连接密码不得进入权限文档、操作日志、文件日志或前端缓存。
- 存储策略切换只影响新上传文件；历史文件依赖文件对象元数据定位实际存储位置。

### 2.10 异常治理独立权限

异常治理是市场分组下的独立左侧模块，位于“新单导入”和“报价处理”之间。该模块用于排查历史销售订单或自动补全异常，不作为新销售订单日常流程入口；不得选择 RFQ，不得新增 `order_rfq` 或 `item_quote_version`。异常治理页面仍复用兼容权限 code `market:sales-match:*`，只调整显示名称，不新增权限。

| 左侧入口 | 独立权限 | 说明 |
| --- | --- | --- |
| 异常治理 | `market:sales-match:view` | 查看异常治理页面和订单级预览结果。 |

| 授权能力 | 权限编码 | 类型 | 说明 |
| --- | --- | --- | --- |
| 异常治理 | `market:sales-match:view` | `MENU` | 控制左侧“异常治理”入口、路由和订单级预览。 |
| 异常治理选择客户 | `market:sales-match:customer-select` | `API` | 控制共享订单选择弹窗中的客户选择能力。 |

- `READONLY` 默认可查看和预览，不授予确认补全权限。

## 6. 当前数据权限默认范围参考

QPO 订单会跨市场、工程、系统管理等角色连续流转，不推荐把订单主流程按部门隔离。功能权限决定用户能进入哪些模块、能执行哪些动作；数据范围只决定用户在这些模块中能看到哪些订单、客户或日志。

### 6.1 推荐数据范围

| 角色类型 | 推荐数据范围 | 说明 |
| --- | --- | --- |
| 超级管理员 | `ALL` | 拥有全部功能和全部数据。 |
| 市场主管 | `ALL` 或 `CUSTOMER` | 管理全部市场订单时用 `ALL`；只负责部分客户时用 `CUSTOMER`。 |
| 市场人员 | `CUSTOMER` | 推荐按负责客户配置；临时过渡账号可用 `SELF`。 |
| 工程核价员 | 通常 `ALL` | 工程需要看到市场导入的待核价订单，建议由功能权限限制其只能做工程动作。 |
| 只读客户账号 | `CUSTOMER` | 只看指定客户订单，可配合只读功能权限使用。 |
| 临时账号 | `SELF` | 只看当前用户导入/创建相关订单；当前兼容 `created_by OR owner_user_id`。 |
| 系统配置账号 | `NONE` | 只做系统配置，不看业务订单。 |

### 6.2 已下线范围

`DEPT`、`DEPT_AND_CHILD`、`CUSTOM` 部门类数据范围已从角色权限配置入口、保存接口和订单数据范围执行逻辑中下线。历史角色如仍存在这些旧值，会通过迁移转为 `ALL`，并清理部门范围关联。

### 6.3 多角色并集规则

同一用户绑定多个角色时，数据范围取并集而不是交集。例如一个角色配置 `CUSTOMER = 客户甲`，另一个角色配置 `CUSTOMER = 客户乙`，最终可见客户为客户甲或客户乙。

### 6.4 配置示例

“只看指定客户但能走报价处理”的角色应这样配置：

1. 功能权限：勾选 `market:quote-process:view`、`market:quote-process:customer-select`、`market:quote-process:order-select`，按职责再勾选 `market:quote-process:update-lead-time`、`market:quote-process:save-quote`、`market:quote-process:export`。
2. 数据权限：选择 `CUSTOMER`，在客户多选中勾选该角色负责的客户名称。
3. 角色权限不再提供部门数据范围配置，避免把同一客户订单按部门错误切开。

订单数据权限当前依赖 `created_by`、`owner_user_id`、`customer_name` 等归属字段；新导入或迁移订单必须保证归属信息可追溯。

- 权限编码唯一。

## 8. 新页面权限开发清单

开发者新增左侧可点击页面时，必须同步完成：

1. 新增一个稳定的 `MENU` 权限编码。
2. 在后端权限目录中设置 `route_path`、`component_key`、`visible`、`sort_order` 和父子关系。
3. 在前端路由中配置同一个 `meta.permission`。
4. 在 `App.vue` 菜单元数据中使用同一个权限编码。
5. 如果页面有导入、导出、删除、重置、保存等动作，新增对应 `BUTTON` / `API` 权限并挂到模块下面。
6. 如果页面需要选择客户、选择订单、文件预览或任务查看，新增页面所属模块的基础能力权限，不直接使用新的可分配 `common:*`。
7. 补充前后端权限测试，并同步更新本文档。

## 9. 销售订单独立主表导入权限口径

销售订单独立主表导入是市场 `新单导入` 页面下销售订单子入口的新阶段能力，不新增左侧模块。导入动作仍沿用 `market:rfq:import-sales-order`，挂在 `market:rfq:view` 下，后端接口必须独立校验该权限，不能复用 `market:rfq:import`。

阶段边界：销售订单导入不再创建 QPO `order_rfq`，不再创建 QPO `item_quote_version`，而是写入独立 `sales_order_header` 和 `sales_order_item`；当前页面统一调用 `/api/market/sales-orders/import-qpo`，操作日志动作使用 `SALES_ORDER_IMPORT_QPO`。旧 Excel 直连 U9 导入接口 `/api/market/sales-orders/import` 已下线；销售订单同步 U9 改由销售订单 U9 同步模块承担。

U9 同步独立模块口径：销售订单导入、模板下载仍沿用 `market:rfq:import-sales-order`；后续 U9 整单同步入口改为独立 `market:u9-sync:*`。同步请求从 `sales_order_header` / `sales_order_item` 组装，`OrderBy` 使用客户主数据 `customer_code` 快照，`DocumentType` 使用页面 `document_type_code`，`ItemCode` 使用 `sales_order_item.material_no` 且必须满足 `material_no_status = 已确认`。操作日志动作使用 `SALES_ORDER_U9_SYNC`，模块为 `MARKET`，`targetType` 为 `sales_order_header`，摘要只记录订单数、成功/失败数、销售订单号样本、U9 编码样本和耗时，不记录 token、密钥或完整 U9 请求/响应。

## 9.1 销售订单管理模块权限口径

销售订单管理入口位于订单分组，路由为 `/sales-orders`，组件为 `SalesOrderManage`，查看权限为 `market:sales-order:view`。该模块只读取销售订单独立主表链路，后续业务接口以 `sales_order_header` / `sales_order_item` 为主数据源，不把销售订单映射回 RFQ 主表。旧 `/history-orders` 只作为兼容入口跳转到 `/sales-orders`，旧 `market:history-order:*` 不再作为可见菜单，也不再控制销售订单新页面。
阶段 5 收口：前端 `HistoryOrderManage.vue` 已删除，`orderApi.deleteOrder` 与 `history-order` 客户选择范围已移除；V72 将 `market:history-order:*` 和 `market:order:delete` 标记为不可分配的兼容权限，后端旧接口仅以 `@Deprecated` 形式保留。
后端只读接口由 `controller/SalesOrderManageController.java` 承载，路径为 `/api/market/sales-order-management`；订单列表和零件分页读取 `sales_order_header` / `sales_order_item`，提单行和工艺表行查询固定使用 `source_type = SALES_ORDER` 与 `source_order_id`，不通过 RFQ 主表或询价零件表回查。

- `market:sales-order:view` 控制左侧“销售订单”入口和路由访问。
- `market:sales-order:customer-select` 控制销售订单页面客户选择。
- `market:sales-order:file-preview` 控制销售订单页面文件预览。
- `market:sales-order:supplement-drawing` 控制销售订单详情整单补传图纸，按图号自动匹配该销售订单下缺图零件。
- `market:sales-order:discard` 控制已报价销售订单废弃。
- `market:sales-order:restore` 控制废弃销售订单恢复为已报价。
