# QPO 权限点清单与现有角色映射

权限清单冻结版本：Stage 8.6 授权树收口版 + 报价状态流转 Stage 3

本文档用于冻结 QPO 企业级 RBAC + 数据权限体系的权限编码、角色映射和授权树口径。后续如果新增、删除或重命名权限点，必须同步更新本文档、权限树开发标准和对应测试。

## 1. 当前角色到目标角色映射

| 旧角色 | 目标角色 | 迁移说明 |
| --- | --- | --- |
| `ADMIN` | `SUPER_ADMIN` | 管理员继续拥有全部功能权限，并默认拥有全部数据权限。 |
| `MARKET` | `MARKET_USER` | 市场与工程账号迁移后默认保持现有可访问页面不变；市场账号继续保留新单导入、报价处理、议价提单、订单管理等市场主流程。 |
| `ENGINEER` | `ENGINEER_USER` | 市场与工程账号迁移后默认保持现有可访问页面不变；工程账号继续保留零件核价、逐件核价、材料工艺等工程主流程。 |

## 2. 冻结权限编码目录

权限编码采用“模块:资源:动作”格式。下表是当前稳定权限目录，每个编码必须唯一。

### 2.1 授权树展示规则

角色授权页不再按平铺 checkbox 展示权限，而是按“市场 / 订单 / 工程 / 系统”分组，再展开到可点击模块和模块内权限。

| 权限类别 | 管理员看到的位置 | 解决的问题 |
| --- | --- | --- |
| 模块权限 `MENU` | 授权树的模块节点，也是左侧可点击入口 | 决定用户能不能看到并进入某个模块。每个左侧入口必须有独立 `MENU` 权限。 |
| 按钮/动作权限 `BUTTON` / `API` | 挂在对应模块权限下面 | 决定用户进入模块后能不能执行导入、导出、删除、重置、保存等动作。 |
| 模块级基础能力 | 挂在实际使用模块下面，例如“报价处理选择订单” | 选择客户、选择订单、文件预览、查看异步任务等能力不再作为泛用 `common:*` 暴露给管理员，而是按业务场景归属到模块。 |
| 数据权限 | 角色管理的数据范围抽屉 | 决定用户在有功能权限后能看到哪些订单、客户或日志，不进入功能授权树。 |

授权保存规则：

- 勾选模块节点时，系统会勾选该模块下的子权限。
- 取消模块节点时，该模块下按钮、接口和模块级基础能力一并取消。
- 只勾选子权限时，后端保存会自动补齐父级模块 `MENU` 权限，避免“有按钮权限但进不了页面”。
- `common:customer:select`、`common:order:select`、`common:file:preview`、`common:task:view` 仅作为历史兼容权限，不再出现在可分配授权树中。

### 2.2 历史订单独立权限

历史订单已经从订单管理中拆出独立模块权限：

| 左侧入口 | 独立权限 | 说明 |
| --- | --- | --- |
| 订单管理 | `market:order:view` | 查看当前订单、图纸、提单和工艺表状态。 |
| 历史订单 | `market:history-order:view` | 查询历史报价、提单和工艺资料。 |

因此，角色拥有 `market:order:view` 但没有 `market:history-order:view` 时，左侧只显示订单管理；反过来，拥有历史订单权限但没有订单数据范围时，页面列表为空而不是报错。

## 6. 当前数据权限默认范围参考

| 当前角色 | 默认数据范围 | 说明 |
| --- | --- | --- |
| ADMIN | ALL | 迁移为 SUPER_ADMIN 后看全部数据。 |
| MARKET | SELF 或 CUSTOMER | 市场专员通常看本人或指定客户数据；市场主管可按部门、子部门或指定客户扩展。 |
| ENGINEER | DEPT 或 CUSTOM | 工程核价员通常看本部门或指定订单/客户范围；工程主管可看本部门及子部门。 |

订单数据权限依赖 `created_by`、`owner_user_id`、`owner_dept_id` 等归属字段；新导入或迁移订单必须保证归属信息可追溯。

## 7. 当前验收基线

- 权限编码唯一。
- 旧 `@RequireRole` 迁移清单保留可追溯记录，主代码不再新增 `@RequireRole`。
- 前端每个受保护路由都出现在路由权限表中。
- 每个左侧可点击入口都有独立 `MENU` 权限。
- 菜单显示快照与独立 `MENU` 权限保持一致。
- 登录、强制改密、禁用用户、旧密码升级等现有行为被测试保护。

## 8. 新页面权限开发清单

开发者新增左侧可点击页面时，必须同步完成：

1. 新增一个稳定的 `MENU` 权限编码。
2. 在后端权限目录中设置 `route_path`、`component_key`、`visible`、`sort_order` 和父子关系。
3. 在前端路由中配置同一个 `meta.permission`。
4. 在 `App.vue` 菜单元数据中使用同一个权限编码。
5. 如果页面有导入、导出、删除、重置、保存等动作，新增对应 `BUTTON` / `API` 权限并挂到模块下面。
6. 如果页面需要选择客户、选择订单、文件预览或任务查看，新增页面所属模块的基础能力权限，不直接使用新的可分配 `common:*`。
7. 补充前后端权限测试，并同步更新本文档。
