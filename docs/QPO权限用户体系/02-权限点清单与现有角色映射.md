## 2. 冻结权限编码目录

权限编码采用“模块:资源:动作”格式。下表是当前稳定权限目录，每个编码必须唯一。

### 2.1 授权树展示规则

角色授权页不再按平铺 checkbox 展示权限，而是按“市场 / 订单 / 工程 / 系统”分组，再展开到可点击模块和模块内权限。

| 权限类别 | 管理员看到的位置 | 解决的问题 |
| --- | --- | --- |
| 模块权限 `MENU` | 授权树的模块节点，也是左侧可点击入口 | 决定用户能不能看到并进入某个模块。每个左侧入口必须有独立 `MENU` 权限。 |
| 按钮/动作权限 `BUTTON` / `API` | 挂在对应模块权限下面 | 决定用户进入模块后能不能执行导入、导出、删除、重置、保存等动作。 |
| 模块级基础能力 | 挂在实际使用模块下面，例如“报价处理选择订单” | 选择客户、选择订单、文件预览、查看异步任务等能力不再作为泛用 `common:*` 暴露给管理员，而是按业务场景归属到模块。 |
| 数据权限 | 角色权限的数据范围抽屉 | 决定用户在有功能权限后能看到哪些订单、客户或日志，不进入功能授权树。 |

授权保存规则：

- 勾选模块节点时，系统会勾选该模块下的子权限。
- 取消模块节点时，该模块下按钮、接口和模块级基础能力一并取消。
- 只勾选子权限时，后端保存会自动补齐父级模块 `MENU` 权限，避免“有按钮权限但进不了页面”。
- `common:customer:select`、`common:order:select` 已通过 V38 退役删除；客户/订单选择必须使用模块归属权限。
- `common:file:preview`、`common:task:view` 暂作为历史兼容权限保留，不出现在可分配授权树中。

### 2.2 订单分组独立权限

询价订单、销售订单、已提零件、锁库零件在左侧订单分组下独立授权：

| 左侧入口 | 独立权限 | 说明 |
| --- | --- | --- |
| 询价订单 | `market:order:view` | 查看当前 RFQ 询价订单、图纸、提单和工艺表状态。 |
| 销售订单 | `market:sales-order:view` | 查看独立销售订单、零件明细、提单行和工艺表状态。 |
| 已提零件 | `market:delivered-item:view` | 查看已生成提单的零件需求池和 MES / WMS 基础状态。 |
| 待产零件 | `market:production-item:view` | 查看 WMS 拆分后仍需下发 MES 生产的待产行。 |
| 锁库零件 | `market:locked-item:view` | 查看 WMS 拆分后的已入库库存锁定和在产库存锁定结果。 |
| U9同步 | `market:u9-sync:view` | 查看销售订单整单 U9 同步入口、同步列表和预览结果。 |
| 提单表据 | `market:delivery-document:view` | 查看 RFQ / 销售订单已生成提单行和动态工艺表行，只面向 `部分已提单` / `已生成提单` 订单。 |

首页看板权限收口：`首页看板` 是登录默认页，不新增 `dashboard:view` 或其他首页独立权限点。页面入口对可登录用户可见，但首页中的图表、数字和待办卡片仍按目标模块权限裁剪：询价相关入口使用 `market:order:view`、工程 / 报价 / 议价提单相关权限；销售订单相关入口使用 `market:sales-order:view`、`market:release:view`、`market:u9-sync:view`；已提零件相关入口使用 `market:delivered-item:view`；待产零件相关入口使用 `market:production-item:view`；锁库零件相关入口使用 `market:locked-item:view`。后端 `GET /api/dashboard/overview` 同样按上述目标模块权限和数据权限裁剪统计数量，不能只依赖前端隐藏。

因此，角色拥有 `market:order:view` 但没有 `market:sales-order:view`、`market:delivered-item:view`、`market:production-item:view` 或 `market:locked-item:view` 时，左侧只显示询价订单；反过来，拥有销售订单、已提零件、待产零件或锁库零件权限但没有订单数据范围时，页面列表为空而不是报错。旧 `market:history-order:*` 仅作为历史兼容权限保留，不再作为可见菜单，也不再控制新的销售订单页面。

RFQ 物料号确认字段收口不新增权限：询价订单详情中的零件物料号和物料号状态展示复用 `market:order:view`，只读展示 `item_quote_version.material_no / material_no_status`；MES 获取物料号仍由已提零件操作权限 `market:delivered-item:mes-sync` 控制。后续 RFQ U9 同步如果拆成独立模块，再按模块入口、订单选择和提交动作单独设计权限，不在本阶段提前新增。

### 2.3 已提零件独立权限

已提零件必须作为订单分组下的独立 `MENU` 权限治理，不得复用询价订单、历史订单或议价提单的查看权限。

| 授权能力 | 权限编码 | 类型 | 说明 |
| --- | --- | --- | --- |

### 2.5 议价提单权限收口

议价提单模块只保留查看、生成和模块级基础能力权限：

数据职责边界：`order_delivery_ticket` 是不可逆发布记录，也是 MES/WMS 对接需求池和工艺快照来源；QPO 内部工艺表展示/导出从 `order_delivery_ticket` 动态生成，`order_process_sheet` 已通过 V36 回填后删除。议价提单权限只控制候选零件查看和正式提单生成；生成后的表据查看和导出由提单表据权限单独控制，不提供发布后回退授权。

### 2.9 系统配置授权

- 系统配置不新增 `common:*` 权限。
- 文件存储配置写操作必须由后端 `@RequirePermission` 校验，前端隐藏按钮不能作为安全边界。
- 出站接口/数据中心配置写操作必须由后端 `@RequirePermission` 校验，前端隐藏按钮不能作为安全边界。
- `system:config:integration:*` 只授权页面维护、测试、激活、停用数据中心连接配置、功能接口配置和旧直连 fallback 配置；不授予 MES/WMS/U9 业务操作权限，业务入口仍使用各自模块权限。
- **U9配置** tab 是系统配置下针对 U9 组织编码的聚焦维护入口，只复用 `system:config:integration:update` 作为保存权限，不暴露 U9 测试、激活、停用或直连参数维护；不新增 U9 组织编码专用权限点，也不改变 U9 同步、客户同步或销售订单业务权限。
- 入站接口配置写操作必须由后端 `@RequirePermission("system:config:inbound:update")` 校验；生成或轮换 QPO 入站开放接口统一 token 必须由 `@RequirePermission("system:config:inbound:token-rotate")` 校验。
- MES 回调、销售订单外部同步等入站开放接口本身不走用户权限树，使用 QPO 入站开放接口统一 token 校验；入站接口配置权限只负责治理统一 token、接口启停和可对外提供的接口 URL。
- MES/U9 运行时优先读取页面激活的 DB 配置；没有 active DB 配置时才回退到 `erp.env` 中的 `ERP_MES_*`、`ERP_U9_*`。WMS 库存锁库运行时只走数据中心 `WMS_INVENTORY_ALLOCATE`，使用 `ERP_DATA_CENTER_WMS_ALLOCATION_PATH` 作为 endpoint path fallback。
- 页面激活配置互斥按系统维度生效，同一系统同一时间只允许一条 active 配置；变更页面配置不需要重启 backend。
- U9、MES、WMS 的 token、secret、认证参数和完整外部请求体不得进入权限文档、操作日志、文件日志或前端缓存。
- 数据中心配置使用 `system_data_center_config` 保存连接配置，使用 `system_data_center_endpoint_config` 保存功能接口配置；默认功能编码包含 `MES_MATERIAL_RESOLVE`、`WMS_INVENTORY_ALLOCATE`、`U9_SALES_ORDER_SYNC` 和 `MES_PRODUCTION_DISPATCH`，且继续复用 `system:config:integration:*` 权限，不新增 `common:*` 或数据中心专用权限。
- MinIO access secret、token、连接密码不得进入权限文档、操作日志、文件日志或前端缓存。
- 存储策略切换只影响新上传文件；历史文件依赖文件对象元数据定位实际存储位置。

### 2.10 销售订单导入自动快照补全

原手工异常治理模块已退役，不再提供独立左侧入口、订单级预览、手工确认或图纸预览权限。销售订单导入自动快照补全保留为导入事务内部步骤：导入销售订单时根据 `图号 + 版本` 查找历史已提 RFQ 生产快照，只补齐销售订单零件缺失的生产快照、MES 已确认物料号和组合件关系状态，不创建 RFQ，不进入手工工作台。

治理口径：

- 自动快照补全继续由 `market:rfq:import-sales-order` 覆盖，不新增独立 `MENU`、`BUTTON` 或 `API` 权限。
- 补全服务由后端导入事务内部调用，不向前端暴露手工预览或手工确认接口。
- 数据权限仍由销售订单导入链路和销售订单数据范围兜底，不能通过构造销售订单 ID 越权补全。
- 不新增可分配 `common:*` 权限；客户选择、订单选择和图纸预览仍按实际页面归属到销售订单、U9同步、提单表据或已提零件模块。
- 预览类读接口不因自动补全产生操作日志；导入确认日志只记录摘要，不记录完整 Excel、token、Authorization header、完整请求体或响应体。

- 导入模板带入的 `sales_order_item.material_no` 默认仍为 `material_no_status = 未确认`，不得直接作为 U9 正式物料号。

### 2.12 销售变更模块权限

销售变更入口位于“变更”一级分组，路由为 `/sales-order-change`，组件为 `SalesOrderChangeManage`。第一阶段只提供已同步 U9 销售订单的列表和只读预览，后续保存与表格替换继续沿用该权限域扩展，不复用 `market:u9-sync:submit`，避免把本地校正误认为二次同步 U9。

| 授权能力 | 权限编码 | 类型 | 推荐默认角色 | 说明 |
| --- | --- | --- | --- | --- |
| 销售变更 | `change:sales-order:view` | `MENU` | `SUPER_ADMIN`, `MARKET_USER`, `MARKET_MANAGER`, `READONLY` | 控制左侧“变更 > 销售变更”入口、路由和只读预览。 |
| 销售变更选择客户 | `change:sales-order:customer-select` | `API` | `SUPER_ADMIN`, `MARKET_USER`, `MARKET_MANAGER`, `READONLY` | 控制销售变更页客户筛选 / 选择能力。 |
| 销售变更选择订单 | `change:sales-order:order-select` | `API` | `SUPER_ADMIN`, `MARKET_USER`, `MARKET_MANAGER`, `READONLY` | 控制销售变更页已同步销售订单选择能力。 |
| 保存销售变更 | `change:sales-order:update` | `BUTTON` | `SUPER_ADMIN`, `MARKET_USER`, `MARKET_MANAGER` | 控制后续行内保存和表格替换确认；`READONLY` 不授予。 |

治理口径：

- 列表固定只返回 `sales_order_header.u9_sync_status = 已同步` 的销售订单。
- 数据范围继续复用销售订单数据权限；没有订单数据范围时返回空列表，不泄露其他客户订单。
- 行内保存和表格替换确认均使用 `change:sales-order:update`，不新增 `common:*` 权限，也不把本地校正权限混入 `market:u9-sync:submit`。
- 销售变更不调用 U9 / MES / WMS；保存后 `u9_sync_status` 继续保持 `已同步`，用于表示该订单仍是“U9 已处理，本地追平”。
- U9 同步前零件行字段编辑仍由 `market:u9-sync:submit` 控制，销售变更权限不能替代 U9 同步模块的提交流程权限。
- 只读列表和预览不写操作日志，不调用 U9 / MES / WMS。
- 不新增可分配 `common:*` 权限，也不复用 U9 同步提交权限。

## 6. 当前数据权限默认范围参考

QPO 订单会跨市场、工程、系统管理等角色连续流转，不推荐把订单主流程按部门隔离。功能权限决定用户能进入哪些模块、能执行哪些动作；数据范围只决定用户在这些模块中能看到哪些订单、客户或日志。

### 6.1 推荐数据范围

| 角色类型 | 推荐数据范围 | 说明 |
| --- | --- | --- |
| 超级管理员 | `ALL` | 拥有全部功能和全部数据。 |
| 市场主管 | `ALL` 或 `CUSTOMER` | 管理全部市场订单时用 `ALL`；只负责部分客户时用 `CUSTOMER`。 |
| 市场人员 | `CUSTOMER` | 推荐按负责客户配置；临时过渡账号可用 `SELF`。 |
| 工程核价员 | 通常 `ALL` | 工程需要看到市场导入的待核价订单，建议由功能权限限制其只能做工程动作。 |
| 只读客户账号 | `CUSTOMER` | 只看指定客户订单，可配合只读功能权限使用。 |
| 临时账号 | `SELF` | 只看当前用户导入/创建相关订单；当前兼容 `created_by OR owner_user_id`。 |
| 系统配置账号 | `NONE` | 只做系统配置，不看业务订单。 |

### 6.2 已下线范围

`DEPT`、`DEPT_AND_CHILD`、`CUSTOM` 部门类数据范围已从角色权限配置入口、保存接口和订单数据范围执行逻辑中下线。历史角色如仍存在这些旧值，会通过迁移转为 `ALL`，并清理部门范围关联。

### 6.3 多角色并集规则

同一用户绑定多个角色时，数据范围取并集而不是交集。例如一个角色配置 `CUSTOMER = 客户编码 C001`，另一个角色配置 `CUSTOMER = 客户编码 C002`，最终可见客户为 C001 或 C002 对应订单。同名客户必须按 U9 客户编码区分，不能按客户名称合并授权。

### 6.4 配置示例

“只看指定客户但能走报价处理”的角色应这样配置：

1. 功能权限：勾选 `market:quote-process:view`、`market:quote-process:customer-select`、`market:quote-process:order-select`，按职责再勾选 `market:quote-process:update-lead-time`、`market:quote-process:save-quote`、`market:quote-process:export`；`market:quote-process:update-lead-time` 同时覆盖报价交期单项保存、保存修改、批量调整和表格数据替换。
2. 数据权限：选择 `CUSTOMER`，在客户多选中勾选该角色负责的 U9 客户编码。
3. 角色权限不再提供部门数据范围配置，避免把同一客户订单按部门错误切开。

订单数据权限当前依赖 `created_by`、`owner_user_id`、`customer_code` 等归属字段；新导入或迁移订单必须保存 U9 客户编码和客户名称快照，后续提单、已提零件、待产、锁库、MES/WMS 等页面通过来源 RFQ 或销售订单回溯客户编码。

## 7. 当前验收基线

- 权限编码唯一。
- 旧 `@RequireRole` 迁移清单保留可追溯记录，主代码不再新增 `@RequireRole`。
- 前端每个受保护路由都出现在路由权限表中。
- 每个左侧可点击入口都有独立 `MENU` 权限。
- 菜单显示快照与独立 `MENU` 权限保持一致。
- 登录、禁用用户、旧密码升级等现有行为被测试保护；QPO 不再设置首次登录或重置密码后的改密阻断。

## 8. 新页面权限开发清单

开发者新增左侧可点击页面时，必须同步完成：

1. 新增一个稳定的 `MENU` 权限编码。
2. 在后端权限目录中设置 `route_path`、`component_key`、`visible`、`sort_order` 和父子关系。
3. 在前端路由中配置同一个 `meta.permission`。
4. 在 `App.vue` 菜单元数据中使用同一个权限编码。
5. 如果页面有导入、导出、删除、重置、保存等动作，新增对应 `BUTTON` / `API` 权限并挂到模块下面。
6. 如果页面需要选择客户、选择订单、文件预览或任务查看，新增页面所属模块的基础能力权限，不直接使用新的可分配 `common:*`。
7. 补充前后端权限测试，并同步更新本文档。

## 9. 销售订单独立主表导入权限口径

销售订单独立主表导入是市场 `新单导入` 页面下销售订单子入口的新阶段能力，不新增左侧模块。导入动作仍沿用 `market:rfq:import-sales-order`，挂在 `market:rfq:view` 下，后端接口必须独立校验该权限，不能复用 `market:rfq:import`。

阶段边界：销售订单导入不再创建 QPO `order_rfq`，不再创建 QPO `item_quote_version`，而是写入独立 `sales_order_header` 和 `sales_order_item`；当前页面统一调用 `/api/market/sales-orders/import-qpo`，操作日志动作使用 `SALES_ORDER_IMPORT_QPO`。旧 Excel 直连 U9 导入接口 `/api/market/sales-orders/import` 已下线；销售订单同步 U9 改由销售订单 U9 同步模块承担。

U9 同步独立模块口径：销售订单导入、模板下载仍沿用 `market:rfq:import-sales-order`；后续 U9 整单同步入口改为独立 `market:u9-sync:*`。同步请求从 `sales_order_header` / `sales_order_item` 组装，`OrderBy` 使用客户主数据 `customer_code` 快照，`DocumentType` 使用页面 `document_type_code`，`ItemCode` 使用 `sales_order_item.material_no` 且必须满足 `material_no_status = 已确认`，`FinallyPriceTC` 使用 `sales_order_item.untaxed_unit_price`。操作日志动作使用 `SALES_ORDER_U9_SYNC`、`SALES_ORDER_U9_ASSIGNMENT_UPDATE`、`SALES_ORDER_U9_RECONCILE` 和 `U9_SYNC_OPTIONS_REFRESH`，模块为 `MARKET`，销售订单动作 `targetType` 为 `sales_order_header`，选项缓存刷新 `targetType` 为 `u9_master_data_sync_run`；摘要只记录订单数、成功/失败数、销售订单号样本、U9 编码样本、Seller/部门编码、核对结果码、同步批次数量和耗时，不记录 token、密钥、完整 U9 请求或完整响应。

## 9.1 销售订单管理模块权限口径

销售订单管理入口位于订单分组，路由为 `/sales-orders`，组件为 `SalesOrderManage`，查看权限为 `market:sales-order:view`。该模块只读取销售订单独立主表链路，后续业务接口以 `sales_order_header` / `sales_order_item` 为主数据源，不把销售订单映射回 RFQ 主表。旧 `/history-orders` 只作为兼容入口跳转到 `/sales-orders`，旧 `market:history-order:*` 不再作为可见菜单，也不再控制销售订单新页面。
阶段 5 收口：前端 `HistoryOrderManage.vue` 已删除，`orderApi.deleteOrder` 与 `history-order` 客户选择范围已移除；V72 将 `market:history-order:*` 和 `market:order:delete` 标记为不可分配的兼容权限；后端旧历史客户接口与物理删除接口已移除。
后端只读接口由 `controller/SalesOrderManageController.java` 承载，路径为 `/api/market/sales-order-management`；订单列表和零件分页读取 `sales_order_header` / `sales_order_item`，提单行和工艺表行查询固定使用 `source_type = SALES_ORDER` 与 `source_order_id`，不通过 RFQ 主表或询价零件表回查。

- `market:sales-order:view` 控制左侧“销售订单”入口和路由访问。
- `market:sales-order:customer-select` 控制销售订单页面客户选择。
- `market:sales-order:file-preview` 控制销售订单页面文件预览。
- `market:sales-order:supplement-drawing` 控制销售订单详情整单补传图纸，按图号自动匹配该销售订单下缺图零件。
- `market:sales-order:discard` 控制 `已生成提单` 且 U9 未同步成功的销售订单废弃。
- `market:sales-order:restore` 控制废弃销售订单恢复为 `已生成提单`。

## 10. 手工销售匹配模块退役口径

旧手工销售匹配 / 异常治理入口已退役。运行时不再提供独立菜单、前端路由、手工预览 API 或手工确认 API；已安装环境通过后续迁移删除旧角色授权和菜单记录，新建环境不得重新暴露旧入口。

保留的数据结构和自动能力：

- `sales_order_item.assembly_relation_status` 继续展示组合件父子关系状态。
- `sales_order_item_assembly_relation` 继续保存销售订单组合件父子关系，只引用 `sales_order_item.id`，不得引用或写入 RFQ `item_assembly_relation`。
- 销售订单导入自动快照补全仍在导入事务中执行，权限边界是 `market:rfq:import-sales-order` 和销售订单数据范围。
# RFQ 派生销售订单与 U9 收口说明

RFQ 议价提单派生销售订单复用现有 `market:release:*`、`market:delivered-item:*`、`market:sales-order:view` 和 `market:u9-sync:*` 权限及其数据范围。本次不新增可分配权限、不新增 `common:*` 权限，派生来源不会改变原有权限 code 或客户数据范围。

页面跳转按钮只受目标模块查看权限控制；后端接口权限和数据范围仍是最终边界。普通订单、客户、提单、U9 选项读取和 U9 预览读取不记操作日志。
