# QPO 角色权限数据范围优化开发文档

**Goal:** 角色权限的数据范围只保留 QPO 当前真正使用的四类范围：`ALL`、`CUSTOMER`、`SELF`、`NONE`。删除部门类高级兼容配置，避免管理员误把跨部门流转订单切成部门资产。

**Architecture:** 功能权限决定“能不能进模块/能不能执行动作”，数据范围决定“进入已授权模块后能看到哪些订单、客户和日志”。QPO 订单跨市场、工程、系统管理流转，因此角色权限不再支持 `DEPT`、`DEPT_AND_CHILD`、`CUSTOM` 部门范围配置。

## Global Constraints

- QPO 订单主流程不按部门隔离。
- 客户范围是 QPO 订单数据隔离的主推荐方式。
- 部门字段仅保留为组织属性、日志展示和未来统计，不作为角色数据范围配置项。
- `SELF` 产品口径为“当前用户导入/创建的订单”；后端当前仍兼容 `created_by OR owner_user_id`。
- 多角色数据范围取并集，不做交集收窄。
- 不新增可分配的 `common:*` 权限。

## 当前可配置范围

| 范围类型 | 编码 | 推荐用途 | 配置项 |
| --- | --- | --- | --- |
| 全部数据 | `ALL` | 超级管理员、总经理、跨部门业务负责人 | 无 |
| 指定客户 | `CUSTOMER` | 市场人员、大客户负责人、只负责部分客户的用户 | 客户多选 |
| 仅本人 | `SELF` | 临时账号、试用人员、只看自己导入订单的人员 | 无 |
| 无数据 | `NONE` | 只做系统配置、账号管理、不看业务订单的角色 | 无 |

## 已下线范围

以下部门类范围已从角色权限 UI、前端 API、后端保存白名单和订单数据范围执行逻辑中下线：

| 历史范围 | 编码 | 当前处理 |
| --- | --- | --- |
| 本部门 | `DEPT` | Flyway 迁移转为 `ALL` |
| 本部门及子部门 | `DEPT_AND_CHILD` | Flyway 迁移转为 `ALL` |
| 指定部门 | `CUSTOM` | Flyway 迁移转为 `ALL`，并清理部门范围关联 |

历史表 `system_role_data_scope_dept` 暂保留数据库兼容，避免破坏旧迁移链路，但角色权限不再读取、展示或保存部门范围。

## 实现要求

### 前端

- `SystemRoleManage.vue` 只展示 `ALL`、`CUSTOMER`、`SELF`、`NONE`。
- 选择 `CUSTOMER` 时才显示客户多选。
- 选择 `ALL`、`SELF`、`NONE` 时不显示任何额外配置。
- 不再导出或调用 `listDataScopeDepartments()`。
- 源码扫描测试要求页面不包含“高级/兼容配置”、部门树和部门范围编码。

### 后端

- `SystemRoleService` 只允许保存 `ALL`、`CUSTOMER`、`SELF`、`NONE`。
- `assignDataScope()` 遇到 `DEPT`、`DEPT_AND_CHILD`、`CUSTOM` 返回业务错误。
- 保存任意数据范围时清理历史 `system_role_data_scope_dept` 关联。
- `DataScopeService` 订单范围只按 `ALL`、`CUSTOMER`、`SELF`、`NONE` 执行。
- `/api/system/data-scope/departments` 不再作为角色权限选项接口暴露。

### 迁移

- `V39__retire_department_data_scopes.sql` 将历史部门范围角色转为 `ALL`。
- 同一迁移清空 `system_role_data_scope_dept`。

## 管理员配置建议

| 角色类型 | 建议数据范围 | 说明 |
| --- | --- | --- |
| 超级管理员 | `ALL` | 全部功能、全部数据。 |
| 市场主管 | `ALL` 或 `CUSTOMER` | 管全部订单用 `ALL`；管部分客户用 `CUSTOMER`。 |
| 市场人员 | `CUSTOMER` | 推荐按负责客户授权。 |
| 工程核价员 | 通常 `ALL` | 工程需要看到市场导入订单，由功能权限限制其只能做工程动作。 |
| 只读客户账号 | `CUSTOMER` | 配合只读功能权限使用。 |
| 临时账号 | `SELF` | 只看当前用户导入/创建相关订单。 |
| 系统配置账号 | `NONE` | 不看业务订单。 |

## 最终完成标准

- 角色权限 UI 不再出现部门范围或高级兼容配置。
- 前端不再调用部门范围选项接口。
- 后端不再接受部门范围保存请求。
- 历史部门范围数据被迁移为常用范围。
- 文档明确：QPO 订单主流程按功能权限和客户范围治理，不按部门隔离。
