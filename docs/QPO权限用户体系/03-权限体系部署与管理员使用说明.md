本文用于记录企业级权限用户体系完成后的部署检查、管理员使用方式、模块树授权规则、数据权限规则和权限编码清单维护要求。

## 1. 部署检查

### 1.1 数据库迁移

后端启动时 Flyway 会自动执行权限体系相关迁移，包括：

- 企业权限基础表：`system_user`、`system_role`、`system_permission`、`system_user_role`、`system_role_permission`、`system_dept`、`system_post` 等。
- 数据范围表：`system_role_data_scope_customer`；历史部门范围表保留数据库兼容，但不再作为角色权限配置入口。
- 订单归属字段：`order_rfq.created_by`、`order_rfq.owner_user_id`、`order_rfq.owner_dept_id`。

部署后建议检查：

```sql
SELECT COUNT(*) FROM system_user;
SELECT COUNT(*) FROM system_role;
SELECT COUNT(*) FROM system_permission;
SELECT created_by, owner_user_id, owner_dept_id FROM order_rfq LIMIT 5;
```

### 1.2 兼容说明

- `erp_user` 作为历史账号来源和备份保留，不作为新的权限配置主表。
- 新权限以 `system_user` + `system_user_role` + `system_role_permission` 为准。
- 后端主代码已移除旧 `@RequireRole` 注解，接口安全边界统一由 `@RequirePermission` 驱动。
- 前端业务页面不再依赖 `meta.roles`，菜单和路由访问由权限点驱动。
- 左侧可点击入口已经收口为独立 `MENU` 权限；例如销售订单使用 `market:sales-order:view`，提单表据使用 `market:delivery-document:view`，不再与询价订单或议价提单共用查看权限。

### 1.3 验证命令

```powershell
cd D:\QPO-Operations-Management-System\quote-backend
.\mvnw.cmd test

cd D:\QPO-Operations-Management-System\quote-frontend
npm test
npm run build
```

### 1.4 数据中心与 MES/WMS/U9/APS 配置检查

QPO 出站调用默认走数据中心：QPO 后端通过 **系统 > 系统配置 > 出站接口** 的数据中心连接配置获取 access token，再按功能接口配置调用 `MES_MATERIAL_RESOLVE`、`WMS_INVENTORY_ALLOCATE`、`U9_SALES_ORDER_SYNC`、`U9_COMMON_ENTITY_QUERY`、`MES_PRODUCTION_DISPATCH`。没有 active DB 配置或功能 path 未配置时才回退到根目录 `erp.env` 中的 `ERP_DATA_CENTER_*` fallback。MES/U9 旧直连变量仅作为 deprecated fallback；WMS 库存锁库只保留 `ERP_DATA_CENTER_WMS_ALLOCATION_PATH` endpoint fallback。真实 `ERP_DATA_CENTER_CLIENT_SECRET` 只写入真实 `erp.env` 或系统配置密文字段。

MES 主数据同步阶段 9 补充：材料工艺模块的“从 MES 同步工艺”按钮继续复用 `engineer:dict:process-manage`，“从 MES 同步材料”按钮继续复用 `engineer:dict:material-manage`。管理员无需新增角色权限，只需要确认工程主管类角色已经具备相应材料/工艺维护权限；普通核价员若只有 `engineer:dict:view`，只能查看同步后的来源、MES 类型、同步时间和单价状态，不能触发同步。

数据中心调用 QPO 的 MES 物料号回调 URL、启停和 token 由 **系统 > 系统配置 > 入站接口** 管理；调用方为数据中心，业务来源为 MES；页面未配置时才兼容 `ERP_MES_CALLBACK_TOKEN` / `ERP_MES_CALLBACK_TOKEN_ENABLED` deprecated fallback。上述 fallback 变量和后端仍需读取的 `ERP_APS_SOURCE_TOKEN` 由 `docker-compose.yml` 注入 backend 容器；`APS_ERP_*` 只作为旧本地桥接工具兼容项保留，不注入 QPO backend。保持 `ERP_` 前缀是为了兼容当前 QPO 部署体系，不代表继续使用 APS 作为新目标系统。

数据中心统一入口进入 QPO 的 SSO 登录配置由 **系统 > 系统配置 > 数据中心登录** 管理。运行时优先使用页面 active DB 配置；没有 active 配置或首次部署应急时，才回退到 `erp.env` / Compose 注入的 `ERP_AUTH_DATA_CENTER_SSO_*`。真实 `ERP_AUTH_DATA_CENTER_SSO_SHARED_SECRET` 优先在系统配置页维护，`erp.env.example` 必须保持空密钥。SSO 只把可信 `username` 换取 QPO 本地 JWT，登录后的菜单、按钮、API 和数据范围仍完全由 QPO 本地账号权限决定。

排查顺序：QPO 主动调用外部系统时，先确认 **系统 > 系统配置 > 出站接口** 是否有 active 数据中心配置和对应 endpoint path；如果没有 active 配置，再检查 Compose 注入的 `ERP_DATA_CENTER_*` fallback。MES/U9 旧直连问题再检查各自 deprecated fallback；WMS 不再检查直连配置。数据中心或外部系统调用 QPO 时，先确认 **系统 > 系统配置 > 入站接口** 顶部统一 token 是否已配置，再确认对应接口行是否启用、接口 URL 是否为调用方可访问地址；页面未配置时再检查 `ERP_MES_CALLBACK_TOKEN` deprecated fallback。数据中心入口 SSO 登录失败时，先确认 **系统 > 系统配置 > 数据中心登录** 是否有 active 且测试成功的配置，再检查 `ERP_AUTH_DATA_CENTER_SSO_*` fallback、数据中心传入的 `username` 是否存在于 QPO、账号是否启用且已配置本地权限。随后在 **系统 > 操作日志** 查看数据中心连接测试/激活记录、endpoint 测试记录、入站接口配置保存/统一 token 轮换/校验记录、数据中心 SSO 成功/失败记录、MES/WMS 任务提交记录或销售订单 U9 同步记录，再用 `taskId` / `batchId` / `externalBizId` / `saleOrderNo` / `requestId` 到 `qpo-backend.log` 和 `qpo-error.log` 关联排查。不要把 `client_secret`、access token、QPO 入站开放接口统一 token、数据中心 SSO 共享密钥、`signature`、完整 SSO URL、MES/WMS token、token hash、U9 token、`ERP_U9_CLIENT_SECRET`、Authorization header 或完整请求/响应 JSON 写入日志或文档。

## 2. 管理员使用手册

### 2.1 用户管理

用户管理负责维护“谁可以登录系统”：

- 新增或编辑账号基础信息。
- 设置账号启用/禁用。
- 重置密码。
- 给用户分配一个或多个角色。

注意：用户本身不直接配置菜单、按钮和接口权限，权限来自角色。

### 2.1.1 个人入口字段边界

右上角个人入口是登录用户的自助资料入口，不是管理员用户管理入口，也不是新的可分配权限模块。

用户本人可以在个人入口中查看登录账号、显示名或真实姓名、所属部门、岗位、角色名称、手机号和邮箱。

用户本人可以维护手机号、邮箱和登录密码；其中手机号、邮箱通过个人入口编辑，登录密码继续使用现有修改密码弹窗。

用户本人不能通过个人入口维护用户名、显示名、真实姓名、部门、岗位、角色、权限、数据范围或启用状态。这些治理属性仍由管理员在用户管理、组织档案、角色权限中维护。

治理要求：

- 个人入口查看和本人联系方式维护只要求用户已登录，不新增左侧菜单，也不新增可分配权限点。
- `PUT /api/auth/me/profile` 只能更新当前登录用户自己的 `phone`、`email`，不能复用管理员 `system:user:update` 权限。
- QPO 不再设置首次登录或重置密码后的改密阻断；账号启用且具备权限即可使用，个人资料编辑按普通登录态处理。
- 本人联系方式更新写入操作日志 `USER_PROFILE_UPDATE`，记录 `phone`、`email` 的 before/after 摘要；不得记录密码、token、Authorization header 或 Cookie。

### 2.2 角色权限

角色权限负责维护“这个人登录后能做什么、能看哪些数据”：

- 角色基础信息：角色编码、角色名称、说明、启用状态。
- 功能授权：按模块树勾选菜单、按钮、接口和模块级基础能力权限点。
- 数据范围：配置角色可见的业务数据。

禁用角色后，该角色不会再给用户贡献功能权限或数据权限。

### 2.3 数据范围配置

角色支持以下数据范围：

| 编码 | 含义 | 适用场景 |
| --- | --- | --- |
| `ALL` | 全部数据 | 超级管理员、总经理等 |
| `CUSTOMER` | 指定客户数据 | 市场人员、大客户负责人、只读客户账号 |
| `SELF` | 当前用户导入/创建相关订单 | 临时账号、试用账号 |
| `NONE` | 无业务数据 | 只允许看系统配置或空列表 |

角色权限的数据范围抽屉中：

- QPO 订单跨市场、工程流转，角色权限只保留 `ALL`、`CUSTOMER`、`SELF`、`NONE` 四类数据范围。
- 指定客户使用 U9 客户下拉多选，保存并按 U9 客户编码匹配；客户名称只作为展示快照，同名不同编码客户不会合并。
- 多角色用户的数据范围取并集。
- 超级管理员角色默认拥有全部功能和全部数据。

U9 客户主数据与同步选项缓存阶段 8 收口 + 供应商代码补充：客户资料读取和同步 U9 客户缓存，不允许新增、完整编辑或删除客户；仅允许通过 `system:customer:supplier-code-update` 维护 QPO 本地字段 `supplierCode`。不要寻找或新建销售部门/销售员管理菜单；Seller / SaleDepartment 只在 U9 同步页作为缓存选项使用。刷新 U9 选项缓存、保存 Seller / SaleDepartment、同步和核对均复用 `market:u9-sync:submit`。后端权限和客户编码数据范围是最终边界，不能依赖前端隐藏按钮或客户名称过滤来兜底。

客户编码切换部署顺序：先备份数据库；执行 `docs/ops/sql/clear_order_business_data_before_u9_customer_cutover.sql`；部署后端并执行 Flyway V6/V7；同步 U9 客户缓存和 U9 同步选项缓存；按 U9 客户编码重新配置角色数据范围；部署前端后再执行全量回归。

默认角色建议：

| 角色类型 | 建议数据范围 | 说明 |
| --- | --- | --- |
| 超级管理员 | `ALL` | 看全部数据。 |
| 市场主管 | `ALL` 或 `CUSTOMER` | 管全部订单用 `ALL`；管部分客户用 `CUSTOMER`。 |
| 市场人员 | `CUSTOMER` | 推荐按负责客户授权。 |
| 工程核价员 | 通常 `ALL` | 工程需要看到市场导入订单，由功能权限限制其只能做工程动作；不按部门隔离。 |
| 只读客户账号 | `CUSTOMER` | 配合只读功能权限使用。 |
| 临时账号 | `SELF` | 只看当前用户导入/创建相关订单。 |
| 系统配置账号 | `NONE` | 不看业务订单。 |

如果要配置一个“只看指定客户但能走报价处理”的角色：

1. 在功能授权中勾选“报价处理”模块，以及“报价处理选择客户”“报价处理选择订单”。
2. 按职责勾选“维护报价交期”“保存报价单”“导出报价单”。
3. 在数据范围中选择 `CUSTOMER`，勾选允许查看的客户。
4. 角色权限不再提供部门范围，避免部门范围和客户范围混淆。

## 3. 模块树授权说明

### 3.1 授权树层级

角色授权抽屉按业务分组展示：

```text
市场 / 订单 / 工程 / 系统
  左侧可点击模块 MENU
    按钮权限
    接口权限
    模块级基础能力
```

管理员配置角色时，建议先勾选用户应该看到的模块，再勾选模块内允许执行的动作。取消模块节点会取消该模块下所有子权限；只勾选子权限时，后端保存会自动补齐父模块 `MENU` 权限。

### 3.2 四类权限的区别

| 类型 | 解决的问题 | 示例 |
| --- | --- | --- |
| 模块权限 | 能不能看到左侧入口、能不能进入页面 | `market:quote-process:view`、`market:sales-order:view`、`market:delivered-item:view` |
| 按钮/动作权限 | 进入页面后能不能执行关键动作 | `market:quote-process:save-quote`、`market:quote-process:export`、`market:release:create` |
| 模块级基础能力 | 页面内选择客户、选择订单、预览文件、查看任务等复用能力 | `market:release:order-select`、`engineer:setup:file-preview`、`market:delivered-item:file-preview` |
| 数据权限 | 有功能权限后能看到哪些订单、客户、日志 | `ALL`、`CUSTOMER`、`SELF`、`NONE` |

公共能力优先按模块归属展示。管理员不会在授权树里看到泛用 `common:*` 权限；同一个“选择订单”动作会按实际页面拆成“报价处理选择订单”“议价提单选择订单”“零件核价选择订单”等模块级权限。

### 3.3 销售订单独立授权

销售订单是订单分组下的独立左侧入口，必须单独授权：

- 勾选“询价订单”只授予 `market:order:view`，不会自动显示销售订单。
- 勾选“销售订单”授予 `market:sales-order:view`，左侧才显示销售订单。
- 销售订单页面的客户选择由 `market:sales-order:customer-select` 控制，文件预览由 `market:sales-order:file-preview` 控制。
- 销售订单补传图纸、废弃、恢复、导出生产任务通知单分别由 `market:sales-order:supplement-drawing`、`market:sales-order:discard`、`market:sales-order:restore`、`market:sales-order:production-task-notice-export` 控制。
- 有销售订单功能权限但没有订单数据范围时，页面正常打开但列表为空。
- 旧 `/history-orders` 只作为兼容入口跳转到 `/sales-orders`，旧 `market:history-order:*` 不再作为可见菜单，也不再控制销售订单新页面。

### 3.4 已提零件与锁库零件独立授权

已提零件和锁库零件都是 **订单** 分组下的独立左侧入口。已提零件用于查看 `order_delivery_ticket` 需求池并承载 MES/WMS 操作按钮；锁库零件用于查看 `order_delivery_ticket_allocation` 拆分结果。两者不等同于询价订单或议价提单，必须单独授权。

| 授权节点 | 权限编码 | 管理员效果 |
| --- | --- | --- |
| 已提零件 | `market:delivered-item:view` | 左侧显示“已提零件”，允许分页查看已生成提单的零件需求池和详情。 |
| 已提零件选择客户 | `market:delivered-item:customer-select` | 允许在已提零件页面打开客户选择弹窗并按客户筛选。 |
| 已提零件预览图纸 | `market:delivered-item:file-preview` | 在已提零件页面打开已绑定图纸；该能力归属已提零件模块，不使用 `common:file:preview` 授权。 |
| 获取MES物料号 | `market:delivered-item:mes-sync` | 在已提零件页面显示“获取物料号 / 重试”按钮，允许提交 `MES_MATERIAL_SYNC` 后台任务。 |
| 提交WMS锁库 | `market:delivered-item:wms-allocate` | 在已提零件页面显示“提交WMS锁库 / 重试WMS”按钮，允许提交 `WMS_ALLOCATION_BATCH` 后台任务。 |
| 待产零件 | `market:production-item:view` | 左侧显示“待产零件”，允许分页查看 WMS 拆分后仍需下发 MES 生产的待产行。 |
| 待产零件选择客户 | `market:production-item:customer-select` | 允许在待产零件页面打开客户选择弹窗并按客户筛选。 |
| 待产零件下发MES生产 | `market:production-item:mes-production-submit` | 在待产零件页面显示“下发MES生产”按钮，允许把待生产 allocation 行手动提交给 MES 生产流程。 |
| 锁库零件 | `market:locked-item:view` | 左侧显示“锁库零件”，允许分页查看 WMS 拆分后的库存锁定和在产锁定结果。 |
| 锁库零件选择客户 | `market:locked-item:customer-select` | 允许在锁库零件页面打开客户选择弹窗并按客户筛选。 |
配置建议：

- 市场主管如负责 MES/WMS 流转，建议勾选“已提零件”“已提零件选择客户”“已提零件预览图纸”“获取MES物料号”“提交WMS锁库”“待产零件”“待产零件选择客户”“待产零件下发MES生产”“锁库零件”“锁库零件选择客户”。
- 市场人员如参与外部系统流转，可与市场主管一致；如只负责跟单查看，只勾选“已提零件”“已提零件预览图纸”“待产零件”“锁库零件”。
- 只读客户账号只建议勾选“已提零件”“已提零件选择客户”“已提零件预览图纸”“待产零件”“待产零件选择客户”“锁库零件”“锁库零件选择客户”，不授予 MES/WMS 操作按钮，也不授予 `market:production-item:mes-production-submit`。
- 只允许查看需求池但不需要打开图纸时，只勾选 `market:delivered-item:view`。
- 需要在已提零件、待产零件或锁库零件页面使用客户选择弹窗时，分别额外勾选 `market:delivered-item:customer-select`、`market:production-item:customer-select`、`market:locked-item:customer-select`。
- 需要把已提零件发送给 MES 获取物料号时，额外勾选 `market:delivered-item:mes-sync`。
- 需要把已提零件发送给 WMS 锁库拆分时，额外勾选 `market:delivered-item:wms-allocate`。
- 需要查看 WMS 拆分结果时，勾选 `market:locked-item:view`；它只控制锁库零件页面，不反向授予 WMS 提交能力。
- 需要把待产零件下发给 MES 生产时，额外勾选 `market:production-item:mes-production-submit`；它只控制生产下发，不反向授予 MES 物料号获取或 WMS 锁库能力。
- 页面里 `PENDING` 行显示“获取物料号”，`FAILED` 行显示“重试”，`PROCESSING` 行不可重复提交，`SUCCESS` 行不显示提交按钮。
- 有功能权限但没有数据范围时，页面正常打开但列表为空；数据范围仍按订单客户等归属控制。

### 3.5 订单状态管理授权

询价订单状态管理能力放在 **询价订单** 模块下，不新增左侧入口。管理员应先勾选 `market:order:view`，再按职责授予下列按钮权限：

| 权限 | 页面按钮 | 允许状态 | 治理边界 |
| --- | --- | --- | --- |
| `market:order:rollback-quoted` | 退回已核价 | `已报价` | 只改状态，不清空报价交期、核价结果或图纸。 |
| `market:order:rollback-priced` | 退回未核价 | `已核价` | 只改状态，已录入核价数据保留为草稿。 |
| `market:order:discard` | 废弃 | `未核价` / `已核价` / `已报价` | 停止继续流转但保留业务数据。 |
| `market:order:restore` | 恢复为已核价 | `废弃` | 恢复后仍按报价处理、导出、提单的业务校验继续流转。 |

注意：

- `部分已提单` / `已生成提单` 不显示废弃或回退入口；只要订单存在 `order_delivery_ticket` 提单行，后端也会拒绝废弃或回退。
- 状态动作会写入 **系统 > 操作日志**，动作分别为 `ORDER_STATUS_ROLLBACK_QUOTED`、`ORDER_STATUS_ROLLBACK_PRICED`、`ORDER_DISCARD`、`ORDER_RESTORE`。
- 文件日志可通过操作日志详情中的 requestId 反查 `Order status change started/completed/rejected/failed`。

### 3.6 议价提单与提单表据授权收口

议价提单模块只提供查看和生成权限，不再提供回退权限：

- 勾选“议价提单”授予 `market:release:view`，用户可以进入生成页面查看候选零件并维护生成前参数；已生成表据不再在该页面展示。
- 勾选“生成提单”授予 `market:release:create`，用户可以按剩余可提数量新增不可逆提单记录，并可在生成前修改单行候选零件版本、导入替换当前已选订单范围内的图纸。
- 多订单选择只是议价提单生成页面的能力扩展：查看批量候选零件继续使用 `market:release:view`，选择订单继续使用 `market:release:order-select`，跨订单导入匹配和按订单分组生成继续使用 `market:release:create`，不需要新增批量提单权限。
- 版本修改和导入替换图纸不拆独立授权点：不新增 `market:release:update-version` / `market:release:replace-drawing`。只读账号不授予 `market:release:create` 时，只能查看候选和选择订单，不能保存版本、替换图纸或生成提单。
- 勾选“U9同步”授予 `market:u9-sync:view`，用户可以进入销售订单 U9 同步页面查看销售订单列表、同步状态和预览结果。
- 勾选“同步U9”授予 `market:u9-sync:submit`，用户才可以提交销售订单整单 U9 同步；只读账号默认只授予查看、选择客户和选择销售订单，不授予提交。
- U9同步的 `market:u9-sync:customer-select`、`market:u9-sync:order-select` 只负责该页面的客户和销售订单选择，不继承新单导入或议价提单的选择权限。
- 勾选“提单表据”授予 `market:delivery-document:view`，用户可以进入只读表据页面查看 RFQ / 销售订单中 `部分已提单` / `已生成提单` 订单的提单行和动态工艺表行；导出必须单独勾选 `market:delivery-document:export`。
- 提单表据的 `market:delivery-document:customer-select`、`market:delivery-document:order-select` 只负责该页面的客户和订单选择，不继承议价提单的选择权限；订单选择接口只返回 RFQ / 销售订单中 `部分已提单`、`已生成提单`，并返回 `sourceType`、`sourceOrderId`、`sourceOrderNo`。
- 只读账号可以授予提单表据查看和选择客户/订单权限，但默认不授予 `market:delivery-document:export`；市场主管和市场人员按职责授予导出权限。
- `market:release:reset` 已废弃，不应出现在授权树、默认角色或新增权限申请中。
- 已生成提单行和已生成工艺表行只读；如果业务数据确需调整，应通过新的受控业务流程处理，而不是删除或重置历史发布记录。
- 数据职责边界：`order_delivery_ticket` 是不可逆发布记录，也是 MES/WMS 对接需求池和工艺快照来源；QPO 内部工艺表展示和导出从 `order_delivery_ticket` 动态生成，`order_process_sheet` 已通过 V36 回填后删除。议价提单负责生成，提单表据负责按 `source_type` / `source_order_id` 查看和导出生成后的 RFQ / 销售订单表据。

### 3.7 组织档案授权

组织档案用于维护用户身份字典，包含部门管理和岗位管理。它解决“用户属于哪个组织、担任什么岗位”的问题，不替代角色，也不作为订单数据范围。

授权树中组织档案建议这样理解：

| 节点 | 权限 | 管理员效果 |
| --- | --- | --- |
| 组织档案 | `system:org:view` | 左侧显示组织档案入口，并允许进入页面。 |
| 部门管理 | `system:dept:view` | 可以查看部门树和部门状态。 |
| 维护部门 | `system:dept:manage` | 可以新增、编辑、启停、删除部门。 |
| 岗位管理 | `system:post:view` | 可以查看岗位列表和岗位状态。 |
| 维护岗位 | `system:post:manage` | 可以新增、编辑、启停、删除岗位。 |

注意：部门、岗位只是用户组织身份属性。QPO 订单跨市场、工程和系统治理流转，角色权限里不再提供部门数据范围；订单可见性仍由 `ALL`、`CUSTOMER`、`SELF`、`NONE` 控制。

## 4. 常见角色配置示例

### 4.1 市场只读

适用于只查看市场流程、不做导入、删除、导出和提单动作的人员。

| 配置项 | 建议 |
| --- | --- |
| 功能权限 | 勾选新单导入、报价处理、议价提单、U9同步、提单表据、询价订单、销售订单、已提零件、锁库零件的 `view` 权限；勾选对应模块下选择客户、选择订单、文件预览、任务查看等基础能力。U9同步只勾选查看、选择客户、选择销售订单；提单表据只勾选查看、选择客户、选择订单。 |
| 不勾选 | RFQ 导入、导入销售订单、上传图纸、维护报价交期、保存报价单、导出报价单、生成提单、同步U9、删除订单兼容接口、获取MES物料号、提交WMS锁库。 |
| 数据权限 | 推荐选择 `CUSTOMER`；临时账号可选 `SELF`；只读但仍受数据范围限制。 |

### 4.2 市场主管

适用于可以处理市场主流程并查看团队或指定客户数据的负责人。

| 配置项 | 建议 |
| --- | --- |
| 功能权限 | 勾选市场全流程模块：新单导入、报价处理、议价提单、U9同步、提单表据、询价订单、销售订单、已提零件、锁库零件；按需要勾选导入 RFQ、导入销售订单、上传图纸、维护报价交期、保存报价单、导出报价单、生成提单（生成时选择订单类型）、同步U9、导出提单表据、补传图纸、销售订单补传图纸、导出生产任务通知单、废弃/恢复销售订单、已提零件预览图纸、获取MES物料号、提交WMS锁库。 |
| 谨慎授予 | 不再新授予删除订单或彻底删除类动作；`market:order:delete` 仅为旧兼容接口，V72 起从角色授权树隐藏且不可分配。 |
| 数据权限 | 推荐选择 `ALL` 或 `CUSTOMER`。 |

### 4.3 订单状态管理员

适用于少数负责处理订单流转异常的市场主管或业务管理员。

| 配置项 | 建议 |
| --- | --- |
| 功能权限 | 勾选询价订单 `market:order:view`、询价订单选择客户 `market:order:customer-select`，再勾选 `market:order:rollback-quoted`、`market:order:rollback-priced`、`market:order:discard`、`market:order:restore`。 |
| 可选权限 | 按需要勾选询价订单预览文件、补传图纸；不再授予彻底删除订单，销售订单导入自动快照补全不需要独立手工治理权限。 |
| 数据权限 | 按职责选择 `ALL` 或 `CUSTOMER`；无数据范围时即使有按钮权限也看不到可操作订单。 |
| 操作要求 | 状态管理只用于修正流转状态，不用于清空核价、报价交期、图纸、材料、工艺或提单记录。已产生提单行的订单不可废弃或回退。 |

### 4.4 工程核价员

适用于完成零件核价、逐件核价和工程字典查询的工程人员。

| 配置项 | 建议 |
| --- | --- |
| 功能权限 | 勾选零件核价、逐件核价相关权限：查看零件核价、保存全局设定、查看逐件核价、保存单件核价、一键刷新核价、完成整单报价、生成核价单、查看异步任务。 |
| 基础能力 | 勾选零件核价选择客户、选择订单、预览图纸；逐件核价查看异步任务。 |
| 字典权限 | 普通核价员只勾选材料工艺查看；工程主管再勾选维护材料、维护工艺、维护费用。 |

MES 主数据同步权限口径：

- “从 MES 同步工艺”属于工艺维护动作，复用 `engineer:dict:process-manage`。
- “从 MES 同步材料”属于材料维护动作，复用 `engineer:dict:material-manage`。
- 同步不会覆盖 QPO 材料单价；材料单价仍由材料费用页签本地维护。
- 不新增 MES 主数据同步专用的 `common:*` 权限，也不新增其他可分配公共权限。
| 数据权限 | 通常选择 `ALL`，由功能权限限制其只能做工程动作。 |

### 4.5 审计员

适用于只查看操作日志和导出审计证据的人员。

| 配置项 | 建议 |
| --- | --- |
| 功能权限 | 勾选操作日志查看；按需要勾选导出操作日志。 |
| 不勾选 | 日志保留策略配置、用户管理、角色权限、业务模块写操作。 |
| 数据权限 | 审计范围按岗位选择 `ALL`、`CUSTOMER`、`SELF` 或 `NONE`；没有数据范围时日志列表为空。 |

### 4.6 只能维护用户组织资料

适用于行政、人事或系统治理人员，只维护部门和岗位字典，不参与报价订单主流程。

| 配置项 | 建议 |
| --- | --- |
| 功能权限 | 勾选组织档案、部门管理、维护部门、岗位管理、维护岗位。 |
| 不勾选 | 用户管理、角色权限、操作日志、市场模块、工程模块、订单模块、报价处理、议价提单。 |
| 数据权限 | 推荐选择 `NONE`；组织档案维护不需要订单、客户或操作日志数据范围。 |

如果该人员还需要在用户管理中给账号选择部门和岗位，应另行授予用户管理相关权限；不要通过部门或岗位权限间接扩大角色授权。

### 4.7 系统配置运维账号

适用于只维护运行参数、不参与订单业务处理的系统运维人员。此类账号可以查看系统配置页，并按职责维护文件存储配置、出站接口/数据中心配置、入站接口配置或数据中心登录配置。

| 配置项 | 建议 |
| --- | --- |
| 功能权限 | 勾选系统配置 `system:config:view`；维护文件存储时勾选 `system:config:storage:update`、`system:config:storage:test`、`system:config:storage:activate`；维护出站接口/数据中心配置时勾选 `system:config:integration:update`、`system:config:integration:test`、`system:config:integration:activate`；维护入站接口配置时勾选 `system:config:inbound:update`、`system:config:inbound:token-rotate`；维护数据中心登录时勾选 `system:config:sso:update`、`system:config:sso:test`、`system:config:sso:activate`。 |
| 管理范围 | 出站接口/数据中心配置当前面向 QPO 调用数据中心，由数据中心转发到 U9、MES、WMS；旧直连 U9、MES、WMS 配置仅作为 fallback。入站接口配置面向数据中心调用 QPO 的回调接口。数据中心登录配置只治理数据中心统一入口 SSO 签名、跳转和启停，不授予任何 QPO 业务权限。 |
| 不勾选 | 市场模块、工程模块、订单模块、客户资料、用户管理、角色权限、操作日志导出和日志保留策略，除非该人员另有明确职责。 |
| 数据权限 | 推荐选择 `NONE`；系统配置页不需要订单、客户或日志数据范围。 |

出站接口/数据中心配置涉及数据中心地址、clientSecret、token 和旧直连 fallback 密钥等敏感信息，入站接口配置涉及 `QPO_OPEN_API_TOKEN`，数据中心登录配置涉及 SSO 共享密钥、`signature` 和跳转白名单；页面和日志都必须脱敏展示。管理员授权时不要把这类权限授给日常业务账号。
页面激活 MES/WMS/U9 配置后，业务调用立即使用页面配置；未激活任何 DB 配置时才按 `erp.env` fallback 运行。本地开发可继续只维护 `erp.env`，生产建议用页面配置做测试、激活和审计闭环。
`QPO_OPEN_API_TOKEN` 由入站接口页顶部生成后通过受控渠道交付给数据中心或外部调用方；查询页面、操作日志、文件日志和接口文档正文不得回显或记录明文 token。
数据中心 SSO 共享密钥优先在 **系统 > 系统配置 > 数据中心登录** 维护，`erp.env` 只作为首次部署或应急 fallback；查询页面、操作日志、文件日志和部署文档不得回显或记录共享密钥明文、`signature`、完整 SSO URL、QPO JWT、Authorization header 或 Cookie。

## 5. 数据权限落地范围

当前数据权限已接入以下关键业务边界：

- 询价订单列表、销售订单、订单详情、订单选择。
- 新单导入后的订单归属写入。
- 零件核价订单进入、保存全局设定、逐件核价、组合件选择。
- 报价处理、报价交期、内部目标交期。
- 议价提单生成工作台、提单表据（已生成提单行和动态工艺表行）、已提零件需求池和详情、锁库零件拆分结果。
- 订单状态管理：已报价退回已核价、已核价退回未核价、废弃、恢复。
- 报价单导出、模板报价导出、异步刷新/导出任务提交。
- 操作日志列表、详情、导出和筛选项。

无数据权限时，列表应返回空结果；直接访问无权限订单或日志详情时，后端拒绝访问。

## 6. 权限编码维护要求

权限编码采用：

```text
模块:资源:动作
```

示例：

- `market:rfq:import`
- `market:rfq:import-sales-order`
- `market:quote-process:save-quote`
- `market:quote-process:export`
- `market:order:discard`
- `market:order:restore`
- `engineer:pricing:save-item`
- `engineer:pricing:export-sheet`
- `system:role:assign-data-scope`

维护规则：

- 新增接口必须先确定权限编码。
- 后端 Controller 必须使用 `@RequirePermission`。
- 前端路由使用 `meta.permission`。
- 按钮使用 `v-permission` 或 `authStore.hasPermission()`。
- 权限编码不得重复；新增编码后同步更新 `02-权限点清单与现有角色映射.md` 和测试清单。
- 不得重新新增 `market:release:reset` 或同义回退权限；提单发布后的记录以只读追溯为准。

新增左侧可点击页面时，开发者必须同时完成：

1. 新增 `MENU` 权限编码，并设置 `route_path`、`component_key`、`visible`、`sort_order`。
2. 前端路由配置同一个 `meta.permission`。
3. `App.vue` 菜单元数据使用同一个权限编码。
4. 按钮或关键操作新增 `BUTTON` / `API` 权限并挂到模块下面。
5. 选择客户、选择订单、文件预览、任务查看等公共能力按页面所在模块新增权限，不新增可分配的 `common:*`。
6. 更新权限清单文档、角色授权树测试、路由权限测试和后端接口权限测试。

## 7. 常用排查

### 7.1 用户看不到菜单

检查顺序：

1. 用户是否启用。
2. 用户是否绑定至少一个启用角色。
3. 角色是否拥有对应菜单权限点。
4. 登录后 `/api/auth/permission-info` 是否返回该权限点。
5. 前端路由 `meta.permission` 是否与权限点一致。
6. 后端菜单树是否返回对应 `route_path`；左侧入口不再通过同权限伴随菜单兜底显示。

### 7.2 用户能进页面但列表为空

检查顺序：

1. 角色数据范围是否为 `NONE`。
2. `SELF` 范围下订单是否有 `created_by` 或 `owner_user_id`。
3. `CUSTOMER` 范围下角色是否配置了 U9 客户编码，并确认订单已保存 `customer_code` 快照。
4. 超级管理员是否能看到同一批数据，用于排除业务数据不存在。

### 7.3 接口返回 403

检查顺序：

1. 当前用户权限集合是否包含接口需要的权限点。
2. 角色是否被禁用。
3. 是否刚修改权限但前端还未刷新权限信息。
4. 后端 Controller 上的 `@RequirePermission` 是否与前端权限编码一致。

## 8. 收尾状态

- 旧 `@RequireRole` 主代码已删除。
- 旧单角色入口不再作为业务安全边界。
- `authStore.hasRole()` 仅保留兼容/超级管理员判断，不作为业务页面直接授权依据。
- `meta.roles` 已从前端业务路由移除。
- `meta.anyPermissions` 已从前端路由权限判断中移除。
- 销售订单拥有独立 `market:sales-order:view` 权限；旧 `/history-orders` 仅兼容跳转到 `/sales-orders`，旧历史订单权限不再作为可见菜单，V72 起也不再作为可分配权限。
- 角色授权已按模块树管理，公共能力优先按业务模块归属展示。
- 权限体系目标状态为：用户绑定角色，角色配置功能权限和数据权限，前端负责体验隐藏，后端负责最终安全校验。

## 9. 销售订单 U9 同步独立模块

- 销售订单导入仍在市场 `新单导入` 页面内，导入动作继续由 `market:rfq:import-sales-order` 控制。
- U9同步已经拆为独立左侧模块，查看入口由 `market:u9-sync:view` 控制，客户筛选由 `market:u9-sync:customer-select` 控制，销售订单选择由 `market:u9-sync:order-select` 控制。
- U9同步不新增权限：保存 Seller / SaleDepartment、提交销售订单整单 U9 同步和核对 U9 结果都复用 `market:u9-sync:submit`；只读账号默认不授予。
- 后端 `@RequirePermission` 与销售订单数据范围是最终边界；前端隐藏按钮只用于体验，不能替代后端校验。
- U9同步只消费 `sales_order_header` / `sales_order_item`，只有 `sales_order_item.material_no_status = 已确认` 的物料号才可作为 U9 `ItemCode`，U9 价格使用 `sales_order_item.untaxed_unit_price`。
- U9 选项读取、销售订单列表刷新和预览不写操作日志；保存选择、同步和核对分别记录 `SALES_ORDER_U9_ASSIGNMENT_UPDATE`、`SALES_ORDER_U9_SYNC`、`SALES_ORDER_U9_RECONCILE` 安全摘要。

## 10. 销售订单管理与导入授权说明

- 销售订单管理已经作为订单分组下的独立左侧模块，路由为 `/sales-orders`，查看入口由 `market:sales-order:view` 控制。
- 旧 `/history-orders` 只作为兼容入口跳转到 `/sales-orders`；旧历史订单权限不再作为可见菜单或可分配权限，销售订单页面只认 `market:sales-order:*`。
- 历史订单页面文件、前端 `deleteOrder` 调用和 `history-order` 客户范围已移除；销售订单只能废弃 / 恢复，不能物理删除订单或零件。
- 销售订单详情里的“导出生产任务通知单”由 `market:sales-order:production-task-notice-export` 控制；导出读取 `sales_order_header` / `sales_order_item` 生成固定 Excel 表单，不新增外部系统调用。
- 给市场用户开放 QPO 销售订单导入时，仍只勾选 `market:rfq:import-sales-order`；客户选择沿用 `market:rfq:customer-select`。
- 当前独立主表阶段不再创建 `order_rfq` 和 `item_quote_version`；销售订单数据写入 `sales_order_header` / `sales_order_item` 后，再由后续来源适配层进入议价提单。
- 后续 U9 同步在独立 `U9同步` 模块内授权和执行，不能把页面初始导入理解成已经完成 U9 生单。
# RFQ 派生销售订单权限收口

RFQ 议价提单派生销售订单进入 U9 不需要新增权限。管理员继续为既有议价提单、已提零件、销售订单和 U9 模块分配原权限，数据范围仍按客户和订单 scope 执行。没有目标模块查看权限时，前端只隐藏对应只读跳转，后端仍执行权限校验。
