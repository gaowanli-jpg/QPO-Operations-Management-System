# QPO 权限体系部署与管理员使用说明

版本：Stage 8.6 授权树收口版 + 报价状态流转 Stage 6 / 提单表据模块拆分版 + MES物料号同步收口版 + WMS锁库分配收口版

本文用于记录企业级权限用户体系完成后的部署检查、管理员使用方式、模块树授权规则、数据权限规则和权限编码清单维护要求。

## 1. 部署检查

### 1.1 数据库迁移

后端启动时 Flyway 会自动执行权限体系相关迁移，包括：

- 企业权限基础表：`system_user`、`system_role`、`system_permission`、`system_user_role`、`system_role_permission`、`system_dept`、`system_post` 等。
- 数据范围表：`system_role_data_scope_customer`；历史部门范围表保留数据库兼容，但不再作为角色管理配置入口。
- 订单归属字段：`order_rfq.created_by`、`order_rfq.owner_user_id`、`order_rfq.owner_dept_id`。

部署后建议检查：

```sql
SELECT COUNT(*) FROM system_user;
SELECT COUNT(*) FROM system_role;
SELECT COUNT(*) FROM system_permission;
SELECT created_by, owner_user_id, owner_dept_id FROM order_rfq LIMIT 5;
```

### 1.2 兼容说明

- `erp_user` 作为历史账号来源和备份保留，不作为新的权限配置主表。
- 新权限以 `system_user` + `system_user_role` + `system_role_permission` 为准。
- 后端主代码已移除旧 `@RequireRole` 注解，接口安全边界统一由 `@RequirePermission` 驱动。
- 前端业务页面不再依赖 `meta.roles`，菜单和路由访问由权限点驱动。
- 左侧可点击入口已经收口为独立 `MENU` 权限；例如历史订单使用 `market:history-order:view`，提单表据使用 `market:delivery-document:view`，不再与订单管理或议价提单共用查看权限。

### 1.3 验证命令

```powershell
cd D:\QPO-Operations-Management-System\quote-backend
.\mvnw.cmd test

cd D:\QPO-Operations-Management-System\quote-frontend
npm test
npm run build
```

### 1.4 MES/WMS 配置检查

MES/WMS 对接配置仍统一放在根目录 `erp.env`，并由 `docker-compose.yml` 注入 backend 容器。保持 `ERP_` 前缀是为了兼容当前 QPO 部署体系，不代表继续使用 APS 作为新目标系统。

必备配置项：

| 配置项 | 用途 | 默认/说明 |
| --- | --- | --- |
| `ERP_MES_BASE_URL` | MES 服务根地址 | 为空时 MES 物料号任务会失败并提示配置错误 |
| `ERP_MES_AUTH_TOKEN` | MES Bearer token | 为空时不发送 Authorization header |
| `ERP_MES_MATERIAL_PATH` | MES 物料号解析路径 | 默认 `/api/mes/materials/resolve` |
| `ERP_MES_TIMEOUT_MS` | MES 请求超时 | 默认 `10000` |
| `ERP_WMS_BASE_URL` | WMS 服务根地址 | 为空时 WMS 锁库任务会失败并提示配置错误 |
| `ERP_WMS_AUTH_TOKEN` | WMS Bearer token | 为空时不发送 Authorization header |
| `ERP_WMS_ALLOCATION_PATH` | WMS 锁库分配路径 | 默认 `/api/wms/inventory/allocate` |
| `ERP_WMS_TIMEOUT_MS` | WMS 请求超时 | 默认 `10000` |
| `ERP_TASK_CORE_POOL_SIZE` | 后台任务核心线程数 | 默认 `2` |
| `ERP_TASK_MAX_POOL_SIZE` | 后台任务最大线程数 | 默认 `4` |
| `ERP_TASK_QUEUE_CAPACITY` | 后台任务队列容量 | 默认 `50` |
| `ERP_TASK_OUTPUT_DIR` | 后台任务文件输出目录 | 容器内默认 `/data/backups/tasks/` |

部署或修改配置后，建议先检查 Compose 注入结果：

```powershell
cd D:\QPO-Operations-Management-System
docker compose --env-file erp.env config | Select-String "ERP_MES"
docker compose --env-file erp.env config | Select-String "ERP_WMS"
docker compose --env-file erp.env config | Select-String "ERP_TASK"
```

修改 MES/WMS 地址、token、path、timeout 或后台任务线程池配置后，需要重启 backend：

```powershell
cd D:\QPO-Operations-Management-System
docker compose --env-file erp.env up -d --build backend
```

排查顺序：先在 **系统 > 操作日志** 查看 MES/WMS 任务提交记录，再用 `taskId` / `ticketId` / `requestId` 到 `qpo-backend.log` 和 `qpo-error.log` 关联排查。不要把 MES/WMS token、Authorization header 或完整请求/响应 JSON 写入日志或文档。

## 2. 管理员使用手册

### 2.1 用户管理

用户管理负责维护“谁可以登录系统”：

- 新增或编辑账号基础信息。
- 设置账号启用/禁用。
- 重置密码。
- 给用户分配一个或多个角色。

注意：用户本身不直接配置菜单、按钮和接口权限，权限来自角色。

### 2.1.1 个人入口字段边界

右上角个人入口是登录用户的自助资料入口，不是管理员用户管理入口，也不是新的可分配权限模块。

用户本人可以在个人入口中查看登录账号、显示名或真实姓名、所属部门、岗位、角色名称、手机号和邮箱。

用户本人可以维护手机号、邮箱和登录密码；其中手机号、邮箱通过个人入口编辑，登录密码继续使用现有修改密码弹窗。

用户本人不能通过个人入口维护用户名、显示名、真实姓名、部门、岗位、角色、权限、数据范围、启用状态或强制改密状态。这些治理属性仍由管理员在用户管理、组织档案、角色管理中维护。

治理要求：

- 个人入口查看和本人联系方式维护只要求用户已登录，不新增左侧菜单，也不新增可分配权限点。
- `PUT /api/auth/me/profile` 只能更新当前登录用户自己的 `phone`、`email`，不能复用管理员 `system:user:update` 权限。
- 强制改密期间仍只允许完成改密；个人资料编辑不进入强制改密放行白名单。
- 本人联系方式更新写入操作日志 `USER_PROFILE_UPDATE`，记录 `phone`、`email` 的 before/after 摘要；不得记录密码、token、Authorization header 或 Cookie。

### 2.2 角色管理

角色管理负责维护“这个人登录后能做什么、能看哪些数据”：

- 角色基础信息：角色编码、角色名称、说明、启用状态。
- 功能授权：按模块树勾选菜单、按钮、接口和模块级基础能力权限点。
- 数据范围：配置角色可见的业务数据。

禁用角色后，该角色不会再给用户贡献功能权限或数据权限。

### 2.3 数据范围配置

角色支持以下数据范围：

| 编码 | 含义 | 适用场景 |
| --- | --- | --- |
| `ALL` | 全部数据 | 超级管理员、总经理等 |
| `CUSTOMER` | 指定客户数据 | 市场人员、大客户负责人、只读客户账号 |
| `SELF` | 当前用户导入/创建相关订单 | 临时账号、试用账号 |
| `NONE` | 无业务数据 | 只允许看系统配置或空列表 |

角色管理的数据范围抽屉中：

- QPO 订单跨市场、工程流转，角色管理只保留 `ALL`、`CUSTOMER`、`SELF`、`NONE` 四类数据范围。
- 指定客户使用客户下拉多选，只按订单客户名称匹配。
- 多角色用户的数据范围取并集。
- 超级管理员角色默认拥有全部功能和全部数据。

默认角色建议：

| 角色类型 | 建议数据范围 | 说明 |
| --- | --- | --- |
| 超级管理员 | `ALL` | 看全部数据。 |
| 市场主管 | `ALL` 或 `CUSTOMER` | 管全部订单用 `ALL`；管部分客户用 `CUSTOMER`。 |
| 市场人员 | `CUSTOMER` | 推荐按负责客户授权。 |
| 工程核价员 | 通常 `ALL` | 工程需要看到市场导入订单，由功能权限限制其只能做工程动作；不按部门隔离。 |
| 只读客户账号 | `CUSTOMER` | 配合只读功能权限使用。 |
| 临时账号 | `SELF` | 只看当前用户导入/创建相关订单。 |
| 系统配置账号 | `NONE` | 不看业务订单。 |

如果要配置一个“只看指定客户但能走报价处理”的角色：

1. 在功能授权中勾选“报价处理”模块，以及“报价处理选择客户”“报价处理选择订单”。
2. 按职责勾选“维护报价交期”“保存报价单”“导出报价单”。
3. 在数据范围中选择 `CUSTOMER`，勾选允许查看的客户。
4. 角色管理不再提供部门范围，避免部门范围和客户范围混淆。

## 3. 模块树授权说明

### 3.1 授权树层级

角色授权抽屉按业务分组展示：

```text
市场 / 订单 / 工程 / 系统
  左侧可点击模块 MENU
    按钮权限
    接口权限
    模块级基础能力
```

管理员配置角色时，建议先勾选用户应该看到的模块，再勾选模块内允许执行的动作。取消模块节点会取消该模块下所有子权限；只勾选子权限时，后端保存会自动补齐父模块 `MENU` 权限。

### 3.2 四类权限的区别

| 类型 | 解决的问题 | 示例 |
| --- | --- | --- |
| 模块权限 | 能不能看到左侧入口、能不能进入页面 | `market:quote-process:view`、`market:history-order:view`、`market:delivered-item:view` |
| 按钮/动作权限 | 进入页面后能不能执行关键动作 | `market:quote-process:save-quote`、`market:quote-process:export`、`market:release:create` |
| 模块级基础能力 | 页面内选择客户、选择订单、预览文件、查看任务等复用能力 | `market:release:order-select`、`engineer:setup:file-preview`、`market:delivered-item:file-preview` |
| 数据权限 | 有功能权限后能看到哪些订单、客户、日志 | `ALL`、`CUSTOMER`、`SELF`、`NONE` |

公共能力优先按模块归属展示。管理员不会在授权树里看到泛用 `common:*` 权限；同一个“选择订单”动作会按实际页面拆成“报价处理选择订单”“议价提单选择订单”“零件核价选择订单”等模块级权限。

### 3.3 历史订单独立授权

历史订单是独立左侧入口，必须单独授权：

- 勾选“订单管理”只授予 `market:order:view`，不会自动显示历史订单。
- 勾选“历史订单”授予 `market:history-order:view`，左侧才显示历史订单。
- 有历史订单功能权限但没有订单数据范围时，页面正常打开但列表为空。

### 3.4 已提零件与锁库零件独立授权

已提零件和锁库零件都是 **订单** 分组下的独立左侧入口。已提零件用于查看 `order_delivery_ticket` 需求池并承载 MES/WMS 操作按钮；锁库零件用于查看 `order_delivery_ticket_allocation` 拆分结果。两者不等同于订单管理或议价提单，必须单独授权。

| 授权节点 | 权限编码 | 管理员效果 |
| --- | --- | --- |
| 已提零件 | `market:delivered-item:view` | 左侧显示“已提零件”，允许分页查看已生成提单的零件需求池和详情。 |
| 已提零件选择客户 | `market:delivered-item:customer-select` | 允许在已提零件页面打开客户选择弹窗并按客户筛选。 |
| 已提零件预览图纸 | `market:delivered-item:file-preview` | 在已提零件页面打开已绑定图纸；该能力归属已提零件模块，不使用 `common:file:preview` 授权。 |
| 获取MES物料号 | `market:delivered-item:mes-sync` | 在已提零件页面显示“获取物料号 / 重试”按钮，允许提交 `MES_MATERIAL_SYNC` 后台任务。 |
| 提交WMS锁库 | `market:delivered-item:wms-allocate` | 在已提零件页面显示“提交WMS锁库 / 重试WMS”按钮，允许提交 `WMS_ALLOCATION` 后台任务。 |
| 锁库零件 | `market:locked-item:view` | 左侧显示“锁库零件”，允许分页查看 WMS 拆分后的库存锁定、在产锁定和待生产结果。 |
| 锁库零件选择客户 | `market:locked-item:customer-select` | 允许在锁库零件页面打开客户选择弹窗并按客户筛选。 |

配置建议：

- 市场主管如负责 MES/WMS 流转，建议勾选“已提零件”“已提零件选择客户”“已提零件预览图纸”“获取MES物料号”“提交WMS锁库”“锁库零件”“锁库零件选择客户”。
- 市场人员如参与外部系统流转，可与市场主管一致；如只负责跟单查看，只勾选“已提零件”“已提零件预览图纸”“锁库零件”。
- 只读客户账号只建议勾选“已提零件”“已提零件选择客户”“已提零件预览图纸”“锁库零件”“锁库零件选择客户”，不授予 MES/WMS 操作按钮。
- 只允许查看需求池但不需要打开图纸时，只勾选 `market:delivered-item:view`。
- 需要在已提零件或锁库零件页面使用客户选择弹窗时，分别额外勾选 `market:delivered-item:customer-select`、`market:locked-item:customer-select`。
- 需要把已提零件发送给 MES 获取物料号时，额外勾选 `market:delivered-item:mes-sync`。
- 需要把已提零件发送给 WMS 锁库拆分时，额外勾选 `market:delivered-item:wms-allocate`。
- 需要查看 WMS 拆分结果时，勾选 `market:locked-item:view`；它只控制锁库零件页面，不反向授予 WMS 提交能力。
- 页面里 `PENDING` 行显示“获取物料号”，`FAILED` 行显示“重试”，`PROCESSING` 行不可重复提交，`SUCCESS` 行不显示提交按钮。
- 有功能权限但没有数据范围时，页面正常打开但列表为空；数据范围仍按订单客户等归属控制。

### 3.5 订单状态管理授权

订单状态管理能力放在 **订单管理** 模块下，不新增左侧入口。管理员应先勾选 `market:order:view`，再按职责授予下列按钮权限：

| 权限 | 页面按钮 | 允许状态 | 治理边界 |
| --- | --- | --- | --- |
| `market:order:rollback-quoted` | 退回已核价 | `已报价` | 只改状态，不清空报价交期、核价结果或图纸。 |
| `market:order:rollback-priced` | 退回未核价 | `已核价` | 只改状态，已录入核价数据保留为草稿。 |
| `market:order:discard` | 废弃 | `未核价` / `已核价` / `已报价` | 停止继续流转但保留业务数据。 |
| `market:order:restore` | 恢复为已核价 | `废弃` | 恢复后仍按报价处理、导出、提单的业务校验继续流转。 |

注意：

- `部分已提单` / `已生成提单` 不显示废弃或回退入口；只要订单存在 `order_delivery_ticket` 提单行，后端也会拒绝废弃或回退。
- 状态动作会写入 **系统 > 操作日志**，动作分别为 `ORDER_STATUS_ROLLBACK_QUOTED`、`ORDER_STATUS_ROLLBACK_PRICED`、`ORDER_DISCARD`、`ORDER_RESTORE`。
- 文件日志可通过操作日志详情中的 requestId 反查 `Order status change started/completed/rejected/failed`。

### 3.6 议价提单与提单表据授权收口

议价提单模块只提供查看和生成权限，不再提供回退权限：

- 勾选“议价提单”授予 `market:release:view`，用户可以进入生成页面查看候选零件并维护生成前参数；已生成表据不再在该页面展示。
- 勾选“生成提单”授予 `market:release:create`，用户可以按剩余可提数量新增不可逆提单记录。
- 勾选“提单表据”授予 `market:delivery-document:view`，用户可以进入只读表据页面查看 `部分已提单` / `已生成提单` 订单的提单行和动态工艺表行；导出必须单独勾选 `market:delivery-document:export`。
- 提单表据的 `market:delivery-document:customer-select`、`market:delivery-document:order-select` 只负责该页面的客户和订单选择，不继承议价提单的选择权限；订单选择接口只返回 `部分已提单`、`已生成提单`。
- 只读账号可以授予提单表据查看和选择客户/订单权限，但默认不授予 `market:delivery-document:export`；市场主管和市场人员按职责授予导出权限。
- `market:release:reset` 已废弃，不应出现在授权树、默认角色或新增权限申请中。
- 已生成提单行和已生成工艺表行只读；如果业务数据确需调整，应通过新的受控业务流程处理，而不是删除或重置历史发布记录。
- 数据职责边界：`order_delivery_ticket` 是不可逆发布记录，也是 MES/WMS 对接需求池和工艺快照来源；QPO 内部工艺表展示和导出从 `order_delivery_ticket` 动态生成，`order_process_sheet` 已通过 V36 回填后删除。议价提单负责生成，提单表据负责生成后的查看和导出。

### 3.7 组织档案授权

组织档案用于维护用户身份字典，包含部门管理和岗位管理。它解决“用户属于哪个组织、担任什么岗位”的问题，不替代角色，也不作为订单数据范围。

授权树中组织档案建议这样理解：

| 节点 | 权限 | 管理员效果 |
| --- | --- | --- |
| 组织档案 | `system:org:view` | 左侧显示组织档案入口，并允许进入页面。 |
| 部门管理 | `system:dept:view` | 可以查看部门树和部门状态。 |
| 维护部门 | `system:dept:manage` | 可以新增、编辑、启停、删除部门。 |
| 岗位管理 | `system:post:view` | 可以查看岗位列表和岗位状态。 |
| 维护岗位 | `system:post:manage` | 可以新增、编辑、启停、删除岗位。 |

注意：部门、岗位只是用户组织身份属性。QPO 订单跨市场、工程和系统治理流转，角色管理里不再提供部门数据范围；订单可见性仍由 `ALL`、`CUSTOMER`、`SELF`、`NONE` 控制。

## 4. 常见角色配置示例

### 4.1 市场只读

适用于只查看市场流程、不做导入、删除、导出和提单动作的人员。

| 配置项 | 建议 |
| --- | --- |
| 功能权限 | 勾选新单导入、报价处理、议价提单、提单表据、订单管理、历史订单、已提零件、锁库零件的 `view` 权限；勾选对应模块下选择客户、选择订单、文件预览、任务查看等基础能力。提单表据只勾选查看、选择客户、选择订单。 |

## 5. 数据权限落地范围

当前数据权限已接入以下关键业务边界：

- 订单列表、历史订单、订单详情、订单选择。
- 新单导入后的订单归属写入。
- 零件核价订单进入、保存全局设定、逐件核价、组合件选择。
- 报价处理、报价交期、内部目标交期。
- 议价提单生成工作台、提单表据（已生成提单行和动态工艺表行）、已提零件需求池和详情、锁库零件拆分结果。
- 订单状态管理：已报价退回已核价、已核价退回未核价、废弃、恢复。
- 报价单导出、模板报价导出、异步刷新/导出任务提交。
- 操作日志列表、详情、导出和筛选项。

无数据权限时，列表应返回空结果；直接访问无权限订单或日志详情时，后端拒绝访问。

## 6. 权限编码维护要求

权限编码采用：

```text
模块:资源:动作
```

示例：

- `market:rfq:import`
- `market:quote-process:save-quote`
- `market:quote-process:export`
- `market:order:discard`
- `market:order:restore`
- `engineer:pricing:save-item`
- `engineer:pricing:export-sheet`
- `system:role:assign-data-scope`

维护规则：

- 新增接口必须先确定权限编码。
- 后端 Controller 必须使用 `@RequirePermission`。
- 前端路由使用 `meta.permission`。
- 按钮使用 `v-permission` 或 `authStore.hasPermission()`。
- 权限编码不得重复；新增编码后同步更新 `02-权限点清单与现有角色映射.md` 和测试清单。
- 不得重新新增 `market:release:reset` 或同义回退权限；提单发布后的记录以只读追溯为准。

新增左侧可点击页面时，开发者必须同时完成：

1. 新增 `MENU` 权限编码，并设置 `route_path`、`component_key`、`visible`、`sort_order`。
2. 前端路由配置同一个 `meta.permission`。
3. `App.vue` 菜单元数据使用同一个权限编码。
4. 按钮或关键操作新增 `BUTTON` / `API` 权限并挂到模块下面。
5. 选择客户、选择订单、文件预览、任务查看等公共能力按页面所在模块新增权限，不新增可分配的 `common:*`。
6. 更新权限清单文档、角色授权树测试、路由权限测试和后端接口权限测试。

## 7. 常用排查

### 7.1 用户看不到菜单

检查顺序：

1. 用户是否启用。
2. 用户是否绑定至少一个启用角色。
3. 角色是否拥有对应菜单权限点。
4. 登录后 `/api/auth/permission-info` 是否返回该权限点。
5. 前端路由 `meta.permission` 是否与权限点一致。
6. 后端菜单树是否返回对应 `route_path`；左侧入口不再通过同权限伴随菜单兜底显示。

### 7.2 用户能进页面但列表为空

检查顺序：

1. 角色数据范围是否为 `NONE`。
2. `SELF` 范围下订单是否有 `created_by` 或 `owner_user_id`。
3. `CUSTOMER` 范围下角色是否配置了客户名称。
4. 超级管理员是否能看到同一批数据，用于排除业务数据不存在。

### 7.3 接口返回 403

检查顺序：

1. 当前用户权限集合是否包含接口需要的权限点。
2. 角色是否被禁用。
3. 是否刚修改权限但前端还未刷新权限信息。
4. 后端 Controller 上的 `@RequirePermission` 是否与前端权限编码一致。

## 8. 收尾状态

- 旧 `@RequireRole` 主代码已删除。
- 旧单角色入口不再作为业务安全边界。
- `authStore.hasRole()` 仅保留兼容/超级管理员判断，不作为业务页面直接授权依据。
- `meta.roles` 已从前端业务路由移除。
- `meta.anyPermissions` 已从前端路由权限判断中移除。
- 历史订单拥有独立 `market:history-order:view` 权限。
- 角色授权已按模块树管理，公共能力优先按业务模块归属展示。
- 权限体系目标状态为：用户绑定角色，角色配置功能权限和数据权限，前端负责体验隐藏，后端负责最终安全校验。
