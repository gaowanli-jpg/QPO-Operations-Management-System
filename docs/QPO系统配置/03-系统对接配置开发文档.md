# QPO 系统配置模块：出站接口配置开发文档（原系统对接配置）

> 阶段 6 收口说明：本文档原“系统对接配置”已更名为 **出站接口配置**，本阶段更名为出站接口配置，只描述 QPO 主动调用 U9、MES、WMS 的地址、认证、路径和超时配置。系统配置页面的信息架构已调整为 **文件存储 / 出站接口 / 入站接口**；MES 回调 QPO 的入站接口配置详见 `04-系统配置出站入站接口拆分与MES回调配置开发文档.md`。本文档不再承载 MES 回调 URL、回调 token 或 token 轮换说明。

> 数据中心统一对接阶段 2 更新：新的出站接口主口径以 `05-数据中心统一对接开发文档.md` 为准。QPO 后续通过数据中心转发 MES / WMS / U9；系统配置页的出站接口承载 **数据中心连接配置** 和 **功能接口配置**，旧 U9 / MES / WMS 直连配置仅作为 deprecated fallback 保留。

> 数据中心统一对接阶段 8 收口：QPO 出站调用统一走数据中心，具体业务功能继续按 MES 物料号、WMS 库存锁定、U9 销售订单同步和 MES 生产下发区分 endpoint；旧 U9 / MES / WMS 直连配置仅作为 deprecated fallback，不作为新部署主链路。

## 1. 背景

当前 QPO 已有“系统配置”模块，但第一版只承载“文件存储配置”，用于管理 LOCAL / MinIO 图纸存储策略。U9、MES、WMS 的对接参数仍主要来自 `erp.env` / `application.yaml`，后端客户端通过 `@Value("${erp.*}")` 读取配置。

这会带来两个问题：

1. 运维或管理员无法在页面上查看、测试、切换 U9 / MES / WMS 对接配置。
2. 如果只新增一个前端配置页面，但后端实际调用仍读取环境变量，页面配置就不会真正生效。

因此，本阶段目标是把“出站接口配置”（原系统对接配置）纳入现有 `/system-config` 模块，形成“页面可维护、后端真实使用、密钥脱敏、操作可审计、测试可验证”的闭环。

## 2. 目标

- 在现有“系统配置”页面新增“出站接口”配置能力。
- 支持 U9、MES、WMS 三个实际对接系统的配置管理。
- 历史阶段曾将数据中心仅作为前端预留；该口径已被 `05-数据中心统一对接开发文档.md` 替代，当前主链路为数据中心连接配置 + 功能接口配置。
- U9 / MES / WMS 后端客户端优先读取数据库中当前激活配置。
- 保留 `erp.env` 作为兼容兜底：数据库没有激活配置时，继续读取现有环境变量。
- 支持新增、编辑、测试连接、激活、停用。
- 密钥字段不回显明文，编辑时留空沿用旧密钥。
- 后端权限、前端权限、权限文档、审计日志和测试同步收口。

## 3. 非目标

- 不新增单独左侧菜单，继续使用 `/system-config`。
- 不改变 MES / WMS / U9 已有业务接口入参、出参和任务逻辑。
- 不改 MES / WMS 当前“QPO POST 调对方并同步读取响应”的通信模式。
- 本文档不重复展开数据中心真实接口调用实现细节；实际数据中心配置表、token 服务和统一 client 以 `05-数据中心统一对接开发文档.md` 为准。
- 不再新增旧 `system_external_integration_config` 的数据中心占位项；数据中心配置使用独立的 `system_data_center_config` 和 `system_data_center_endpoint_config`。
- 不把 token、secret、完整外部请求体写入操作日志或文件日志。
- 不新增可分配的 `common:*` 权限。

### 5.3 弹窗表单字段

公共字段：

| 字段 | 说明 |
| --- | --- |
| 配置名称 | 例如“MES 测试环境”、“WMS 正式环境” |
| 系统类型 | U9 / MES / WMS；编辑时不允许修改 |
| Base URL | 外部系统根地址 |
| 认证方式 | NONE / BEARER_TOKEN / U9_AUTH_LOGIN |
| 超时时间 | 毫秒 |
| 启用状态 | 是否允许被激活 |
| 备注 | 运维说明 |

MES 字段：

| 字段 | 默认值 | 说明 |
| --- | --- | --- |
| materialPath | `/api/mes/materials/resolve` | QPO 获取 MES 物料号接口路径 |
| authToken | 空 | Bearer token，可为空 |
| timeoutMs | `10000` | 连接和读取统一超时 |

WMS 字段：

| 字段 | 默认值 | 说明 |
| --- | --- | --- |
| allocationPath | `/api/wms/inventory/allocate` | QPO 提交 WMS 锁库接口路径 |
| authToken | 空 | Bearer token，可为空 |
| timeoutMs | `10000` | 连接和读取统一超时 |

U9 字段：

| 字段 | 默认值 | 说明 |
| --- | --- | --- |
| authLoginPath | `/webapi/OAuth2/AuthLogin` | U9 获取 token 接口 |
| salesOrderCreatePath | `/webapi/SO/Create` | U9 创建销售订单接口 |
| userCode | 空 | U9 登录账号 |
| entCode | 空 | 企业编码 |
| orgCode | 空 | 组织编码 |
| clientId | 空 | U9 client id |
| clientSecret | 空 | U9 client secret |
| connectTimeoutMs | `5000` | 连接超时 |
| readTimeoutMs | `30000` | 读取超时 |

### 5.4 密钥交互

- 列表和编辑弹窗不展示明文 token / secret。
- DTO 返回 `******` 表示已保存过密钥。
- 编辑时密钥字段留空或传 `******`，后端沿用旧值。
- 新增配置时，必填的密钥字段必须填写；MES/WMS token 可为空，因为当前逻辑允许不发 Authorization header。
- 测试失败信息必须脱敏后返回前端。

## 6. 后端设计

### 6.1 新增表

新增 Flyway migration。当前仓库最新迁移为 `V63__sales_order_qpo_import_fields.sql`，因此本阶段建议使用 `V64__system_external_integration_config.sql`；如果实施前其它会话已经占用 V64，则顺延到下一个可用编号。

```text
quote-backend/src/main/resources/db/migration/V64__system_external_integration_config.sql
```

表名：

```sql
system_external_integration_config
```

建议结构：

```sql
CREATE TABLE IF NOT EXISTS system_external_integration_config (
    id BIGSERIAL PRIMARY KEY,
    system_code VARCHAR(30) NOT NULL,
    name VARCHAR(100) NOT NULL,
    active BOOLEAN NOT NULL DEFAULT FALSE,
    enabled BOOLEAN NOT NULL DEFAULT TRUE,
    auth_type VARCHAR(30) NOT NULL DEFAULT 'NONE',
    config_json JSONB NOT NULL DEFAULT '{}'::jsonb,
    remark VARCHAR(500),
    last_test_status VARCHAR(20),
    last_test_message VARCHAR(500),
    last_test_at TIMESTAMP,
    created_by VARCHAR(100),
    updated_by VARCHAR(100),
    created_at TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP,
    updated_at TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP,
    CONSTRAINT ck_system_external_integration_system CHECK (system_code IN ('U9', 'MES', 'WMS')),
    CONSTRAINT ck_system_external_integration_auth CHECK (auth_type IN ('NONE', 'BEARER_TOKEN', 'U9_AUTH_LOGIN')),
    CONSTRAINT ck_system_external_integration_test_status CHECK (
        last_test_status IS NULL OR last_test_status IN ('SUCCESS', 'FAILED')
    )
);

CREATE UNIQUE INDEX IF NOT EXISTS uk_system_external_integration_active
    ON system_external_integration_config(system_code, active)
    WHERE active = TRUE;

CREATE INDEX IF NOT EXISTS idx_system_external_integration_system
    ON system_external_integration_config(system_code);

CREATE INDEX IF NOT EXISTS idx_system_external_integration_enabled
    ON system_external_integration_config(enabled);
```

说明：

- `system_code` 第一版只允许 `U9`、`MES`、`WMS`。
- 数据中心不落库，前端静态展示。
- 每个系统最多只能有一条 active 配置。
- `config_json` 存放各系统差异字段。

### 6.4 配置读取规则

新增 `ExternalIntegrationConfigService`：

```text
activeConfig(systemCode)
```

读取优先级：

1. 查询 `system_external_integration_config` 中 `system_code = ? AND active = TRUE AND enabled = TRUE`。
2. 如果存在，转换为领域配置并返回。
3. 如果不存在，回退到当前环境变量配置。
4. 如果最终仍缺少必填字段，在实际调用时抛出清晰错误，例如 `MES base URL is not configured`。

这样可以保证：

- 老部署不配置数据库时，原有 `erp.env` 仍可继续工作。
- 管理员在页面激活配置后，后端立即使用数据库配置。
- 不需要为了修改外部系统地址而重启容器。

### 6.5 客户端改造

必须改造：

- `MesMaterialClient`
- `WmsAllocationClient`
- `U9TokenService`
- `U9SalesOrderClient`

改造后：

- 不直接在业务方法里使用 `@Value` 字段作为唯一来源。
- 注入 `ExternalIntegrationConfigService`。
- 每次调用前读取对应系统当前激活配置。
- 没有激活配置时使用环境变量 fallback。
- 日志只记录 systemCode、baseUrl host、path、timeout，不记录 token / secret。

MES：

```text
POST {baseUrl}{materialPath}
Authorization: Bearer {authToken}
```

WMS：

```text
POST {baseUrl}{allocationPath}
Authorization: Bearer {authToken}
```

U9：

```text
GET {baseUrl}{authLoginPath}?userCode=...&entcode=...&orgcode=...&clientid=...&clientsecret=...
POST {baseUrl}{salesOrderCreatePath}
Header: token: {token}
```

### 6.7 测试连接逻辑

测试连接必须是真正网络请求，但不能产生业务写入。

第一版建议：

| 系统 | 测试方式 |
| --- | --- |
| MES | POST 到 `materialPath`，使用最小 mock 请求；如果对方没有测试接口，允许返回业务失败但 HTTP 可达时标记为“接口可达但业务校验失败” |
| WMS | POST 到 `allocationPath`，使用最小 mock 请求；同 MES |
| U9 | 调用 `authLoginPath` 获取 token；不调用销售订单创建接口，避免产生业务单据 |

如果 MES/WMS 对方能提供专用健康检查接口，后续可扩展：

```json
{
  "healthPath": "/api/health"
}
```

但第一版不要强依赖对方一定有 health 接口。

### 6.8 激活规则

- 只有 `enabled = TRUE` 的配置可以激活。
- 建议要求 `last_test_status = SUCCESS` 后才能激活。
- 激活某系统配置时，只取消同一 `system_code` 下其它配置的 active。
- 激活 MES 不影响 WMS / U9。
- 停用 active 配置必须拒绝，先激活其它配置后才能停用当前配置。

## 8. 数据中心预留展示

第一版数据中心仅做前端展示：

```text
数据中心
状态：预留
说明：后续用于统一主数据、跨系统数据同步或集团数据平台对接；当前版本未接入。
操作：无
```

实现要求：

- 不进入 `system_external_integration_config`。
- 不新增 DATA_CENTER 后端枚举。
- 不新增 DATA_CENTER 权限。
- 不提供保存、测试、激活按钮。
- 页面文案必须清楚表达“当前没有实际功能”。

这样做的好处是：

- 满足当前对外展示和规划说明。
- 避免管理员误填配置后以为系统已调用数据中心。
- 后续真正对接时可以单独增加 DATA_CENTER 枚举、配置字段和调用服务。

| `SYSTEM_INTEGRATION_CONFIG_TEST_FAILED` | SYSTEM | `system_external_integration_config` | 测试出站接口配置失败 |
| `SYSTEM_INTEGRATION_CONFIG_ACTIVATE` | SYSTEM | `system_external_integration_config` | 激活出站接口配置 |
| `SYSTEM_INTEGRATION_CONFIG_DISABLE` | SYSTEM | `system_external_integration_config` | 停用出站接口配置 |

### 9.2 日志脱敏要求

不得记录：

- token
- Authorization header
- clientSecret
- U9 AuthLogin 完整 URL
- 完整外部请求体
- 完整外部响应体

可以记录：

- systemCode
- configId
- baseUrl host
- path
- timeout
- HTTP 状态码
- 脱敏后的失败摘要

## 10. 部署兼容

### 10.1 `erp.env`

继续保留现有环境变量：

```env
ERP_MES_BASE_URL=
ERP_MES_AUTH_TOKEN=
ERP_MES_MATERIAL_PATH=/api/mes/materials/resolve
ERP_MES_TIMEOUT_MS=10000

ERP_WMS_BASE_URL=
ERP_WMS_AUTH_TOKEN=
ERP_WMS_ALLOCATION_PATH=/api/wms/inventory/allocate
ERP_WMS_TIMEOUT_MS=10000

ERP_U9_BASE_URL=
ERP_U9_USER_CODE=
ERP_U9_ENT_CODE=
ERP_U9_ORG_CODE=
ERP_U9_CLIENT_ID=
ERP_U9_CLIENT_SECRET=
ERP_U9_CONNECT_TIMEOUT_MS=5000
ERP_U9_READ_TIMEOUT_MS=30000
```

说明：

- 运行时优先级固定为：`system_external_integration_config` 中 `active = TRUE AND enabled = TRUE` 的 DB 配置优先；没有 active DB 配置时才读取 `erp.env` / `application.yaml` 环境变量 fallback。
- 老环境和本地开发可以继续只靠 `erp.env` 运行，不需要为了启动本地环境先创建 DB 对接配置。
- 新环境推荐在页面新增、测试并激活 U9 / MES / WMS 出站接口配置；激活后业务调用使用页面配置。
- 页面激活配置后，修改外部系统地址、token、超时不需要重启容器。
- `erp.env.example` 只提供变量名和默认 path / timeout；真实 token、clientSecret 只允许写入本机或生产 `erp.env`，不得提交。

### 10.2 `docker-compose.yml`

`backend.environment` 继续注入 `ERP_MES_*`、`ERP_WMS_*`、`ERP_U9_*`：

- 这些环境变量是本地开发和无 active DB 配置时的兼容 fallback，不代表页面配置失效。
- 即使生产环境主要通过页面维护出站接口配置，也不要删除 Compose 中的外部系统变量注入，避免回滚或新库初始化时失去兜底。
- 只有修改 `erp.env` fallback 值时才需要重启 backend；在页面新增、编辑、测试、激活对接配置不需要重启 backend。

### 10.3 `application.yaml`

保留现有 `erp.u9.*`、`erp.mes.*`、`erp.wms.*` 兼容映射。

如果当前 `application.yaml` 缺少 `erp.mes.*` 或 `erp.wms.*` 映射，需要补齐，确保 fallback 一致。

### 10.4 部署验证口径

- 未创建或未激活任何出站接口 DB 配置时，`MesMaterialClient`、`WmsAllocationClient`、`U9TokenService`、`U9SalesOrderClient` 继续使用 `ERP_MES_*`、`ERP_WMS_*`、`ERP_U9_*`。
- 页面新增并激活 MES / WMS / U9 配置后，上述客户端使用 active DB 配置，环境变量仅保留为后备。
- 数据中心第一版只展示预留说明，不落库、不注入环境变量、不参与业务调用。
- 操作日志和后端文件日志只记录系统类型、配置 ID、host/path、状态和脱敏摘要，不记录 token、clientSecret、Authorization header 或完整请求/响应。
