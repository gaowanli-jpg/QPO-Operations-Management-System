# QPO 系统配置模块：数据中心数据库只读直连开发文档

> 本文档描述的是“数据中心直接连接 QPO PostgreSQL 做只读查询”的方案，不走接口，不复用 `system_data_center_config` / `system_data_center_endpoint_config` 那条 QPO -> 数据中心 HTTP 网关链路。

## 1. 背景

数据中心这次要做两类能力：

- 订单追踪
- 零件追踪

讨论结果已经明确：不要通过 API 中转，数据中心直接连 QPO 数据库，只做只读查询。

QPO 当前已经有完整的订单、提单、MES、WMS 业务表，但这些表之间不是单表单字段就能串起来，尤其是：

- RFQ 追踪
- 销售订单追踪
- 提单追踪
- MES 批次追踪
- WMS 锁库追踪

它们都需要跨表 join。数据中心如果直接查库，就要拿到完整的表关系和字段口径。

## 2. 目标

- 让数据中心可以直连 QPO PostgreSQL。
- 数据中心只读，不做写入、不做接口调用。
- 数据中心可以读取业务库中的全部内容。
- QPO 继续保持现有业务流程不变。
- 给数据中心一份可执行的表关系、追踪口径和连接信息。

## 3. 非目标

- 不新增 API。
- 不改现有 MES / WMS / U9 出站链路。
- 不改现有业务表结构。
- 不做复制库、CDC、消息同步或中间层。
- 不把这条直连方案混进现有 `system_data_center_config` / `system_data_center_endpoint_config`。

## 4. 当前事实

当前仓库里可确认的事实：

- PostgreSQL 通过 `docker-compose.yml` 暴露端口，端口绑定受 `POSTGRES_BIND` 控制。
- `erp.env` 当前默认还是 `127.0.0.1:5432`。
- 后端应用内部仍然通过容器内服务名 `postgres:5432` 访问数据库，不受宿主机端口开放影响。
- 当前业务主表都在 `public` schema。
- 相关迁移最高到 `V14`，如果后续要把授权或只读视图写成迁移，必须走下一版迁移，不要改已执行迁移。

## 5. 推荐方案

### 5.1 网络开放

把 PostgreSQL 的宿主机绑定从本机回环改成数据中心可达地址。

推荐做法：

- `POSTGRES_BIND=<QPO服务器内网IP>`
- 或者在需要更宽松连通时使用 `0.0.0.0`

这只影响宿主机端口映射，不影响容器内应用继续用 `postgres:5432` 访问数据库。

### 5.2 只读账号

新增一个专用只读账号，不复用 `postgres`。

账号密码通过 `erp.env` / `erp.env.example` 配置项传入，正式环境使用 `POSTGRES_DATACENTER_RO_PASSWORD`，示例文件留空。

推荐权限：

```sql
CREATE ROLE qpo_datacenter_ro LOGIN PASSWORD '<password>';

GRANT CONNECT ON DATABASE postgres TO qpo_datacenter_ro;
GRANT USAGE ON SCHEMA public TO qpo_datacenter_ro;
GRANT pg_read_all_data TO qpo_datacenter_ro;
GRANT SELECT ON ALL TABLES IN SCHEMA public TO qpo_datacenter_ro;
GRANT USAGE, SELECT ON ALL SEQUENCES IN SCHEMA public TO qpo_datacenter_ro;

ALTER ROLE qpo_datacenter_ro SET search_path = public;
```

如果后续新增表或视图，应该在同一版迁移里补授权，或者在执行迁移的 owner 名下补默认权限。

仓库实现上建议通过新的 Flyway 迁移创建 / 更新该角色，并把密码从 `POSTGRES_DATACENTER_RO_PASSWORD` 注入迁移占位符。

### 5.3 连接参数

给数据中心的连接信息只需要这些：

| 项 | 示例 |
| --- | --- |
| Host | `<QPO服务器内网IP>` |
| Port | `5432` |
| Database | `postgres` |
| Username | `qpo_datacenter_ro` |
| Password | `<只读密码>` |
| SSL | 当前环境可先用 `disable` |

## 6. 追踪口径

数据中心不要把追踪逻辑只压在一张表上。推荐按入口分类。

### 6.1 订单追踪入口

可按这些字段查：

- `sales_order_no`
- `document_no`
- `customer_order_no`
- `internal_project_no`
- `rfq_no`

主链路建议：

```text
sales_order_header
  -> sales_order_item
  -> order_delivery_ticket
  -> order_delivery_ticket_allocation
  -> mes_integration_batch / mes_material_batch_item / mes_production_batch_item
  -> wms_reservation_batch / wms_reservation_item / wms_reservation_ticket
```

### 6.2 零件追踪入口

可按这些字段查：

- `part_no`
- `version`
- `material_no`
- `drawing_url`
- `material_shape`

主链路建议：

```text
item_quote_version
  -> order_delivery_ticket
  -> order_delivery_ticket_allocation
  -> MES / WMS 批次表
```

### 6.3 RFQ 追踪入口

RFQ 侧的主链路建议：

```text
order_rfq
  -> item_quote_version
  -> order_delivery_ticket
```

### 6.4 销售订单来源追踪

销售订单可能有两种来源：

- 直接导入
- RFQ 派生

所以不能只靠一条固定规则。尤其不能只用 `order_delivery_ticket.source_item_id = sales_order_item.id` 这一种判断。

推荐联合判断：

- `sales_order_header` / `sales_order_item`
- `sales_order_source_rfq`
- `sales_order_item.source_ticket_id`
- `order_delivery_ticket.source_type`
- `order_delivery_ticket.source_order_id`
- `order_delivery_ticket.source_item_id`

## 8. 增量与追踪水位

如果数据中心要自己做增量抓取，不要只盯 `order_delivery_ticket` 一张表。

原因很简单：

- `order_delivery_ticket` 没有统一的 `updated_at`
- 有些状态变化只写在关联表里
- 删除没有统一墓碑

推荐水位策略：

- 销售订单：用 `sales_order_header.updated_at`、`sales_order_item.updated_at`
- 提单分配：用 `order_delivery_ticket_allocation.updated_at`
- MES：用 `order_delivery_ticket_mes_request.updated_at`、`order_delivery_ticket_mes_waiter.updated_at`、`mes_integration_batch.updated_at`、`mes_material_batch_item.updated_at`、`mes_production_batch_item.updated_at`
- WMS：用 `wms_reservation_batch.updated_at`、`wms_reservation_item.updated_at`、`wms_reservation_ticket.updated_at`

如果要做全量镜像，直接全表读也可以，但追踪链路还是要按上面的 join 关系组装。

## 9. 追踪 SQL 示例

### 9.1 按销售订单号追踪

```sql
SELECT
  h.sales_order_no,
  i.line_no,
  i.part_no,
  i.version,
  t.id AS ticket_id,
  t.material_no,
  t.mes_sync_status,
  t.wms_allocate_status,
  a.allocation_type,
  a.qty,
  wb.external_biz_id,
  wt.status AS wms_ticket_status,
  mb.status AS mes_material_status,
  pb.status AS mes_production_status
FROM sales_order_header h
JOIN sales_order_item i
  ON i.sales_order_id = h.id
LEFT JOIN order_delivery_ticket t
  ON t.source_type = 'SALES_ORDER'
 AND t.source_order_id = h.id
 AND t.source_item_id = i.id
LEFT JOIN order_delivery_ticket_allocation a
  ON a.ticket_id = t.id
LEFT JOIN wms_reservation_ticket wt
  ON wt.ticket_id = t.id
LEFT JOIN wms_reservation_batch wb
  ON wb.id = wt.batch_id
LEFT JOIN mes_material_batch_item mb
  ON mb.ticket_id = t.id
LEFT JOIN mes_production_batch_item pb
  ON pb.allocation_id = a.id
WHERE h.sales_order_no = :salesOrderNo;
```

### 9.2 按零件号追踪

```sql
SELECT
  q.rfq_no,
  qv.part_no,
  qv.version,
  qv.material_no,
  t.id AS ticket_id,
  t.mes_sync_status,
  t.wms_allocate_status,
  a.allocation_type
FROM item_quote_version qv
LEFT JOIN order_rfq q
  ON q.id = qv.rfq_id
LEFT JOIN order_delivery_ticket t
  ON t.item_id = qv.id
LEFT JOIN order_delivery_ticket_allocation a
  ON a.ticket_id = t.id
WHERE qv.part_no = :partNo
  AND (:version IS NULL OR qv.version = :version);
```

## 10. 实施步骤

1. 修改 `POSTGRES_BIND`，让数据中心网络能连到宿主机端口。
2. 创建 `qpo_datacenter_ro` 只读账号。
3. 授予数据库和 schema 的只读权限。
4. 把连接参数交给数据中心。
5. 让数据中心先做几条只读校验查询。
6. 再让数据中心按上面的 join 关系实现订单追踪和零件追踪。

## 11. 验收标准

- 数据中心可以用只读账号登录数据库。
- 数据中心可以查询全部业务表。
- 数据中心不能写入数据。
- 数据中心能按销售订单号追到提单、MES、WMS。
- 数据中心能按零件号追到 RFQ、提单、MES、WMS。
- 数据中心不会把单表状态当成完整链路。

## 12. 交付给数据中心的内容

- 数据库地址、端口、库名、账号、密码
- 关键表说明
- 订单追踪 join 规则
- 零件追踪 join 规则
- 增量水位建议
- 只读权限说明

## 13. 后续约束

如果未来要把“只读账号创建”和“必要的辅助视图”写进仓库，必须走下一版 Flyway 迁移，不能改已执行迁移。当前仓库最高迁移版本是 `V14`。
