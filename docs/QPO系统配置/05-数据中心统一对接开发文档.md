# QPO 系统配置模块：数据中心统一对接开发文档

> 2026-08-06 销售订单导入即提单阶段 7 收口：销售订单来源提单行由销售订单导入自动生成，不再要求市场用户手动销售匹配或手动议价提单。销售订单导入后直接进入已提零件需求池；后续 U9 同步仍走数据中心，但价格补齐前不可同步 U9。

## 1. 背景

当前 QPO 已经具备以下外部系统对接能力：

- QPO -> MES：已提零件获取物料号、锁库待生产零件下发 MES 生产。
- QPO -> WMS：已提零件获取库存锁库信息。
- QPO -> U9：销售订单整单同步 U9。
- MES -> QPO：MES 物料号异步回调 QPO。

新的集成口径调整为：

```text
QPO 不再直接点对点调用 MES / WMS / U9。
QPO 统一调用数据中心。
数据中心负责把请求转发给 MES / WMS / U9。
其他系统也不直接调用 QPO，而是通过数据中心调用 QPO 的入站接口。
```

数据中心是一个独立系统，由数据中心团队维护。QPO 侧仍然保留业务模块语义，例如“MES 物料号”“WMS 锁库”“U9 同步”，因为用户和业务流程关注的是最终业务系统；但技术配置、token 获取、出站 HTTP 调用和入站调用方口径统一收敛为“数据中心”。

## 2. 目标

- 建立“数据中心统一网关”的系统配置口径。
- QPO 出站调用统一从 `erp.env` 或系统配置页读取数据中心连接配置。
- QPO 通过数据中心提供的 OAuth2 `client_credentials` 方式获取 access token。
- QPO 调用数据中心接口时携带数据中心 access token，由数据中心转发到 MES / WMS / U9。
- 系统配置页面依旧可以配置数据中心对接信息。
- 系统配置页面支持按功能配置不同接口地址和接口参数口径。
- 保留业务模块名称和业务状态，不把页面上的“MES / WMS / U9”全部改成“数据中心”。
- QPO 入站接口继续由系统配置页生成 QPO 侧回调 token，调用方从 MES 调整为数据中心。
- 更新文档、权限、日志、测试和部署说明，确保运维和联调口径一致。

## 3. 非目标

- 不改变已提零件、锁库零件、销售订单 U9 同步等业务模块的用户操作入口。
- 不删除现有 MES / WMS / U9 业务服务类；只改造底层调用链路为数据中心网关。
- 不把数据中心 access token、client_secret、QPO 入站 token 写入文档、操作日志、文件日志或前端持久化缓存。
- 不在开发文档中写入真实 `client_secret`。
- 不新增可分配的 `common:*` 权限。
- 不要求第一版做完全动态 JSON 映射引擎；每个功能仍由明确的后端 adapter 组装请求和解析响应。

## 4. 总体架构

### 4.1 出站调用

调整前：

```text
QPO -> MES
QPO -> WMS
QPO -> U9
```

调整后：

```text
QPO -> 数据中心 -> MES
QPO -> 数据中心 -> WMS
QPO -> 数据中心 -> U9
```

QPO 后端只维护一套数据中心认证和 HTTP 调用能力：

```text
DataCenterTokenService
  -> POST 数据中心 token 地址
  -> client_id + client_secret + grant_type=client_credentials
  -> 缓存 access_token 到过期前

DataCenterIntegrationClient
  -> 按 endpointCode 获取功能接口配置
  -> POST/GET 数据中心业务接口
  -> Authorization: Bearer {access_token}
```

### 4.2 入站调用

调整前：

```text
MES -> QPO /api/integrations/mes/material-callback
```

调整后：

```text
MES -> 数据中心 -> QPO /api/integrations/mes/material-callback
```

QPO 对外提供的接口路径可以保持不变，接口文档交付对象从 MES 调整为数据中心。数据中心调用 QPO 时携带：

```http
Authorization: Bearer {QPO_INBOUND_CALLBACK_TOKEN}
```

`QPO_INBOUND_CALLBACK_TOKEN` 仍由 QPO 管理员在：

```text
系统配置 -> 入站接口 -> MES 物料号回调
```

中生成或轮换，明文只展示一次，并通过受控渠道交付给数据中心。

## 5. 数据中心 token 获取口径

数据中心当前提供的 token 获取方式为：

```http
POST http://192.168.70.250:8080/realms/api-platform/protocol/openid-connect/token
Content-Type: application/x-www-form-urlencoded

client_id={DATA_CENTER_CLIENT_ID}
client_secret={DATA_CENTER_CLIENT_SECRET}
grant_type=client_credentials
```

已知配置口径：

| 字段 | 当前口径 | 是否可写入文档 | 说明 |
| --- | --- | --- | --- |
| `tokenUrl` | `http://192.168.70.250:8080/realms/api-platform/protocol/openid-connect/token` | 可以 | 数据中心 token 地址。 |
| `client_id` | `app_8ed28b2a1faf4a0b` | 可以 | 数据中心分配给 QPO 的客户端 ID。 |
| `client_secret` | 由数据中心提供 | 不可以 | 真实密钥只允许写入真实 `erp.env` 或系统配置密文字段。 |
| `grant_type` | `client_credentials` | 可以 | 固定授权模式。 |

> 安全要求：本文档和后续提交不得包含真实 `client_secret`。真实值由部署人员写入服务器 `erp.env`，或由管理员在系统配置页面维护。

## 6. `erp.env` 配置设计

`erp.env` 作为本地开发、首次部署和页面配置缺失时的 fallback。新增以下变量：

```env
# Data Center outbound gateway fallback.
# QPO calls Data Center only; Data Center forwards requests to MES/WMS/U9.
ERP_DATA_CENTER_ENABLED=true
ERP_DATA_CENTER_BASE_URL=http://192.168.70.250:8080
ERP_DATA_CENTER_TOKEN_URL=http://192.168.70.250:8080/realms/api-platform/protocol/openid-connect/token
ERP_DATA_CENTER_CLIENT_ID=app_8ed28b2a1faf4a0b
ERP_DATA_CENTER_CLIENT_SECRET=
ERP_DATA_CENTER_GRANT_TYPE=client_credentials
ERP_DATA_CENTER_CONNECT_TIMEOUT_MS=5000
ERP_DATA_CENTER_READ_TIMEOUT_MS=30000
ERP_DATA_CENTER_TOKEN_EXPIRE_SKEW_SECONDS=60

# Data Center business endpoint fallback paths.
# Actual paths are confirmed with Data Center and can be overridden in System Config.
ERP_DATA_CENTER_MES_MATERIAL_PATH=
ERP_DATA_CENTER_WMS_ALLOCATION_PATH=
ERP_DATA_CENTER_U9_SALES_ORDER_SYNC_PATH=
ERP_DATA_CENTER_U9_COMMON_ENTITY_QUERY_PATH=
ERP_DATA_CENTER_MES_PRODUCTION_DISPATCH_PATH=
```

说明：

- `ERP_DATA_CENTER_CLIENT_SECRET` 在 `erp.env.example` 中必须为空。
- 真实 `ERP_DATA_CENTER_CLIENT_SECRET` 只写入本机或服务器真实 `erp.env`。
- 系统配置页面存在已启用的数据中心配置时，优先使用页面配置。
- 页面配置缺字段时可以回退 `erp.env`。
- `ERP_MES_*`、`ERP_WMS_*`、`ERP_U9_*` 旧变量第一版保留为兼容 fallback，但标记为 deprecated。

## 7. 系统配置页面设计

系统配置页继续保持三类信息架构：

```text
文件存储 / 出站接口 / 入站接口
```

### 7.1 出站接口页调整

出站接口页从“分别配置 U9 / MES / WMS”调整为：

```text
出站接口
  - 数据中心连接配置
  - 功能接口配置
```

#### 数据中心连接配置

用于维护 QPO 调用数据中心所需的统一连接与认证信息：

| 字段 | 说明 |
| --- | --- |
| 配置名称 | 例如“数据中心测试环境”“数据中心正式环境”。 |
| 启用状态 | 是否允许该配置被激活。 |
| 激活状态 | 当前运行时是否使用该配置。 |
| Base URL | 数据中心根地址。 |
| Token URL | 数据中心获取 token 地址。 |
| Client ID | 数据中心分配给 QPO 的客户端 ID。 |
| Client Secret | 密文字段，列表和查询接口不回显明文。 |
| Grant Type | 第一版固定 `client_credentials`。 |
| 连接超时 | HTTP 连接超时。 |
| 读取超时 | HTTP 读取超时。 |
| Token 提前刷新秒数 | access token 到期前多少秒刷新。 |
| 最后测试状态 | 测试 token 获取和基础连通性的结果。 |
| 备注 | 运维说明。 |

#### 功能接口配置

每个业务功能单独配置接口 path、方法、请求/响应适配口径：

| 功能编码 | 业务模块显示 | 目标业务系统 | 默认方法 | 说明 |
| --- | --- | --- | --- | --- |
| `MES_MATERIAL_RESOLVE` | 获取物料号 | MES | POST | 已提零件模块调用，支持即时返回和待回调。 |
| `WMS_INVENTORY_ALLOCATE` | 获取库存信息 | WMS | POST | 已提零件模块调用，返回库存锁定、在产锁定和待生产数量。 |
| `U9_SALES_ORDER_SYNC` | U9 同步 | U9 | POST | 销售订单整单同步 U9。 |
| `U9_COMMON_ENTITY_QUERY` | U9 通用实体查询 | U9 | POST | 读取组织 `101` 的 Seller / SaleDepartment 选项，并按 DocNo 做 U9 订单核对。 |
| `MES_PRODUCTION_DISPATCH` | 下发 MES 生产 | MES | POST | 待产零件模块把待生产行下发生产流程。 |

U9 同步相关 `U9_SALES_ORDER_SYNC` 和 `U9_COMMON_ENTITY_QUERY` 的 timeout 不低于 `60000ms`；数据中心 U9 登录上下文组织必须为 `101`。

功能接口字段：

| 字段 | 说明 |
| --- | --- |
| endpointCode | 功能编码，固定枚举。 |
| displayName | 页面显示名称。 |
| targetSystemCode | MES / WMS / U9，用于业务归类和日志筛选。 |
| method | GET / POST，第一版主要使用 POST。 |
| path | 数据中心分配给该功能的接口路径。 |
| enabled | 是否启用该功能接口。 |
| timeoutMs | 功能级超时；为空时使用数据中心连接配置默认超时。 |
| requestAdapter | 后端固定 adapter 名称，例如 `MES_MATERIAL_V1`。 |
| responseAdapter | 后端固定 adapter 名称，例如 `MES_MATERIAL_RESPONSE_V1`。 |
| requestSchemaJson | 用于页面说明和测试，不作为第一版动态执行脚本。 |
| responseSchemaJson | 用于页面说明和测试，不作为第一版动态执行脚本。 |
| lastTestStatus | 最近一次接口配置测试结果。 |
| remark | 运维说明。 |

### 7.2 入站接口页调整

入站接口页保留现有能力，但文案调整为“数据中心调用 QPO”：

```text
入站接口
  MES 物料号回调
    调用方：数据中心
    业务来源：MES
    回调 URL：{QPO_PUBLIC_BASE_URL}/api/integrations/mes/material-callback
    Token：由 QPO 系统配置页生成，真实值单独交付数据中心
```

后续如果数据中心还需要调用 QPO 的其他入站接口，可以继续新增卡片，例如：

- MES 生产状态回调。
- WMS 锁库状态回调。
- U9 同步结果回调。

## 8. 数据模型设计

### 8.1 数据中心连接配置表

新增迁移，建议使用实际下一编号，例如：

```text
V80__data_center_integration_config.sql
```

新增表：

```sql
CREATE TABLE IF NOT EXISTS system_data_center_config (
    id BIGSERIAL PRIMARY KEY,
    name VARCHAR(100) NOT NULL,
    active BOOLEAN NOT NULL DEFAULT FALSE,
    enabled BOOLEAN NOT NULL DEFAULT TRUE,
    base_url VARCHAR(500),
    token_url VARCHAR(500),
    client_id VARCHAR(200),
    client_secret_cipher TEXT,
    grant_type VARCHAR(50) NOT NULL DEFAULT 'client_credentials',
    connect_timeout_ms INTEGER NOT NULL DEFAULT 5000,
    read_timeout_ms INTEGER NOT NULL DEFAULT 30000,
    token_expire_skew_seconds INTEGER NOT NULL DEFAULT 60,
    last_test_status VARCHAR(20),
    last_test_message VARCHAR(500),
    last_test_at TIMESTAMP,
    remark VARCHAR(500),
    created_by VARCHAR(100),
    updated_by VARCHAR(100),
    created_at TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP,
    updated_at TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP,
    CONSTRAINT ck_system_data_center_grant_type CHECK (grant_type IN ('client_credentials')),
    CONSTRAINT ck_system_data_center_test_status CHECK (
        last_test_status IS NULL OR last_test_status IN ('SUCCESS', 'FAILED')
    )
);

CREATE UNIQUE INDEX IF NOT EXISTS uk_system_data_center_active
    ON system_data_center_config(active)
    WHERE active = TRUE;
```

```sql
    ON system_data_center_endpoint_config(target_system_code);
```

### 8.3 为什么不只扩展旧 `system_external_integration_config`

不建议只把 `DATA_CENTER` 塞进旧 U9 / MES / WMS 配置表，原因：

- 新口径下运行时激活对象是“数据中心连接”，不是某个业务系统连接。
- 各业务功能需要不同 path、不同参数适配、不同响应解析，适合独立 endpoint 表。
- 旧表语义是“QPO 直接调用某个外部系统”，新表语义是“QPO 调用数据中心，再由数据中心转发”。
- 分离连接配置和功能接口配置后，页面更清楚：认证只配置一次，业务接口按功能维护。

旧表可以保留一段时间用于兼容和回滚，但新链路以 `system_data_center_config` + `system_data_center_endpoint_config` 为准。

## 9. 后端设计

### 9.1 新增枚举

```text
DataCenterEndpointCode
  - MES_MATERIAL_RESOLVE
  - WMS_INVENTORY_ALLOCATE
  - U9_SALES_ORDER_SYNC
  - MES_PRODUCTION_DISPATCH

DataCenterTargetSystemCode
  - MES
  - WMS
  - U9

DataCenterAuthGrantType
  - client_credentials
```

### 9.2 新增服务

建议新增：

```text
DataCenterConfigService
DataCenterTokenService
DataCenterIntegrationClient
DataCenterEndpointRegistry
SystemDataCenterConfigManageService
SystemDataCenterConfigController
```

职责：

| 服务 | 职责 |
| --- | --- |
| `DataCenterConfigService` | 运行时读取 active DB 配置，缺失时 fallback 到 `erp.env`。 |
| `DataCenterTokenService` | 使用 `client_credentials` 获取并缓存 access token。 |
| `DataCenterIntegrationClient` | 按 endpointCode 调用数据中心业务接口。 |
| `DataCenterEndpointRegistry` | 管理 endpointCode 与 request/response adapter 的绑定。 |
| `SystemDataCenterConfigManageService` | 系统配置页面的增改查、测试、激活、停用。 |
| `SystemDataCenterConfigController` | 暴露系统配置页面 API。 |

### 9.3 token 获取

请求：

```http
POST {tokenUrl}
Content-Type: application/x-www-form-urlencoded

client_id={clientId}
client_secret={clientSecret}
grant_type=client_credentials
```

响应兼容字段：

```json
{
  "access_token": "xxx",
  "expires_in": 3600,
  "token_type": "Bearer"
}
```

处理规则：

- `access_token` 不能为空。
- `expires_in` 为空时按短 TTL 缓存，例如 5 分钟。
- 到期前 `token_expire_skew_seconds` 秒刷新。
- token 获取失败时，不调用业务接口，直接返回清晰错误。
- access token、client_secret、完整 token 响应体不得进入日志。

### 9.4 业务 adapter

第一版不做动态脚本映射，避免引入不可控复杂度。每个功能保留明确 adapter：

| endpointCode | requestAdapter | responseAdapter | 原业务服务 |
| --- | --- | --- | --- |
| `MES_MATERIAL_RESOLVE` | `MES_MATERIAL_V1` | `MES_MATERIAL_RESPONSE_V1` | `MesMaterialSyncService` |
| `WMS_INVENTORY_ALLOCATE` | `WMS_ALLOCATION_V1` | `WMS_ALLOCATION_RESPONSE_V1` | `WmsAllocationService` |
| `U9_SALES_ORDER_SYNC` | `U9_SALES_ORDER_V1` | `U9_SALES_ORDER_RESPONSE_V1` | `SalesOrderU9SyncService` |
| `U9_COMMON_ENTITY_QUERY` | `U9_COMMON_ENTITY_QUERY_V1` | `U9_COMMON_ENTITY_RESPONSE_V1` | `U9MasterDataService` / `U9SalesOrderReconciliationService` |
| `MES_PRODUCTION_DISPATCH` | `MES_PRODUCTION_DISPATCH_V1` | `MES_PRODUCTION_DISPATCH_RESPONSE_V1` | `MesProductionDispatchService` |

好处：

- 参数不同的问题由各 adapter 清晰处理。
- 每个 adapter 可以单独测试。
- 数据中心后续调整某个功能参数时，只影响对应 adapter。
- 页面可展示该功能的请求/响应 schema，但不在第一版运行时执行动态 JSON 脚本。

### 9.5 改造现有 client

需要改造：

```text
MesMaterialClient
WmsAllocationClient
U9TokenService / U9SalesOrderClient
MesProductionDispatchClient
```

改造后：

- 业务服务仍调用各自 client。
- client 内部不再直接拼 MES / WMS / U9 地址。
- client 调用 `DataCenterIntegrationClient.call(endpointCode, payload)`。
- 原状态写回、异步任务、幂等、去重、fan-out、销售订单物料号回写、U9 同步幂等逻辑不变。

- endpointCode
- targetSystemCode
- baseUrl host
- path
- HTTP status
- timeout
- 脱敏失败摘要
- taskId

不得记录：

- `client_secret`
- access token
- refresh token
- Authorization header
- 完整 token 响应体
- 完整业务请求体
- 完整业务响应体
- QPO 入站回调 token

## 14. 完成定义

- QPO 外部交互口径统一为数据中心。
- 业务模块仍能表达 MES / WMS / U9 的业务含义。
- 数据中心连接配置可由 `erp.env` fallback，也可由系统配置页面维护。
- 每个业务功能可以配置独立接口 path 和适配口径。
- U9 销售订单创建和 U9 通用实体查询分属 `U9_SALES_ORDER_SYNC`、`U9_COMMON_ENTITY_QUERY` 两个功能 endpoint，均启用且 timeout 不低于 `60000ms`。
- 数据中心 token 通过 `client_credentials` 获取和缓存。
- 入站接口由数据中心调用 QPO，QPO 入站 token 由系统配置页生成并单独交付。
- 权限、日志、部署文档、联调文档和测试全部同步更新。
