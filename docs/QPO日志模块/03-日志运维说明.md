## 1. 日志类型与入口

QPO 当前保留三类日志，各自职责不同：

| 日志类型 | 查看方式 | 主要用途 |
| --- | --- | --- |
| 操作日志 | 系统页面：系统 > 操作日志 | 查询谁在什么时候做了什么业务动作 |
| 后端运行日志 | 容器内 `/data/backups/logs/backend/` | 排查 Java 后端接口、任务、异常和 requestId |
| Postgres 慢 SQL / 锁等待日志 | `docker logs quote-postgres` | 排查数据库慢查询、锁等待、死锁相关问题 |

操作日志用于业务审计，后端运行日志和数据库日志用于运维排查；不要把所有运行日志写入 `audit_log`。

首页看板只读聚合口径：`GET /api/dashboard/overview` 是登录后首页看板的普通读取接口，页面进入、手动刷新、图表点击和卡片跳转不写操作日志，也不新增高频文件日志。该接口只读取数据库聚合结果，不调用 MES / WMS / U9 / 数据中心写操作；排查时可按普通页面请求的 requestId 查看后端运行日志，但不应在 **系统 > 操作日志** 中期待首页普通读取记录。日志中不得记录 token、Authorization header、外部系统密钥、完整业务请求体或外部接口敏感响应。

## 2. 操作日志

系统管理员在页面查看：

```text
系统 > 操作日志
```

适合查询：

- 登录成功、登录失败、账号锁定、登出。
- 用户、字典、报价模板、RFQ 导入、报价处理、提单等关键业务动作。
- 日志保留策略修改、手动归档清理等系统动作。

报价模板审计口径：

- 上传报价模板写入操作日志 `QUOTE_TEMPLATE_UPLOAD`，摘要记录文件名、更新时间和模板状态，不记录文件内容。
- 保存表头校验行配置写入操作日志 `QUOTE_TEMPLATE_CONFIG_UPDATE`，摘要记录 `headerRowNumber`、`groupHeaderRowNumber`、`detailStartRowNumber`。
- 后端文件日志记录 `Quote template upload started/completed/validation failed` 和 `Quote template config updated`，不记录 Excel 内容或完整 multipart 请求体。

字典维护审计口径：

- 材料、工艺大类、具体工艺、普通百分比费用、组装件百分比费用类、非工时费用工艺的新增/编辑/删除写入操作日志；普通查询不写操作日志，也不增加业务 INFO。
- 工艺大类动作编码为 `DICT_PROCESS_CATEGORY_CREATE`、`DICT_PROCESS_CATEGORY_UPDATE`、`DICT_PROCESS_CATEGORY_DISABLE`、`DICT_PROCESS_CATEGORY_ENABLE`；具体工艺动作编码为 `DICT_PROCESS_DETAIL_CREATE`、`DICT_PROCESS_DETAIL_UPDATE`、`DICT_PROCESS_DETAIL_DISABLE`、`DICT_PROCESS_DETAIL_ENABLE`，摘要只记录 ID、编码、名称、启停和小时价格等低敏字段。
- MES 主数据同步动作编码为 `DICT_PROCESS_MES_SYNC`、`DICT_MATERIAL_MES_SYNC`，`targetType` 为 `mes_master_data_sync_run`；排查时按 `syncRunId`、同步类型、执行人或 requestId 查询，只看计数摘要和脱敏失败原因。材料/工艺定时同步策略保存动作编码为 `DICT_MES_MASTER_DATA_SYNC_SCHEDULE_UPDATE`，`targetType` 为 `mes_master_data_sync_schedule_config`，只看启停、延迟、间隔和上次状态摘要。
- 组装件百分比费用类动作编码为 `DICT_ASSEMBLY_MARKUP_FEE_CREATE`、`DICT_ASSEMBLY_MARKUP_FEE_UPDATE`、`DICT_ASSEMBLY_MARKUP_FEE_DELETE`，`targetType` 为 `dict_assembly_markup_fee`。
- 排查时可在 **系统 > 操作日志** 按模块 `DICT`、上述动作编码、操作人或 requestId 查询。

个人入口审计口径：

- `USER_PROFILE_UPDATE`：当前登录用户通过右上角个人入口更新自己的手机号、邮箱。
- 该动作归入 `SYSTEM` 模块，`targetType` 为 `system_user`，`before/after` 只记录 `phone`、`email` 摘要。
- 个人入口不能修改部门、岗位、角色、权限、数据范围或启用状态；这些管理员治理动作仍分别通过用户管理、组织档案、角色管理记录。
- 排查时可按动作 `USER_PROFILE_UPDATE`、操作人或 requestId 查询；严禁在操作日志或文件日志中记录密码、token、Authorization header、Cookie。

提单相关审计口径：

- `order_delivery_ticket` 是不可逆发布记录，也是 MES/WMS 对接需求池和工艺快照来源。
- `order_process_sheet` 已通过 `V36__decommission_order_process_sheet.sql` 在回填快照后删除；新提单的 QPO 工艺表展示/导出从 `order_delivery_ticket` 动态生成。
- 分批提单通过累计提单数量和剩余可提数量控制；操作日志应记录本次生成数量和剩余摘要。
- 多订单议价提单仍是前端按订单分组调用现有生成接口：批量候选零件分页、订单选择、跨订单导入匹配不新增操作日志；实际生成时继续写入 `DELIVERY_TICKET_GENERATE`，并按订单分别产生审计记录。
- 议价提单生成前的单行版本修改写入 `RELEASE_ITEM_VERSION_UPDATE`，摘要只记录 `rfqId`、`rfqNo`、`itemId`、`partNo`、`beforeVersion`、`afterVersion`。
- 议价提单导入替换图纸写入 `RELEASE_DRAWING_REPLACE`，摘要只记录 `sources`、`rfqIds`、`salesOrderIds`、上传数量、匹配数量、替换数量、未匹配数量和跳过数量；不得记录 PDF 内容、文件字节、完整请求体、Authorization header、token 或 Cookie。
- 议价提单表格数据替换的 `item-data-replacement` preview 只做解析和差异预览，不写操作日志；无 RFQ 数据权限时由后端数据范围校验直接拒绝，不能通过构造 RFQ ID 预览。confirm 只有业务字段实际保存时写入 `RELEASE_ITEM_DATA_REPLACEMENT`，摘要只保留 `rfqIds`、`importedCount`、`matchedCount`、`updatedItemCount`、`quantityAppliedCount`、`unmatchedCount`、`skippedCount`、`changedFieldCounts`，不得记录完整 Excel、完整 multipart 请求体、完整业务体、Authorization header、token 或 Cookie。
- 提单表据导出写入操作日志，动作编码为 `DELIVERY_TICKET_EXPORT`、`DELIVERY_PROCESS_SHEET_EXPORT`；RFQ 来源 `targetType` 为 `order_rfq`，销售订单来源 `targetType` 为 `sales_order_header`。摘要只记录 `sourceType`、`sourceOrderId`、`sourceOrderNo`、`status`、`exportType` 和 `rowCount`。
- 提单表据页面打开、客户/订单选择、摘要和分页查询不新增操作日志；只有导出动作写入上述业务审计记录。
- 订单最终状态仍使用 `已生成提单`，零件最终状态使用 `已提单`。
- `market:release:reset` 已废弃；操作日志中旧删除/重置动作仅作为历史查询，不再新增。

MES 物料号同步审计口径：

- MES 物料号同步是已提零件模块下的受控写操作，权限点为 `market:delivered-item:mes-sync`。
- MES 同图号版本去重不新增用户权限，继续使用 `market:delivered-item:mes-sync`；MES 回调接口使用 `QPO_OPEN_API_TOKEN`，不进入用户权限树。
- MES 去重只负责活动主请求和 follower；已确认物料号复用由 RFQ 重复件核价和销售订单导入自动快照补全在提单前完成，不在已提零件 MES 日志中重复记录。
- 操作日志动作：`DELIVERY_MES_MATERIAL_SYNC_SUBMIT`、`DELIVERY_MES_MATERIAL_SYNC_SUCCESS`、`DELIVERY_MES_MATERIAL_SYNC_ACCEPTED`、`DELIVERY_MES_MATERIAL_SYNC_FAILED`、`DELIVERY_MES_MATERIAL_CALLBACK_SUCCESS`、`DELIVERY_MES_MATERIAL_CALLBACK_FAILED`、`DELIVERY_MES_MATERIAL_CALLBACK_CONFLICT`、`DELIVERY_MES_MATERIAL_DEDUP_FOLLOW`、`DELIVERY_MES_MATERIAL_DEDUP_FANOUT`。
- 该动作归入 `DELIVERY` 模块，`targetType` 为 `order_delivery_ticket`，`targetId` 为提单行 ID。
- 操作日志摘要应包含 `ticketId`、`taskId`、`mesRequestId`、`rfqId`、`partNo`、`version`、`internalProjectNo`，成功时可记录 `materialNo`；去重摘要可记录 `dedupKey`、`masterTicketId`、`masterMesRequestId`，批量任务摘要可记录 `callbackPendingCount`、`dedupFollowerCount`、`submittedToMesCount`，不得记录 MES token、QPO 入站开放接口统一 token、Authorization header、完整请求体或完整回调体。
- 来源主表物料号回写是 MES 物料号同步成功链路的一部分，不新增单独操作日志动作：RFQ 来源写回 `item_quote_version.material_no / material_no_status`，销售订单来源写回 `sales_order_item.material_no / material_no_status`。询价订单详情和零件分页只读展示物料号状态，不写操作日志，也不新增高频业务 INFO。
- 排查时先在 **已提零件** 页面或 **系统 > 操作日志** 拿到 `taskId` / `requestId` / `mesRequestId` / `dedupKey`，再到后端文件日志按 `MES material sync`、`MES material callback`、`MES material dedup`、`System task failed`、`taskId`、`requestId`、`mesRequestId` 或 `dedupKey` 关联查询。

WMS 锁库分配审计口径：

- WMS 锁库分配是已提零件模块下的受控写操作，权限点为 `market:delivered-item:wms-allocate`。
- 操作日志动作：`DELIVERY_WMS_ALLOCATION_SUBMIT`、`DELIVERY_WMS_ALLOCATION_SUCCESS`、`DELIVERY_WMS_ALLOCATION_FAILED`、`DELIVERY_WMS_ALLOCATION_RESULT_UNKNOWN`、`DELIVERY_WMS_ALLOCATION_APPLY_FAILED`、`DELIVERY_WMS_ALLOCATION_RECONCILED`。
- 该动作归入 `DELIVERY` 模块，`targetType` 为 `order_delivery_ticket`，`targetId` 为提单行 ID；拆分结果写入 `order_delivery_ticket_allocation`。
- 操作日志摘要应包含 `ticketId`、`taskId`、`rfqId`、`materialNo`、`demandQty`，成功时记录 `allocationCount`、`inStockQty`、`inProductionQty`、`productionRequiredQty`，不得记录 WMS token、Authorization header 或完整请求/响应 JSON。
- 排查时先在 **已提零件** 页面或 **系统 > 操作日志** 拿到 `taskId`、`batchId`、`externalBizId`、`saleOrderNo`、`requestId`，再按 `WMS reservation batch`、`taskType=WMS_ALLOCATION_BATCH`、`status`、`durationMs` 关联文件日志和错误堆栈。

待产零件 MES 生产下发审计口径：

- 待产零件 MES 生产下发是待产零件模块下的受控写操作，权限点为 `market:production-item:mes-production-submit`。
- 操作日志动作：`PRODUCTION_ITEM_MES_PRODUCTION_SUBMIT`、`PRODUCTION_ITEM_MES_PRODUCTION_SUCCESS`、`PRODUCTION_ITEM_MES_PRODUCTION_FAILED`。
- 该动作归入 `DELIVERY` 模块，`targetType` 为 `order_delivery_ticket_allocation`，`targetId` 为 allocation ID；批量提交时可在摘要中记录 `taskId` 和首个 `allocationId`。
- 操作日志摘要应包含 `taskId`、`allocationId`、`ticketId`、`requestId`、`sourceType`、`sourceOrderId`、`sourceItemId`、`productionQty`、`ticketQty`，成功时可记录 `externalId`；批量汇总可记录 `successCount`、`failedCount`、`skippedCount`。
- 只记录生产下发摘要，不得记录 token、Authorization header、完整请求体或完整响应体。
- 排查时先在 **锁库零件** 页面或 **系统 > 操作日志** 拿到 `allocationId`、`ticketId`、`taskId`、`requestId`，再到后端文件日志按 `MES production dispatch`、`allocationId`、`taskId`、`requestId` 关联查询；失败堆栈进入 `qpo-error.log`。

订单状态管理审计口径：

- 询价订单新增 `废弃` 状态，用于停止订单继续流转但保留全部业务内容。
- 状态管理只改订单和非提单零件状态，不清空核价、报价交期、图纸、材料、工艺、提单快照等业务字段。
- `部分已提单` / `已生成提单` 不允许废弃或回退；只要订单存在 `order_delivery_ticket` 提单行，即使订单状态异常也必须拒绝状态动作。
- 操作日志动作：`ORDER_STATUS_ROLLBACK_QUOTED`、`ORDER_STATUS_ROLLBACK_PRICED`、`ORDER_DISCARD`、`ORDER_RESTORE`。
- 排查时可在 **系统 > 操作日志** 按模块 `ORDER`、动作编码、操作人、对象 ID 或 requestId 查询；详情里的 before/after 展示状态变化、更新零件数和提单行数量摘要。

组织档案审计口径：

- 组织档案用于维护用户的部门、岗位身份字典；这些动作在 **系统 > 操作日志** 中归入系统治理类事件。
- 部门动作：`SYSTEM_DEPT_CREATE`、`SYSTEM_DEPT_UPDATE`、`SYSTEM_DEPT_ENABLE`、`SYSTEM_DEPT_DISABLE`、`SYSTEM_DEPT_DELETE`。
- 岗位动作：`SYSTEM_POST_CREATE`、`SYSTEM_POST_UPDATE`、`SYSTEM_POST_ENABLE`、`SYSTEM_POST_DISABLE`、`SYSTEM_POST_DELETE`。
- 用户组织属性变更：`SYSTEM_USER_ORG_UPDATE`，用于追踪用户部门、岗位、真实姓名、手机号、邮箱等组织身份资料调整。
- 排查时可按模块 `SYSTEM`、动作编码、操作人或 requestId 筛选；部门和岗位是身份属性，不作为订单数据范围。

客户资料阶段 4 U9 只读收口：

- 客户资料来自 U9 只读缓存；普通客户资料分页查询不写操作日志，客户选项查询不写操作日志，客户选择弹窗不写操作日志。
- QPO 不再记录客户本地新增、编辑、删除动作，因为后端不再提供对应写接口。
- 手动同步 U9 客户写入 `U9_CUSTOMER_SYNC`，归入 `SYSTEM` 模块，`targetType` 为 `u9_master_data_sync_run`。
- 更新 U9 客户定时同步策略写入 `U9_CUSTOMER_SYNC_SCHEDULE_UPDATE`，归入 `SYSTEM` 模块，`targetType` 为 `u9_customer_sync_schedule_config`，只记录 `enabled`、`startupDelayMs`、`fixedDelayMs`、`lastScheduledStatus` 等安全摘要；读取策略、后台定时巡检和普通客户查询不写操作日志。
- 操作日志只记录 `syncRunId`、`syncType`、`status`、`fetchedCount`、`upsertedCount`、`disabledCount`、`safeMessage` 等安全摘要。
- 后端文件日志只记录同步批次摘要，例如 `U9 customer sync started syncRunId={}` 和 `U9 customer sync completed syncRunId={} fetchedCount={} upsertedCount={} disabledCount={}`。
- 不记录完整 U9 请求、响应、token、Authorization、Cookie、client secret 或 Data.Headers。

U9 客户主数据与同步选项缓存阶段 8 收口：普通主数据查询不产生操作日志噪声，客户资料分页、客户选项、Seller / SaleDepartment 选项和 U9 预览读取都只作为普通读取处理；写操作只记录安全摘要。敏感信息扫描测试覆盖 U9 客户同步、U9 选项刷新和销售订单 U9 同步，禁止完整 U9 请求、完整 U9 响应、token、Authorization header、Cookie、client secret、账号密码、完整业务请求体或完整业务响应体进入操作日志和文件日志。

出站接口配置审计口径：

- 出站接口配置属于系统治理动作，页面入口为 **系统 > 系统配置 > 出站接口**，权限点为 `system:config:integration:update`、`system:config:integration:test`、`system:config:integration:activate`。
- 操作日志动作：`SYSTEM_INTEGRATION_CONFIG_CREATE`、`SYSTEM_INTEGRATION_CONFIG_UPDATE`、`SYSTEM_INTEGRATION_CONFIG_TEST`、`SYSTEM_INTEGRATION_CONFIG_TEST_FAILED`、`SYSTEM_INTEGRATION_CONFIG_ACTIVATE`、`SYSTEM_INTEGRATION_CONFIG_DISABLE`。
- 该动作归入 `SYSTEM` 模块，`targetType` 为 `system_external_integration_config`，`targetId` 为配置 ID；摘要只记录 `systemCode`、`configId`、`active/enabled`、host/path、timeout、测试状态和脱敏失败摘要。
- MES/U9 业务调用优先使用页面激活的 DB 配置；没有 active DB 配置时才回退到 `erp.env` 中的 `ERP_MES_*`、`ERP_U9_*`。WMS 库存锁库只走数据中心 `WMS_INVENTORY_ALLOCATE`，排查 path 时检查 `ERP_DATA_CENTER_WMS_ALLOCATION_PATH` 或页面 endpoint 配置。
- **系统配置 > U9配置** 只维护 QPO 调用数据中心时使用的 U9 组织编码，不维护 U9 连接、认证、密钥或超时参数；保存动作记录 `SYSTEM_U9_ORG_CONFIG_UPDATE`，`targetType=u9_runtime_config`，摘要只包含变更前后的 `orgCode`。客户、Seller、SaleDepartment、销售订单同步前校验和 U9 核对读取组织编码属于运行时普通读取，不新增操作日志或高频文件日志。
- U9 客户定时同步优先使用客户资料页保存的 `u9_customer_sync_schedule_config`；`ERP_U9_CUSTOMER_SYNC_*` 只在配置行缺失时作为兜底默认值。排查定时同步间隔时先看页面策略，再看环境变量和后台巡检频率 `ERP_U9_CUSTOMER_SYNC_CHECK_MS`。
- 后端文件日志只记录 `Integration config created/updated/tested/activated/disabled` 级别摘要，不记录 token、clientSecret、Authorization header、完整请求体或完整响应体。
- 数据中心连接配置已进入后端治理链路，操作日志动作：`SYSTEM_DATA_CENTER_CONFIG_CREATE`、`SYSTEM_DATA_CENTER_CONFIG_UPDATE`、`SYSTEM_DATA_CENTER_CONFIG_TEST`、`SYSTEM_DATA_CENTER_CONFIG_TEST_FAILED`、`SYSTEM_DATA_CENTER_CONFIG_ACTIVATE`、`SYSTEM_DATA_CENTER_CONFIG_DISABLE`。
- 数据中心连接配置归入 `SYSTEM` 模块，`targetType` 为 `system_data_center_config`，摘要只记录 `configId`、`active/enabled`、baseUrl/tokenUrl、clientId、timeout、token 测试状态和脱敏失败摘要，不记录 `client_secret`、access token 或 Authorization header。
- 后端文件日志只记录 `Data center config created/updated/token test completed/token test failed/activated/disabled` 级别摘要，不记录完整 token 响应、完整请求体或真实密钥；没有 active DB 配置时才回退到 `ERP_DATA_CENTER_*`。
- 数据中心功能接口配置归入 `SYSTEM` 模块，操作日志动作：`SYSTEM_DATA_CENTER_ENDPOINT_UPDATE`、`SYSTEM_DATA_CENTER_ENDPOINT_TEST`、`SYSTEM_DATA_CENTER_ENDPOINT_TEST_FAILED`；`targetType` 为 `system_data_center_endpoint_config`。
- 功能接口配置和统一 client 文件日志只记录 `endpointCode`、`targetSystemCode`、host、path、timeout 和脱敏摘要，不记录 access token、Authorization header、完整业务请求体或完整业务响应体；接口测试只校验 token 和 path 配置完整性，不产生真实业务写入。
- 数据中心统一对接阶段 8 收口：QPO 出站调用统一走数据中心；操作日志和文件日志不得记录 `client_secret`、access token、QPO 入站开放接口统一 token、Authorization header 或完整请求/响应体。

入站接口配置审计口径：

- 入站接口配置属于系统治理动作，页面入口为 **系统 > 系统配置 > 入站接口**，用于维护 QPO 入站开放接口统一 token 状态，以及 MES 物料号回调、销售订单外部同步等入站接口的 URL、启停状态和接口元数据。
- 操作日志动作：`SYSTEM_INBOUND_CALLBACK_CONFIG_UPDATE`、`SYSTEM_INBOUND_CALLBACK_TOKEN_ROTATE`、`SYSTEM_INBOUND_CALLBACK_CONFIG_VALIDATE`。
- 该动作归入 `SYSTEM` 模块，`targetType` 为 `system_inbound_callback_config`，`targetId` 为配置 ID；摘要只记录 `callbackCode`、`sourceSystemCode`、`enabled`、`authMode`、`tokenConfigured`、`tokenRotated`、`configSource`、接口 path、校验状态和脱敏失败摘要。统一 token 明文、token hash、Authorization header 和完整入站请求体不得写入操作日志。
- 生成或轮换 token 时，明文 token 只允许接口响应返回一次给前端弹窗；操作日志不得记录真实 token、token hash、Authorization header 或完整回调体。
- 后端文件日志只记录 `Inbound callback config updated/open API token rotated/config validated` 级别摘要；不得输出 token、token hash、Authorization header 或完整请求体。

保留策略在页面中配置。当前策略设计为：

- 默认关闭自动清理。
- 默认在线保留 180 天。
- 开启自动清理后，到期日志先按配置归档 CSV，再从在线库删除。
- 归档文件默认在容器内 `/data/backups/audit-logs/<yyyyMMdd>/`。

## 3. 后端运行日志

后端文件日志位于 backend 容器内：

```text
/data/backups/logs/backend/
```

常用命令：

```powershell
docker exec quote-backend sh -lc "ls -lh /data/backups/logs/backend"
docker exec quote-backend sh -lc "tail -n 200 /data/backups/logs/backend/qpo-backend.log"
docker exec quote-backend sh -lc "tail -n 200 /data/backups/logs/backend/qpo-error.log"
```

文件说明：

| 文件 | 内容 |
| --- | --- |
| `qpo-backend.log` | INFO/WARN/ERROR 级别后端运行日志 |
| `qpo-error.log` | ERROR 级别错误日志和异常堆栈 |
| `archive/*.gz` | 按日期和大小滚动后的历史日志 |

日志格式包含 `requestId`，例如：

```text
2026-07-17 20:11:54.085 INFO [http-nio-8080-exec-2] [requestId=stage-6-1-check] ...
```

如果页面操作日志中有 requestId，可以用它反查后端文件日志：

```powershell
docker exec quote-backend sh -lc "grep -R 'requestId值' /data/backups/logs/backend"
```

如果先在 `qpo-error.log` 中发现 requestId，也可以复制该值到 **系统 > 操作日志** 的 `Request ID` 筛选框，反查对应业务审计记录。

## 5. Postgres 慢 SQL 与锁等待日志

Postgres 日志输出到 Docker 容器日志，通过以下命令查看：

```powershell
docker logs quote-postgres
```

筛选慢 SQL：

```powershell
docker logs quote-postgres 2>&1 | Select-String "duration:"
```

筛选锁等待：

```powershell
docker logs quote-postgres 2>&1 | Select-String "lock"
```

当前 Compose 配置只打开轻量排查项：

- `log_min_duration_statement=${POSTGRES_LOG_MIN_DURATION_STATEMENT_MS:-500}`：记录超过阈值的 SQL。
- `log_statement=none`：不记录每条 SQL，避免日志爆炸。
- `log_lock_waits=on`：记录锁等待。
- `deadlock_timeout=${POSTGRES_DEADLOCK_TIMEOUT:-1s}`：锁等待超过阈值后记录。
- `log_timezone=Asia/Shanghai`：数据库日志使用北京时间。

本地 `erp.env` 建议值：

```env
POSTGRES_LOG_MIN_DURATION_STATEMENT_MS=500
POSTGRES_DEADLOCK_TIMEOUT=1s
```

如果慢 SQL 日志过多，可以把阈值调高：

```env
POSTGRES_LOG_MIN_DURATION_STATEMENT_MS=1000
```

| --- | --- |

## 8. 注意事项

- 不要打开 `log_statement=all`，否则会记录大量 SQL，并可能泄露业务数据。
- 不要把 JWT、Authorization header、密码、上传文件内容写入任何日志。
- 后端运行日志与操作日志可以通过 requestId 关联，但职责保持分离。
- 当前日志文件存放在 Docker named volume 中，不改成 Windows 可见目录挂载。
## 9. 主流程文件日志事件命名

主流程文件日志统一采用“英文事件名 + key=value”的稳定格式，便于 `grep` 和跨日志关联。新增业务日志时优先沿用下列命名风格：

| 场景 | 事件名前缀示例 | 关键字段 |

| 生成核价单 | `Pricing sheet export started/completed/rejected/failed` | `rfqId`、`status`、`itemCount`、`durationMs` |
| 后台任务 | `System task submitted/started/completed/failed` | `taskId`、`taskType`、`durationMs`、`filePath` |
| MES物料号同步 | `MES material sync submitted/started/completed/accepted/rejected/failed`、`MES material callback received/completed/rejected/conflict`、`MES material dedup master/follow/fanout` | `ticketId`、`taskId`、`mesRequestId`、`rfqId`、`partNo`、`materialNo`、`sourceType`、`sourceItemId`、`dedupKey`、`callbackPendingCount`、`dedupFollowerCount`、`submittedToMesCount`、`durationMs` |

| 待产零件MES生产下发 | `MES production dispatch submitted/started/completed/skipped/failed` | `allocationId`、`ticketId`、`taskId`、`requestId`、`sourceType`、`sourceOrderId`、`sourceItemId`、`productionQty`、`ticketQty`、`externalId`、`durationMs` |

| 提单与交期 | `Delivery ticket generation started/completed/failed`、`Quote lead time set` | `rfqId`、`selectedItemCount`、`ticketCount`、`dynamicProcessSheetCount`、`remainingItemCount`、`toOrderStatus` |

| 系统治理 | `System governance action completed`、`Department created/updated/deleted` | `action`、`deptId`、`deptCode`、`deptName` |

- 正常列表查询、字典查询、健康检查不加业务 INFO。

- 严禁记录密码、JWT、Authorization header、Cookie、上传文件内容和完整 Excel/JSON 明细。

## 11. 销售订单 U9 同步审计口径

- 旧 Excel 直连 U9 导入接口 `/api/market/sales-orders/import` 已下线；销售订单导入只记录 `SALES_ORDER_IMPORT_QPO`，销售订单 U9 同步模块的写操作记录 `U9_SYNC_OPTIONS_REFRESH`、`SALES_ORDER_U9_ASSIGNMENT_UPDATE`、`SALES_ORDER_U9_SYNC` 和 `SALES_ORDER_U9_RECONCILE`。
- 旧阶段 5 历史直连 U9 过渡口径只作为兼容保留，不创建 QPO 订单、不进入议价提单，摘要保留 `batchNo`、`successOrderCount`、`failedOrderCount`，不记录完整 Excel 内容、U9 token、clientsecret 或完整 U9 请求体。
- 独立销售订单 U9 同步动作编码为 `SALES_ORDER_U9_SYNC`，模块为 `MARKET`，`targetType` 为 `sales_order_header`。
- U9 同步页 Seller / SaleDepartment 选项缓存手动刷新动作编码为 `U9_SYNC_OPTIONS_REFRESH`，模块为 `MARKET`，`targetType` 为 `u9_master_data_sync_run`；摘要只记录 `syncRunId`、`syncType`、`status`、`fetchedCount`、`upsertedCount`、`disabledCount`、`safeMessage`，不记录完整 U9 主数据、完整请求或完整响应。
- Seller / SaleDepartment 保存动作编码为 `SALES_ORDER_U9_ASSIGNMENT_UPDATE`；摘要只记录销售订单 ID/编号、Seller 编码/名称和 SaleDepartment 编码/名称，允许为空，不记录完整选项缓存或 U9 原始主数据。
- 结果待确认核对动作编码为 `SALES_ORDER_U9_RECONCILE`；摘要只记录销售订单 ID/编号、attemptId、resultCode、u9SyncStatus、U9 编码样本、消息摘要和耗时，不记录完整 U9 查询响应。
- U9 同步独立模块口径只记录 `totalOrderCount`、`successOrderCount`、`failedOrderCount`、`salesOrderNoSample`、`u9OrderCodeSample`、`durationMs` 等排查字段。
- 预览、选项读取和列表刷新不写操作日志，不新增高频业务 INFO；手动刷新选项缓存属于低频写操作，只记录同步批次摘要。
- 不记录完整 Excel 内容、U9 token、clientsecret、完整 U9 请求体、完整 U9 响应大对象、Authorization header 或 Cookie。
- 独立销售订单同步从 `sales_order_header` / `sales_order_item` 组装请求，`ItemCode` 使用 `sales_order_item.material_no`，且要求 `material_no_status = 已确认`；`FinallyPriceTC` 使用 `sales_order_item.untaxed_unit_price`；不得实时从 `order_delivery_ticket.material_no` 组装 U9 请求。
- 运维排查时先在 **系统 > 操作日志** 按 `U9_SYNC_OPTIONS_REFRESH`、`SALES_ORDER_U9_SYNC`、`SALES_ORDER_U9_ASSIGNMENT_UPDATE`、`SALES_ORDER_U9_RECONCILE`、销售订单号或 requestId 查询，再到后端文件日志按 `U9 sync options refresh`、`Sales order U9 sync` 和 `orderCount` / `durationMs` 关联。

## 12. requestId + taskId + audit_log 关联排查方法

推荐从用户现象出发按以下顺序排查：

1. 在 **系统 > 操作日志** 按操作人、模块、动作或 `Request ID` 找到业务动作。
2. 复制操作日志中的 requestId，到后端文件日志里查同一次请求的主流程事件。
3. 如果该动作提交了后台任务，先在操作日志详情或业务页面拿到 taskId，再查 `System task submitted/started/completed/failed`。
4. 如果是 MES/WMS 任务，同时记录 `ticketId`：用 `ticketId` 定位同一条已提零件，用 `taskId` 定位本次异步任务，用 `requestId` 定位触发任务的页面请求。
5. 如果 `qpo-error.log` 里先出现异常，复制其中的 requestId 反查操作日志；如果异常里有 taskId，再继续查任务生命周期。
6. 如果日志显示数据库耗时或锁等待，再去 `docker logs quote-postgres` 查 `duration:` 或 `lock`。

常见组合：

```text
操作日志 audit_log.request_id
  -> qpo-backend.log requestId=...
  -> qpo-backend.log taskId=...
  -> qpo-backend.log ticketId=...
  -> qpo-error.log taskId=... / requestId=...
  -> docker logs quote-postgres duration: / lock
```

## 13. 销售订单 QPO 导入审计口径

- 销售订单导入独立主表写入操作日志，动作编码为 `SALES_ORDER_IMPORT_QPO`，模块为 `MARKET`，`targetType` 为 `sales_order_import_batch`。
- 操作日志摘要只记录 `batchNo`、`sourceFileName`、`customerCode`、`customerName`、`documentTypeCode`、`totalOrderCount`、`successOrderCount`、`failedOrderCount`、`salesOrderNos`、`matchedItemCount`、`unmatchedItemCount`、`durationMs` 等排查字段。
- 不记录完整 Excel 内容、完整行明细、图纸文件内容、token、Authorization header、Cookie 或完整请求体。
- 第一阶段销售订单导入只落地独立主表骨架并隔离旧 RFQ 写入方向；实际独立表写入接入后也不调用 U9，后续 U9 同步在独立 `U9同步` 模块内授权和执行，排查按 `SALES_ORDER_U9_SYNC` 和独立 U9 文件日志口径处理。
- 文件日志事件名使用 `Sales order QPO import started/parsed/enriched/completed/rejected/failed`，只记录批次级摘要，保持低噪声。

## 14. 销售订单独立主表阶段 8 回归收口

- 销售订单独立主表阶段 8 回归收口确认：`SALES_ORDER_IMPORT_QPO` 只记录独立主表导入摘要，`SALES_ORDER_U9_SYNC` 只记录独立销售订单 U9 同步摘要；销售订单数据不进入 `order_rfq` / `item_quote_version`。
- RFQ 导入、核价、报价、议价提单、提单表据、已提零件、锁库零件原流程继续使用既有动作编码和日志口径，不因销售订单独立主表切换而回退。
- 日志不记录 token、密钥或完整请求体，不记录完整 Excel 内容、完整 U9 请求/响应或客户敏感大对象。

## 15. 销售订单管理审计口径

- 销售订单管理只治理 `sales_order_header` / `sales_order_item`，不写入 RFQ 主表或询价零件表。
- 废弃销售订单动作编码为 `SALES_ORDER_DISCARD`，模块为 `MARKET`，`targetType` 为 `sales_order_header`；只允许 `已生成提单` 且 U9 未同步成功的销售订单。
- 恢复销售订单动作编码为 `SALES_ORDER_RESTORE`，模块为 `MARKET`，`targetType` 为 `sales_order_header`；只允许 `废弃` 恢复为 `已生成提单`。
- 销售订单补传图纸动作编码为 `SALES_ORDER_DRAWING_SUPPLEMENT`，模块为 `MARKET`，`targetType` 为 `sales_order_header`，`targetId` 为销售订单 ID；接口按整单匹配缺图零件，图纸仍绑定到 `sales_order_item.drawing_url`，并同步 `has_drawing=true`。
- 文件日志事件名使用 `Sales order status change started/completed/rejected` 和 `Sales order drawing supplement completed`，只记录订单 ID、状态、上传数量、绑定数量、已跳过数量、未匹配数量、跳过数量和耗时摘要，不记录文件内容或完整请求体。

## 16. RFQ 派生销售订单与 U9 日志收口

- RFQ 议价提单生成一张派生销售订单属于议价提单写操作，操作日志只记录批次摘要、销售订单 ID/编号、来源 RFQ 数量、提单行数量和事务结果。
- MES 双写、U9 预览阻断和 U9 状态回写只记录安全摘要；普通订单选择、客户选择、列表刷新、详情读取和只读跳转不记操作日志。
- 文件日志不记录 token、密钥、Authorization header、完整 Excel、完整外部请求体或完整外部响应体。
