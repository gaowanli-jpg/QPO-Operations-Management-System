# QPO 日志运维说明

## 1. 日志类型与入口

QPO 当前保留三类日志，各自职责不同：

| 日志类型 | 查看方式 | 主要用途 |
| --- | --- | --- |
| 操作日志 | 系统页面：系统 > 操作日志 | 查询谁在什么时候做了什么业务动作 |
| 后端运行日志 | 容器内 `/data/backups/logs/backend/` | 排查 Java 后端接口、任务、异常和 requestId |
| Postgres 慢 SQL / 锁等待日志 | `docker logs quote-postgres` | 排查数据库慢查询、锁等待、死锁相关问题 |

操作日志用于业务审计，后端运行日志和数据库日志用于运维排查；不要把所有运行日志写入 `audit_log`。

## 2. 操作日志

系统管理员在页面查看：

```text
系统 > 操作日志
```

适合查询：

- 登录成功、登录失败、账号锁定、登出。
- 用户、字典、报价模板、RFQ 导入、报价处理、提单等关键业务动作。
- 日志保留策略修改、手动归档清理等系统动作。

保留策略在页面中配置。当前策略设计为：

- 默认关闭自动清理。
- 默认在线保留 180 天。
- 开启自动清理后，到期日志先按配置归档 CSV，再从在线库删除。
- 归档文件默认在容器内 `/data/backups/audit-logs/<yyyyMMdd>/`。

## 3. 后端运行日志

后端文件日志位于 backend 容器内：

```text
/data/backups/logs/backend/
```

常用命令：

```powershell
docker exec quote-backend sh -lc "ls -lh /data/backups/logs/backend"
docker exec quote-backend sh -lc "tail -n 200 /data/backups/logs/backend/qpo-backend.log"
docker exec quote-backend sh -lc "tail -n 200 /data/backups/logs/backend/qpo-error.log"
```

文件说明：

| 文件 | 内容 |
| --- | --- |
| `qpo-backend.log` | INFO/WARN/ERROR 级别后端运行日志 |
| `qpo-error.log` | ERROR 级别错误日志和异常堆栈 |
| `archive/*.gz` | 按日期和大小滚动后的历史日志 |

日志格式包含 `requestId`，例如：

```text
2026-07-17 20:11:54.085 INFO [http-nio-8080-exec-2] [requestId=stage-6-1-check] ...
```

如果页面操作日志中有 requestId，可以用它反查后端文件日志：

```powershell
docker exec quote-backend sh -lc "grep -R 'requestId值' /data/backups/logs/backend"
```

如果先在 `qpo-error.log` 中发现 requestId，也可以复制该值到 **系统 > 操作日志** 的 `Request ID` 筛选框，反查对应业务审计记录。

## 4. Docker 容器日志

容器控制台日志仍然可用：

```powershell
docker logs quote-backend
docker logs quote-postgres
docker logs quote-frontend
```

查看最近日志：

```powershell
docker logs --tail 200 quote-backend
docker logs --tail 200 quote-postgres
```

实时跟随：

```powershell
docker logs -f quote-backend
docker logs -f quote-postgres
```

Docker `json-file` 日志轮转由 `erp.env` 控制：

```env
LOG_MAX_SIZE=20m
LOG_MAX_FILE=5
```

总保留空间约为：

```text
LOG_MAX_SIZE * LOG_MAX_FILE
```

## 5. Postgres 慢 SQL 与锁等待日志

Postgres 日志输出到 Docker 容器日志，通过以下命令查看：

```powershell
docker logs quote-postgres
```

筛选慢 SQL：

```powershell
docker logs quote-postgres 2>&1 | Select-String "duration:"
```

筛选锁等待：

```powershell
docker logs quote-postgres 2>&1 | Select-String "lock"
```

当前 Compose 配置只打开轻量排查项：

- `log_min_duration_statement=${POSTGRES_LOG_MIN_DURATION_STATEMENT_MS:-500}`：记录超过阈值的 SQL。
- `log_statement=none`：不记录每条 SQL，避免日志爆炸。
- `log_lock_waits=on`：记录锁等待。
- `deadlock_timeout=${POSTGRES_DEADLOCK_TIMEOUT:-1s}`：锁等待超过阈值后记录。
- `log_timezone=Asia/Shanghai`：数据库日志使用北京时间。

本地 `erp.env` 建议值：

```env
POSTGRES_LOG_MIN_DURATION_STATEMENT_MS=500
POSTGRES_DEADLOCK_TIMEOUT=1s
```

如果慢 SQL 日志过多，可以把阈值调高：

```env
POSTGRES_LOG_MIN_DURATION_STATEMENT_MS=1000
```

## 6. 常用验收命令

重建 Postgres 和 backend：

```powershell
docker compose --env-file erp.env up -d --build postgres backend
```

确认 Postgres 正常启动：

```powershell
docker logs --tail 80 quote-postgres
```

人工触发慢 SQL：

```powershell
docker exec quote-postgres psql -U postgres -d postgres -c "SELECT pg_sleep(0.7);"
```

确认出现 `duration:`：

```powershell
docker logs quote-postgres 2>&1 | Select-String "duration:"
```

确认未打开全量 SQL：

```powershell
docker exec quote-postgres psql -U postgres -d postgres -c "SHOW log_statement;"
```

预期结果：

```text
none
```

## 7. 保留策略汇总

| 日志类型 | 保留策略 |
| --- | --- |
| Docker json-file | `LOG_MAX_SIZE * LOG_MAX_FILE` |
| 后端文件日志 | `LOG_FILE_MAX_HISTORY`，默认 30 天 |
| 操作日志 | 系统页面保留策略配置，默认 180 天在线保留 |
| Postgres 慢 SQL / 锁等待日志 | 跟随 `quote-postgres` Docker json-file 轮转 |

## 8. 注意事项

- 不要打开 `log_statement=all`，否则会记录大量 SQL，并可能泄露业务数据。
- 不要把 JWT、Authorization header、密码、上传文件内容写入任何日志。
- 后端运行日志与操作日志可以通过 requestId 关联，但职责保持分离。
- 当前日志文件存放在 Docker named volume 中，不改成 Windows 可见目录挂载。
## 9. 主流程文件日志事件命名

主流程文件日志统一采用“英文事件名 + key=value”的稳定格式，便于 `grep` 和跨日志关联。新增业务日志时优先沿用下列命名风格：

| 场景 | 事件名前缀示例 | 关键字段 |
| --- | --- | --- |
| RFQ 导入 | `RFQ import started/completed/failed` | `rfqId`、`rfqNo`、`itemCount`、`durationMs` |
| 核价与刷新 | `Item quote saved`、`Order quote refresh completed` | `rfqId`、`itemId`、`partNo`、`skippedCount` |
| 后台任务 | `System task submitted/started/completed/failed` | `taskId`、`taskType`、`durationMs`、`filePath` |
| 提单与交期 | `Delivery ticket generation completed`、`Quote lead time set` | `rfqId`、`itemCount`、`ticketCount` |
| 日志清理 | `Audit log cleanup started/completed/failed` | `manual`、`retentionDays`、`deletedCount`、`archiveFile` |

新增日志时注意：

- 正常列表查询、字典查询、健康检查不加业务 INFO。
- 批量循环内不打 INFO，只在流程结束打汇总。
- 业务可恢复问题用 WARN，例如缺图、跳过无效文件、模板校验失败。
- 未预期失败用 ERROR，并把异常对象作为最后一个参数传给 logger。
- 严禁记录密码、JWT、Authorization header、Cookie、上传文件内容和完整 Excel/JSON 明细。

## 10. 常用 grep 示例

按 RFQ 导入排查：

```powershell
docker exec quote-backend sh -lc "grep -R 'RFQ import' /data/backups/logs/backend"
docker exec quote-backend sh -lc "grep -R 'rfqId=123' /data/backups/logs/backend"
```

按后台任务排查：

```powershell
docker exec quote-backend sh -lc "grep -R 'taskId=45' /data/backups/logs/backend"
docker exec quote-backend sh -lc "grep -R 'System task failed' /data/backups/logs/backend/qpo-error.log"
```

按操作日志清理排查：

```powershell
docker exec quote-backend sh -lc "grep -R 'Audit log cleanup' /data/backups/logs/backend"
```

按 requestId 排查一次页面请求：

```powershell
docker exec quote-backend sh -lc "grep -R 'requestId=页面上的requestId' /data/backups/logs/backend"
```

## 11. requestId + taskId + audit_log 关联排查方法

推荐从用户现象出发按以下顺序排查：

1. 在 **系统 > 操作日志** 按操作人、模块、动作或 `Request ID` 找到业务动作。
2. 复制操作日志中的 requestId，到后端文件日志里查同一次请求的主流程事件。
3. 如果该动作提交了后台任务，先在操作日志详情或业务页面拿到 taskId，再查 `System task submitted/started/completed/failed`。
4. 如果 `qpo-error.log` 里先出现异常，复制其中的 requestId 反查操作日志；如果异常里有 taskId，再继续查任务生命周期。
5. 如果日志显示数据库耗时或锁等待，再去 `docker logs quote-postgres` 查 `duration:` 或 `lock`。

常见组合：

```text
操作日志 audit_log.request_id
  -> qpo-backend.log requestId=...
  -> qpo-backend.log taskId=...
  -> qpo-error.log taskId=... / requestId=...
  -> docker logs quote-postgres duration: / lock
```
