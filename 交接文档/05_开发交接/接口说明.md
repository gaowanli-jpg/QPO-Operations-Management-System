# 接口说明

本文档说明 ERP 与 APS 两个系统的后端接口。接口以当前代码为准，主要用于前端维护、系统交接、跨系统对接和运维排查。

## 1. 通用约定

### 1.1 服务地址

| 系统 | 本地后端默认地址 | Docker 内部地址 | 前端访问方式 |
| --- | --- | --- | --- |
| ERP | `http://localhost:8080` | `http://quote-backend:8080` | 前端 Nginx 反代 `/api` |
| APS | `http://localhost:8091` | `http://aps-backend:8091` | 前端 Nginx 反代 `/api` |

正式部署时，用户通常访问外层 Nginx 的 HTTPS 域名。前端页面不应写死后端公网地址。

### 1.2 鉴权头

ERP 和 APS 的普通前端接口都使用登录后返回的 Token：

```text
Authorization: Bearer <JWT_TOKEN>
```

也兼容：

```text
X-Auth-Token: <JWT_TOKEN>
```

APS 调用 ERP 的跨系统接口使用服务端 Token：

```text
Authorization: Bearer <APS_ERP_AUTH_TOKEN>
```

ERP 侧校验变量：

```env
ERP_APS_SOURCE_TOKEN=
```

APS 侧发送变量：

```env
APS_ERP_AUTH_TOKEN=
```

两者必须一致。

### 1.3 公开接口

无需登录即可访问：

| 系统 | 接口 |
| --- | --- |
| ERP | `POST /api/auth/login` |
| ERP | `GET /api/health` |
| APS | `POST /api/auth/login` |
| APS | `GET /api/health` |

ERP 的 `/api/aps/source/**` 不是普通公开接口，它需要 APS 服务端 Token。

### 1.4 常见响应

普通 JSON 接口通常返回：

```json
{
  "success": true,
  "message": "操作成功",
  "data": {}
}
```

部分查询接口直接返回数组、分页对象或实体对象。

常见错误状态：

| 状态码 | 含义 |
| --- | --- |
| 400 | 请求参数错误或业务校验失败 |
| 401 | 未登录、Token 无效或跨系统 Token 错误 |
| 403 | 当前角色无权限 |
| 428 | 账号需要先修改初始密码 |
| 500 | 服务端异常 |

## 5. 接口维护注意事项

1. 前端新增接口调用应走统一请求封装，不直接写死后端地址。
2. ERP 与 APS 的跨系统接口不要绕过 Token 校验。
3. 新增 ERP 输出给 APS 的字段时，要同时改 ERP DTO、APS DTO、APS 同步逻辑、数据库迁移和文档。
4. 删除或改名 ERP 字典字段前，要确认 APS 同步是否依赖。
5. 文件下载接口需要保留 `Content-Disposition` 暴露头。
6. 生产环境 CORS 只配置正式前端地址。
7. 后端和数据库端口不直接暴露给用户网络。
