# 数据库表说明

本文档说明 ERP 与 APS 两个系统的数据库表用途、关键字段、上下游关系和维护注意事项。两个系统各自使用独立 PostgreSQL 数据库，不共享数据库表。

## 1. 数据库边界

| 系统 | 默认数据库 | 主要职责 |
| --- | --- | --- |
| ERP | `postgres` | 订单、报价、工程核价、交付单、工艺单、用户权限、审计 |
| APS | `aps` | ERP 同步、APS 工单、库存锁定、材料锁定、派工、部门、机台、APS 用户 |

维护原则：

- ERP 表只能由 ERP 后端维护。
- APS 表只能由 APS 后端维护。
- 跨系统数据通过接口同步，不直接跨库读写。
- 生产环境改表必须新增 Flyway 迁移，不直接手工改结构。
- 生产数据手工修复前必须先备份。

## 2. ERP 表

ERP 后端路径：

```text
D:\Code\quote-backend
```

ERP 迁移路径：

```text
D:\Code\quote-backend\src\main\resources\db\migration
```

### 2.1 order_rfq

用途：ERP 询价单或订单主表，是市场部新单导入后的主记录。

关键字段：

| 字段 | 说明 |
| --- | --- |
| `id` | 主键 |
| `rfq_no` | 询价单号，唯一 |
| `customer_name` | 客户名称 |
| `project_name` | 历史兼容字段，新单不以此作为核心项目名称 |
| `status` | 单据状态 |
| `engineer_config` | 工程部全局设定 JSON |
| `created_at` | 创建时间 |

上下游：

- 上游：市场部新单导入。
- 下游：报价项目、工程核价、交付单、工艺单。
- APS 同步时通过 `rfq_id` 关联获取客户和订单状态。

维护注意：

- `rfq_no` 不应手工重复。
- 单据状态会影响页面筛选和业务流程。
- `engineer_config` 是 JSONB，不能随意写入非法 JSON。

## 5. 不建议手工修改的表

以下表强烈不建议直接手工改生产数据：

- ERP：`order_rfq`
- ERP：`item_quote_version`
- ERP：`order_delivery_ticket`
- ERP：`order_process_sheet`
- APS：`aps_work_item`
- APS：`aps_work_item_process`
- APS：`aps_part_inventory_lock`
- APS：`aps_part_inventory_lock_detail`
- APS：`aps_material_lock`
- APS：`aps_department_assignment`
- APS：`aps_department_task`

原因：

- 这些表存在跨表一致性。
- 直接修改容易造成库存占用、派工占用、工序快照和同步记录不一致。
- 必要时应通过页面、接口或专门修复脚本处理。

## 6. 数据修复原则

如生产数据需要修复，建议流程：

1. 记录问题现象和影响范围。
2. 停止相关用户操作。
3. 执行 ERP 或 APS 手动备份。
4. 在测试库复现并验证修复 SQL。
5. 由负责人审核修复 SQL。
6. 在生产执行。
7. 执行页面验收。
8. 记录修复时间、人员、SQL 和结果。

不要在没有备份的情况下直接修改生产库。
