# 运维常见问题

本文档汇总 ERP 与 APS 在部署、启动、登录、数据库、备份恢复、跨系统同步和安全配置中常见的问题与处理方法。

## 2. 环境变量问题

### 2.1 ERP 和 APS 是否共用一个 env 文件？

不共用。

当前约定：

| 系统 | 环境变量文件 | Compose 文件 |
| --- | --- | --- |
| ERP | `D:\Code\erp.env` | `D:\Code\docker-compose.yml` |
| APS | `D:\Code\aps.env` | `D:\Code\docker-compose.aps.yml` |

原因：

- 两个系统数据库不同。
- 两个系统端口不同。
- 两个系统 JWT 密钥不同。
- 两个系统有不同的资源限制和备份策略。
- APS 与 ERP 的跨系统 Token 虽然要求一致，但不代表整个 env 文件共用。

### 2.2 env 文件从哪里来？

ERP：

```powershell
cd D:\Code
Copy-Item erp.env.example erp.env
notepad erp.env
```

APS：

```powershell
cd D:\Code
Copy-Item aps.env.example aps.env
notepad aps.env
```

必须填写生产值：

- 数据库密码。
- JWT 密钥。
- APS 与 ERP 对接 Token。
- 正式前端地址或 CORS 地址。

### 2.3 env 改了为什么没生效？

常见原因：

- 只改了 env，但没有重启容器。
- 改错文件，例如改了 `aps.env.example` 而不是 `aps.env`。
- Compose 命令没有带 `--env-file`。
- 旧容器仍在运行。

处理：

```powershell
cd D:\Code
docker compose --env-file aps.env -f docker-compose.aps.yml up -d --build
```

ERP 同理使用 `erp.env` 和 `docker-compose.yml`。

## 3. Docker 启动问题

### 3.1 docker compose up 后服务没起来

先看状态：

```powershell
docker compose --env-file aps.env -f docker-compose.aps.yml ps
```

再看日志：

```powershell
docker logs aps-backend --tail 200
docker logs aps-postgres --tail 200
docker logs aps-frontend --tail 200
```

常见原因：

- env 必填项为空。
- 数据库密码不匹配。
- 端口被占用。
- 镜像未拉取且服务器不能联网。
- 后端等待数据库健康检查超时。

### 3.2 端口被占用怎么办？

查看端口占用：

```powershell
netstat -ano | findstr :8095
```

处理方式：

- 停止占用端口的旧服务。
- 或修改 env 中的前端端口，例如 `APS_FRONTEND_PORT=8096`。

不要随意暴露后端端口和数据库端口给用户网络。

### 3.3 为什么后端和数据库端口看不到映射？

这是预期设计。

上线更安全的方式是：

- 只映射前端 Nginx 端口给宿主机或外层 Nginx。
- 后端只在 Docker 网络内部被前端 Nginx 访问。
- 数据库只在 Docker 网络内部被后端访问。

这样可以降低后端接口和数据库被直接访问的风险。

## 4. 数据库和 volume 问题

### 4.1 为什么 Docker 启动后还是旧数据库？

原因通常是 Docker volume 没变。

PostgreSQL 容器数据保存在 volume 中。只要 volume 名称不变，即使重新 build 镜像、重启容器，数据库仍然是原来的数据。

查看 volume：

```powershell
docker volume ls
```

APS 正式新库建议：

```env
APS_POSTGRES_VOLUME_NAME=aps_postgres_data_prod
```

ERP 正式库同理应使用部署规划中的生产 volume。

### 4.2 想要初始化全新 APS 库怎么办？

如果旧 APS 数据不需要保留：

1. 停止 APS。
2. 修改 `aps.env`：

```env
APS_POSTGRES_VOLUME_NAME=aps_postgres_data_prod
```

3. 启动 APS：

```powershell
cd D:\Code
docker compose --env-file aps.env -f docker-compose.aps.yml up -d --build
```

后端启动后 Flyway 会自动创建表并初始化默认管理员。

不要在生产误执行 `docker compose down -v`，该命令会删除数据库 volume。

### 4.3 数据库密码改了后启动失败

PostgreSQL volume 已初始化后，容器环境变量中的密码改变，不一定会自动修改数据库内部已有用户密码。

常见表现：

- 后端日志提示认证失败。
- 数据库容器正常，后端连不上。

处理方式：

- 如果是新部署，使用新 volume 初始化。
- 如果必须改已有库密码，需要进入数据库执行 ALTER USER。
- 改密码前先备份。

## 5. 登录问题

### 5.1 ERP 默认账号是什么？

ERP 初始化会有管理员和业务角色账号，但正式部署后必须修改默认密码。

以当前项目文档为准，不要在生产长期使用默认账号密码。

### 5.2 APS 默认账号是什么？

APS 新库初始化默认：

```text
用户名：admin
初始密码：admin123
```

注意：

- 如果使用旧数据库 volume，密码可能已经被修改。
- 正式部署后必须立即改密。
- 初始 `admin` 账号不可删除。

### 5.3 为什么提示必须修改初始密码？

账号字段 `force_password_change` 为 true。

触发场景：

- 初始账号首次使用。
- 新增用户首次登录。
- 管理员重置密码后登录。

处理：

- 按页面提示修改密码。

### 5.4 为什么登录后刷新又回到登录页？

常见原因：

- JWT 密钥变化，旧 Token 失效。
- 浏览器 localStorage 中 Token 被清除。
- 后端时间异常导致 Token 过期判断异常。
- 前端请求的 API 地址不对。

处理：

- 清理浏览器缓存或重新登录。
- 检查 `ERP_JWT_SECRET` 或 `APS_JWT_SECRET` 是否变化。
- 检查前端 Nginx `/api` 是否正确反代后端。

## 6. ERP 与 APS 同步问题

### 6.1 APS 同步 ERP 失败，提示 401

原因：

- APS 的 `APS_ERP_AUTH_TOKEN` 与 ERP 的 `ERP_APS_SOURCE_TOKEN` 不一致。
- APS 请求没有携带 Bearer Token。
- ERP 没有重启加载新 Token。

处理：

1. 检查 ERP `erp.env`。
2. 检查 APS `aps.env`。
3. 确认两个 Token 值一致。
4. 重启 ERP 和 APS 后端。
5. 再次执行 APS 同步。

### 6.2 APS 同步 ERP 失败，提示连接不上

原因：

- `APS_ERP_BASE_URL` 配置错误。
- APS 后端容器无法访问 ERP 后端。
- ERP 后端未启动。
- 防火墙限制。

处理：

- ERP 在同一宿主机且 Docker Desktop 场景可试用：

```env
APS_ERP_BASE_URL=http://host.docker.internal:8080
```

- ERP 在另一台服务器时使用 ERP 后端内网地址。
- 在 APS 后端容器中测试网络连通性。

### 6.3 APS 同步成功但没有新工单

可能原因：

- ERP 没有新提单。
- APS 已经同步过这些 `ticketId`。
- `afterTicketId` 起点大于 ERP 当前数据。
- ERP 提单数据被删除或没有满足输出条件。

排查：

- ERP 查询提单页面是否有数据。
- APS 查询 `aps_work_item.erp_ticket_id` 最大值。
- APS 查看 `aps_erp_sync_run` 的 received/imported/skipped 统计。

### 6.4 ERP 修改了提单，APS 为什么没变化？

当前 APS 是增量拉取并以 `erp_ticket_id` 去重。

已同步的 ERP 交付项不会自动覆盖 APS 工单。这是为了避免 ERP 后续修改直接破坏 APS 已经派工或锁定的生产计划。

如果后续需要重同步，应设计专门功能：

- 指定工单重同步。
- 差异对比。
- 是否释放旧锁定。
- 是否保留派工。
- 操作审计。

## 7. 库存和派工问题

### 7.1 APS 零件库存删除失败

原因：

- 该库存存在锁定占用。

处理：

- 查零件锁定记录。
- 释放相关锁定。
- 确认没有占用后再删除。

### 7.2 APS 材料库存删除失败

原因：

- 该材料存在锁定重量。

处理：

- 查材料锁定记录。
- 释放相关锁定。
- 确认 `locked_weight_kg` 为 0 后再删除。

### 7.3 APS 派工失败，提示产能不足

原因：

- 目标部门剩余工时小于工单工时。

处理：

- 调整或重置部门产能。
- 选择其他部门。
- 检查已分配任务是否需要释放。

### 7.4 APS 删除工单要注意什么？

删除 APS 工单会释放：

- 部门派工占用。
- 零件库存锁定。
- 材料库存锁定。

应通过页面或后端接口删除，不建议手工删数据库表。

## 8. 文件和导出问题

### 8.1 ERP 图纸打不开

排查：

- 文件是否存在于 `ERP_UPLOAD_DIR`。
- 数据库中的 `drawing_url` 是否正确。
- 后端 `/uploads/**` 是否可访问。
- 外层 Nginx 是否转发 `/uploads`。
- 浏览器是否携带登录 Token。

### 8.2 报价导出失败

排查：

- 后端日志。
- 报价模板是否存在。
- `ERP_TASK_OUTPUT_DIR` 是否可写。
- 订单是否已经完成核价。
- 异步任务 `system_task` 状态和错误信息。

### 8.3 下载文件名乱码

接口已使用 `Content-Disposition` 和 UTF-8 文件名。若仍乱码：

- 检查前端下载逻辑是否读取响应头。
- 检查 Nginx 是否透传 `Content-Disposition`。
- 检查 CORS 是否暴露 `Content-Disposition`。

## 9. 备份和恢复问题

### 9.1 ERP 如何手动备份？

参考：

```text
D:\Code\交接文档\04_部署运维\ERP备份与恢复说明.md
```

### 9.2 APS 如何手动备份？

```powershell
cd D:\Code
.\scripts\backup-aps.ps1 -ProjectRoot D:\Code
```

备份目录默认：

```text
D:\Code\backups\aps
```

### 9.3 恢复演练和正式恢复有什么区别？

恢复演练：

- 使用临时 PostgreSQL 容器。
- 不覆盖当前业务库。
- 用于验证备份文件可用。

正式恢复：

- 覆盖当前业务库。
- 必须加 `-Force`。
- 执行前必须通知用户、停业务、做即时备份。

### 9.4 恢复后数据不对怎么办？

排查：

- 是否选错备份目录。
- 是否恢复到错误环境。
- 是否有多个 Docker volume。
- 前端是否访问了另一套系统。
- 外层 Nginx 是否指向正确前端。

## 10. CORS 和 HTTPS 问题

### 10.1 本地能访问，部署后接口跨域失败

原因：

- CORS 允许来源没有包含正式前端地址。

处理：

ERP：

```env
ERP_CORS_ALLOWED_ORIGINS=https://erp.example.com
```

APS：

```env
APS_CORS_ALLOWED_ORIGINS=https://aps.example.com
```

如果前端和后端通过同域 `/api` 反代，CORS 问题会少很多。

### 10.2 HTTPS 是否需要项目代码实现？

当前交接边界：

- ERP 和 APS 容器内部继续 HTTP。
- 外层 Nginx 或网关负责 HTTPS。
- 部署人员配置域名和证书。

项目代码一般不需要为了 HTTPS 修改业务逻辑。

### 10.3 内网系统是否也需要 HTTPS？

建议正式使用时由外层 Nginx 提供 HTTPS，尤其是涉及账号密码、订单、报价、图纸和生产数据。

容器内部 HTTP 是常见做法，前提是：

- 后端和数据库不直接暴露到用户网络。
- Docker 网络或服务器内网受控。
- 外层访问入口使用 HTTPS。

## 11. 日志问题

### 11.1 日志会不会无限变大？

Compose 中配置了 json-file 日志限制：

- `max-size`
- `max-file`

ERP 使用 `LOG_MAX_SIZE`、`LOG_MAX_FILE`。

APS 使用 `APS_LOG_MAX_SIZE`、`APS_LOG_MAX_FILE`。

### 11.2 如何查看最近错误？

ERP：

```powershell
docker logs quote-backend --tail 300 | Select-String -Pattern "ERROR|Exception|WARN"
```

APS：

```powershell
docker logs aps-backend --tail 300 | Select-String -Pattern "ERROR|Exception|WARN"
```

## 12. 上线前最常见遗漏

上线前重点确认：

| 项目 | ERP | APS |
| --- | --- | --- |
| env 已从 example 复制并填写 | 是 | 是 |
| 数据库密码为强密码 | 是 | 是 |
| JWT 密钥为强随机 | 是 | 是 |
| APS/ERP 对接 Token 一致 | ERP_APS_SOURCE_TOKEN | APS_ERP_AUTH_TOKEN |
| 使用生产 volume | 是 | 是 |
| 后端测试通过 | 是 | 是 |
| 前端构建通过 | 是 | 是 |

| 备份脚本可执行 | 是 | 是 |
| 恢复演练通过 | 是 | 是 |
| 默认密码已修改 | 是 | 是 |
| 后端端口未直接暴露 | 是 | 是 |
| 数据库端口未直接暴露 | 是 | 是 |
| 外层 HTTPS 入口确认 | 部署人员 | 部署人员 |

## 13. 不建议的操作

不要执行：

```powershell
docker compose down -v
```

除非明确要删除数据库 volume。

不要直接修改：

- 生产数据库结构。
- 生产用户密码哈希。
- APS 工单锁定表。
- APS 派工表。
- ERP 已生成的核心订单数据。

不要把以下内容提交到代码仓库或普通文档：

- 生产 env 文件。
- 数据库密码。
- JWT 密钥。
- ERP 与 APS 对接 Token。
- HTTPS 证书私钥。
- 生产备份文件。
